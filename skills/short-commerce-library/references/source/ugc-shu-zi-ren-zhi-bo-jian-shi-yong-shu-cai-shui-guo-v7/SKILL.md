# 直播卖水果数字人 (Digital Fruit Streamer)

## 概述

本技能用于在抖音、快手、小红书、视频号等直播平台上，使用数字人（支持3D卡通风格与写实人像风格）讲解水果进行卖货。完整流程包含五大阶段：数字人形象创建 → 水果信息采集 → 口播文案生成 → 直播背景视频生成 → 视频合成与导出。

## 涉及的模型调用

| 阶段 | 模型类型 | 工具/接口 | 用途 |
|------|----------|-----------|------|
| 数字人形象创建 | 图片模型（文生图/图生图） | `ImageGen` | 自拍照片转绘为3D卡通数字人或写实人像 / 文字描述生成数字人（卡通或写实风格） |
| 口播文案美化 | 语言大模型 | Agent自身对话能力 | 将用户卖点信息美化为直播口语化文案 |
| 直播背景视频生成 | 视频模型（文生视频/图生视频） | `VideoGen` | 生成水果农场/果园场景背景视频 |
| 数字人口播视频生成 | 数字人模型 | 外部数字人平台API | 数字人朗读口播文案，生成口播视频 |
| 视频融合合成 | 视频融合模型（参考视频生成） | `Seedance 2.0 Fast` | 以背景视频+数字人口播视频为参考，AI直接融合生成数字人在场景中介绍的视频（无需抠像） |

## 积分确认机制（强制规则）

**任何消耗积分的模型调用，在发起调用之前，必须先根据平台调用的模型算法计费机制，为用户计算本次操作的预计积分/算力消耗，向用户确认并获得明确同意后才可执行。** 该规则贯穿全部五个阶段，适用于所有付费模型调用。计费机制与消耗计算方法详见 `references/credits_policy.md`。

### 消耗积分的操作（必须先计算消耗并确认）

| 阶段 | 操作 | 消耗积分的模型 | 计费机制 |
|------|------|---------------|---------|
| 阶段一 | 数字人形象生成 / 重新生成 / 自定义（每次生成） | 图片模型 `ImageGen`（文生图/图生图） | 按生成次数计费 |
| 阶段四 | 背景视频生成（文生视频） / 图片转视频（图生视频） | 视频模型 `VideoGen` | 按生成次数/视频时长计费 |
| 阶段五 | 数字人口播视频生成（每次生成） | 数字人模型API | 按时长/次数计费 |
| 阶段五 | 最终视频融合生成（每次生成，含分段拼接） | `Seedance 2.0 Fast` | 按视频时长计费（时长越长消耗越高） |

### 不消耗积分的操作（无需确认）

- 对话问答、需求询问与信息采集
- 口播文案美化（语言大模型，Agent 自身对话能力）
- 上传素材的安全过滤、内容识别
- 文件的保存、路径记录

### 积分确认流程（每次调用付费模型前执行）

1. **发起调用前，先计算消耗，再向用户明确告知**：
   - 本次要执行的生成操作内容（如"将您的自拍照片转绘为3D卡通数字人"）
   - **计算出的预计积分/算力消耗**：根据平台各模型的计费规则（按次/按时长/按分辨率等）计算具体数值（如"图片生成 1 次 = X 积分；15秒视频 = X 积分；60秒口播视频 = X 算力"）；平台无公开计费标准时，按已知规则估算并明确标注"估算值，实际以平台结算为准"
   - 是否可能产生多次消耗（如"每次重新生成都会消耗一次积分"）
2. **等待用户明确同意**，使用标准确认话术（见下），得到用户"确认/同意"后再执行调用
3. **用户拒绝或取消**：
   - 不发起调用，不消耗积分
   - 询问用户是否调整需求后重试，或跳过该生成步骤（如跳过自定义重新生成，直接采用当前形象）
4. **生成失败重试**：若重试会产生新的积分消耗，同样需要重新计算并与用户确认；若失败不扣费可直接重试
5. **多阶段连续生成**：每个付费调用都必须单独计算消耗并确认，不可将多次生成合并为一次确认

### 标准确认话术模板

> "接下来将调用【图片模型/视频模型/数字人模型/Seedance视频融合模型】，为您【生成数字人形象/生成背景视频/生成数字人口播/融合生成最终视频】。
> 根据平台计费规则计算，本次操作预计消耗 **X 积分 / X 算力**（估算值，实际以平台结算为准），且每次重新生成都会额外消耗。
> 是否确认执行？
> - **确认** → 开始生成
> - **取消/修改** → 我可以先调整需求再生成，或跳过本步骤"

## 完整工作流程

### 阶段一：数字人形象创建

数字人形象支持两种风格，贯穿本阶段所有分支：

- **3D卡通数字人**：皮克斯/迪士尼风格3D卡通渲染形象，亲和力强，适合轻松活泼的直播氛围
- **实景人像（写实人物）**：照片级写实风格人物形象，真实感强，适合专业可信的直播氛围

#### 步骤 1.1 — 询问用户是否上传自拍照片

向用户提问：

> "是否可以上传一张您的自拍照片？我们将通过AI识别您的人像，并转绘成数字人形象。您可以自由选择生成3D卡通数字人或实景写实人像风格。"

- **用户选择上传自拍照片** → 进入步骤 1.2
- **用户没有自拍照片** → 进入步骤 1.3

#### 步骤 1.2 — 识别用户照片并选择风格，然后转绘（图生图）

1. 接收用户上传的自拍照片，识别照片中的人像特征（五官、脸型、发型等）
2. **询问用户选择风格**：

> "已识别您的人像特征。您希望将数字人生成哪种风格？
> - **3D卡通数字人**：皮克斯风格3D卡通形象，亲和力强
> - **实景人像**：照片级写实风格，真实感强"

3. 根据用户选择的风格，调用 `ImageGen` 工具，使用 **image-to-image** 模式进行人像转绘：
   - **积分确认**：发起调用前，必须先按「积分确认机制」计算并告知用户本次图片生成的预计积分/算力消耗，获得用户同意后才执行
   - 选择**3D卡通数字人** → prompt 模板参考 `references/image_prompts.md` 中的"自拍转3D卡通数字人"部分
   - 选择**实景人像** → prompt 模板参考 `references/image_prompts.md` 中的"自拍转写实人像"部分
4. 将生成的数字人形象展示给用户，并**确认图片形象**：

> "已按您选择的【3D卡通/实景写实】风格生成数字人形象（见图片）。请确认：
> - **满意** → 进入下一步，配置口播参数
> - **不满意** → 请告诉我调整方向（可切换风格，或自定义服饰/发色/长相/肤色等），我将为您重新生成（重新生成会再次消耗积分）"

5. 用户确认满意 → 进入步骤 1.5（配置口播参数）
6. 用户不满意 → 进入步骤 1.4（自定义与重新生成）

#### 步骤 1.3 — 默认形象生成（文生图，同时提供两种风格）

1. 询问用户性别（男/女）
2. **积分确认**：按「积分确认机制」计算并告知用户将同时生成两个默认形象（卡通+写实各1张，共2次图片生成的积分/算力消耗），获得用户确认后执行
3. 根据性别**同时生成两个默认形象**供用户选择：
   - **默认3D卡通数字人形象**（prompt 参考 `references/image_prompts.md` 中的"默认3D数字人生成"部分）
   - **默认写实人物形象**（prompt 参考 `references/image_prompts.md` 中的"默认写实人像生成"部分）
3. 将两个默认形象同时展示给用户，并询问：

> "已为您生成两种默认形象：
> - **形象一：3D卡通数字人** — 亲和力强，活泼有趣
> - **形象二：实景写实人像** — 真实自然，专业可信
> 您更喜欢哪一个？"

4. 用户选定其中一个形象后，**确认图片形象**——询问是否满意：
   - **满意** → 进入步骤 1.5（配置口播参数）
   - **不满意** → 进入步骤 1.4（可切换风格重新生成，或自定义外形）

#### 步骤 1.4 — 数字人形象自定义与重新生成

向用户说明可自定义的参数：

> "您可以自定义数字人的以下外形条件，告诉我您想要的调整：
> - **风格**：可随时切换为3D卡通数字人 / 实景写实人像
> - **服饰**：如休闲装、围裙、古装、运动装等
> - **发色**：如黑色、棕色、金色、粉色、蓝色等
> - **长相/风格**：如可爱风、酷飒风、亲和力强、专业感等
> - **肤色**：如白皙、小麦色、古铜色等
> - **其他细节**：眼镜、帽子、配饰等"

1. 收集用户自定义需求
2. **积分确认**：按「积分确认机制」计算并告知用户重新生成将再次消耗积分/算力（每次生成消耗一次），获得用户确认后执行
3. 调用 `ImageGen` 工具重新生成数字人形象（图生图或文生图，保持用户当前所选风格或按用户要求切换风格）
4. 将新形象展示给用户，**确认图片形象**（满意 / 继续调整），并同步说明"每次重新生成都会再次消耗积分"
5. 循环询问直到用户确认满意 → 进入步骤 1.5（配置口播参数）

> **重要提示**：每次生成数字人形象后，必须保存最终确认的数字人图片路径，后续合成阶段需要使用。

#### 步骤 1.5 — 配置数字人口播参数

数字人形象确认后，向用户收集口播参数。这些参数将用于阶段五的数字人口播视频生成：

> "数字人形象已确认！接下来请配置口播参数：
> - **口音**：普通话 / 粤语 / 四川话 / 东北话 / 河南话 / 陕西话等（支持地方方言）
> - **声音性别**：男声 / 女声（如与数字人形象性别不同，可单独指定）
> - **语速**：慢速（稳重讲解） / 正常（标准直播） / 快速（激情带货）
> - **肢体动作**：自然手势 / 适度比划 / 静态讲解
> - **是否手持物品**：是否需要数字人手持水果或道具展示（如手持芒果、举着车厘子篮、拿着西瓜等）
> - **直播具体动作**：是否需要数字人展示直播动作（如试吃品尝、剥皮展示果肉、称重展示、切开展示等）"

1. 逐项收集用户选择，如用户不确定某项可提供默认值（默认：普通话、女声、正常语速、自然手势、手持水果、展示动作）
2. 保存全部口播参数，后续数字人口播视频生成时使用
3. 进入阶段二

### 阶段二：水果信息采集

#### 步骤 2.1 — 采集水果种类（必填项）

向用户提问：

> "请告诉我您要直播卖什么水果？（如：苹果、芒果、荔枝、车厘子等）
> 如有实物图片，也可上传水果照片，我将根据图片识别水果种类和品质。"

- **必填项**：用户必须输入水果名称（或上传可识别的水果图片），否则不进入下一步
- 如用户上传水果图片，结合图片分析识别水果种类，并与用户确认
- 收集后进入步骤 2.2

#### 步骤 2.2 — 采集果实规格参数

根据水果种类询问果实规格（尺寸/大小等级/单果重量），可参考 `references/fruit_specs_guide.md`：

> "请提供您的水果规格信息：
> - **直径/大小等级**：如车厘子分3J、5J等级；葡萄/草莓按果实直径分级
> - **单果重量**：如苹果单个约200克、西瓜单个约5斤、鸭梨单个约250克等"

- **图片分析辅助**：如用户已上传水果图片，结合图片分析果实大小，并主动向用户确认："根据图片分析，您的车厘子约为3J大小，对吗？"
- **按水果种类引导**（根据种类选择对应问题）：
  - 浆果类（车厘子、葡萄、草莓、蓝莓等）→ 询问大小等级（如J级）或果实直径（mm/cm）
  - 仁果类/核果类（苹果、鸭梨、橙子、桃子、芒果等）→ 询问单个重量（克/斤）
  - 瓜类（西瓜、哈密瓜、甜瓜等）→ 询问单个重量（斤）
- 规格信息为**建议填写项**，用户提供后可用于口播文案增强说服力（如"3J大果"、"单个5斤重的西瓜"）
- 收集后进入步骤 2.3

#### 步骤 2.3 — 采集水果产地信息

向用户提问：

> "请问您的水果产地是哪里？如：山东烟台苹果、海南三亚芒果、智利进口车厘子、新疆库尔勒香梨等"

- 产地信息为**建议填写项**，用户提供后可在口播文案中增强产地背书
- 收集后进入步骤 2.4

#### 步骤 2.4 — 采集水果卖点与附加信息（选填项）

向用户提问：

> "请提供以下信息（可选填）：
> - **水果卖点**：如产地直发、新鲜采摘、甜度XX度、有机种植等
> - **发货时间**：如48小时内发货、当天发货等
> - **优惠活动**：如买二送一、限时折扣、满减等"

- 用户可以填写一项或多项，也可以全部跳过
- 收集后进入步骤 2.5

#### 步骤 2.5 — 水果信息汇总核对（必须确认）

将阶段二采集到的全部信息汇总展示给用户，**逐项核对确认**：

> "请核对以下水果信息，确认无误后我们再进行下一步：
> - **水果名称**：芒果
> - **果蔬大小/规格**：单果约250克（未提供 → 请补充，或确认不展示）
> - **产地**：海南三亚（未提供 → 请补充，或确认不展示）
> - **发货时间**：48小时内发货（未提供 → 请补充，或确认不展示）
> - **优惠活动**：买三送一（未提供 → 请补充，或确认不展示）
> - **卖点**：树上熟、甜度18度"

- **核对重点**：产地、发货时间、是否有优惠信息、果蔬大小（规格/重量）四项必须逐一列出核对，**缺失项明确提示用户补充**（用户可选择不展示）
- 用户确认无误 → 进入阶段三
- 用户补充/修改 → 更新对应信息后再次汇总展示核对
- 循环直到用户确认全部信息无误
- 核对后的信息将作为口播文案生成（阶段三）的最终依据

### 阶段三：口播文案生成

#### 步骤 3.1 — 询问是否需要美化文案

向用户提问：

> "您输入的卖点信息可以原样作为口播文案，也可以由AI帮您美化成更适合直播间表达的口语化文案。是否需要美化文案？"

- **不需要美化** → 直接使用用户输入的卖点信息作为口播文案，进入步骤 3.3
- **需要美化** → 进入步骤 3.2

#### 步骤 3.2 — 调用语言大模型美化文案

1. 将用户输入的水果名称、果实规格（直径/大小等级/单果重量）、产地、卖点、发货时间、优惠活动等信息整合
2. 按照直播间口播风格进行美化，美化要点参考 `references/script_guide.md`
3. 将美化后的口播文案展示给用户
4. 进入步骤 3.3

#### 步骤 3.3 — 确认口播文案（必须确认）

将口播文案**全文展示**给用户（不可只展示摘要），并请用户逐项核对文案中的关键信息（水果名称、规格、产地、发货时间、优惠活动）与步骤 2.5 核对确认的信息一致，然后询问：

> "以上是完整口播文案，请确认：
> - **确认无误** → 进入阶段四
> - **直接修改** → 请直接给我修改后的文案，或告诉我需要修改的内容
> - **重新生成** → 我将重新为您生成文案
> - **具体修改建议** → 请告诉我如何调整（如：更热情一点、加入价格、缩短到30秒内等）"

- 用户确认后 → 进入阶段四
- 用户要求修改 → 根据用户反馈重新生成/修改文案，再次全文展示并确认
- 循环直到用户确认满意，**未经用户确认的口播文案不得进入阶段四**

> **重要提示**：保存最终确认的口播文案文本，后续数字人口播和视频时长计算需要使用。

### 阶段四：直播背景视频

#### 步骤 4.1 — 询问用户是否有直播场景素材

向用户提问：

> "您是否有直播场景素材？可以上传30秒以内的短视频或图片作为直播背景。
> - 如果有，请上传
> - 如果没有，我可以为您生成水果场景背景视频"

- **用户上传视频/图片** → 进入步骤 4.2
- **用户没有素材** → 进入步骤 4.3

#### 步骤 4.2 — 上传素材安全过滤

对用户上传的视频或图片进行内容安全过滤：

1. 检查内容是否涉及违规内容（色情、赌博、毒品等违反社区规定的内容）
2. **如果检测到违规内容**：
   - 拒绝该素材
   - 提示用户："您上传的内容违反了社区规定，请重新上传合规的素材。"
   - 返回步骤 4.1 重新询问
3. **如果内容合规**：
   - 进入步骤 4.4

#### 步骤 4.3 — AI生成水果场景背景视频

1. 询问用户："您需要生成横屏还是竖屏的背景视频？"
   - **横屏**（16:9）→ 适合抖音/快手横屏直播
   - **竖屏**（9:16）→ 适合竖屏直播
2. **积分确认**：按「积分确认机制」计算并告知用户将调用视频模型生成15秒背景视频的预计积分/算力消耗，获得用户确认后执行
3. 调用 `VideoGen` 工具，根据水果种类生成场景视频：
   - prompt 参考 `references/video_prompts.md` 中的"水果农场场景"模板
   - 生成时长：15秒
   - 尺寸根据用户选择的横屏/竖屏
3. 将生成的背景视频展示给用户
4. 进入步骤 4.5

#### 步骤 4.4 — 上传素材生成背景视频

1. **积分确认**：按「积分确认机制」计算并告知用户将调用视频模型把图片/视频转换为15秒背景视频的预计积分/算力消耗，获得用户确认后执行
2. 如果用户上传的是图片 → 调用 `VideoGen` 的 image-to-video 模式，将图片转换为15秒动态背景视频
3. 如果用户上传的是短视频 → 直接使用该视频作为背景（或根据需要调用视频模型进行风格化处理，如需处理同样先积分确认）
4. 询问用户横屏还是竖屏
5. 将生成的背景视频展示给用户
6. 进入步骤 4.5

#### 步骤 4.5 — 确认背景视频

向用户展示背景视频，并询问：

> "背景视频已生成/处理完成，请确认：
> - **满意** → 进入阶段五
> - **不满意/需要修改** → 请告诉我您的修改建议（如：换个场景、更明亮、加入水果特写等）"

- 用户确认满意 → 进入阶段五
- 用户要求修改 → 根据用户反馈调整prompt重新生成，再次展示并确认
- 循环直到用户确认满意

> **重要提示**：保存最终确认的背景视频文件路径。

### 阶段五：视频合成与导出

#### 步骤 5.1 — 确认数字人位置

向用户提问：

> "数字人将放置在画面中的哪个位置？
> - **左侧**
> - **中间**
> - **右侧**"

- 记录用户选择的位置参数

#### 步骤 5.2 — 数字人口播视频生成

1. **积分确认**：按「积分确认机制」计算并告知用户将调用数字人模型生成口播视频的预计积分/算力消耗（按口播时长计费，时长越长消耗越高；每次重新生成都会额外消耗），获得用户确认后执行
2. 将确认的数字人形象图片和口播文案传入数字人模型
3. 调用数字人模型生成口播视频：
   - 数字人声情并茂地朗读口播文案
   - 口播时长根据文案长度自动计算
   - 生成包含数字人口播的说话视频
4. 生成完成后进入步骤 5.3

> **技术说明**：数字人口播视频生成依赖外部数字人平台API。需确认API已配置并可调用。参考 `references/digital_human_api.md` 了解API对接方式。

#### 步骤 5.3 — 确认最终视频时长

数字人口播视频生成后，向用户确认最终视频时长：

> "数字人口播预计时长约 **X 分 X 秒**（按口播文案与语速估算）。
> 请确认最终视频时长：
> - **与口播时长一致**（推荐）：视频随口播完整结束
> - **指定时长**：请告诉我您期望的时长（如30秒、60秒、90秒），我将按该时长生成并适配口播内容"

- **默认推荐**：最终视频时长 = 数字人口播时长
- 用户指定时长 < 口播时长 → 提示用户需精简口播文案或加快语速，回到阶段三调整文案
- 用户指定时长 > 口播时长 → 告知用户视频将在口播结束后以场景画面收尾
- 记录确认的最终视频时长参数，供步骤 5.4 融合生成与时长控制使用

#### 步骤 5.4 — 调用 Seedance 2.0 Fast 融合生成最终视频（无需抠像）

使用 **Seedance 2.0 Fast** 视频融合模型，以背景视频和数字人口播视频为参考，直接生成数字人在场景中介绍水果的融合视频：

1. **积分确认**：按「积分确认机制」计算并告知用户将调用 Seedance 2.0 Fast 融合生成最终视频的预计积分/算力消耗（按时长计费，时长越长消耗越高；分段生成/重新生成都会额外消耗），获得用户确认后执行
2. **输入参考**：
   - 参考视频一：背景场景视频（阶段四确认）
   - 参考视频二：数字人口播视频（步骤 5.2 生成）
   - 融合 prompt：描述数字人站在场景中介绍水果的画面，**必须包含用户选择的位置（左/中/右）**
2. **融合生成要求**（写入 prompt）：
   - 数字人**完整出现在画面中**，身体任何部位不得被画面边缘裁剪
   - 数字人为**实体不透明人物**，严禁出现半透明/透明效果
   - 数字人**自然融入场景**：光照方向与场景一致、色调协调、有接地感，如同真实站在场景中拍摄
   - 保持数字人五官、服饰、手持物品与口播视频一致，保持口型与口播内容同步
   - 背景场景延续参考视频一的取景与氛围
3. **时长控制**：按步骤 5.3 确认的最终视频时长生成；若单次生成时长不足，分段生成后按时间顺序无缝拼接
4. 融合生成的 prompt 模板、调用参数与时长处理方法参考 `references/seedance_fusion.md`

> **技术说明**：本方案不使用抠像/叠加合成技术，直接由 AI 融合模型生成"数字人在场景中"的一体化视频，融合效果更自然。依赖 Seedance 2.0 Fast 模型接口，使用前需确认模型已接入并可调用。

#### 步骤 5.5 — 确认最终视频（含时长核对）

向用户展示最终融合视频，并询问：

> "最终直播视频已融合生成完成，时长 **X 分 X 秒**，请确认：
> - **满意** → 可以导出/下载
> - **不满意** → 请告诉我需要调整的地方（如：数字人位置、人物完整性、融合自然度、时长、场景氛围等）"

- 展示时必须**明确告知实际视频时长**，并与步骤 5.3 确认的时长核对；不一致时说明原因并询问是否重新生成
- 交付前执行**质量自检**（参考 `references/seedance_fusion.md` 的质量校验清单）：数字人完整不裁剪、不透明、位置正确、口型同步、融合自然、时长符合
- 用户满意 → 进入步骤 5.6
- 用户不满意 → 根据用户反馈调整融合 prompt 参数，重新生成，再次展示并确认
- 循环直到用户确认满意

#### 步骤 5.6 — 导出/下载

1. 将最终合成视频导出为MP4格式
2. 提供下载链接给用户
3. 询问用户是否需要调整分辨率或格式

## 流程速查

```
数字人创建 → 口播参数 → 水果信息 → 口播文案 → 背景视频 → 视频合成 → 导出

[0] 积分/算力确认（强制，贯穿全程）
    └─ 每次调用付费模型(ImageGen/VideoGen/数字人/Seedance)前，必须先按平台计费机制计算预计消耗，告知用户并获得确认

[1] 数字人创建（支持3D卡通 / 实景写实人像两种风格）
    ├─ 有自拍 → 识别人像 → 用户选风格(卡通/写实) → [积分确认] → ImageGen图生图转绘 →
    │   展示图片 → 确认形象(满意→1.5 / 不满意→1.4重新生成)
    └─ 无自拍 → 询问性别 → [积分确认] → 同时生成默认卡通+写实两个形象 → 展示图片 →
        用户二选一 → 确认形象 → 不满意进入1.4自定义外形 → 确认形象

[1.5] 口播参数配置
    └─ 口音(方言) / 男声或女声 / 语速 / 肢体动作 / 是否手持物品 / 直播动作

[2] 水果信息
    ├─ 必填：水果名称（可上传图片辅助识别）
    ├─ 规格：直径/大小等级(如车厘子3J/5J) 或 单果重量(如苹果200g、西瓜5斤)
    ├─ 产地：如山东烟台、海南三亚、智利进口等
    ├─ 选填：卖点、发货时间、优惠活动
    └─ 2.5 汇总核对（必须）：产地/发货时间/优惠/果蔬大小逐项核对确认，缺失项提示补充

[3] 口播文案
    ├─ 不美化 → 原样使用（不消耗积分）
    └─ 美化 → LLM口语化 → 全文展示+关键信息核对 → 用户确认（必须）/修改/重新生成

[4] 背景视频
    ├─ 有素材 → 安全过滤 → [积分确认] → 图生视频/直接使用
    └─ 无素材 → 询问横竖屏 → [积分确认] → VideoGen文生视频(15s) → 确认/重新生成

[5] 视频合成（AI融合生成，无需抠像）
    └─ 选位置(左/中/右) → [积分确认] → 按口播参数生成数字人口播 → 确认最终视频时长 →
       [积分确认] → Seedance 2.0 Fast 双参考融合生成(完整/不透明/自然融入) + 质量自检 →
       确认(含时长核对)/重新生成 → 导出
```

## 注意事项

1. **积分/算力确认（最高优先级）**：任何消耗积分的模型调用（ImageGen / VideoGen / 数字人模型 / Seedance 2.0 Fast），发起前必须先按平台模型计费机制计算预计积分/算力消耗，告知用户并获得明确同意；用户拒绝时不得调用，不得擅自扣费
2. **安全过滤**：用户上传的视频/图片必须进行内容安全检查，拒绝黄赌毒等违规内容
3. **必填项校验**：水果名称为必填项，不可跳过；数字人形象与口播参数需确认后才可进入下一阶段
4. **数字人形象确认**：数字人形象图片生成后必须展示给用户确认（满意/重新生成），未经用户确认的形象不得进入后续阶段；重新生成前需再次积分确认
5. **水果信息核对**：阶段二必须执行步骤2.5汇总核对，重点核对产地、发货时间、优惠信息、果蔬大小四项，缺失项提示补充或确认不展示
6. **口播文案确认**：口播文案必须全文展示并由用户确认（关键信息与核对结果一致），未经确认的文案不得进入阶段四
7. **循环确认机制**：每个阶段都设有用户确认环节，不满意时可循环重新生成；每次重新生成消耗积分，均需重新计算消耗并确认
8. **文件路径管理**：各阶段产出的文件路径需保存，最终合成阶段需要调用
9. **时长确认**：阶段五必须与用户确认最终视频时长（默认与口播时长一致），交付时核对实际时长并明确告知
10. **模型依赖**：数字人口播视频生成依赖外部数字人平台API，最终融合合成依赖 Seedance 2.0 Fast 模型接口，使用前需确认两者均已接入可调用
11. **口播参数传递**：阶段1.5配置的口音/音色/语速/动作/手持物品/直播动作等参数，必须在阶段5.2生成数字人口播视频时完整传递
12. **规格参数应用**：采集到的果实规格（直径/大小等级/单果重量）和产地信息，应自然融入口播文案增强说服力
13. **数字人完整性**：融合生成时数字人必须完整入画，严禁裁剪导致头顶/身体不完整；该要求必须写入融合prompt
14. **数字人不透明**：融合生成的数字人必须为实体不透明人物，严禁出现半透明/透明体；该要求必须写入融合prompt
15. **自然融合**：采用 Seedance 2.0 Fast 参考视频融合方案（背景视频+数字人口播视频→一体化生成），不使用抠像/叠加技术；生成后必须通过质量自检再交付用户确认
