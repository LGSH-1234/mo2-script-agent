# 积分确认指南 (Credits Policy)

本文档是「直播卖水果数字人」技能中**积分确认机制**的详细执行指南。核心原则：**任何消耗积分的模型调用，发起之前必须先根据平台模型计费机制计算预计积分/算力消耗，向用户确认并获得明确同意后才可执行。**

## 一、消耗积分的操作清单

| 阶段 | 操作 | 模型 | 计费机制 |
|------|------|------|---------|
| 阶段一 步骤1.2 | 自拍照片转绘数字人（图生图） | ImageGen | 按生成次数计费 |
| 阶段一 步骤1.3 | 默认形象生成（卡通+写实各1张，共2张） | ImageGen | 一次确认消耗2次 |
| 阶段一 步骤1.4 | 自定义/重新生成数字人形象 | ImageGen | 按生成次数计费，每次1次 |
| 阶段四 步骤4.3 | AI生成15秒背景视频（文生视频） | VideoGen | 按次数/视频时长计费 |
| 阶段四 步骤4.4 | 图片转背景视频 / 素材风格化（图生视频） | VideoGen | 按次数/视频时长计费 |
| 阶段五 步骤5.2 | 数字人口播视频生成 | 数字人模型API | 按时长/次数计费，口播越长消耗越高 |
| 阶段五 步骤5.4 | 最终视频融合生成（含分段拼接） | Seedance 2.0 Fast | 按视频时长计费，分段生成/重新生成均额外消耗 |

## 二、积分/算力消耗计算方法（发起调用前必须先计算）

### 计算步骤

```
第1步：确认本次调用的模型与生成参数
        （模型类型、生成次数、视频时长、分辨率等）
第2步：查询平台该模型的计费规则
        （按次计费：单价 × 次数；按时长计费：单价/秒 × 秒数）
第3步：套用公式计算预计消耗，得出具体数值
第4步：向用户展示计算过程与结果，请用户确认
```

### 各模型计算公式

| 模型 | 计费机制 | 计算公式 | 示例 |
|------|---------|---------|------|
| ImageGen 图片生成 | 按生成次数 | 单价 × 生成张数 | 单价 P 积分/张 × 2张（双默认形象）= 2P 积分 |
| VideoGen 背景视频 | 按次数/时长 | 单价 × 时长（或按次） | 15秒视频 = 单价/秒 × 15s |
| 数字人口播 | 按时长 | 单价/秒 × 口播时长（按语速与字数估算） | 60秒口播 = 单价/秒 × 60s |
| Seedance 2.0 Fast 融合 | 按时长 | 单价/秒 × 最终视频时长（分段时求和） | 90秒（60s+30s两段）= 单价/秒 × 90s |

### 口播时长估算（用于按时长计费模型的消耗计算）

- 正常语速约 **4字/秒**（240字/分钟）；慢速约3字/秒；快速约5字/秒
- 口播时长 ≈ 文案字数 ÷ 语速字数/秒
- 示例：180字文案、正常语速 → 约45秒口播 → 数字人模型消耗 = 单价/秒 × 45s

### 计算结果展示要求

1. **给出具体数值**：优先按平台计费规则算出"本次预计消耗 X 积分 / X 算力"
2. **展示计算依据**：简要说明计算过程（如"15秒 × 2积分/秒 = 30积分"），让用户看得懂
3. **估算值标注**：平台无公开计费标准时，按已知规则估算并注明"估算值，实际以平台结算为准"
4. **多次消耗提示**：如流程中可能多次生成（循环确认不满意），预估时按"单次消耗 × 可能次数"给出区间提示
5. **全流程消耗预估**：用户询问"整个流程要花多少"时，汇总各阶段预计消耗给出总预算表

## 三、不消耗积分的操作（无需确认）

- 对话问答、需求询问与信息采集
- 口播文案美化（语言大模型，Agent 自身对话能力）
- 上传素材的安全过滤、内容识别
- 文件保存、路径记录、状态管理

## 四、确认流程（每次调用付费模型前执行）

```
调用付费模型前
      │
      ▼
根据平台计费机制计算本次预计消耗（见第二节计算方法）
      │
      ▼
告知用户：①本次生成操作内容  ②计算出的预计积分/算力消耗  ③是否可能多次消耗
      │
      ▼
等待用户明确同意（确认话术见下）
      │
      ├─ 用户【确认】 → 发起模型调用
      ├─ 用户【取消】 → 不调用、不消耗；询问调整需求后重试或跳过该步骤
      └─ 用户【询问明细】→ 展示计算依据后再确认
```

### 标准确认话术

> "接下来将调用【图片模型/视频模型/数字人模型/Seedance视频融合模型】，为您【生成数字人形象/生成背景视频/生成数字人口播/融合生成最终视频】。
> 根据平台计费规则计算，本次操作预计消耗 **X 积分 / X 算力**（估算值，实际以平台结算为准），且每次重新生成都会额外消耗。
> 是否确认执行？
> - **确认** → 开始生成
> - **取消/修改** → 我可以先调整需求再生成，或跳过本步骤"

### 各步骤确认话术示例（含计算过程）

**阶段一 数字人形象生成：**

> "接下来将调用【图片模型】为您生成数字人形象，按平台计费规则计算：1张 × P积分/张 = **P 积分**。确认生成吗？每次重新生成都会再次消耗。"

**阶段一 无自拍默认形象（双形象）：**

> "将同时为您生成【3D卡通】和【实景写实】两个默认形象，共2张：2 × P积分/张 = **2P 积分**。确认生成吗？"

**阶段四 背景视频生成：**

> "接下来将调用【视频模型】为您生成15秒水果场景背景视频：15秒 × R积分/秒 = **15R 积分**。确认生成吗？不满意可以按您的要求修改后重新生成，每次重新生成都会额外消耗。"

**阶段五 数字人口播：**

> "接下来将调用【数字人模型】生成口播视频。您的口播文案约 X 字，按正常语速估算口播时长约 Y 秒：Y秒 × D积分/秒 = **YD 积分 / 算力**。确认生成吗？"

**阶段五 Seedance 融合：**

> "接下来将调用【Seedance 2.0 Fast】融合生成最终视频，按时长计费：最终时长 Z 秒 × S积分/秒 = **ZS 积分**。确认生成吗？如需分段生成或重新生成，将产生额外消耗。"

## 五、特殊场景处理

| 场景 | 处理方式 |
|------|---------|
| 用户拒绝积分确认 | 不发起调用；询问是调整需求后重试，还是跳过该生成步骤（如跳过自定义重生成，直接采用当前形象） |
| 生成失败 | 若失败不扣费 → 可直接重试；若重试会扣费 → 必须先重新计算消耗并与用户确认 |
| 多次重新生成（循环确认不满意） | 每次重新生成前都必须单独计算消耗并确认，不可合并为一次确认后连续生成 |
| 多步骤连续生成 | 每个付费调用单独确认，禁止"一次确认覆盖后续所有生成" |
| 用户询问总消耗 | 汇总已消耗+待消耗积分明细（含各阶段计算过程），透明告知 |
| 用户询问全流程预算 | 按第二节方法预估全流程总消耗，给出预算表（各阶段明细+总计） |
| 积分不足 | 提示用户积分不足，暂停生成，询问充值或调整方案（减少生成次数、缩短视频时长、复用已有素材等） |
| 计费标准不明确 | 按已知规则估算并标注"估算值，实际以平台结算为准"，不虚报、不承诺 |
| 平台计费规则变更 | 以平台最新规则为准重新计算，并向用户说明变更 |
| 用户要求跳过确认 | 必须礼貌拒绝："为了确保您的积分使用透明，每次生成前都需要您的确认。" |

## 六、透明沟通原则

1. **先算后报**：先根据平台计费机制计算出具体数值，再告知用户；计算过程可展示
2. **事前告知**：积分消耗信息必须在调用前告知，绝不先斩后奏
3. **如实告知**：有计费标准就报具体值，没标准就按已知规则估算并标注"以平台结算为准"，不夸大不隐瞒
4. **单次确认**：每次生成（含重新生成）都单独计算、单独确认，让用户对每次消耗都有掌控
5. **拒绝保护**：用户拒绝时立即停止，不反复诱导、不擅自扣费
6. **消耗透明**：用户可随时询问已消耗积分与剩余积分，如实汇总作答
