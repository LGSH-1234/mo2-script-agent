
# 说服质量契约（商品专属性 · 证明闭环 · 功能耐用品证明 · 情绪因果 · 新鲜机制 · 转化收束）

> 本文件是“脚本为什么值得看、为什么可信、为什么只能由这个商品完成、为什么值得行动”的唯一权威正文。它不增加面向用户的格式，不要求输出内部分析；它只约束第 3 步的方案选择、第 4 步的实际故事脚本以及进入生成前的质量验收。

## 1. 先过可执行性门，不把输入问题伪装成创意问题

创意候选生成前，先整理 `brief_integrity`：

- 用户明确指定的人群、场景、时长、比例、语言、商品、品牌、SKU、数量、价格、Hook、Play、Style、固定文案、禁止项与审核节点；
- 参考素材能确认与不能确认的事实；
- 输入内部的冲突与缺失，例如“必须展示某功能”但又“禁止商品出现”、两张素材指向不同商品、主张需要证据但素材不可读取；
- 所有未解决冲突、不可读取的关键素材和未经支持的高风险主张。

硬性要求：每个用户点名的必需元素都要在内部登记为 `covered / blocked / user_waived`。`blocked` 不得被创意包装掩盖；先向用户提出一个最小问题，或改成素材和事实能够支持的低风险表达。品牌、SKU、数量和结构必须逐字逐项从权威来源抄录，禁止凭“看起来像”补全。

## 2. 商品专属因果门

故事不是“一个完整情节 + 中间放入商品”，而是：**商品事实制造或解决了一个无法被普通同类商品无损替换的关键节点。**

内部必须完成替换测试：把当前商品替换成一个无品牌、同品类的普通商品后，Hook、关键动作、证明、结果、人物决定或 CTA 中至少两处必须需要重写；否则判为通用植入，重新选机制。

商品专属可以来自：确切结构、使用动作、口感/声音、规格组合、包装开启方式、商品与人物关系、经验证的功能路径、品牌资产、价格机制或用户明确选择的模板与商品事实的独特组合。仅在台词中念品牌名、把包装摆进画面、换颜色/场景/人物，不算商品专属。

## 3. 主证明闭环门

每条视频只选一个主证明。主证明必须形成：

`买家顾虑或前态 → 当前商品的具体动作 → 同一对象上的可观察变化 → 可核验结果 → 人物判断/任务后果`

最小可验收链可简记为：`前态 → 商品动作 → 可观察变化 → 结果`。

硬性要求：

- 包装展示只能证明“这是哪个商品”，不能证明功能、口感、体验或效果；
- 口播只能解释已经发生的证明，不能代替证明；
- 幻想特效可以放大感受，但必须有一个真实可观察的基础动作或结果作锚；
- 人物惊讶、围观、微笑、被种草只能发生在证明之后，不能替代证明；
- 高风险功效、时长、性能、绝对化、安全或背书主张必须有权威依据；没有依据就改成合规的使用动作、即时物理结果、主观体验或场景结果；
- 证明所需的动作、商品面、结构或界面缺素材时，回到素材门补证据或降低动作风险，不虚构。

## 4. 情绪因果门

剧情、爱情、家庭、反转、喜剧、人物 UGC 等人物主导内容，必须形成：

`具体压力/欲望 → 人物做出选择 → 商品动作产生证据 → 人物因为证据改变判断或决定 → 关系/任务/处境发生可见变化`

“疲惫—看到礼物—微笑”“被嘲讽—展示商品—围观惊讶”这类只有情绪标签、没有证据触发的跳变不通过。人物变化必须能回答：**他究竟看见、听见或体验了什么，才改变了决定？**

非人物主导内容可把此门标为不适用，但必须说明由什么物体、任务或环境状态变化承担回报，不能留空。

## 4A. 功能型硬件与耐用品专项证明门

当商品的购买理由主要来自“能完成某项任务、改善操作过程或长期承担某种功能”时，启用本门。典型对象包括 3C、电脑及手机配件、小家电、工具、办公设备、功能家居、耐用品和硬件 + App 组合；是否启用取决于本条主张是否依赖功能，不按品类名称机械判断。纯造型展示、收藏品或只卖审美的款式可标不适用，但必须说明原因。

启用后，外观、配色、透明材质、旋转、悬浮、液态特效、走秀或包装陈列只能承担 Hook、审美和商品识别，**不得成为唯一证明**。脚本必须同时落地：

1. `functional_action`：当前商品真实执行至少一个与购买理由直接相关的功能动作；点击、滑动、连接、开合、操控、输出、收纳、照明等动作必须符合已知产品事实与素材证据。
2. `user_task_result`：同一用户任务在动作后得到可观察结果，例如完成选择、提高定位精度、减少步骤、稳定连接、完成清洁或让具体操作继续推进。只拍人物惊讶或商品变漂亮不算任务结果。
3. `user_benefit`：把结果翻译成一个具体使用收益；不得只说“更好用”“高级”“有质感”。有转化目标时仍须按转化收束门提供明确 CTA。
4. `sku_variant_coverage`：用户明确要求展示 N 个 SKU、颜色或款式时，内部逐项或逐数量登记，并让实际故事脚本覆盖至少 N 个可区分对象；不得用“一排产品”“多色闪过”等模糊词冒充完整覆盖。用户没有明确数量时不自行扩充 SKU。

这是一条规则门，不是鼠标、液态色彩或某个案例的固定脚本。视觉奇观可以保留，但必须服务于功能动作、任务结果或款式选择；若奇观挤压了上述证据，优先缩短奇观而不是删除功能证明。

## 5. 新鲜机制门

新鲜度不等于换语言、换场景、换演员、加粒子、加冰霜或加入一个流行模板。内部必须写清一个 `product_specific_mechanism`：商品的哪条真实特征与哪种叙事/视觉规则结合，制造了此前没有的状态变化。

以下任一情况判为表层换皮并重写：

- 换成同类商品后镜头顺序与台词基本不变；
- 创意仅是“痛点提问—展示—好评—CTA”的通用序列；
- 奇观只改变背景，没有作用到人物、商品或任务；
- 模板标志动作被保留，但与商品动作和证明互不影响；
- 只靠形容词、地域语言或音乐制造“新鲜”。

## 6. 转化收束门

CTA 不是片尾附加句，必须承接观众刚刚看见的证据或情绪回报：

`已见证的结果 → 当前商品的选择理由 → 明确行动`

有购买、搜索、商品卡、预约、到店或获客目标时，内部必须登记 `choice_reason / witnessed_evidence / action`，并确保三者属于同一条因果链。只有“点击购买”“同款搜商品名”而没有前置选择理由，只能算形式完整，不能算转化闭环。

## 7. 两道实际产物验收门

### 第 3 步：结构化说服合同

在 `validate_creative_contract.py` 使用的内部 JSON 中填写：

- `persuasion_quality_contract.brief_integrity`
- `persuasion_quality_contract.product_exclusivity`
- `persuasion_quality_contract.proof_chain`
- `persuasion_quality_contract.functional_durable_goods_guard`
- `persuasion_quality_contract.emotional_causality`
- `persuasion_quality_contract.novelty_mechanism`
- `persuasion_quality_contract.conversion_closure`
- 顶层 `quality_acceptance_contract`

字段模版见 `references/contract-json-schemas.md`。任何一项只靠口播、包装文字、无依据反应或纯特效代替真实证明，任何商品替换测试未通过，或适用的功能耐用品只拍外观而没有功能动作、任务结果、具体利益点与用户要求的款式覆盖，均不得进入故事脚本。

### 第 4 步：回看实际故事脚本

`quality_acceptance_contract.requirements` 必须使用当前项目真实动作和结果派生的字面证据，至少验收：商品动作、可观察结果、改变后的结局；人物剧情再验收情绪转折，转化任务再验收 CTA。不得写“使用产品”“效果明显”“人物感动”之类无法验收的空词。

将同一份 `quality_acceptance_contract` 原样传给 `validate_story_script.py`。校验器会在实际分镜里回看这些证据词与 `商品动作 → 可观察结果 → 改变后的结局/CTA` 的先后顺序，但这属于 `warnings`(提示、不阻塞 `ok`)——逐字命中与否是语义判断，收到提示时自查：确属漏写了该环节就补进故事脚本，只是换了等价说法就忽略，不为字面命中把好表达改生硬，也不得只改合同迎合产物。

## 8. 高质量选择门

候选方案进入脚本前，必须同时满足：

1. Hook 在开场成立，并把问题交给商品动作；
2. 当前商品不可被普通同类无损替换；
3. 主证明包含前态、动作、变化和结果；
4. 人物反应或任务后果由证明触发；
5. 创意机制不只是模板换皮；
6. CTA 承接选择理由；
7. 所有关键事实、SKU、品牌、数量、结构和主张均与权威输入一致；功能型硬件/耐用品还必须完成真实功能动作、用户任务结果、具体利益点及用户明确数量的 SKU/款式覆盖。

任一项失败，先重选或重写候选；不要用更长的说明、更多卖点、更多镜头或更华丽的特效掩盖失败。
