
# 素材与本地化契约（市场/语言/人物本地化 · 素材隔离 · 多图局改 · 素材台账 · 禁止自生成产品图）

> 本文件是以下约束的**唯一权威正文**：市场、语言与人物本地化合同、商品素材与达人素材隔离合同、多图借鉴与局部修改绑定合同、参考素材台账合同、禁止 Agent 自行生成产品图合同。SKILL.md 只做激活与调度，遇到这些主题以本文件为准。

### 市场、语言与人物本地化合同

平台、目标市场、语言、人物身份与人物参考是不同维度，必须分别登记、再检查组合是否一致。语言约束不能只作用于台词和字幕而漏掉人物与生活语境。

先建立内部本地化状态：

```yaml
localization_contract:
  target_market:
  platform:
  spoken_language:
  on_screen_language:
  cast_localization:
  character_reference_authority: locked_by_user | unlocked_reference | agent_generated | none
  locale_inference_source:
  conflicts: []
```

- 用户明确指定市场时，以该市场为准。若未写市场，但同时要求单一当地语言、当地电商平台或当地购买路径，可把市场作为**可修改的低风险本地化默认值**，不是商品事实；例如全片仅泰语并投 TikTok/TikTok Shop、且无相反信息时，默认 `target_market: Thailand`。
- 只要目标市场已确定且人物未被用户锁定，角色、达人、路人和家庭成员默认采用当地可信人物与生活语境。泰国市场默认生成泰国成年人物，并使用当代泰国环境、服装和行为细节；不以夸张民族符号替代真实本地化。
- `locked_by_user` 的人物参考优先于市场默认值：保持其身份，同时在内部记录本地化覆盖原因。用户上传了一张人物图但没有说必须照此身份生成时，不自动视为锁定；按素材角色和上下文判断，无法判断且会实质改变人物身份时只问一个最小问题。
- `unlocked_reference / agent_generated / none` 不得压过市场本地化。系统自动搜索或生成的西方面孔不能因为“画面质量合格”就用于泰国本地广告；质量自检必须同时检查市场匹配。
- 市场本地化不要求所有人物长相完全相同，也不凭语言对具体个人国籍下结论；它决定的是默认选角方向、生活场景、表演语气和商业语境。
- 最终脚本与 Prompt 中的人物描述、语言、场景和 CTA 必须相互一致。若 `target_market / spoken_language / cast_localization` 出现无用户授权的冲突，判为阻塞项并自动修正；只有用户锁定来源相互冲突时才询问。

### 商品素材与达人素材隔离合同（硬性）

当用户上传商品图片，同时视频需要人物、模特、角色或达人形象图时，必须把两类素材彻底分工：

- **达人/人物形象图只生成人物，不带商品，且用白底干净出图。** 生成人物、角色、达人、模特形象参考图时，**默认白色（或纯净中性）背景、干净构图、只有人物本身**——不要让图中出现营销商品、商品包装、商品同款道具、购物袋、包装盒、Logo 牌、商品卡、货架、手持物或任何可能被误认为 `产品1` 的物体，也不要加杂乱场景、多余道具或复杂背景。人物图只稳定五官、发型、体型、妆容、服装风格、姿态、气质和人设，作为纯净的人物身份参考。**生成人物/角色/达人形象参考素材图时，若用户没有明确指定比例，一律默认使用 `3:4`；仅当用户明确要求其它比例、或该素材有明确的下游取景/关键帧构图需要另一比例时才偏离该默认。此默认只作用于人物素材图的生成，不改变整片视频的比例，也不覆盖商品、场景等其它类型素材各自的取景需要。**
- **产品与人物的关系（拿放、使用、互动、所处场景）不在人物图里预置，全部交给 `视频生成Prompt.md` 控制。** 人物图阶段只解决"这个人长什么样"；"人怎么拿产品、怎么用产品、在什么场景用"这类产品使用方式与人货关系，一律在视频生成 Prompt 的分镜里按已确认的商品素材与商品模型描述，由视频模型在生成时合成。不得为了"提前看到效果"而在人物图里合成商品或摆出持握/使用姿态。
- **商品图只绑定产品，不绑定达人服装。** 制作视频时，达人图是 `主体1/达人1` 的人物形象参考；用户商品图或商品系统素材才是 `产品1` 的唯一外观权威。不得把达人图里的衣服、配饰、包、帽子、背景摆件、图案、手持物误认为需要营销的商品，也不得用它们替代用户商品图。**若达人身上的衣服/配饰本身就是被营销的商品，必须由用户明确说明，并把它注册为商品素材或商品事实，否则一律按人物服装处理、不当作 `产品1`。**
- **素材角色必须显式写清 adopted / ignored dimensions。** 例如：`@图片1为商品图，只采用产品1的正面包装、颜色、形状、Logo位置和大小比例，不采用图片背景或人物；@图片2为达人图，只采用人物五官、发型、妆容、服装风格和姿态，不采用其中任何物品作为产品1。`
- **人物图阶段绝不提前合成商品或使用场景。** 人物图保持白底干净人像即可；商品、场景、使用动作只在视频分镜中按已确认的商品素材出现，由 `视频生成Prompt.md` 统一控制。既不在人物图里放商品，也不在人物图里摆使用姿态或搭建场景。
- **达人/人物图默认贴合目标市场，尽量用当地人特征（除非用户已锁定人物）。** 生成达人、模特、角色、路人等人物形象图时，若人物未被用户锁定（`character_reference_authority` 非 `locked_by_user`），默认按已确定的 `target_market / cast_localization` 选角，**优先采用目标市场当地人的可信特征**——面孔与肤色、发型发色、体型、妆容取向、服装风格与得体度、气质与表演语气都朝当地当代真实人群靠拢，而非默认西方面孔或与市场不符的长相。例如泰国市场默认生成当代泰国成年人物、印尼市场默认印尼本地人物；市场未明确但「单一当地语言 + 当地电商平台/购买路径」高度一致时，按「市场、语言与人物本地化合同」采用可修改的低风险本地化默认值。**这是让画面更贴近目标市场、更像当地人拍的，不是用夸张民族服饰或刻板符号贴标签**：只做自然、当代、真实的本地化，不堆砌民族图腾式装扮。用户已锁定人物参考（上传形象图并要求照此身份、或明确指定长相/国籍）时，锁定优先，保持其身份，不因市场默认值改脸；市场与锁定人物冲突时按本地化合同处理（内部记录覆盖原因，只在必要时问一个最小问题）。生成后第 5 步质量自检须一并核对「人物特征是否与目标市场一致」，视觉质量合格但市场不匹配仍判不合格、自动重生成或换候选。

### 多图借鉴与局部修改绑定合同（硬性）

当用户要求“基于 A 修改，并借鉴 B 的某一部分”时，无论是改颜色、文字、Logo/标签、材质、部件、包装状态、数量、背景、构图还是风格，都必须按维度拆分素材权限，不能把每张参考图都当作完整成品参考。

- **先确定基础对象和修改清单。** 明确哪张图是 `base_source`，列出每项 `keep / change / add / remove`，并写清目标对象或区域。未被点名修改的维度默认继承基础图并锁定不变。
- **每个修改维度只绑定一个权威来源。** 可拆分为：`shape_structure`（轮廓、比例、部件、开孔、按键）、`color_material`（色相、色块、材质、纹理）、`text_label`（文案、字体层级、Logo/标签内容与位置）、`component_detail`（附件、装饰、局部元素）、`state_content`（开合状态、内容物、数量、组合关系）、`scene_composition`（背景、机位、构图、光线）和 `visual_style`（表现风格）。参考图只授权被指定的维度，其余内容一律忽略。
- **文字修改以明确文本为最高权威。** 用户给出的目标文字或已验证商品字段控制最终文案；参考图只可控制清晰可见的排版、字体风格、字号层级、颜色与位置。文字模糊、遮挡或未提供时不得猜写，先请用户粘贴准确文字或上传清晰标签图。
- **如果映射不清，给 2-3 个针对性选项。** 例如：`图1保留产品外形，只把正面文字改成“XXX”`、`图1外形 + 图2配色，文字保持图1`、`图1产品不变，只借鉴图3背景和构图`，并保留自由描述入口。一次只询问真正冲突或缺失的维度。
- **每张素材都写 adopted / ignored dimensions。** 例如：`@图1为基础产品，只采用结构、轮廓、比例、部件和Logo位置，忽略原颜色与旧文案；@图2只采用军绿色色相和黑绿分区，忽略其结构、角度和背景；目标文字严格使用用户提供的“XXX”，仅替换正面标签文字，其余包装不变。`
- **最终提示词必须复述编辑边界。** 明确基础图、目标区域、修改项、来源、保留项和忽略项；不得只写“参考这些图片修改”“融合多张图”或让未授权维度跨图泄漏。

### 参考素材台账合同（硬性）

统辖所有会进入生成的参考图/视频/音频。它管住两类高频失败：**素材绑定错乱**（图对不上实体、多图无差别塞入让模型乱挑）与**衍生素材被当权威**（Agent 自己搜/生成的图未经验证就当商品真相）。核心铁律：**每个实体、每个状态只允许一个主锚点；其它素材必须声明具体用途，禁止无角色地批量塞入。**

台账不新开 md 文件——它就活在两处且两处必须一致：`营销脑图.md` 的「素材注册表」（内部逐图登记，字段见 intake）与 `视频生成Prompt.md` 里 `对应@图片N` 的内联声明（喂给模型）。

- **单主锚点（唯一绑定）**：每个实体（`产品1`/`主体1`/`场景1`……）、每个需要区分的状态（关闭/打开/使用中/使用后），在同一用途上**有且仅有一张主锚点图**。确需多图时，除主锚点外的每一张都必须写明它**额外补什么**（补某个视角、某个状态、某个局部细节、某个 SKU），不允许几张同类图无差别地一起塞进 `ImageList` 让模型自己挑。
- **逐图声明用途（无角色不入列）**：每张进入生成的图都要在注册表里写清——绑定哪个产品/人物/场景（`linked_entity_id`）、属外观真值/尺寸比例/动作状态/风格哪一类参考（`authority_scope`）、对应哪个状态（`state`）、被哪些镜头使用（`used_in_shots`）、只采用/不采用哪些维度（`preserve`/`ignore`）。**没有明确角色声明的图一律不进 `ImageList`。**
- **冲突有裁决**：当多张图在同一维度给出不同信息（两张图颜色不同、标签位置不一致等）时，必须为该维度指定**唯一胜出图**（`conflict_winner`），其余图在该维度记入 `ignore`；不得把互相冲突的图一起喂进去让模型平均或随机取舍。
- **根真值 vs 待确认衍生（硬性分级）**：**用户上传、商品系统、达人系统给出的原始素材是「根真值」**（`authority_tier: root_truth`）；**Agent 自己搜索、生成或从其它图衍生出来的素材，一律只是「待确认衍生素材」**（`authority_tier: pending_derived`）。待确认衍生素材**未经对照检查或用户确认，禁止升级为视频生成参考**——不得进 `ImageList`、不得充当商品外观/身份/尺寸权威。升级只有两条合法路径：① 通过第 5 步生成图像质量自检的逐面比对（对齐商品模型与根真值）且经用户确认符合预期；② 用户明确认可。通过后才把注册表里的 `verify_status` 记为 `confirmed` 并可使用；否则保持 `pending`，只能作占位/参考思路，不进生成。凭正面图脑补出的背面图、搜来的近似商品图，都属 `pending_derived`，默认不得当真值使用。

### 禁止 Agent 自行生成产品图合同（硬性）

**默认禁止 Agent 自行生成「产品图」——产品的真实外观只能来自用户上传/商品系统的根真值素材，不允许 Agent 用文生图/图生图凭空造一张商品外观图来当参考。** 这条合同专治「缺产品图就自己生成一张顶上」这一高危失败:AI 生成的商品外观几乎必然与真实产品存在不一致(形态、比例、Logo、标签、部件、颜色细节偏差),一旦当成参考喂进视频模型,成片就与真实商品对不上。

- **适用对象:承载商品身份与外观真值的「产品图」**——即会被当作 `产品1`(或任何被营销商品)外观/形态/尺寸/包装/Logo/标签/状态权威的图。**明确的例外(不受本合同禁止)**:①**分镜示意图/故事板图**——用于表达镜头构图、机位、动作走位的示意画面,不作为商品外观真值;②**关键帧图**——为多请求连贯性生成的首/末帧,其中商品外观仍须来自已确认的根真值产品图或已确认的参考图,不得借关键帧引入新的臆造外观;③人物/达人形象图、场景图、风格参考图等**非产品外观**素材(它们各自受既有隔离与素材合同约束)。除这些例外,凡是要充当商品外观权威的产品图,默认不生成。
- **缺产品图/缺某个面时的默认动作:请用户补真图,或调分镜回避,不是自己生成。** 与「商品完整视图保障原则」「关键信息保守收集合同」一致——缺哪个面就请用户补传那个面的真实商品图/短视频;用户补不了又不同意生成时,改分镜收敛到现有真图能支撑的视图。**不得因为「用户没给、进度卡住」就擅自生成一张产品图充数。**
- **仅当用户强烈要求 Agent 生成产品图时,才走以下强制流程(缺一不可,顺序不得颠倒):**
  1. **先声明不一致风险(前置、显式)。** 动手生成前,必须先明确告诉用户:「我们自己生成的产品图可能与你的真实产品存在不一致(形态、比例、Logo、标签、部件、颜色等细节可能有偏差),仅供在你确认后作参考使用。」让用户在知情该风险的前提下再决定是否继续。
  2. **生成后必须经用户确认,不能由 Agent 自己确认放行。** 生成的产品图先经第 5 步「生成图像质量自检」(崩坏/畸变、是否符合商品建模、是否符合用户要求)过滤掉明显不合格的;**但自检通过并不等于可用**——必须用 `present_sandbox_file` 展示给用户,再由用户明确确认「这张图符合我的真实产品、可以用作参考」。**Agent 的自检只是内部把关,绝不能替代用户确认;用户没确认前,该图在注册表里保持 `authority_tier: pending_derived` + `verify_status: pending`,禁止进入 `ImageList`、禁止充当商品外观权威。** 用户确认后才升级为 `confirmed` 可用。
  3. **正式调用视频生成模型时,传入完整的三视图。** 当用户已确认使用 Agent 生成的产品图、且要正式调用视频生成模型时,该产品的参考素材必须是**完整三视图**(至少正面 + 背面 + 侧面三个主视角;有必要展示顶/底/内部/使用状态时一并补齐),而不是只凭单张角度图去合成——单角度参考会让模型对未见的面自由脑补,放大不一致。因此走到「生成产品图」这一步时,须按三视图逐面生成(或补齐),每个视角图都经上述①②流程(风险声明 + 用户确认)后,作为一组完整三视图一起绑进视频请求的 `ImageList`,并在 `视频生成Prompt.md` 的 `产品1：` 定义行里逐图用 `对应@图片N` 声明各视角及其只采用/不采用维度。
- **此项在第 5 步与第 6 步生成前方案检查里强制执行**:出现「未经用户强烈要求即 Agent 自生成的产品外观图」「Agent 自生成产品图未经用户确认就进 `ImageList`」「用户确认使用生成图但正式调用时未传入完整三视图」任一情形,即为阻塞项,不通过。
