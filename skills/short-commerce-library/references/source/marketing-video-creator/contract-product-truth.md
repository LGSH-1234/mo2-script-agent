
# 商品事实契约（产品真相 · 完整视图 · 卖点覆盖 · 关键信息 · 真实形态与使用）

> 本文件是以下约束的**唯一权威正文**：商品建模合同、商品完整视图保障原则、核心卖点收敛与全覆盖合同、关键信息保守收集合同、产品真实形态与使用逻辑合同。SKILL.md 只做激活与调度，遇到这些主题以本文件为准。

### 商品建模合同（硬性，前置强节点）

**动手做任何创意之前，先把商品搞清楚。** 无论输入是一句话意图、一张商品图还是一段解析数据，进入营销判断（第 2 步）时都必须先为 `产品1`（多商品则逐一）建一份**商品模型**，并把建模结果**完整写入 `营销脑图.md` 里一个固定的「商品模型」区块**——这是 `营销脑图.md` 的固定必含部分（涉及具体商品时），不是可有可无的临时推理，也不允许只停留在脑内。多商品时该区块内按 `产品1/产品2……` 逐一登记。目标只有一个:**让后续所有脚本、分镜、提示词都建立在"我确实知道这是个什么东西、它怎么用"之上,而不是脑补**。这条合同是「关键信息保守收集合同」「产品真实形态与使用逻辑合同」「商品素材与达人素材隔离合同」的共同前置——那几条负责事实红线与素材边界,这条负责在开工第一时间就把商品的**形态**与**用法**结构化落到纸面、把缺口一次性问清。

**建模第一步先判「物态」，据此决定整套建模/素材/约束该怎么走(硬性,前置于填字段)。** 别默认被推广的对象一定是能拿在手里、有正背侧面、要手持演示的实物。先把 `产品1` 归入下面某一类物态,后续的「参数与形态」「功能与使用」两大部分照填,但**每个维度的含义、要不要问、用什么素材证明,全部随物态切换**——绝不能拿实物那套"正面/背面/侧面分面还原、材质质感、手持尺度、拿起/打开/倒出物理动作、商品各角度图视角覆盖必判"去套一个没有实体形态的对象,那会大面积误判 `n/a`、或把用户往"上传产品各角度图/手持演示视频"这类对它毫无意义的要求上逼,起负面效果。

- **实物商品**：有真实物理实体、能拿在手里/穿在身上/摆在场景里——服饰、食品、美妆、3C、家居、配件等。走完整实物流程：外观分面还原、材质质感、手持与场景尺度、物理使用动作状态机、商品各角度图视角覆盖必判,全部生效。
- **数字/虚拟商品**：没有实体外壳,本体是软件、系统、App、SaaS、平台、小程序、在线服务、课程、会员、订阅、虚拟权益等(如"仓储管理系统""某 SaaS 平台")。它的"形态"不是正背侧面,而是**界面/信息架构/可视化呈现/交付载体**;它的"使用"不是手持物理动作,而是**操作流程/数据流转/功能路径/使用场景与角色**。此时"外观分面还原、材质质感、手持尺度、物理动作状态机、商品各角度图视角覆盖"整类默认按 `n/a` 处理、不向用户索取,改用下面「数字/虚拟」专属维度,证据类型换成**界面截图/录屏/产品文档/功能列表/品牌视觉规范**而非商品各角度实拍图。
- **品牌本身**：推广对象不是某一件具体商品,而是**一个品牌/企业/IP 的形象与心智**(如"为每个品牌做宣推")。此时没有单一"产品1"实体,建模重心转到**品牌资产与调性**:Logo/标准字/主色/辅助图形/视觉语言、品牌定位与价值主张、目标人群与心智、语气个性、代表性符号/场景、可展示的信任背书。"外观分面/材质/手持/物理动作/视角覆盖"整类 `n/a`;证据类型是**品牌 VI/视觉规范、Logo 源文件、既有物料、官网/官方账号**。
- **混合**：一次推广里既有实物又有数字/品牌成分(如为某品牌旗下一款实物做宣推、或一个硬件+App 的组合)。按成分拆开,实物成分走实物流程,数字/品牌成分走对应流程,各自登记、各自约束,别互相污染。

**物态判定优先靠权威信息与常识自行判定,不为此单独弹问卷**;只有当对象性质确实模糊到影响建模走向(既像实物又像服务)时,才在第 2 步统一待问清单里顺带问一句。判定结果写进商品模型的 `物态` 字段,并驱动下面两大部分里哪些维度生效、哪些 `n/a`。

商品模型按[输入与项目状态](references/base/intake-and-project-state.md)「商品模型」小节的**半固定骨架**写入 `营销脑图.md`：**冻结的是「先判物态 + 两大部分必存在 + 填写铁律 + 下游据它压商品尺寸台账并把保真事实带进 Prompt」，不冻结具体维度字段**。下面列的子维度是**实物品类**的通用骨架起点——**遇到数字/虚拟、品牌本身,或有品类特有维度的商品,应按物态与品类整体替换/增删字段、改字段名、补维度**(数字/虚拟补交付载体/界面架构/核心功能路径/使用角色与场景/接入与有效期,品牌补 VI 视觉资产/定位/心智/调性),让模型真正装得下这件被推广的对象,而不是硬套实物清单。用户补充素材或修正后，就地更新该区块，保持它始终是商品事实的最新单一真相源。

**两种缺省状态要分清：`unknown`**（该维度对本商品适用、本该填但暂缺 → 进待补缺口、要问用户）与 **`n/a`**（该维度对本品类根本不适用，如纯服务无"打开启动方式"、软件商品无"重量"、连衣裙无"接口"、数字产品无"外观分面/材质/重量" → 不进待补缺口、不追问）。别把 `n/a` 当 `unknown` 骚扰用户，也别把该问的 `unknown` 藏成 `n/a`。

**商品模型分两部分,都必须尽力填、适用却缺的标 `unknown`、品类不适用的标 `n/a`;每个维度先过一遍物态、不适用当前物态的整类标 `n/a`,别硬填:**

**① 参数与形态(它是个什么东西)——目标是"仅凭文字就能在脑中还原这个被推广的对象",实物是还原实物,数字是还原它的界面/载体,品牌是还原它的视觉资产:**

*实物物态填这些:*

- **物理规格**:大小/尺寸/尺码、重量、容量/规格、数量(按品类只留相关项)。**尺寸/大小是硬性必确定项**:优先取用户素材可见参照物、商品字段、规格标注;对规格公认固定的常见品类(AA/AAA/18650 电池、A4 纸、标准易拉罐、信用卡、家用插座等)可**按品类标准规格直接推导**并注明"按品类标准推导",无需追问;既非固定规格、素材又看不出大小时标 `unknown`——它是阻塞项,须问清用户后才能进入 prompt 阶段(见「商品尺寸台账 + 商品大小保障原则」);
- **材质与质感**:外壳/面料/主体材质、质感(软/硬/哑光/亮面/透明/磨砂)、工艺特征;
- **结构与组成**:由哪几个部件/模块构成,它们如何连接/嵌套/开合;
- **外观分面还原(尽量按面描述)**:**正面**有什么(主视觉、Logo、屏幕、按键、开口)、**侧面**有什么(接口、卡扣、厚度轮廓)、**顶部/底部**有什么(盖子、泵头、出料口、散热孔、铭牌、支脚)、**背面/内部**有什么(仅当有权威素材支持时才写,否则标 `unknown`,绝不脑补未见过的面);
- **颜色/款式/型号/SKU 区分**;
- **品类特有维度按需增补**:服饰补版型廓形/垂坠感/上身效果/面料克重、食品补口味/口感/份量、3C 补屏幕/接口/续航等——字段名自拟,别硬塞进上面的通用名。

*数字/虚拟物态改填这些(上面实物的物理规格/材质/外观分面/手持尺度整类 `n/a`):*

- **交付载体与入口**:它以什么形式存在与被访问——Web 后台、App、小程序、桌面客户端、API、大屏、公众号、线下终端等;
- **界面与信息架构**:核心界面/关键页面有哪些、主要模块与信息层级、可视化呈现方式(仪表盘/列表/流程图/数据大屏),**只描述权威素材(截图/录屏/文档)实际展示过的界面,没见过的界面标 `unknown`、绝不脑补 UI**;
- **品牌与视觉呈现**:产品 Logo、主色/辅色、界面视觉风格、可上镜的标志性画面(如某张标志性仪表盘);
- **版本/套餐/SKU 区分**:如基础版/专业版/企业版、坐席数、模块组合。

*品牌本物态改填这些(实物形态整类 `n/a`):*

- **视觉资产(VI)**:Logo(标准组合/单色/最小尺寸)、标准字、主色辅色色板、辅助图形、标志性符号/吉祥物、既有物料风格;
- **品牌定位与心智**:一句话定位、价值主张、区别于对手的核心差异;
- **代表性场景/资产**:能代表品牌的画面、门店/产品家族/代言符号等可上镜元素。

**② 功能与使用(它怎么用/它主张什么)——实物是正确物理用法,数字是操作与价值路径,品牌是心智与调性:**

*实物物态填这些:*

- **核心功能/用途/工作原理**:它能做什么、解决什么问题、靠什么机制生效;
- **打开/启动方式**:如何打开、拧开、掀盖、按压、插拔、上电、解锁(无"打开"概念的品类标 `n/a`);
- **关键操作部件的作用**:每个按钮/旋钮/开关/接口/卡扣分别是干什么的、怎么触发、有什么反馈(无此类部件整项标 `n/a`);
- **标准使用流程**:从起始状态到完成的动作顺序(拿起→打开→操作→取出/涂抹/倒出→收纳等),含手/工具接触点、受力方向、内容物流向、使用终点;
- **易错点与禁忌**:哪些是错误用法、会导致什么后果,以避免脚本演示出违反物理或说明书的动作;
- **品类特有维度按需增补**:服饰补穿搭场景/搭配/洗护、食品补食用方式/冲泡步骤、服务补履约流程/使用门槛等。

*数字/虚拟物态改填这些(上面的物理"打开/操作部件/手持流程"整类 `n/a`):*

- **核心功能与解决的问题**:它替谁解决什么痛点、关键能力有哪些;
- **典型使用流程/功能路径**:用户从登录到达成目标的关键步骤(如"入库→上架→拣货→出库→对账"),用可上镜的界面动作/数据流转表达,而非手部物理动作;
- **使用角色与场景**:谁在用(仓管、运营、老板)、在什么场景用(移动端扫码、后台看板);
- **接入/开通/有效期**:如何开通、部署或接入方式、订阅周期/有效期(不适用标 `n/a`);
- **可证明的成效**:效率提升/成本下降/准确率等——**只用权威文案/案例给出的数字,禁止编造效果数据**。

*品牌本物态改填这些:*

- **品牌语气与个性**:说话方式、情绪基调、性格标签;
- **目标人群与心智目标**:想让谁记住什么、建立什么联想;
- **本次宣推的主张/主题**:这支片子要传递的品牌信息或活动主题;
- **可用信任背书**:资质、代表客户、荣誉、数据(只用权威给定的)。

**填模型的铁律(与既有合同一致,不得违背):**

- **先判物态、再判品类、最后定维度**:拿到被推广对象先归物态(实物/数字虚拟/品牌/混合),再在该物态内归品类,据此决定哪些维度保留、哪些整类标 `n/a`、还要补哪些专属维度。**允许增删字段、改字段名、加子项、按物态整体换一套维度**——骨架服务于把对象说清,不是逼对象套实物清单;唯一不许动的是「先判物态 + 两大部分 + 这几条铁律」。
- **`unknown` 与 `n/a` 分清**:适用却缺→`unknown`(进待问清单);品类根本不适用→`n/a`(不追问、不进待补缺口)。
- **只填权威来源已支持的**:商品系统解析数据、用户上传素材/文案、已锁定文案、可见商品图**实际拍到的面**。适用却缺失或不确定的一律标 `unknown`,**禁止推断、禁止臆造、禁止用"通常/一般/应该"或行业惯例值补全**(见「关键信息保守收集合同」「产品真实形态与使用逻辑合同」)。**例外从严:「外观」与「使用方式/场景」两类维度,纯文字(用户口述、已锁定文案里的描述性文字)不构成权威来源——即便用户已用文字描述,对应维度仍记 `unknown`、仍须要求图片/视频,只有用户被要求补媒体后仍强烈坚持只用文字时才升格(见本合同第 3 段末「文字默认不作外观/使用方式置信点」)。** **此例外优先级最高,压过"已锁定文案""用户明确指定"这类权威身份:用户在需求里把使用动作/外观写成"锁定文案""明确指定的动作序列",或加上"按此执行/动作要准确/一镜到底拍这个动作"等措辞,均不改变其纯文字本质——它仍是 `unknown`、仍须先要媒体,不得据此当作已确认用法直接写进 `确认用法`/脚本。把用户初始文字当成"锁定/坚持"从而跳过要媒体这一步,是禁止的漏放路径。**
- **图片/素材只对实际展示到的内容构成权威**:实物只有正面图时,背面/侧面/顶底/内部/材质纹理一律 `unknown`,不得据正面图猜写其它面;数字/虚拟只有某几张界面截图时,没截到的界面/功能页一律 `unknown`,绝不脑补 UI 布局或菜单;品牌只有 Logo 时,未给定的视觉规范/物料风格标 `unknown`,不得自造 VI。都不得为了呈现某卖点虚构未见过的面/界面/物料。
- **形态与功能不互相倒推**:不能从外观脑补功能/功效/用法,也不能为呈现某功能虚构不存在的部件或开口。
- **用户表述 > 图片/视频 Caption 机读结果(冲突时以用户为准)**:填模型的事实同时来自"用户的文字表述/已锁定文案/商品系统字段"和"对上传图片、视频自动读取的 Caption / 视觉理解结果"两类来源。当这两类在同一维度不一致时(如用户说这是"钛灰色",但图片 Caption 识别成"银色";用户说容量 500ml,视频画面理解成"看起来像 350ml";用户说这是"电动牙刷",Caption 读成"剃须刀"),**一律以用户的表述为准**,按用户所述写进模型,不采信与之冲突的 Caption 机读值。Caption/视觉理解只是辅助解析,不得覆盖用户明示的事实。仅当用户完全没就该维度表态、只有 Caption 提供了信息时,才把 Caption 结果作为参考填入并标注来源为机读解析(非用户锁定,后续可被用户表述覆盖)。若发现两者冲突且该维度会实质影响成片(如商品品类、颜色、关键规格被读错),可在统一待问清单里顺带向用户确认一句,但在用户改口之前默认按用户原表述执行,绝不因 Caption 不同就擅自改掉用户说过的事实。**注意:本条只解决"两个非权威机读/口述来源打架时信谁",不改变外观/使用方式的证据门槛——用户文字在此胜过 Caption,只代表按用户说法登记这条线索,不代表该外观/用法就此升格为权威事实;它仍是 `unknown`、仍须图片/视频佐证,除非走完强烈要求流程。**

**建模过程中发现的模糊/缺口,汇总后一次性向用户确认(低打扰):**

1. **先建模、再盘缺、后统一发问**:填模型时同步记下所有被标 `unknown`、且会实质影响成片可信度或购买理由的关键项,汇总成**一份**待问清单,**与「关键信息保守收集合同」的待问清单合并为同一轮向用户发问**,尽量一轮问全,避免本可预见却拆成多轮的挤牙膏式追问,不重复打扰。**发问方式(默认统一走 `dynamic_questionnaire`、用点选代替打字降成本、及其唯一例外)以「关键信息保守收集合同」为唯一权威,本段不另作规定。**
2. **发问前先自检**:能从权威来源、用户已给文案、可见商品图得到答案的,不再问;只问真正缺、且属于会影响成片的关键项。纯创意性、低风险的空白(运镜、氛围、次要转场)不进此清单,继续自行低风险推断。**但「外观」与「使用方式/场景」不因"用户文案里写过"而算已答:这两类只有图片/视频/界面截图/VI 才算已得到答案,纯文字仍须发问要媒体(见下第 3 段末规则)。**
3. **索取证据按物态与缺口类型分优先级,优先要媒体而非只让用户打字描述**:
   - **实物·参数/形态类缺口(大小、材质、结构、外观分面、颜色款式等)**:**必须引导用户上传对应角度/细节的商品图或短视频**(缺哪个面就要哪个面、缺材质质感就要特写)——**这是唯一能作为外观置信点的证据**。**即便用户一开始就用文字描述了外观,也不得据此把外观当已知事实,仍须要求图片/视频**;文字只作非权威占位、维度记 `unknown`,不进外观置信点(升格规则见下「文字默认不作外观/使用方式置信点」)。**不要凭已有正面图生成一张背面/细节图来补,也不要只靠文字脑补外观。** **特别地,当某 P00/主打卖点或用户点名的易错点是一种立体结构关系(部件一体还是独立、凹凸、层叠、连接方式、内外、开合等),而现有素材只有单一视角、无法证清该结构时——不要因为"这个面已经拍到了"就当已知,要把它当作缺口列进待问清单,明确向用户要能看清该结构的多视角图(侧面/斜 45°/该结构特写);详见「商品完整视图保障原则」的立体结构充分性子门。**
   - **实物·功能/使用类缺口(打开方式、按钮作用、操作顺序、物理交互等)**:**必须引导用户上传演示/使用过程的参考视频**;视频拿不到时,退而求其次接受**按顺序排列的多张状态图**(至少标"起始/未打开 → 接触点 → 中间状态 → 完成/已打开")并补充受力方向与先后顺序——**视频与顺序状态图才是使用方式的置信点**。**即便用户一开始就用文字描述了使用方式/使用场景,也不得据此把用法当已知事实,仍须要求视频/图片**;文字只作非权威占位、维度记 `unknown`,不进使用方式置信点(升格规则见下「文字默认不作外观/使用方式置信点」)。单张终态图只授权"产品已处于该状态"的展示,不得被扩写成完整动作路径。
   - **数字/虚拟·形态与功能缺口(界面长什么样、有哪些功能页、操作流程等)**:首选引导用户**上传界面截图/操作录屏/产品文档/功能列表**(缺哪个界面就要哪张截图、缺流程就要录屏),**绝不脑补 UI 或凭想象生成一张假界面**;拿不到时退到用户文字描述关键界面与流程,并在模型里标 `unknown`/`AI 推导`。不要向数字产品用户索取"商品各角度实拍图/手持演示视频"这类对它无意义的素材。
   - **品牌·视觉资产缺口(Logo、色板、VI 规范、既有物料等)**:首选引导用户**上传 Logo 源文件/品牌 VI 手册/既有物料/官网链接**,确保成片视觉与品牌一致;拿不到时按已给视觉线索保守呈现、缺口标 `unknown`,不自造品牌视觉资产。
   - 说明每项素材为什么需要(如实物"用于呈现开盖卖点镜头"、数字"用于真实还原后台看板"、品牌"用于保证 Logo 和主色准确")。用户仍可随时用文字补充说明,但**对外观与使用方式/场景,文字只是待核实线索、默认不作置信点**(见下条),不能替代图片/视频取证。
   - **用户要求由 AI 自行生成/推导时:照做,但先给一句一致性提醒(不阻塞、不需确认)**。当用户不愿提供图/视频/界面截图/VI、明确要求让模型自己补齐外观、界面或品牌视觉时,尊重该选择直接继续,不强求素材;但在动手前用一句话平实提醒:这些缺口将由纯 AI 推导补全,**可能与真实的商品外观、真实界面或品牌视觉规范存在不一致**,如果在意可随时补一张对应素材来校正。提醒只发一次、点到为止,**不要求用户确认、不因此停下等待**;推导出的内容在模型里按 AI 推导标注(证据来源标为 `AI 推导`、非权威事实),不得升格为已验证事实,后续仍可被用户补传的真实素材覆盖。
   - **文字默认不作外观/使用方式置信点,仅在用户强烈要求后才升格(硬性)**:纯文字承载不了外观与使用方式的真实信息量,**对商品外观(形态、分面、材质、颜色款式、比例)与使用方式/使用场景(怎么用、动作顺序、人货交互、使用情境),文字描述默认不构成置信点**——**哪怕用户一开始就提供了这类文字,也只当作待核实的非权威线索、对应维度记 `unknown`,并仍按上面优先级要求用户补图片/视频**,不得因为"用户已经用文字说过了"就把外观/用法当成已知事实写进脚本或 Prompt。**唯一的升格路径:只有当用户在被要求补媒体后、仍强烈坚持"就用我这段文字、不再提供也不需要图片/视频"时**,才把这段文字升格为该维度的置信点使用;升格前须一句话提醒"纯文字对外观/用法的控制力较弱、可能与真实产品有偏差",升格后在模型/注册表里按 `AI 推导`/文字来源标注(非权威、后续可被真实素材覆盖)。此升格门槛与「禁止 Agent 自行生成产品图合同」「商品使用方式保障原则」的"用户强烈要求"一致,不得自行放宽。
4. **低打扰兜底,不因证据边界机械追问**:遵循既有「产品真实形态与使用逻辑合同」的低打扰原则——若现有素材已能支撑脚本(如只有"已打开"图就从已打开状态起拍),则**不必**仅因缺完整动作路径就停下追问;只有在①用户明确要求保留完整动作/形态、②核心卖点或证明必须依赖该动作/该面、③缺失会实质改变用户意图且现有素材不足时,才把补媒体设为优先询问项。其余情况先自行改成素材支持的低风险方案并继续,把补图/补视频作为可选项而非阻塞项。**但低打扰不适用于"用户点名要拍、却只有纯文字撑着的使用动作/外观":当用户要求成片里出现某个具体使用动作(如掰断、挤压、点涂、安装、展开),而该动作目前只有文字描述、无视频/顺序图时,恰恰命中上面①(用户明确要求保留该动作),必须走证据阶梯把它列为要媒体的询问项,不得援引"低打扰/现有素材已能支撑"把这套动作当已知直接开拍。低打扰只用于"缺的动作本就不必展示"的情形,不能用来跳过"用户明确要展示、却无媒体佐证"的动作。**
5. **用户没答的关键项保持 `unknown` 待定**,不得脑补后继续;用户明确说某项"不用体现/不用放"才可在模型里标该项「已豁免」。一次问齐是目标而非硬约束,后续步骤浮现新缺口时允许追加补问。

**商品模型是下游一切的事实底座**:第 2 步的「卖点账本」只能从模型里已知(非 `unknown`)的事实中提炼卖点;第 4 步分镜、第 5 步素材完整性检查(实物类做视角覆盖必判,数字/品牌类改判界面/VI 素材是否齐备)、第 6 步最终 Prompt 的「产品1」形态与使用描述,都必须与模型一致,不得超出模型已知范围去表现未知的面或用法。模型随商品信息或用户补充素材更新,是修改路由里 `营销脑图.md` 层的组成部分。

**商品完整视图保障原则(硬性,决策门阻塞项)。** 「只拿到一张正面图,却把背面/侧面/内部/使用状态当成可脑补、直接往下走」是本 Skill 最高频、最致命的失败,生成的视频会与真实商品对不上、不可用。**商品的「完整视图」必须在进入 prompt 阶段前收集齐全,这是硬性阻塞门,不是软性建议**:

- **什么叫「完整视图」,按物态判定(与第 5 步视角覆盖必判、各物态真实性检查同一把尺子)**:
  - **实物商品**:凡**当前故事脚本的分镜实际要展示到的每个面/状态/细节**,都必须有权威真图支撑——正面、以及**分镜会拍到的背面/侧面/顶底/内部/材质纹理/Logo 标签/开合或使用状态/不同颜色款式或 SKU**。判据不是「凑齐机械三视图」,而是「片子要给观众看的每一个面,都有真实素材可依」;分镜只拍正面三分之二时,单张正面图即为该片的完整视图;分镜要翻面展示背标或倒出内容,则背面图/该状态图缺一不可。**分镜需要、而现有素材看不到的面,一律视为视图不完整。**
    - **立体结构充分性子门(硬性,与"面覆盖"并列、独立判定):当某个 P00/主打卖点、或用户点名的易错点,其本质是一种立体结构关系——例如某部件是与主体一体成型还是独立可拆、凹进还是凸出、层叠关系、连接/固定方式、内外包含关系、开合方式等——而现有素材只有单一视角(如仅正面图或仅顶视图),该角度在物理上无法证伪其它解读(单看这一张,"一体"和"独立"、"凸起"和"平贴"都能说得通)时,该结构判 `unknown`,视为视图不完整,必须回头向用户索取能确认该结构的多视角图(侧面图 / 斜 45° 角图 / 该结构的特写),而不是靠"正面图已经拍到这个部件了"或"用户文字已经描述过这个结构"就当作已知。** 换言之:对这类立体结构卖点,"某个面被拍到了"不等于"这个面所承载的结构关系被证清楚了"——**面覆盖通过、结构却说不清,仍算视图不完整**。此判定压过本段上文"单张正面图即为完整视图"与「关键信息保守收集合同」里"用户文字已描述"的宽松解读:**说不清那个结构到底长什么样、部件与主体是什么关系,就不算视图完整,fail-closed。** 触发范围保守限定在 P00/主打卖点与用户点名的易错点(其它次要外观维度不因本子门而强行追加多视角要求,避免过度打扰);判 `unknown` 后按下文「视图不完整时怎么办」处理,首选向用户要多视角图。
      - **正例(必须触发本子门、必须回头要图):** 用户要拍宠物窝并强调「一体式凸出软枕,凸出部分属于窝体本身,窝内绝无独立枕头靠垫」——"软枕与窝体是一体还是独立"正是用户点名的 P00 立体结构关系;而用户只上传了一张**正面/俯拍**商品图,单看这一张,"软枕一体成型凸出"与"窝里另放了一个独立靠枕"在画面上完全可以两解、无法证伪。此时**即便正面这个面已经拍到、即便用户已用文字反复强调结构、即便宠物窝用法直观(猫走进去趴下)**,该结构仍判 `unknown`、视图仍不完整,**必须停下向用户补要能看清软枕与窝体连接关系的侧面图 / 斜 45° 角图 / 该凸出结构的特写**,不得因为"正面图拍到了窝""用户文字说清了""用法很通用"就当已知直接开拍。这正是本 Skill 最容易漏放、最须警惕的一类:**用法通用 ≠ 结构已知,文字描述 ≠ 图片取证,拍到某个面 ≠ 证清该面承载的立体结构。**
  - **数字/虚拟商品**:改判「界面/功能覆盖完整」——片子要展示的每个界面/看板/功能路径/数据视图都有真实截图/录屏/产品文档支撑,缺任一页即不完整,绝不脑补 UI。
  - **品牌本身**:改判「VI 资产覆盖完整」——片子要用到的 Logo/主色/标准字/代表性视觉元素都有官方素材支撑,缺任一即不完整,不自造 VI。
- **进入 prompt 阶段前必须视图完整。** 编译 `视频生成Prompt.md`(以及任何要拍到该面/该状态/该界面的分镜)之前,上述「分镜实际要展示的视图」必须已由权威真实素材覆盖。**只要存在分镜要展示、却在商品模型里仍是 `unknown`、现有真图/截图/VI 又看不到的视图,即为「视图不完整」——禁止进入 prompt 阶段、禁止呈现最终方案、禁止用已有的正面图/某张界面图脑补或生成其它面来充数。**
- **视图不完整时怎么办(优先补真素材,其次调分镜回避,禁止脑补硬闯)。** 停下按「关键信息保守收集合同」第 3 条的证据优先级向用户交涉:①**首选请用户补传缺失视图的真实商品图/短视频**(缺哪个面就要哪个面、缺状态就要该状态图、缺界面就要该截图/录屏、缺 VI 就要官方素材;**若缺的是立体结构充分性子门判 `unknown` 的结构关系,就明确向用户要能看清该结构的多视角图——侧面图、斜 45° 角图、该结构特写,而不是再要一张同角度正面图**);②用户无法补、又不同意生成时,**改分镜、回避看不到的面**,把片子收敛到现有素材能可信支撑的视图范围内;③**绝不用「凭正面图生成一张背面/细节图」来假装视图齐全**(那本质是臆造未见过的外观,违反关键信息保守原则),Agent 自行生成产品图另受「禁止 Agent 自行生成产品图合同」严格约束。
- **仅在两种前提下才允许「未拿到真图仍继续」**:① 该面/该状态属于**不承载权威商品事实的纯氛围/占位用途**(不影响商品身份与卖点可信度);② 用户**明确要求让 AI 自行补齐外观**并已知悉不一致风险(按「禁止 Agent 自行生成产品图合同」的强烈要求流程走,且生成图须经用户确认)。除此之外,视图不完整一律阻塞。
- 此项在第 6 步生成前方案检查里强制执行:分镜要展示的视图存在未被真实素材覆盖的 `unknown` 面/状态/界面,且既未向用户补齐、又非上述豁免情形,即为阻塞项,检查不通过。**立体结构充分性子门同样在此强制执行:某 P00/主打卖点或用户点名易错点所依赖的结构关系仍判 `unknown`(现有单一视角无法证清)、又未向用户补多视角图,同样是阻塞项,不得进入 prompt 阶段。**

### 核心卖点收敛与全覆盖合同（硬性，强制校验）

好的营销视频**不是把所有卖点都塞进去，而是集中篇幅打透少数几个核心卖点**——卖点越多，单个能分到的篇幅越少，最重要的信息反而被稀释，观众一个都记不住。所以这条合同管两件相反又互补的事：一头做**减法与收拢**（选出该重点打的核心卖点，其余收编成支撑），另一头做**兜底**（被判为核心的卖点，尤其用户点名的元素，绝不允许因排序/节奏而在成片里彻底消失却无人察觉）。这是贯穿第 2、4、6 步的强制校验链：

1. **第 2 步——建卖点账本（先收拢，再排序，控总量）**：在 `营销脑图.md` 里强制生成「卖点账本」。先把权威商品事实**按主题收拢**——所有外观相关（颜色、款式、廓形、剪裁）并成一条，材质/工艺并成一条，收纳/便携/容量并成一条，依此类推；再排出**唯一 1 条主打卖点（USP，整片消费主线）和候选支撑卖点池**，并按上文「时长—卖点—信息节拍预算」只激活当前时长放得下的条目；例如 9–15 秒默认只有 1 条主打卖点、最多 1 条支撑卖点，而不是固定凑 3–5 条。给候选条目标 `优先级`（`P00`/`P0`/`P1`）与 `篇幅权重`（高/中/低），未激活条目进入后续选题，不进入本条覆盖矩阵。颜色、尺码、材质、规格、价格优惠这类硬事实除非本身就是主打差异点，否则不各自升格成核心卖点，而是收进「关键事实清单」挂靠到某条已激活卖点下顺带呈现。**每个字段值必须直接来自权威商品信息（商品系统解析数据、用户上传、已锁定文案），禁止推断、禁止臆造、禁止用"通常/一般"补全**；权威信息里没有的字段留空并标 `unknown`。P00 判定依据：用户明确点名要覆盖的、构成主要购买理由或差异点的、商品标题/主图直接主打的卖点；用户点名的特定元素一律至少 P00，即使被收进某条主题卖点，也要在其「内容」里显式列出。
2. **第 4 步——分镜按篇幅勾稽**：写 `故事脚本.md` 时，在内部建立 `shot_selling_point_map`，把每条核心卖点映射到真正让观众看到/听到它的镜号与动作。**篇幅按优先级递减分配**——主打卖点与 P00 占最多镜头/时长，P0/P1 点到为止；一条核心卖点可被多镜覆盖，**不必也不应给每个原子事实各留一个镜头**。挂靠的「关键事实」随所属卖点镜头顺带呈现即可，但出现即须与账本一致。该映射只留在内部脑图，不把 `[USP] / P00 / 卖点#N` 等内部标签写进面向用户的故事脚本。
3. **第 6 步——卖点覆盖矩阵自校验（决策门阻塞项）**：编译 `视频生成Prompt.md` 之前，以「卖点账本」的**核心卖点**为行、各镜号为列做自校验。任何一条 **主打卖点或 P00 级核心卖点未被任一镜头覆盖，必须停下询问用户**——补镜头覆盖它，还是由用户明确拍板放弃（拍板才可标「已豁免」）；未经拍板不得静默跳过进入生成。P0/P1 未覆盖至少在面向用户的说明里点名列出。此外抽查落在画面/台词里的「关键事实」（颜色/尺码/材质/价格优惠等）与账本是否一致，不一致即阻塞。此校验与「生成前方案检查」一起构成决策门，未通过不得呈现最终方案。

这条合同同时兜住三类失败：**"卖点堆砌、平均用力、没有重点"**（靠收拢+篇幅权重解决）、**"核心信息缺失"**（颜色/尺码/材质/场景该出现却没落地）、以及**"用户点名的核心卖点被漏掉"**（收拢也不许把它糊掉）。收拢是把事实归类分主次，绝不是丢弃事实或臆造细节。

### 关键信息保守收集合同（硬性）

**营销关键信息一律不许推导、不许猜测、不许用"通常/一般/应该"补全；权威来源里没有的，就问用户，绝不臆造。** 收集节奏上**尽量一次问齐**，但不强求一定一轮拿全：确有必要时允许在首次询问后再追加补问（见下「批量收集」第 4 点）。这条合同专门修「模型爱推导、随意猜商品功能/尺寸/卖点」这一类失败。它与「卖点全覆盖合同」互补：那条负责把缺口标成 `unknown`、并追踪覆盖；这条负责把这些缺口一次性向用户问清，而不是自己脑补。

**判定为「关键信息」（禁止推导，缺失必问）的类别：**

- 商品**功能 / 功效 / 用途 / 工作原理**（它能做什么、解决什么问题）；
- 商品**尺寸 / 尺码 / 容量 / 规格 / 重量 / 数量**；
- **材质 / 面料 / 成分 / 工艺**；
- **颜色 / 款式 / 型号 / SKU 区分**；
- 构成**主要购买理由或差异点**的卖点（对应「卖点账本」里判为 `P00` 的项）；
- **价格 / 折扣 / 优惠 / 赠品 / 库存 / 截止日期 / 资格 / 排名 / 认证 / 实测数据**等既有「绝不推断为已验证事实」清单里的项。

对以上类别：**权威来源（商品系统解析数据、用户上传素材/文案、已锁定文案、可见的商品图）里有的，照用；没有或不确定的，标 `unknown` 并列入待问清单，绝不用推断值、示例值、行业惯例值填充，也不得在脚本里含糊带过。** 只有「不影响成片可信度、也不构成购买理由」的创意性空白（如运镜偏好、背景氛围、次要转场）才允许继续用低风险推断自行填补。

**尽量一次问齐，允许必要时追加（软性防打扰）：**

1. **先扫全、再发问（发问方式的唯一权威在本条）。** 在进入故事脚本创作之前（第 1-2 步规范化输入、建「卖点账本」的同时），**尽力**把整个任务里已能预见的、缺失的关键信息一次性盘点齐，汇总成一份待问清单，**默认统一用一次 `dynamic_questionnaire` 抛给用户（信息收集优先问卷，用点选代替打字降低用户成本；凡走问卷只按真实候选出题，遵守「动态表单合同」）**。目标是尽可能一轮问全，避免本可预见却零散补问的挤牙膏式打扰。仅当整份待问清单只有一个自由文本类问题、做成问卷反而更绕时，才可退回纯文本单问。**全流程一切向用户收集信息/澄清缺口的"用问卷还是纯文本、默认哪种、例外条件"均以本条为准，其它文件（`步骤文件`、`intake`、`动态表单合同`、`SKILL.md`）只指向本条，不另立规定。**
2. **发问前先自检**：能从权威来源、用户已给文案、可见商品图里得到答案的，不要再问；只问真正缺、且属于上述关键类别、且会实质影响成片的项。既不过度打扰，也不放过关键缺口。**「外观」与「使用方式/场景」例外：不因用户文案里描述过就算已答，纯文字不足以作这两类的权威，仍须发问、要求图片/视频（见「商品建模合同」第 3 段末与「商品使用方式保障原则」）。**
3. **给出低负担的回答方式**：批量提问时对每项标明它属于哪个商品/SKU、为什么需要（如"用于尺码卖点镜头"），并允许用户对不在意的项回复"这条不用放"——用户明确说不放，才可把对应卖点在账本里标为「已豁免」；用户没答的关键项保持 `unknown` 待定，不得自行脑补后继续。
4. **允许追加补问**：一次问齐是**目标而非硬性约束**。若用户回答后暴露出新的、或当时无法预见的关键缺口，或后续步骤（分镜、素材完整性检查、生成规划）中才浮现出必须澄清的关键信息，可以再发起一轮补问——追加询问是被允许且鼓励的，好过带着 `unknown` 硬推或自行脑补。只是每一轮都仍应尽量把当下能预见的缺口一并问全，避免明明可以预见却故意拆成多轮的零散追问。
5. **收敛为准**：批量收集属于前置澄清，**不是**「最终生成信息确认」这处阻塞确认门；它发生在写产物之前，目的正是让唯一的确认门不再因为缺关键信息而反复返工。

违背本合同的典型失败（须避免）：把没给尺码的商品脑补成"均码/S-XL"；把没说明的面料写成"亲肤棉质"；把用户没提的功能编造进脚本；以及明明可以一次预见的缺口却故意拆成多轮零散追问，让用户反复被打断。

### 产品真实形态与使用逻辑合同（按物态适配，硬性）

**本合同按商品模型的 `物态` 字段分轨执行——先看是哪一类物态，再套对应那一套「真实性」标尺，别把实物那套物理外观检查硬套到数字/品牌类对象上。** 无论哪一类，共同铁律是：呈现必须服从真实素材与已验证事实，绝不为呈现某个卖点而虚构未被授权的内容。

**A. 实物商品（`物态: 实物`）——沿用完整物理形态与使用检查：**

- **外观和卖点不能互相倒推。** 不能为了呈现某个卖点而虚构产品的背面、侧面、配料表、成分表、认证标、规格、容量、口味、内部内容、剖面、结构、包装开口或附件；也不能从外观自行推导卖点、功效或使用方法。
- **产品形态、大小、比例与用户图一致。** `产品1` 的包装类型、外形轮廓、厚薄、软硬、颜色、Logo/标签位置、数量、大小比例、手持尺度和场景尺度必须与用户提供图片或权威商品素材一致。若只有正面图，只能把正面或正面三分之二角度作为权威，不拍背面/侧面/内部。
- **脚本适配真实信息。** 如果真实素材和卖点不足以支持某个炫技演示，就改成外包装同框、使用场景、用户反应、前后结果、口播说明或请用户补素材；不得靠编造产品外观内容完成证明。
- **使用方法符合逻辑和物理规律。** 拿起、递出、打开、按压、喷洒、涂抹、倒出、穿戴、点击、安装、收纳等动作必须有可见手/工具/接触点、方向和结果；包装不能悬浮、瞬移、自行打开、从未打开状态直接倒出内容，不能用不符合该形态的打开/使用方式。

**商品使用方式保障原则（硬性，决策门阻塞项）。** 商品「怎么用」是模型最爱自推导、也最容易拍得与真实产品不符的维度——很多产品的核心使用动作**因设计而异**：同样叫「拖把」，普通拖把、免洗拖把、旋转脱水拖把、平板静电拖把的换洗/脱水/更换动作可以完全不同；同样叫「按摩仪」「清洁刷」「收纳盒」「厨房小工具」，不同型号的开合、佩戴、操作顺序、人货交互也大相径庭。一旦凭外观或品类名自行脑补用法，大概率与用户真实产品对不上，成片不可用。为此，对**涉及使用动作的实物商品**：

- **进入 prompt 阶段前必须先弄清「使用方式」，且权威依据默认必须是媒体。** 编译 `视频生成Prompt.md`（以及任何要拍到使用/操作/人货交互的分镜）之前，产品的核心使用方式——**怎么打开/启动、操作哪个部位、动作顺序、人怎么拿怎么用、关键交互结果**——必须已有权威依据。**对使用方式，合法权威依据只有：用户上传的使用演示视频/顺序状态图、商品系统字段、产品文档、或该品类公认单一用法（下一条）。用户的纯文字说明/使用场景描述默认不构成使用方式的权威依据**——哪怕用户一开始就用文字讲了怎么用，也只当待核实线索、`使用方式` 记 `unknown`，仍须按证据升级阶梯要求视频/顺序图；只有走完阶梯、用户在被要求补媒体后仍强烈坚持只用文字并经检查确认的文字版，才算例外（见证据升级阶梯第 3 档）。
- **可推导才推导，且只限「通用标准用法」品类，不打扰用户。** 仅当该品类使用方式**公认单一、直观、无设计差异**（如吹风机吹头发、电池装进电池仓、水杯喝水、雨伞撑开、普通签字笔书写）时，才允许直接按通用常识推导，并在内部注明「按品类通用用法推导」，无需追问。**判据是唯一一条通用轴——「用法能否只凭品类名完全确定」，必须同时满足下面两条才算通用标准用法，只要有一条不满足即不豁免、走证据升级阶梯要媒体（fail-closed：说不清就当不通用）：**
  1. **品类名自足**：完整核心使用动作能**仅凭通用品类名**说全，不需要看这件商品的外观图/包装/说明书。内部自检问句：「把这件商品的外观图和包装全遮住、只告诉我品类名，我能不能 100% 说全它怎么用？」——能(电池=装入电池仓、水杯=盛水喝、雨伞=撑开遮雨、签字笔=落笔书写) → 过；需要看到包装/外观才知道怎么取用/开启 → 不过。
  2. **无本商品专属的开启/取用/操作机构**：使用动作里**不含任何针对本商品设计的**开启、取用、分装、组装、展开、操作动作（如掰断密封盖、拧开、按压泵头、滴管吸取、走珠涂抹、撕膜、拨阀、拼装、折叠展开、特定按键顺序等）。出现任一个 → 判为设计相关 → 不豁免。
  - **不是靠「拍没拍到使用动作」来判**：动作能不能被拍下来与通不通用无关（电池装入也是可拍动作，但仍通用）；唯一标准是上面两条「只凭品类名能否说全 + 有无专属机构」。
- **禁止用外观图/Caption 反推使用动作、再拿它论证「通用标准用法」（硬性）。** 恰恰相反：凡是**必须去看外观图/包装/Caption 才能说清取用或开启方式**的，这一事实本身就证明其用法**不是品类名自足**的 → 直接判定不通用、记 `unknown`、走证据阶梯要媒体。绝不允许「从外观图 Caption 推出开启/挤压/涂抹动作 → 再反过来当作常识把它当成通用标准用法豁免掉」这条路径。
- **「通用标准用法」豁免只作用于「使用方式」证据门，绝不外溢到「外观/立体结构视图」门（硬性防串门，最高频漏放）。** 一件商品用法直观、被判为通用标准用法（如猫走进窝趴下、水杯盛水喝、雨伞撑开），**仅仅免掉「要一段使用演示视频/顺序状态图」这一项**，绝不代表它的外观、真实尺寸、尤其**立体结构关系**（部件一体还是独立、凹凸、层叠、连接方式、内外、开合等）已被现有素材证清。**使用方式门与外观/结构视图门相互独立、各判各的**：用法可以豁免，外观/结构视图仍可能不足、仍须按「商品完整视图保障原则」向用户补多视角图。**明令禁止这条推理链：「用法直观 → 通用标准用法 → 素材齐全 → 直接进 prompt」**——它把两道本应独立判定的门错误合并成一道，是本 Skill 最高频、最隐蔽的漏放。判「用法是否通用」时只准看使用动作是否品类名自足，**绝不因用法通用就顺带把外观/尺寸/结构也判成已知**；哪怕一件商品用法再直观，只要它带一个用户点名的立体结构卖点、而现有素材只有单一视角，视图门照样阻塞、照样要图。
- **设计相关/非直观用法一律硬卡，禁止自推导。** 只要满足任一条即视为「使用方式待确认」：① 该品类不同设计/型号的核心使用动作会出现**实质差异**（免洗拖把、多功能料理器、异形包装、需特定安装/组装/展开的产品、带专利机构的工具等）；② 仅凭现有素材（尤其只有外观图）**看不出到底怎么用**；③ 使用涉及**特定操作顺序或非直观交互**（先按哪个键、往哪个方向拧、哪一步才出内容物）。此时 `使用方式` 记 `unknown`，**禁止进入 prompt 阶段、禁止呈现最终方案、禁止用「通常/一般/应该」脑补一套用法**——须停下按下面的证据升级阶梯请用户补齐，绝不自行脑补一套用法硬闯。
- **非简单产品涉及使用时的证据升级阶梯（硬性，按顺序降级，禁止跳过）。** 当用户要生成的视频里涉及「使用方式待确认」的非简单产品（即上一条命中，区别于牙刷/发梳这类基本无使用歧义的简单产品）的使用动作时，按以下顺序取证，**每一档拿不到才降到下一档**：
  1. **首选:必须向用户要求「使用产品的参考视频」。** 优先请用户上传真实使用/操作演示视频——它是使用动作时序、接触点、受力方向、变形、内容物流向的最强权威。**即便用户一开始已用文字描述了使用方式或使用场景,也仍须要求视频,不得用那段文字替代取证。**
  2. **无视频时:可要求上传「完整使用过程的图片」。** 用户没有视频时，退而请用户上传**完整使用过程的顺序状态图**（至少标「起始/未打开 → 接触点 → 中间状态 → 完成/已打开」），并补充受力方向与先后顺序。
  3. **视频、图片都拿不到、且用户强烈坚持只用文字时:才可把「使用方式的文字版」升格为置信点,并显式声明「文字版控制力较弱」、交由用户检查确认后才可用。** 文字默认不作使用方式置信点——**只有当用户在被要求补视频/顺序状态图后、仍强烈坚持"就用我这段文字描述、不再提供也不需要视频/图片"时**,Agent 才可基于用户这段文字与商品模型已知事实、品类常识,整理出一版**文字描述的使用方式**（怎么打开/启动、操作哪个部位、动作顺序、人怎么拿怎么用、可见结果）;给出这版文字时**必须显式声明「这是文字推断版本,对生成的控制力较弱、可能与真实产品操作存在偏差」**,然后用 `present_sandbox_file` / 对话把这版使用方式**交给用户检查**。**用户检查并明确确认之后,才按这版使用方式写进 `视频生成Prompt.md` 的对应分镜;用户未强烈坚持用文字、或未确认前,`使用方式` 保持 `unknown`,禁止进入 prompt 阶段。** 用户检查时若修正了动作,按修正后的版本使用。此文字版在模型/注册表里标 `AI 推导`（非权威、后续可被真实素材覆盖）。**特别注意"强烈坚持"必须发生在"被要求补媒体之后":用户在最初需求里就把动作写清楚(哪怕写得很详细、很肯定、并要求"按此拍/动作要准")不等于"被要求补媒体后仍坚持"——那只是初始文字描述,升格前提尚未满足。正确顺序恒为:先记 `unknown` → 在问卷/对话里向用户要视频/顺序图(同一轮里可并列给出"我没有视频/图,就用我文字描述的动作"这个兜底选项) → 用户明确选择该兜底项、拒绝补媒体后,才走本档升格并提醒控制力弱。绝不允许跳过"先要媒体"直接把初始文字当成已坚持。**
- **用户明确要求 AI 自行发挥、不愿检查时，照做但一句话提醒、不阻塞。** 若用户明确表示不提供任何使用素材、也不想检查、直接让模型自己想象用法，尊重该选择继续，但先平实提醒一句「使用方式将由 AI 推导、可能与真实产品操作不符，在意可补一段使用演示校正」，并把该用法标为 `AI 推导`。提醒只发一次、不等待确认。这与上一档「Agent 推断文字版交用户检查」的区别在于:上一档是用户愿意检查、需用户确认后才用;本档是用户主动放弃检查权、授权 Agent 直接发挥。
- **使用方式落进 Prompt 且全片一致。** 弄清后，把核心使用动作写进对应分镜（具名操作部位、接触点、方向、顺序、可见结果），与「产品真实形态」「有方向性商品使用朝向」两处约束一致；全片同一产品保持同一套使用逻辑，不得这镜这么用、那镜那么用。
- **使用方式取证与其它素材缺口合并成同一轮交涉，不单独多问一次（硬性，避免重复打扰）。** 上面的升级阶梯规定「问什么、按什么顺序降级」，但**「什么时候问」统一归到第 5 步素材完整性检查那一轮**：使用方式所需的证据（使用参考视频 / 完整使用过程顺序图 / 文字版待用户确认）必须与商品视图缺口（缺背/侧/内部等真图）、场景、达人等其它素材缺口**打包在第 5 步的同一轮交涉里一次性一起问齐**，不要在建模阶段先为使用方式单独问一轮、到第 5 步再为视图单独问一轮。第 2 步建模时若已判定某非简单产品使用方式为 `unknown`，只需在模型里挂起该 `unknown`、留到第 5 步随素材缺口一并交涉即可；仅当第 5 步问答后仍浮现新缺口时才追加补问。
- 此项在第 6 步生成前方案检查里强制执行：涉及使用动作的实物商品，其「使用方式」为 `unknown`、既非通用标准用法又未向用户澄清，即为阻塞项，检查不通过。

**B. 数字/虚拟商品（`物态: 数字/虚拟`，如 SaaS、App、系统、平台、在线服务）——把「物理外观检查」整体换成「界面与流程真实性检查」：**

- **界面与信息架构不能凭空脑补。** 真实性权威是用户提供的界面截图/录屏/产品文档/功能列表——只有它们授权的界面布局、菜单结构、功能名称、数据字段、操作路径才能出现在画面里。**绝不脑补 UI**：没截到的页面、没给出的按钮/菜单/图表、没说明的数据，一律 `unknown`，不得自行画一套界面冒充产品真容；缺了就用局部截图、口播、结果数据或抽象可视化承载，而不是编一个界面。
- **功能与成效不能互相倒推。** 不能为了讲某个卖点就虚构产品并不具备的功能、并不存在的界面或编造的效果数据；也不能从一个界面截图反推出未被说明的功能、集成或性能指标。
- **表达用「界面动作 / 数据流转 / 场景结果」，不套物理手部动作。** 数字产品的「使用」是点击、切换视图、数据实时更新、流程节点推进（如仓储系统的入库→上架→拣货→出库→对账在看板上流动）、多端联动、报表生成等——用屏幕内的界面动作与数据变化来表达，不需要、也不应硬安一套「手拿产品、拆开包装」的实物物理动作。真人出镜操作电脑/手机时，屏幕内容仍受上面「界面不能脑补」约束。
- **没有实物形态维度就整类置 `n/a`，不因此判素材不足。** 外观分面（正面/背面/侧面）、材质质感、手持尺度、开合状态、物理动作路径这些实物维度对纯数字产品整类 `n/a`，不要向数字产品用户索取「商品各角度实拍图/手持演示视频」，也不要在生成前检查里拿「视角覆盖不足」阻塞它。

**C. 品牌本身（`物态: 品牌本身`，为品牌调性/心智做宣推而非卖单一 SKU）——把检查换成「品牌视觉与主张一致性检查」：**

- **品牌视觉资产以官方 VI 为准，不得自造。** Logo 的造型/配色/留白/组合规范、品牌主色与辅助色、标准字体、代表性视觉元素以官方 VI 手册 / Logo 源文件 / 既有官方物料 / 官网为权威；未给定的规范标 `unknown`，不得自造一套 VI、不得改 Logo 比例配色、不得杜撰 slogan。
- **主张与背书不能编造。** 品牌定位、心智关键词、本次宣推主题、可用信任背书（获奖、合作、用户规模等）只能来自已验证信息；不得为拔高调性而虚构荣誉或数据。
- **表达重调性与心智，不必绑定单一产品物理形态。** 品牌片可用场景蒙太奇、情绪叙事、代表性产品群像、用户群像、价值主张字幕/口播来承载；若片中出现具体产品，则该产品仍回落到 A（实物）或 B（数字）那一套真实性检查。

**D. 混合（`物态: 混合`）——拆开各成分，各自套 A/B/C 对应的检查，不混用标尺。**

**约束要编译成可核验的不变量，不要堆泛化文字（硬性）。** 别再往提示词里加「严格参考、不得变形、务必一致」这类空话——它们不可验证、模型也读不进约束。凡涉及具体商品，第 6 步编译 `视频生成Prompt.md` 前，先从「商品模型」已知事实里锁定最容易被模型带偏的两件事——**① 商品的真实尺寸/大小，② 商品在画面里的可见比例**——压成一张**简短商品尺寸台账**（挂在商品模型下，不新开 md）。商品的形态/部件/材质/颜色/文字/朝向等其它保真维度**不再单列进这张表**：它们已记在「商品模型」里，并通过 `产品1：` 定义行的「只采用/不采用」采纳条款内联进 Prompt（见下文与 seedance 指南），避免与商品模型重复登记。台账维度按物态取舍：实物必须填真实尺寸与可见比例；数字/虚拟、品牌本身无物理尺度时填 `n/a`：

```yaml
商品尺寸台账:
  产品id:
  物态:              # 实物 | 数字/虚拟 | 品牌本身 | 混合
  真实尺寸:          # 实物的真实大小/规格，必须有据：优先用户素材可见参照物、商品字段、规格标注；常见且规格固定的品类（如 AA/AAA/18650 电池、A4 纸、标准易拉罐、信用卡、家用插座）可按公认标准规格直接推导并注明「按品类标准推导」；完全无从判断填 unknown（阻塞项，须问用户，不得默认）。数字/品牌填 n/a
  可见比例:          # 换算成画面里相对手掌/人物/常见参照物/场景的可见比例，供分镜与全片一致性锁定；数字/品牌填 n/a
  source:            # 内部台账字段：尺寸依据来自哪张用户素材/哪个字段/哪条品类标准。仅供 Agent 自检追溯，不内联进 视频生成Prompt.md 正文（正文来源已由「对应@图片N」承载）
```

台账只登记「商品模型」里已知（非 `unknown`、非 `n/a`）的事实；`真实尺寸` 为 `unknown` 时按下面的「商品大小保障原则」处理，不得留空硬闯后续流程。

**商品大小保障原则（硬性，决策门阻塞项）。** 商品的绝对大小和画面比例是模型最容易失控的维度之一——同一件商品在不同分镜里忽大忽小、或整体尺寸明显失真（把随身小物拍成半人高、把大件拍成掌中物），都会立刻穿帮。为此：

- **进入 prompt 阶段前必须先弄清尺寸。** 编译 `视频生成Prompt.md` 之前，`真实尺寸` 必须已确定——要么来自用户素材/字段/规格标注，要么对常见固定规格品类按公认标准直接推导（如电池按 AA/AAA/18650 尺寸、A4 纸按 210×297mm）。**尺寸仍为 `unknown` 时禁止进入 prompt 阶段**：停下来用一句话问用户「这件商品的实际大小/规格大概是多少（或对标什么日常物件）」，拿到答复或可靠推导后再继续，绝不默认、不臆测一个大小硬编进 Prompt。
- **可推导就直接推导，不打扰用户。** 对规格公认固定的常见品类，直接按标准规格推导尺寸并在 `source` 注明「按品类标准推导」，无需为此追问；只有既非固定规格、素材又看不出大小的商品才停下询问。
- **尺寸落进 Prompt 且全片锁死。** 把 `真实尺寸`/`可见比例` 内联进 `产品1：` 定义行（如「产品1约为一节 AA 电池大小，置于掌心时长度约到指根」），并在「全片连续一致性说明」里写明该商品在所有分镜中保持同一真实尺寸与相对比例，杜绝忽大忽小。
- 此项在第 6 步生成前方案检查里强制执行：`真实尺寸` 为 `unknown` 且未向用户澄清即为阻塞项，检查不通过。

**商品尺寸与保真事实默认要编译进 `视频生成Prompt.md`，不是只当自检清单（硬性）。** 涉及具体商品时：**尺寸**——把 `真实尺寸`/`可见比例` 内联写进 `产品1：` 定义行（可核验的具体描述，如「约一节 AA 电池大小，掌心可完全握住」），而非「大小合适」这类空话；**形态/部件/材质/颜色/文字/朝向等保真维度**——通过 `产品1：` 定义行的「只采用@图片N 的结构/颜色/标签位置……、不采用其背景与无关物」采纳条款承载（与 seedance 指南一致），不必再单列正向 match 表或否定清单。`source` 是内部追溯字段、不写进 Prompt 正文。全部作为 `产品1：` 定义行内的描述文本存在，保持 `视频生成Prompt.md` 封闭集合结构不变。

**提交前反向检查：逐条比对最终 Prompt 正文有没有与商品模型/尺寸台账相反的描述**——商品在各分镜的大小是否前后一致、可见比例是否与 `真实尺寸` 相符（没有忽大忽小、没有整体失真），颜色/文字/部件/朝向是否与「商品模型」采纳的事实一致。出现矛盾即回改 Prompt，不得带矛盾提交。此项在第 6 步生成前方案检查里强制执行。

**动态产品用「状态机」表达动作，不只给静态外观（硬性，但必须短·确定·可视）。** 涉及打开/按压/倒出/穿戴/安装等连续动作时，别只描述最终外观、也别写成一长串自由发挥的动作散文，把它压成一条**短状态机**。**这套状态机主要服务实物商品的物理动作**；数字/虚拟商品若要表达「流程推进」（如入库→上架→拣货→出库），可复用同一 `S0→动作→S1→S2` 骨架，但把「接触点/方向/受力」换成「界面动作/数据流转/视图切换」，把「全过程产品形态不变」换成「全过程界面框架/品牌视觉不变」；纯品牌调性片无连续物理动作时不必套状态机。

```text
S0 初始状态（可见起点，绑定开始态参考图）
 → 动作：主体 / 接触点 / 方向 / 旋转轴或受力方式（一句话，只写必要变量）
 → S1 中间状态（可选，仅当中间态会被看到时才写）
 → S2 最终状态（可见终点，绑定结束态参考图）
全过程不变量：整段动作里产品的形态/颜色/Logo/比例/部件数保持不变
```

- **短、确定、可视**：每个状态只写画面能看见的关键变化，动作只写接触点、方向、旋转轴/受力这几个必要变量。**不要过度分解**——切碎成过多微动作反而给模型更大自由去脑补出多种结构/多套外观，是要极力避免的失败（避免把一个「拧开瓶盖」拆成七八帧机械步骤）。目标是「刚好锁死物理路径」而非「写满每一帧」。
- **有方向性/易出错的商品，必须钉死「哪个功能部位对准什么、朝向如何」（硬性）。** 凡是「用错方向就明显穿帮」的商品——吹风机（出风口 vs 进风口）、喷雾/喷头（喷嘴朝向）、话筒（拾音头）、电动牙刷/剃须刀（刷头/刀网）、注射/滴管、遥控器/扫码枪（发射端）、插头（插脚方向）、瓶口/壶嘴（倒出口）等——**不能只写「手持产品对准X使用」这种含糊说法**（模型极易拿反：把进风口、瓶底、非工作端对准目标）。必须在动作里写明：①**哪个具名功能部位**（如「出风口/喷嘴/刷头」而非笼统「产品」）②**对准哪个目标**③**朝向/角度/距离**④**气流/水流/内容物的可见流向或作用结果**。例:不要写「手持吹风机对准湿发吹风」，要写「手持吹风机、**出风口朝向发丝**（进风口在后、朝向手臂一侧），暖风从出风口吹出、发丝顺风向被吹动」。这些方向不变量同时落进 `产品1：` 定义行或对应分镜的画面内容，别让模型自由发挥。
- **两端各绑一张参考图**：S0 绑开始态参考图、S2 绑结束态参考图，按参考素材台账各占一个主锚点。
- **素材不足时的降级**：只有一张静态图却需要复杂展开时，先请用户补对应状态参考图或先生成关键帧作为缺失端的锚点；补不到就按低打扰规则退回到素材能证明的静态状态展示，不硬编一条猜出来的动作路径。

**商品实例与交互连续性合同（实物类硬性）。** 商品穿帮不能只靠一句“保持一致”兜底。凡是实物商品进入手持、挤压、倾倒、刷动、翻面、交接、遮挡或悬挂动作，第 4 步先建立、并在第 6 步编译以下内部台账：

```yaml
product_entity_contract:
  product_id: 产品1
  instance_budget: 1
  multi_instance_authority: none | user_locked | proof_requires_multiple
  immutable_signature: []   # 轮廓、真实尺寸、颜色/材质、部件数、工作面、孔/挂绳等可见身份锚点
  shot_entity_ledger:
    - shot_id:
      instance_count:
      product_state_in:
      product_state_out:
      left_hand_job:
      right_hand_job:
      other_similar_objects: []
      high_risk_interaction:
      occlusion_or_handoff:
      reanchor_after_occlusion:
```

- **默认全片恰好一个商品实例。** 若证明确需两个或用户明确锁定多件，分别命名 `产品1-A / 产品1-B`、各绑来源并说明各自位置与职责；否则任何镜头 `instance_count > 1` 都是阻塞项。Prompt 用正向、可数的表达写“画面中恰好一把/一件产品1”，不能只写“不要复制商品”。
- **相似道具也必须具名。** 与商品同材质、同轮廓或同颜色的瓶、刷、木片、附件若无信息职责就移除；必须出现时命名为其它道具并写清它不是产品1、从哪里进入、由哪只手控制，避免被模型补成第二件商品。
- **一拍只承担一个高风险交互。** 翻面、跨手交接、超过 40% 遮挡、挤压形变、悬挂、液体倒出、工具叠放均算高风险动作；同一节拍不叠两项。复杂演示拆成“稳定起态 → 单一交互 → 稳定结果态”的相邻切镜，而不是让模型在一个长镜头里同时翻转、遮挡、换手和叠物。
- **手部职责必须可执行。** 每个交互镜头明确左手、右手分别固定什么、操作什么；没有职责的手不入镜。像“刷毛打圈”必须写成“同一把产品1的刷毛工作面直接接触目标表面并移动”，不能写成可能被理解为“另一把刷子在商品上打圈”的含糊短语。
- **遮挡后重新报身份。** 商品经历超过 40% 遮挡、出画、换手、翻面或切镜后，下一可见状态重新写 `恰好一个产品1 + immutable_signature + 当前朝向/工作面 + 持握点`；物体不得借遮挡无因出现、消失、增殖、变成长短柄另一 SKU。
- **素材视角决定动作上限。** 只有单一参考面时，不主动安排无法由素材约束的背面、内部、悬挂孔特写或大角度翻面；若这些是核心卖点才按既有低打扰规则补素材，否则换成已知视角可完成的低风险证明。
- 第 6 步运行 `validate_creative_contract.py` 校验内部 JSON 合同:实例数、身份签名、手部职责、相似道具、遮挡后重锚(这些都是可结构化断言的字段,在自撰 JSON 里逐项核对);任一失败先回改,不提交生成。`validate_final_prompt.py` 只对实际 Prompt 做确定性禁止项/结构扫描,不再做单实例措辞的正向匹配——「画面中恰好一件产品1、相似道具具名、遮挡后重报身份」这类写法由你依据本合同正文自行落进 Prompt,脚本不裁决。

用户反馈后的素材引导：

- **统一顺序是“先诊断，再判断证据缺口，再给选项”。** 先结合原始商品素材、生成结果和用户反馈，指出最可能出错的维度或动作节点；不要未经分析就只回复“请补图/视频”。已有素材足以确定修法时，直接给出精准修改方案，不强制重复上传。
- **默认低打扰，不因证据边界自动追问。** 单张图片只能证明某个静态状态，不代表必须停下来询问。若该状态足以承载脚本，直接从该状态开始、只展示该状态或在该状态结束：例如只有“已打开”图时，可让镜头一开始产品就已打开并接着展示，不追问它是怎么打开的。只有“未打开”图时，可以只展示完整包装、口播和结果，不擅自生成撕开过程或未知打开后的外观。
- **只有三类情况才优先询问补证据。** 用户明确要求保留完整打开/使用过程；核心卖点或证明必须依赖该连续动作；移除或降级该动作会实质改变用户意图。除此之外，Agent 先自行改成素材支持的低风险方案并继续出方案，不把补图/视频设为阻塞项。
- 若用户说产品**形态、外观、大小比例、颜色、包装面、文字、Logo/标签位置、SKU 或局部元素**有问题，先分析错误维度，再判断缺少哪个静态事实。若现有素材不足，首选项优先引导上传对应角度、局部细节、正确版本或不同状态的**产品参考图**；其余选项可为只保留已知视角、按准确文字描述修改、强化局部约束或回避高风险镜头。
- 若用户说产品**打开方式、使用方式、手部动作、倒出/喷洒/涂抹/穿戴/安装路径、物理交互**有问题，先分析开口位置、接触点、受力方向、动作顺序、内容物流向和使用终点。若命中上述询问门槛且缺少连续动作路径，首选项优先引导上传真实或近似的**参考视频**；用户也可以上传按顺序排列的多张**状态参考图**，至少标明“未打开/起始状态 → 手或工具接触位置 → 半开/中间状态 → 已打开/完成状态”，并补充受力方向或先后顺序。单张终态图可以直接用于终态展示且无需追问，只是不能被扩写成完整动作路径。
- **证据优先级按问题类型决定。** 静态外观、文字、部件和开合状态优先参考图；连续手部路径、受力、形变、倒出流向和安装顺序优先参考视频；多状态图是动作视频缺失时的次优证据。用户无法提供充分证据时，再提供已打开/已完成状态、静态展示+口播、结果对比或更简单低风险交互。
- 选项必须写成用户能直接选择的自然语言，不只问"请补素材吗"；每次都保留"你也可以直接描述哪里不对和想怎么改"的自由入口。用户暂时不能提供对应素材时，回退到低风险表达：少展示不确定视角，不展示高风险动作，用口播、结果、反应或静态正面产品同框承载卖点。
