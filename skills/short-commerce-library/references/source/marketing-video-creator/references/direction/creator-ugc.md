
# 达人 UGC 创意引擎与 Prompt 画像

当 `primary_specialist: creator_ugc` 时使用。归属边界与模型编译层交接是 [`_shared-profile-preamble.md`](_shared-profile-preamble.md) 中的共享规则;请先阅读它。新增声明:本画像也不拥有人像生成。

## 目的

保留原始 UGC 生成包的密度:达人信任、产品真实、原生镜头行为、上手操作、口播、证明与连续性,逐镜保持显式,而不是被打磨成一个通用的商业广告。

## 专项创意引擎（先于 Prompt 画像）

UGC 的核心不是“有人对镜说话”，而是一个可信的人在可信场景里亲自完成可信证明。先完成：

`购买情境 → 信任障碍 → 达人身份与商品关系 → 原生内容类型 → 首拍理由 → 亲自上手 → 可见证明 → 个人结论 → 单一行动`

### 先定达人，再写脚本

达人必须绑定六项：年龄段、生活/职业角色、外观与着装锚点、真实场景、为什么会使用或推荐该商品、说话与反应质感。角色必须能解释其可信度：通勤用户、家庭照顾者、美妆测评朋友、数码实测者、生活方式种草者、实在型家庭用户、探店达人、玩家、穿搭试穿者等。达人图和脚本角色必须一致。

达人可信度来自角色、使用场景、停顿、目光、手势、真实操作和克制结论，不来自网红脸、棚拍光或一直把产品举在脸旁。

### 选择一个主创意类型

- 有明确价格、券、套餐或到手利益 → **利益前置口播**；
- 依赖质感、舒适、日常使用或朋友推荐 → **口播种草 / 真实场景 Vlog**；
- 需要验证功能、参数、质地或差异 → **产品测评 / 卖点演示 / 效果展示**；
- 多 SKU、多颜色、多口味或多穿搭 → **清单轮播 / 稳定对比**；
- 门店、套餐、核销或服务流程 → **探店与团购**；
- 年轻受众、玩梗或强视觉打断 → **荒诞/表情包/视觉 Hook**，但前半段必须回到亲自证明；
- 冲突、误会或反转承载说服 → 路由剧情主专项；只有信任仍为核心时才保留 UGC 为主。

每支片只选一个主类型和一个主卖点。Hook 必须与后续亲自证明相连，不能是独立段子。

### 30 秒参考节奏

`0-3s 原生 Hook/痛点/结果 → 3-8s 达人与使用情境可信 → 8-14s 商品进入真实动作并明确主卖点 → 14-21s 证明 1 → 21-27s 证明 2/结果/反应 → 27-30s 商品名、个人结论与单一 CTA`。

15 秒压缩为 `Hook/情境 → 商品动作 → 一个完整证明 → 结论/CTA`，不把 30 秒脚本机械截短。

### 证明与表演规则

- 每个利益句映射为 `用户需要 → 商品动作 → 可观察结果 → 对这个人的意义`；
- 包装亮相、正常使用和达人微笑都不能单独证明“更好”；
- 手机感来自自然光、生活空间、轻微手持、非完美停顿与视线关系，不来自故意做粗糙画质；
- 产品外观只由产品素材定义；达人素材只定义人物，不得让服装、配饰、包或背景物变成商品；
- CTA 像角色会说的话，只给一个下一步。

### 专项退出标准

- 换成另一类达人后脚本需要变化；否则角色过于通用；
- 达人亲自完成了主证明，且证明在静音下仍可读；
- 镜头、场景、语言和反应符合角色与平台，不像品牌棚拍或广告念稿；
- 一个主卖点贯穿 Hook、操作、证明与结论；
- 产品事实、外观、用法和数量均由权威素材支撑。

## 必需载荷结构

用以下八个区块写出完整的 Prompt 载荷:

```text
【material_manifest】
<每一个 @image/@video/@audio 输入、它唯一的职责、采用的维度、
忽略的维度,以及消费它的场景>

【product_identity_lock】
<SKU、形态、颜色、材质、包装/logo/文字位置、数量、状态、
允许的交互,以及已核实的主张>

【creator_identity_lock】
<达人角色与信任基础、面部/头发/着装锚点、体型与嗓音、
镜头关系、说话质感,以及允许的状态变化>

【global_visual_bible】
<平台原生房间、光线、取景、手持/稳定行为、颜色、
背景密度、产品可读性,以及 Style 处理>

【audio_and_text_bible】
<语言、精确的口播台词、嗓音表达、停顿、环境声、拟音、
音乐密度、字幕规范,以及口播 CTA>

【shot_instructions】
镜头或阶段1：<参考素材使用、达人/产品起始状态、镜头、连续
动作、手部接触、证明/结果、口播台词、转场、完成状态>
<对所有已确认的节拍重复>

【continuity_ledger】
<达人状态、产品状态、道具归属、场景朝向、光线、
口播与转场的交接>

【final_render_checks】
<可观察的 Hook、证明、产品身份、自然表演、口播 CTA,
以及所选 Hook/Style/Play 的成功条件>
```

在任何可能产生歧义的镜头里,重复相关的素材标签与状态。产品上手操作或说话人分配,不要仅依赖一个全局清单。

当因为用户只上传了产品图,或请求一个达人形象,而生成了达人/人物参考图时,达人图绝不可包含被推广的产品。它只是一个人物身份参考。`material_manifest` 必须显式区分:

- 达人/人物图:采用面部、头发、妆容、体型、着装风格、姿态、达人气质与说话临场感;忽略所有物体、包装、购物袋、产品卡、Logo、货架、背景道具与手持物件,不把它们当作产品参考;
- 产品图:只采用被推广产品的可见表面、形态、颜色、材质、包装/标签/Logo 位置、数量、尺度与已确认状态;忽略人物、服装、手部与背景。

在 UGC 脚本与 Prompt 中,绝不让达人的服装、配饰、包、帽子或背景物件变成被推广的产品,除非用户明确说那件正是产品。达人信任来自角色、使用场景、语气、上手操作与证明,而不是把产品塞进人像参考里。

## 家族投射

- Hook 是一个原生的口播式、行为式、结果先行、测试、警示或情境化开场,并立即桥接到使用或证明。
- Style 必须保留生活化的可信度;打磨不能抹掉达人可信的环境或表演。
- Play 成为一个原生的达人动作、演示、挑战、试穿、转场或形式机制。
- 证明是一个已完成的可见动作或结果,而不是拿着包装夸赞。
- CTA 是一个短促的、可听的动作,与平台和活动意图一致,除非已明确确认输出为静音。

## 模型编译层交接

遵循 [`_shared-profile-preamble.md`](_shared-profile-preamble.md) 中的共享交接规则,应用于这个八区块包。新增必保留条款:不可移除包含活跃信息的区块,也不可合并达人身份锁与产品身份锁。

## 检查

- 达人角色说明了为什么这个人是可信的。
- 口播文案契合上手操作与证明所需的时间。
- 产品外观与状态在每个相关镜头中保持绑定。
- 达人/人物参考只是一个人物身份参考,不包含也不定义被推广的产品。
- 产品参考是产品形态、尺寸、包装、标签位置与可见表面的唯一权威。
- 产品主张与证明有来源支撑;Prompt 不臆造背标、侧面板、成分表、认证、内部内容或无支撑的使用方法。
- 镜头、房间、停顿、目光、手势与反应对这个角色而言都是原生的。
- 最终 Prompt 包含已确认的资格条件与一个口播 CTA。
