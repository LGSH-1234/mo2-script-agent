
# 剧情带货创意引擎与 Prompt 画像

当 `primary_specialist: story_commerce` 时使用。归属边界与模型编译层交接是 [`_shared-profile-preamble.md`](_shared-profile-preamble.md) 中的共享规则;请先阅读它。本文件不额外添加归属声明。

## 目的

保留原始剧情带货的控制面:压力、回应式对白、产品介入、证据、见证反应、结果改变与转化,必须保持为一条可执行的因果链。

## 专项创意引擎（先于 Prompt 画像）

剧情带货先从受众爱看的类型与情绪回报出发，再让商品成为赢法；不能从卖点直接跳到一个通用使用场景。

`商品品类 → 目标受众 → 类型偏好 → 受众幻想 → 压力关系 → 首屏情绪债 → 人物选择 → 商品剧情功能 → 可见证明 → 见证反应 → 情绪回报 → 转化`

### 类型与商品角色

只选一个主类型：

- **甜宠/关系确认**：被看见、被选择、被照顾；商品是照顾证据、亲密细节、关系修复或确认道具；
- **女频/男频逆袭**：被低估后公开赢回尊重；商品是反转证据、能力武器、身份信号；
- **职场爽剧**：截止时间、客户或公开考核；商品是效率武器、标准或结果证明；
- **家庭伦理**：误解、照顾与劳动被看见；商品是关怀证据、省心证明或关系修复；
- **重生纠错**：上次错误造成损失，这次提前做对；商品是正确选择和避免损失的证据；
- **悬疑误会/喜剧**：异常行为被误读，商品在后段重新解释前面；商品是最终揭示钥匙；
- **隐藏身份/公开反转**：商品或结果让他人改判身份、品位或能力。

商品只能承担一个主要剧情功能：反转证据、身份信号、秘密武器、照顾物、错误选择纠正、最终揭示钥匙或关系修复证据。拿掉商品后主角若仍以同样方式获胜，该创意不合格。

### 先写因果骨架，再写对白

锁定六问：谁在什么场景下有何压力；谁误解/质疑/测试谁；主角为何不能离开；商品为何此刻出现；商品具体解决什么并产生什么可见证据；这个证据如何改变关系、身份、判断或任务。

对白必须回应上一句并推动下一句。15 秒至少 4 句、30 秒至少 8 句有效对白；口号、无意义感叹、独白式旁白和纯 CTA 不计。先有疑问/误会/委屈/试探，再有回应与行动；先有场景需要，再有商品功能；先有证明，再有情绪变化。

### 30 秒参考节奏

`0-3s 类型清晰的异常/压力 Hook → 3-8s 压力升级并锁住人物 → 8-14s 主角做隐藏选择、商品进入 → 14-22s 商品证明升级并被见证 → 22-27s 类型回报/关系或判断改变 → 27-30s 产品 Hero Shot 与承接情绪的 CTA`。

15 秒压缩为 `Hook/压力 → 商品进入与问答 → 商品细节完成反转 → 情绪收束 + CTA`，至少让四句对白形成完整问答链。

### 模板融合

当有 Hook 或创意模板时，不照抄模板编舞。保留传播职责、因果机制与标志性线索，把模板变成剧情事件的一部分：Hook 的异常应制造或放大人物压力；商品动作应同时完成模板后果与剧情证明；Style 只调制类型语法。甜宠等玩法决定关系因果，Hook 决定首拍如何抓人，二者共同作用于同一事件。

### 专项退出标准

- 主类型、受众幻想、压力关系和回报一致，不混成多个弱类型；
- 商品使主角以一种不可替代的方式赢、被理解或完成关系确认；
- 证据发生在原压力来源或关键见证者面前，并直接回答其错误判断；
- 每句有效对白都回应、升级、追问、揭示或改变前一句；
- 反转由商品证据导致，不靠突然自信、巧合或最后硬塞产品特写；
- CTA 承接改变后的情绪与商品意义，不打断剧情。

## 必需载荷结构

按此顺序写出完整的 Prompt 载荷:

```text
【生成目标】
<剧情带货类型、请求本地时长、语言、商业结果>

【素材职责与人物绑定】
<每个 @asset 的职责;具名人物、关系、身份锚点、
产品身份,以及场景权威>

【剧情因果锁】
压力/欲望/误会：<具体的起始债务>
人物选择：<开启动作的选择>
产品剧情功能：<为什么这个产品此刻登场,以及它改变了什么>
可见证据：<可观察的证明>
见证与反应：<谁感知到它,以及判断如何改变>
结局与转化：<改变后的结果与自然的口播 CTA>

【角色与表演】
<姿态、目光、距离、表情习惯、说话关系、情绪
触发,以及可见的反应递进>

【分阶段剧情与对白】
阶段或镜头1：<起始状态、压力事件、镜头、精确对白、
动作、产品状态、声音、完成状态>
<贯穿证据、反应、回报与转化重复>

【产品与连续性锁】
<SKU、数量、开启/使用状态、物理成因、道具归属、人物
状态、场景朝向,以及交接>

【结束状态】
<最终关系/判断/结果、可读的产品状态、口播 CTA>
```

对白链留在 `分阶段剧情与对白` 内;不要用旁白、干瞪眼或字幕替换因果对白。产品动作必须创造出改变结果的证据。

## 家族投射

- Hook 制造精确的情感或信息债务,由正文偿还。
- Style 支撑类型与压力,但不能替代因果。
- Play 提供一个相容的类型容器、反转装置、表演范式或视觉机制。
- 产品是证据、工具、赠品、剧情钥匙、纠正、身份线索,或其他具体的剧情功能。
- 只要范式需要,原始压力来源或见证者在收束时保持在场。

## 模型编译层交接

遵循 [`_shared-profile-preamble.md`](_shared-profile-preamble.md) 中的共享交接规则,应用于这个高控制度的剧情载荷。新增必保留条款:不可重排因果链,不可削弱已确认的精确对白、证明、反应与结尾。

## 检查

- 压力、选择、产品介入、证据、反应与结果构成因果。
- 每一句有效台词都在回应、升级、质问、揭示或改变前一句。
- 产品真实与物理动作保持可信。
- 收束由证据引发,而不是无来由的自信或姗姗来迟的产品特写。
- 口播 CTA 跟在结果改变之后,而不是打断它。
