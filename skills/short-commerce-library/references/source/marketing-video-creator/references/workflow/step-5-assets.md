
# 工作流 · 第 5 步：素材完整性检查与参考素材准备

> 本文件是第 5 步的权威正文。进入本步时即时读取。

## 5. 素材完整性检查与参考素材准备

读[素材与执行](../base/assets-and-execution.md)的中间素材章节（素材决策、绑定与执行的权威正文都在那里，按「全局文件读取设置」读到末尾再动手）。**本步据以判素材的权威合同（「商品素材与达人素材隔离合同」「多图借鉴与局部修改绑定合同」「参考素材台账合同」「禁止 Agent 自行生成产品图合同」「市场/语言/人物本地化合同」）都在根级 `contract-assets-and-localization.md` 里；进入本步前必须对 `contract-assets-and-localization.md` 过 SKILL.md 不变量 #14「真读门」，下文按合同名引用它们时指的就是这份 contract 的正文。** **在故事脚本写好后立即执行。**

以故事脚本分镜表里被引用的实体为起点，盘点所有实体（角色/达人、商品、场景及其它必要素材），逐一判断是否已有可用权威素材（用户上传、商品系统、达人系统等）。真正逐一交涉在这一步完成，结论留在对话里，**不写入 md 文件（不创建 `asset-plan.md`）**。

- **素材已完整时**：向用户说明素材已齐全，确认是否就用这些素材图。
- **存在缺失时**：先把已选定/已齐备的部分同步给用户，再对每个缺失或不足以支撑其信息角色的素材，在对话中二选一交涉——请用户上传，或询问是否由你生成。用户给出「上传」或「同意生成」的答复前，该素材保持待定，既不生成也不用不相关素材替代。
- **外观/使用方式的证据来源必须独立复核，不能只信第 2 步的 `unknown` 标记（硬性）**：本步不得默认「第 2 步没标 `unknown` 就是齐了」。对分镜要展示的每个外观维度与每个使用动作，**回到「证据来源」逐条核对其权威来源是不是图片/视频/界面截图/VI**：凡某维度当前是靠**纯文字**（用户口述、已锁定文案里的描述性文字、或标了「用户文字(非权威)」）撑着的，一律**就地改判为 `unknown`、视同缺口**，与视图/使用方式缺口一并在这一轮向用户要图片/视频——即便第 2 步误把它填成了"已知"。只有走完「使用方式保障原则·证据升级阶梯」、用户在被要求补媒体后仍强烈坚持只用文字并经检查确认的文字版才算例外。这道复核专门堵「第 2 步误把文字当已知、第 5 步就不再查」的漏放。
- **商品图视角覆盖必判（硬性）**：「有一张图」≠「素材充分」。**以第 2 步「商品模型」为清单**，对照分镜里各镜头**实际要展示的视角与细节**（正/背/侧/顶底/内部、材质纹理特写、logo/标签、开合状态、不同颜色款式或 SKU 等），逐一核对现有图能否可信支撑；凡分镜要展示的面在模型里仍是 `unknown`、或现有图（如只有正面图）看不到，判为「不足以支撑其信息角色」，**主动请用户补传该视角的真实商品图（或短视频），不要直接从正面图生成一张背面/细节图**——凭已有图脑补未见过的外观违反关键信息保守原则。用户无法补图又不同意生成时，调整分镜回避看不到的视角，而非硬拍猜测外观。素材补齐后回填商品模型对应字段。此项与其它素材缺口一并向用户交涉，**尽量在这一轮把素材缺口一次问齐**；若第 2 步的建模/关键信息澄清未覆盖到，允许在此追加一轮补问。**这是「商品完整视图保障原则」的执行点：分镜要展示、却无真实素材覆盖的视图未补齐前，视为视图不完整，不得推进到第 6 步 prompt 编译（详见「商品完整视图保障原则」硬性阻塞门）。** **「商品视图缺口」与「使用方式缺口」必须打包在同一轮问齐：** 若本片涉及非简单产品的使用动作、其「使用方式」在第 2 步被挂为 `unknown`（或按上一条被就地改判为 `unknown`），则「使用方式保障原则·证据升级阶梯」所需的证据（使用参考视频 / 完整使用过程顺序图 / 文字版待确认）要与本条的视图缺口、场景/达人等其它素材缺口**在这一轮一次性一起向用户交涉**，不为使用方式单独另起一轮提问（详见「商品使用方式保障原则」）。
- **立体结构充分性必判，且不得被「分镜不拍这个角度」或「用法通用」放过（硬性，本步高频漏放）**：视角覆盖不只看「分镜会不会拍到某个面」,还要看**用户点名的 P00 立体结构关系(部件一体还是独立、凹凸、层叠、连接方式、内外、开合)有没有被现有素材证清**。**判据与「分镜拍不拍这个角度」无关**——哪怕全片都用正面/自然观察角度、根本不给侧面特写,只要该 P00 结构靠现有单一视角在物理上无法证伪(单看这一张,"一体"和"独立"都说得通),就判 `unknown`、判「不足」,**必须在本轮向用户补要能看清该结构的侧面/斜 45°/结构特写图**,不得用"反正分镜不拍侧面,正面图足以支撑"把它放过。同时**严禁用「用法直观/通用标准用法」来论证「素材已齐全」**:用法是否通用只免「要使用演示素材」这一项,与外观/尺寸/立体结构视图是否充分是两码事,绝不能因为"商品用法很直观"就顺势判"现有正面图已够、素材齐全"直接进第 6 步。**本步收尾自检必答三问,任一为「否」即不得判素材齐全、必须回到用户交涉:①用户点名的每个 P00 立体结构,现有真图能不能明确证清(而不是"能两解")?②每个要展示的外观面,是靠真图还是靠用户纯文字撑着?③我判「素材齐全」是不是(哪怕部分地)建立在"用法通用/用户文字已说清"之上?**
- **产品外观图默认不由 Agent 自行生成（硬性，见「禁止 Agent 自行生成产品图合同」）**：缺产品图/缺某个面时，默认动作是**请用户补真图**或**调分镜回避**，而不是 Agent 自己文生图/图生图造一张商品外观图充数（分镜示意图、关键帧图不在此限——但关键帧里的商品外观仍须来自已确认真图）。**仅当用户强烈要求时才可生成产品图，且必须走强制流程**：① 生成前先向用户声明「自生成的产品图可能与真实产品不一致（形态/比例/Logo/标签/部件/颜色偏差）」；② 生成后经第 5 步质量自检过滤明显不合格的，再用 `present_sandbox_file` 展示、**由用户明确确认符合真实产品**（Agent 自检不替代用户确认），确认后才在注册表置 `verify_status: confirmed` 并可进 `ImageList`，未确认前保持 `pending` 禁止进生成；③ 正式调用视频生成模型时，该产品参考须为**完整三视图**（正+背+侧，必要时补顶/底/内部/使用状态），逐视角走①②流程后一起绑进 `ImageList`。
- **多图借鉴/局部修改必判（硬性）**：当用户要求基于一张图改文字、颜色、材质、Logo/标签、部件、状态、数量、背景、构图或风格时，不要默认所有图共同定义一个完整商品。必须确认基础图、每项修改的目标区域与权威来源，以及各图的保留/忽略维度；若映射不清，给 2-3 个针对性选项让用户选择或描述。未明确之前，不进入最终 prompt。
- **分镜图 / 商品多视图强制合并（硬性，只要出现多张就必做）**：**只要出现多张分镜示意图，或同一商品的多张视角参考图（含「完整三视图」），就必须先用内置脚本 `scripts/merge_images_grid.py` 把多张图合并成少数几张「拼图大图」——这是强制行为，不以「图数是否超单次调用上限」「用户是否明确要求」为前提**。合并覆盖两处：①向用户 `present_sandbox_file` 做分镜确认展示时，**默认展示合并后的分镜总览拼图，禁止一张一张地逐张展示**（仅当用户明确要求看单张原图时才额外附原图）；②把分镜图/多视角图绑进 `ImageList` 时，先合并成拼图再绑，不得靠多拆视频请求或丢图硬凑：
  - 分镜图用 `--mode storyboard`（每格带序号/时间/景别/节拍/画面动作等字段）；商品多视图用 `--mode product-views`（每格带正/背/侧/顶底/内部/材质等视角标签）。
  - 用 `--max-per-sheet` 按当前运行时图片上限自动分页成 `<prefix>_1.png`、`<prefix>_2.png`……保证合并后拼图总数 ≤ 单次调用上限；`--cols` 控制列数。
  - 合并在第 5 步参考素材准备阶段完成——既用于分镜确认展示，也用于进入第 6 步 prompt 编译之前绑进 `ImageList`；拼图作为新素材登记进注册表（记明由哪些原图合并而来），prompt 里用「@图片N 的第 X 格 / 『背面』格」引用具体分镜或视角。合并不改变每格原图的信息角色与「只采用/不采用」采纳条款，逐格声明照旧。
  - 具体用法（含两种 `--mode` 的**输入 JSON 字段模板**，照模板写 `--input` 文件、不必去读脚本源码）见[素材与执行](../base/assets-and-execution.md)「分镜图与商品多视图的合并」。正式字段名为 `tiles`/`image`/`view`/`desc`（`images`/`path`/`label`/`note` 等同义写法脚本会自动归一并打 `WARN`，不会再失败）；报错时按中文 `ERROR` 字面修输入 JSON，不要去读脚本源码反推。**产品多视图仍受「禁止 Agent 自行生成产品图合同」约束：合并的必须是已确认的真实视角图，合并动作本身不等于允许自造视角。**

默认复用所提供素材或纯文本生成；仅当中间图像能实质稳定商品/达人身份、多套已确认服装、反复出现的角色、场景几何、风格、关键帧构图或跨片段连贯性时才生成。**但「承载商品身份/外观真值的产品图」是例外：默认禁止 Agent 自行生成，只有在用户强烈要求时才按「禁止 Agent 自行生成产品图合同」的强制流程（风险声明 → 生成 → 用户确认 → 完整三视图）生成；分镜示意图、关键帧图、人物/达人/场景/风格图不受该禁止约束（关键帧里的商品外观仍须取自已确认真图）。** **生成人物/角色/达人形象素材图时，若用户未明确指定比例，默认使用 `3:4`（仅作用于人物素材图，不改变整片视频比例），且人物图不得包含营销商品或任何可能被误认为产品的物体；商品只在视频分镜/商品素材中绑定。** 用户同意生成后，具体生成动作不再逐一征求同意；但**生成的关键参考素材产出后要通过 `present_sandbox_file` 展示给用户确认是否符合预期**（Agent 生成的产品图尤须经用户确认，Agent 自检不替代用户确认），通过后再进入视频生成，次要或一次性素材可径直使用。展示时说明每个素材要稳定的信息角色、登记实际返回素材，不暴露内部图像提示词。

- **生成图像质量自检与不合格重生成（硬性）**：流程中**每生成一张图（人物/达人形象、商品外观、场景、关键帧等），在展示给用户或投入下游之前，Agent 必须先自己逐张核验**，不合格的一律重新生成、不得将崩坏或跑偏的图直接抛给用户或带入视频生成。核验维度：
  1. **崩坏/畸变**：多手多指、肢体扭曲、五官错乱、结构断裂、文字乱码、明显 AI 伪影、糊成一团、比例失真等生成缺陷；
  2. **是否符合商品建模**：商品的形态、大小比例、颜色款式、材质质感、Logo/标签位置、可见面等是否与第 2 步「商品模型」里已知（非 `unknown`）的事实一致——**不得出现模型未覆盖的面或臆造外观**，也不得把 `unknown` 的面猜画出来；
  3. **是否符合用户要求、市场本地化与素材约束**：是否满足用户明确点名的元素与创意要求；人物图是否遵守白底、干净、无商品、无使用姿态；素材角色是否被污染（如达人图混入了商品）；比例是否符合规则；人物未被用户锁定时是否与 `target_market / cast_localization` 一致。视觉质量合格但市场不匹配仍判不合格，自动重生成或换候选。
  - **判不合格就重生成**：定位具体问题（哪种崩坏 / 违背哪条建模事实 / 不满足哪条要求），据此调整生成提示词并重新生成，直至通过自检；同一张图重试建议上限 3 次仍无法通过时，停下来向用户说明具体问题、给出选项（换角度重试 / 请用户补传参考图 / 调整分镜回避该呈现），不静默使用坏图。
  - **自检通过后才进入"展示给用户确认"环节**：自检是 Agent 的内部把关，展示确认是用户把关，两者不互相替代；商品外观类素材尤其要对着「商品模型」逐面比对，避免把跑偏的商品图带进视频生成。

`sandbox_generate_video` 支持直接视听输出时，不要生成完整 TTS 口播轨再混合；把确切旁白、说话人、语言、演绎、停顿、时间直接放进视频生成提示词。TTS 只用作简短中性音色锚点。生成图像不得捏造经核实的主张，不得悄悄替换权威商品/达人/用户参考。
