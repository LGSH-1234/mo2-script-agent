
# 工作流 · 第 1 步：输入与成熟度判断

> 本文件是第 1 步的权威正文。进入本步时即时读取；上游被改动重跑到本步再读。

## 1. 输入与成熟度判断

**先过「有效意图闸」**：在做任何规范化之前，先判断这一轮输入是否携带**可推进的营销制作意图**。若输入属于以下情形之一——空白 / 只有问候或语气词（"在吗""hi""你好"）/ 表达无从下手或直接询问能力（"你能做什么""这个怎么用""帮我做点东西""给点灵感"）/ 与营销视频完全无关又无可提取信息 / 语义残缺到无法判断想做什么——**不要进入下面的规范化与七步流程，也不要甩问卷逼用户填框架**，而是用一段简短、说人话的能力介绍回应，主动告诉用户这个 Skill 能帮他做什么、并给出可直接照抄的上手示例，把球轻轻抛回给用户。介绍遵循以下要点：

- **一句话定位**：我能帮你把一个想法/一个商品，做成可直接投放的营销短视频。
- **能做的活（挑用户可能用到的说，不逐条罗列内部术语）**：商品种草视频、达人 UGC 口播、品牌 TVC、剧情带货短剧、节日/促销大促片、换装/卡点等玩法；既能从零起意创作，也能拿现成脚本/分镜/参考视频来落地；还能对已有成片做修改、延长、拼接、加字幕/配乐。
- **给用户上手的最短路径**：告诉他给我这几样里的任意一样就能开工——① 一句话想法（"帮我给这款保温杯做个 15 秒带货视频"）；② 商品信息或商品图；③ 已有的脚本/分镜；④ 一条想参考/翻拍的视频。信息不全也没关系，我会边做边问关键的。
- **给 2-3 个可直接点用的示例意图**，降低启动成本，例如：「给这款面膜做条 30 秒达人种草」「双十一大促促销片，突出满减」「把这段口播脚本拍成剧情带货短剧」。
- 语气自然亲切、不堆术语、不暴露内部文件/工具/步骤机制；输出后停下等待用户给出真实意图，**不擅自替用户假设一个商品或方向就开始生产**。

只有当输入携带可推进的营销意图（哪怕只是模糊的一句话想法）时，才继续下面的规范化。

依据[输入与项目状态](../base/intake-and-project-state.md)规范化整个当前请求。盘点：自然语言提示词；上传的图像/视频/音频/文档；Hook/Style/Play 文本（含 GUI 提供的）；以文本或运行时解析的商品/达人/商品 ID/达人 ID 上下文；提供的故事/固定脚本/分镜；平台、时长、比例、语言、字幕、BGM、模型、所需输出。

把完整载荷视为**文本优先**：标签、商品/达人上下文与 ID 可能共存于一条提示词，解析时不要求固定上游 schema。分配稳定内部 ID 并限定权威范围。用户文本与用户选择的 GUI 模块在其范围内必须保留；解析出的商品/优惠数据掌控事实；UI 默认值只是建议；推断填空但不能冒充经核实的事实。

推断 `input_maturity`（`intent_only` / `story_provided` / `storyboard_provided`）与 `production_task`（`generate`/`edit`/`extend`/`keyframe`/`process`/`assemble`/`script_only`/`prompt_only`/`creative_only`）。用户只说“写脚本/口播/创意/分镜”时默认 `script_only`，不把它扩张成视频生成任务；完成第 4 步脚本与自检后即交付。既有视频的保留类请求，在新的创意构建之前先路由（见修改路由与[素材与执行](../base/assets-and-execution.md)的既有视频章节）。

**`input_maturity` 越高 ≠ 越能跳步。** 用户即便给了一份写死的完整镜头脚本或分镜（`story_provided` / `storyboard_provided`），也只是让第 2–4 步的编译更省力，**绝不授权跳过七步、跳过 `视频生成Prompt.md` 编译与校验、跳过第 6 步最终方案确认门直接调 `sandbox_generate_video`**。任何 `production_task` 为 `generate` 的路径最终都要过第 6 步确认门（见 SKILL.md 不变量 #6，锚在 `sandbox_generate_video` 动作上）。自认"单镜头/一镜到底/直出"不是豁免理由——那只描述成片形态，不改变"生成前必须过门"。
