
# Seedance 共享编译器规则（与版本无关）

请将本文件与你所加载的版本专属编译器（`seedance-2.0.md` 或 `seedance-2.5.md`）一并阅读。本文件收录在各 Seedance 家族之间完全一致的规则；版本文件只收录彼此不同的部分（能力默认值、任务/模式措辞、Prompt 公式、时间标注风格、高级模式）。单独任一文件都不完整:版本文件在这些章节处指向本文件，并补充其自身的差异部分。

这是一份面向模型的编译层，而非创作工作流。根 Skill 掌管已确认内容、家族画像、请求数量、披露、授权与执行。

## 编译器边界

只编译已确认的载荷:故事、脚本、分镜、素材、Hook、Style、Play、事实、文案、专家内容、家族画像与交付设置。模型能力不得添加创意含义，也不得悄然修改已确认产物。若要提升模型表现就必须做创意或内容改动，则应返回到拥有该内容的 Markdown 产物及其确认门。

当前可调用的运行时 schema 才是受支持字段、时长、比例、分辨率、任务类型与参考数量上限的执行权威。本 Reference 提供面向模型的组织方式与有文档记载的兜底假设;它不保证某字段或模式在每个运行时都存在，也不构成改动已确认工作流的理由。

## 主体与素材绑定

使用面向模型的标签，如 `@图片1`、`@视频1`、`@音频1`，并严格按传入工具的顺序使用。内部素材 ID 可以出现在请求元数据中，但绝不能在 Prompt 内取代这些标签。

在动态动作之前，先定义每一个重要的重复出现主体:

- 使用稳定标签，如 `主体1（达人）`、`主体2（顾客）` 或 `产品1`;
- 绑定两到三个决定性的可见锚点，如面部、发型、服装、物体类型、颜色、包装形状或标志性配饰;
- 当多份素材或多个视角展示同一主体时，分别定义每份素材/每个视角，并明确说明它们共同描述同一个连续主体;为每份素材指派一个角色。不要依赖图片上的批注，也不要让模型去猜映射关系;
- 存在歧义可能时，重复使用稳定的主体标签;避免使用含糊的代词;
- 仅当多人身份漂移是真实风险时，才分别映射每个人并禁止重复/双胞胎输出;
- 使产品的形状、颜色、材质、包装、标签位置、比例、数量与状态紧扣权威产品参考图。

每份被参考的素材都需要一个被采用的角色。当背景、人物、文字或构图可能泄漏进结果时，声明被忽略的维度。以下是"每份素材角色 + 被忽略维度"的示例:

```text
<达人A>对应@图片1，只采用五官、发型和服装，不采用图片背景。
<产品A>对应@图片2，只采用结构、材质、颜色和标签位置。
<卧室场景>参考@图片3，只采用空间、家具和光线，不采用图中人物。
@视频1用于<达人A>的动作节奏和运镜，不采用人物身份、服装和场景。
@音频1用于<达人A>的音色和指定台词。
```

## 多图借鉴与局部修改

对任何多图借鉴或局部修改，不要让多张图片以完整参考身份相互竞争。要按维度拆分权威归属，而不是说"参考所有图片"。Prompt 必须指明基础图/源素材、目标物体/区域、`keep/change/add/remove` 操作、每个被改动维度的来源，以及被保留/被忽略的维度。支持的维度包括形状/结构、颜色/材质、文字/logo/标签、部件/细节、状态/内容、数量、背景/场景/构图、光照与视觉风格。

精确的替换文字必须来自用户提供的文本或经核验的产品数据;只有当图中文字清晰可辨时，图片才可用于控制版式——不得推断无法辨认的文字。示例:

```text
以@图片1为产品1基础，保持结构、轮廓、比例、部件、开孔和Logo位置；仅采用@图片2的军绿色与黑绿分区，忽略其结构、角度和背景；正面文字严格替换为用户确认的“XXX”，其它包装内容不变。
```

若映射关系不清晰，在生成最终 Prompt 之前，请用户在 2-3 个任务专属映射方案中做选择，或对其加以描述。

## 开启与使用动作

对开启或使用类动作，当时序路径、接触点、施力方向、时机、形变、流动或先后顺序很重要时，优先使用参考视频;参考视频只在被请求的范围内控制这些维度。也可改用有序的产品状态图来定义 `closed/start -> contact -> intermediate -> open/complete`;按顺序把每张图绑定到一个状态，并用用户文本补充任何不可见的方向、力度或时机。绝不能从一张结束态图片推断出完整动作——单张结束态图片只控制终点，绝不控制完整运动路径——但该图片可以直接用作一个已完成的起始态或展示态，无需询问某个未见过的先前动作。

## 达人 / 产品角色分离

当同时出现达人/人物图片与产品图片时，在 Prompt 中强制执行角色分离:

- 达人/人物图片只采用人物身份——面部、发型、妆容、体型、服装风格、姿态、表情与气质。它绝不能引入 `产品1`，也不能从达人图片里借用产品。
- 若达人图片中包含服装、配饰、包、帽子或道具，除非用户明确指出该物件正是 `产品1`，否则只将其视为人物/场景的一部分，而非被推广的产品。
- 若生成的达人肖像是为本项目制作的，它应当不含任何产品、包装、购物袋、产品卡、logo 展板、货架或类产品道具。在视频 Prompt 中，重申达人参考图仅为人物身份参考。
- 产品图片只采用被推广产品的可见表面、形状、颜色、材质、包装/标签/logo 位置、数量、尺寸比例与已确认状态。除非另行指派，它绝不能从达人图片里借用服装、配饰、手部、背景道具、手持物、人物或背景。
- 若只可见产品正面，则只使用正面或 3/4 正面产品视角。不要展示、描述或臆造背面标签、侧面板、成分表/清单、条形码、内部内容物、容量/规格文字、配方/认证视觉或未见过的包装细节。
- 不要让 agent 自行生成一张产品外观图去填补缺失的视角;被推广产品的真实外观必须来自用户上传的 / 产品系统的真实图片。只有当用户强烈要求时，才允许 agent 生成产品图片，且必须在以下条件之后进行:(1) 披露不一致风险，(2) 用户明确确认生成的图片与真实产品相符(agent 自查不能替代),(3) 一套完整的三视图(正面 + 背面 + 侧面，并按需加上顶部/底部/内部/使用态)被传入 `ImageList`，并在 `产品1：` 定义行中用 `对应@图片N` 绑定每个视角。单一角度的生成图片绝不能顶替产品。
- 只使用有来源支撑的卖点(用户文本、产品标题/上架数据、可见的包装文字或其它明确素材)。不要通过制作包装标签、成分表、背面板、剖面图、内部内容、认证或无支撑的使用宣称，来为某个卖点臆造视觉证明。若某个证明需要虚构产品外观或标签信息，则把该证明改为对白、反应、结果或对比，或索取一份参考。
- 产品动作与使用方式必须契合产品的真实形态与尺寸。开启、按压、喷洒、倾倒、涂抹、佩戴、安装、点击或递交都必须包含可见的手/工具/接触点、运动方向与终点。

## 声音、字幕与文字规范

自然语言已经足够;当某种区分有帮助时再使用特殊记号:

- 音乐: `（背景播放轻快器乐）`;
- 音效: `<包装纸轻响>`;
- 对白: `{这套上身比我预想的更利落}`;
- 花字 / 屏幕文字或 花字(仅当用户希望将其烧录进画面时): `【新品上架】`。

写出确切的已确认台词，附带说话人、语言、语气、语速与动作情境。明确标注非中文对白的语言，在有必要时补充地区变体或口音。让口播台词短到能容纳进动作预算内。当精确渲染至关重要时，把事实性文字保留在提供的卡片或后期拼装中。

**字幕(口播台词的字幕)在生成阶段不会烧录进画面。默认情况下，成片交付时不带字幕——对白/旁白的字幕只在其后的交付步骤中，当用户明确要求字幕时，通过 `render_video` 追加。因此生成 Prompt 应默认无烧录字幕:声明约束 `全程保持无字幕，不生成任何文字、字幕、标题、标识或说明性文本`，除非用户明确希望把屏幕花字(例如一张风格化的标题卡 / 花字)烧录进画面。** 口播台词仍作为音频进入 Prompt(说话人/语言/语气/语速);只有它们的字幕渲染被推迟到后期。相关时可直接声明 Logo/水印的抑制。

## 家族画像保真

- Brand 保留紧凑、可供导演阅读的品牌片画像及其工艺丰富的节拍。
- UGC 保留全部八个生成包模块以及每个镜头的达人/产品状态。
- 剧情带货 保留因果锁、对白链、证据、旁观者反应与被改变的结局。
- 季节促销 保留经核验的事实锁、利益层级、卡片/UI 处理、证明、路径与口播 CTA。
- 通用营销 保留一个价值、一条证明路径与一个可读的结尾。

版本编译层可以在所选画像内部调整标签、排序、时间密度或稳定性措辞，并使用其自身更丰富的素材/阶段控制。它绝不能把所选家族画像压平成一段通用段落，也不能用通用模板将其替换。

## 共享出口检查

- 已确认内容与家族画像模块保持存在且含义不变。
- 每个面向模型的素材标签都映射到一个实际的、有序的输入、一个信息角色、必要时其被忽略的维度，以及一个消费它的场景。
- 重复出现的主体使用稳定标签与决定性锚点;不同的人物、产品、道具与场景被逐一命名并绑定。
- 动作连续、具体，并以一个可观察状态结束;产品证明可见;对白与 CTA 契合时长。
- 身份、数量、服装、产品状态、道具归属、空间、镜头、光线与声音保持一致。
- Prompt 的时间标注(若使用)从本地 `0s` 起算，绝不泄漏成片的整体时间偏移。
- 运行时字段与上限来自当前能力，指南默认值仅用作兜底。
- 生成无法可靠渲染的精确文字与参数，指派给提供的素材或后期制作。
