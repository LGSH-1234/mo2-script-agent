
# Seedance 2.0 编译器

仅当活动运行时明确解析为 Seedance 2.0 家族时才加载。这是一份面向模型的编译层，而非创作工作流。根 Skill 掌管已确认内容、家族画像、请求数量、披露、授权与执行。

来源依据:本地 `seedance-reprompt-skill`，源自《Seedance 2.0 参考生视频常见问题与处理指南 V1.8》(2026-06-02) 及其合并后的通用提示词规则。

**先读 `_shared-compiler-rules.md`。** 它承载与版本无关的规则:编译器边界、主体与素材绑定、多图借鉴与局部修改、开启与使用动作、达人 / 产品角色分离、声音 / 字幕 / 文字规范、家族画像保真以及共享出口检查。本文件只补充 2.0 家族特有的内容。

## 能力默认值

当当前运行时未暴露素材上限时，仅将以下 Seedance 2.0 指南假设作为保守的规划兜底:

- 0-9 张参考图;
- 0-3 段参考视频;
- 0-3 段参考音频。

运行时证据会覆盖这些默认值。若已确认的素材包超出真实上限，按信息角色合并参考素材，或使用根 Skill 基于能力的请求规划。不要仅仅因为 Prompt 里包含多个镜头就拆分。

## 任务分类

选择一个面向模型的主任务:

- `reference`:生成新视频，同时借鉴明确的主体、风格、场景、动作、镜头、声音或音色维度;
- `edit`:修改一段源视频，同时保持所有未指定内容不变;
- `extend`:在源视频之前或之后续接，同时保持边界状态;
- `combined`:参考一份素材的同时编辑另一份素材。

使用明确的动词:

```text
参考@图片1中的主体外观……
参考@视频1中的动作、运镜或声音……
严格编辑@视频1，只把……修改为……
延长@视频1，生成……
向前延长@视频1，生成……
参考@图片1的外观，严格编辑@视频2……
```

对 edit 与 extend，直接把目标称呼为 `@视频N`。不要称其为 `参考视频N`，那会把任务模糊成参考生成。

## Prompt 构建

保留所选家族画像，并按以下优选信息顺序调整其模块:

1. 任务类型与一个主生成目标;
2. 主体定义与素材角色;
3. 环境与起始状态;
4. 连续动作或事件链;
5. 镜头与有用的内部剪切;
6. 光照与材质表现;
7. 可见的证明、回报或最终结果;
8. 对白、声音、音乐与文字规范;
9. 结束态与连续性控制;
10. Style 作为最后的成片层。

一个请求通常应只有一套主体系统、一条核心动作链、一个主导情绪/使用场景、一条证明路径，以及至多一个 CTA。若已确认内容包含互不相容的目标，应返回根规划，而不是把多个视频藏进一个过载的 Prompt 里。

把抽象目标翻译成可见事实:

- `高级` -> 受控色调、干净光线、材质特写、克制的运动;
- `真实` -> 自然光、逼真质感、可信的操作、克制的手持取景;
- `防水` -> 水珠滚落而受保护表面仍明显保持干燥;
- `稳定` -> 形状、身份、位置与结束态在动作全程保持一致。

## 动作、证明与时间

把动作写成一条连续、有序的链。使用具体的身体部位、接触、方向、以及在有必要时的速度或力度，并给出一个可见的终点。优先用 `拿起 -> 倒入 -> 举向镜头 -> 展示结果`，而非彼此脱节的动作列表。

明确说明最终的可见结果。一个宣称应当由动作、材质表现、对比、产出或可信的反应来证明，而不是靠反复说出口。

Seedance 2.0 通常从镜头顺序与相对推进中获益更多，而非密集的微观时间戳。默认使用 `镜头1/镜头2/镜头3`、`随后` 或 `3秒后`。仅当已确认时间范围用于分配重要的 Hook、对白、证明、转场或 CTA 预算时才保留。任何请求本地的时间标注都必须从 `0s` 起算;成片的整体时间偏移留在 Prompt 正文之外。

对中等复杂度的内容，使用 3-5 个有意义的节拍。当运行时执行仍为一次调用时，不要为每个节拍单独建一个请求。

## 任务专属措辞

### Reference

说明每份素材贡献什么，然后描述新的主体、环境、动作链、镜头、证明/结果、声音与结束态。

### Edit

使用:

```text
严格编辑@视频1，只修改<目标>为<结果>。
保持@视频1中的<身份、时机、镜头、运动、场景、音频与事件顺序>不变。
```

只承诺运行时与已确认编辑合同所支持的保留项。

### Extend

界定延长是向后还是向前、源视频的边界构图、主体/产品状态、运动趋势、光线、声音、新动作与结束态。仅靠提示词无法保证完美衔接;优先采用切镜或转场边界，并在相关时披露后期处理风险。

### Combined

指明参考素材被借用的确切维度、被编辑的源视频、有界的改动，以及所有被保留的维度。

## 失败缓解

只施加相关的控制:

- 身份漂移:在可用时使用清晰的面部特写外加单独的服装/场景参考;把最强的身份参考放在前面;
- 人物重复:把每个人映射到一个标签，让每个人保持单一，并避免把多视角拼图作为主要身份输入;
- 风格漂移:命名该风格，并把它翻译成镜头、场景、光线、色调、材质、剪辑与声音;
- 多余台词:缩短台词，保持语言一致，并给每个说话人明确的指派;
- 精确数值效果:在可用时使用正确的效果参考视频，而非纯文字指令;
- 超过四个受控人物:准备分组的静态参考，而非依赖一长串身份列表;
- 反复延长导致画质退化:在工作流支持时，使用白模运动参考外加高清身份/场景图;
- 精确的边缘情形遵循:当仅靠措辞反复失败时，准备分镜/关键帧图片;
- 中文发音风险:仅在用户认可措辞的前提下使用常见谐音字，或规划一套受支持的音频参考工作流;
- 强音乐/口型对齐保真:优先使用受支持的、由视频携带的音频参考，并在已确认时精确匹配时长;
- 结尾咔哒声或截断:视为重绘或后期处理;`音频自然淡出` 是指引，而非保证。

优先描述正面期望状态。仅对素材泄漏、禁用文字/音频、重复、logo/水印或另一种已知的高影响失败保留否定式指令。

## 2.0 出口检查

在 `_shared-compiler-rules.md` 的共享出口检查之外，另外执行以下检查:

- 任务措辞区分了 reference、edit、extend 与 combined 工作。
- 失败控制是有针对性的，而非一长串通用否定清单。
