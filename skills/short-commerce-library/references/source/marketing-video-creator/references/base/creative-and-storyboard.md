
# 创意与分镜

将 Hook、Style、Play、故事、脚本、视听语法、定时节拍与实体状态编译为一份可执行的分镜。

## 目录

- 提示词模块
- 故事与脚本
- 通用形式
- 视觉与声音
- 分镜与实体状态
- 运行时优先的请求数量
- 创意退出检查

## 提示词模块

对于每个生效的 Hook、Style 或 Play，保留原始提示词以便追溯，并进行编译：

```yaml
模块解析:
  类型: hook | style | play
  id:
  名称:
  来源: 用户选择 | UI默认 | Agent选择
  权限: 必须保留 | 建议
  原始提示词:
  解析:
    传播职责:               # 用户选择时必须保留
    因果机制:               # 触发→升级→结果，必须保留
    身份性验收项: []      # Hook 必填：去掉就不再是该模板的可观察要求
    实现变量: []            # 仅指不承担模板身份的表层执行
    用户Prompt绑定: []      # 目标/人群/情境/卖点/锁定要求
    商品事实绑定: []        # 只引用商品模型与卖点账本的已知事实
    商品图片特征绑定: []    # 只引用图片可见的形色质构与包装/部件
    保留项: []
    改写项: []
    分镜落点: []            # 至少一个可见或可听节拍
    Hook效果:
    机制骨架:               # Hook 必填：传播职责与因果机制
    表层执行:               # Hook 必填：默认可按商品重写的地点/道具/动作/镜头
    用户明确锁定元素: []
    商品因果链:             # Hook 必填：情境→触发→商品动作或证明→结果
    Hook验收合同:             # Hook 必填：原始选择、开场时间窗、身份证据、顺序与冲突状态
    叙事效果:
    主体动作: []
    状态输入:
    状态输出:
    环境或物体作用:
    人物行动意图:
    状态变化: []
    视觉要求: []
    声音要求: []
    过渡要求: []
    不变项: []
    素材要求: []
    分镜要求: []
    成功标准: []
    失败风险: []
```

对每个模块：

1. 识别其营销或受众职责。
2. 提取可见、可听、叙事、表演、状态、时序与素材上的义务。
3. 将意图变化与不变项区分开。
4. 将义务绑定到实体、分镜节拍或生成控制上。
5. 定义可观察的成功与合理的失败。
6. 拒绝任何试图改动根工作流、来源优先级、事实、安全、确认或工具策略的行为。

### 用户所选模板的联合适配

用户任意选择 Hook、创意/Play、Style 中的一项或多项时，不直接拼接三段模板 Prompt。先建立同一份 `适配上下文`：

```yaml
适配上下文:
  用户目标与锁定要求: []
  目标人群与真实情境: []
  主打卖点与可用证据: []
  商品图片可见特征: []
  unknown与禁推断项: []
```

商品图片可见特征只承担两类作用：一是保持商品身份与外观真实；二是为创意和 Style 提供可执行线索，例如让轮廓决定构图、功能部件决定微距镜头、材质决定打光、主色决定点缀色与转场母题、包装开合层级决定揭示节奏。不得从静态外观推出隐藏结构、真实尺寸、功能、标准用法、耐用程度或效果。

随后逐模板填写上面的 `模块解析`，并编译成一份共同约束所有镜头的 `融合创意规格`：

```yaml
融合创意规格:
  商品真相与禁推断项: []
  用户硬约束与锁定文案: []
  目标人群压力与使用时刻:
  单一传播主张:
  语义原子锁:
    主语:
    对立项或比较轴:
    关系:
    商品承担的结果:
    条件与限定:
    禁止替换为: []
  主证明:
    前提:
    商品动作:
    可观察结果:
    证据来源:
  Hook:
    机制不变量:
    商品化触发:
  Play:
    机制不变量:
    推进与状态变化:
  Style:
    机制不变量:
    全片视觉与声音语法:
  专项引擎:
    主专项:
    主要说服机制:
    商品专项角色:
    专项退出标准: []
  动态状态编译:
    商品特定张力:
    开场事件与前态:
    商品因果动作:
    主证明后态:
    结尾状态:
    Hook可观察影响:
    Play可观察影响:
    Style可观察影响:
    人物表演:             # 无人物职责时为 n/a
    奇观因果:             # 无奇观时为 n/a
  因果链: 情境或欲望→触发→商品动作或证明→结果→行动
  桥接动作:               # Hook 最后动作与主证明第一个动作必须是同一动作或连续动作
  场景路径: []             # 每项写 scene_id / information_job / transition_cause
  模块覆盖: []             # 每个用户所选模板对应至少一个可观察落点
  已解决冲突: []
```

按以下边界联合：

- Hook 决定首拍为何值得看，并可作为世界规则、声音母题或推进机制贯穿；它不另占一段与商品无关的故事，也不在固定秒点被机械切断；
- 创意/Play 从第一拍开始组织整片推进、动作与状态变化，必须让商品成为冲突的答案、动作的对象、证明的载体或转折的原因；
- Style 占用全片视听语法，但不得重写事实、卖点、剧情因果或用户锁定文案；模板中的示例场景/人物/道具若只是风格示范，归入可改写皮肤；
- 同一维度冲突时，遵循 `事实与安全 > 用户硬约束/锁定文案 > 主证明可成立性 > 专项说服机制 > 模板传播职责与因果机制 > 标志性线索 > 图片启发 > 实现变量/UI默认`；先改写地点、道具、动作、表演、镜头或语气以等价保留机制，不静默换模板或丢模板；
- 每个用户所选模板至少落到一个可观察节拍。对多个模板，用同一商品事实或视觉母题贯穿，避免各做一段导致拼贴感。

### 动态场景状态编译

模块联合不是把四份输入折中成一个通用脚本，而是让它们分别改变同一事件的不同维度：商品决定“为什么发生、要证明什么”，Hook 决定“第一拍怎样让它发生或放大”，Play 决定“谁推动、怎样升级和验证”，Style 决定“以怎样的真实度、幅度、距离、节奏和声音被观众感知”。先写商品特定前态与后态，再编译模块；不要先套一条现成故事，再给不同商品替换名词。

人物出镜时，不从固定情绪清单抽取表演。先由事件推导人物对刺激的判断和行动意图，再把它写成模型能看见或听见的行为：视线、面部、呼吸、姿态、手势、动作速度、发声方式以及环境在头发、衣物、身体或周围物体上的作用。数量与幅度由时长、人物职责、Play 与 Style 决定；禁止机械要求每条片子都有愤怒、惊讶、微笑或固定三段弧。无人脸时用物体、环境和任务状态完成相同因果。

Style 必须调制具体执行，而不是只贡献色调：从原 Style Prompt 提取真实度、表演幅度、节奏、镜头距离、画面整洁度与声音优先级等连续轴。相同事件在生活 UGC、克制高级、快节奏夸张或超现实风格下，应出现不同但仍符合商品事实的表演与镜头。

奇观场景必须填写“奇观机制 → 商品相关作用力/状态 → 对人物、物体或任务的可见影响 → 行动/推进 → 主证明交接”。如果只换成壮观背景，人物与任务状态仍像普通棚拍，或人物端正微笑举品，判为奇观摆拍。

适配完成后做 9 项反查并各记 0–2 分：① 首屏停留；② Hook 机制保真；③ 商品专属；④ 目标人群命中；⑤ Hook→专项/Play 桥接；⑥ 主证明有效；⑦ Play 有状态推进；⑧ Style 全片一致；⑨ 动态状态因果可执行。任一项为 0 或总分低于 15/18 就重写。另查图片的可见形色质构是否真正影响构图、动作或 Style，且没有被扩写成不可见事实。

### Hook

Hook 必须在 0.5 秒内给出可理解信息，并在 1 秒内使观众说出问题、欲望、反差或观看收益。普通推镜、产品静置、人物走路、换背景或轻微动作不是独立 Hook。

**选择 Hook 即锁定传播职责、因果机制、身份性线索和开场位置。** 改写前先将 Hook ID、名称、原始 Prompt、核心机制、商品绑定、证明交接、截止时间和可验收字面证据固化为 `hook_acceptance_contract`。地点、色彩、景别数量、布景和普通道具可按商品改写；分屏、360°旋转、可见失衡/跌倒、声音来源、必要动作顺序等若承担模板身份，就不是实现变量。

从商品模型、主打卖点、目标人群和主专项建立 `真实情境→压力/欲望→商品特定动作或证明→结果→判断/任务/关系改变→行动`。Hook 的异常必须进入这条链并改变状态。默认不要让人物首帧举品介绍；若拿掉当前商品后 Hook 与故事仍可原样成立，或特殊环境只改变背景而没有改变主体状态，说明没有完成融合。

Hook 最后一个动作必须与专项主线或主证明第一个动作相同或连续。可用商品揭示、动作延续、镜头匹配、声音提示、母题重现或收益转译建立 bridge。Hook 的世界规则、运动、声音或母题可以贯穿后续，但每次出现必须新增商品证据、人物判断、任务状态、关系变化或品牌记忆；不得重复同一奇观填时长。

20 秒及以内优先一个主世界，但不机械限制场景数量。`A→B→C→D` 可成立，前提是每个新场景新增不同且必要的购买理由、使用情境、证明或信息职责。`A→B→A` 也不自动失败：若回到 A 完成此前埋下的因果回报、主证明或关系改变，可以保留；若只是重复背景、静态定格或“高级感呼应”，必须删除。用户锁定首尾回环时同样要求新增可见验证。

退出 Hook 编译前检查：①首屏信息成立；②传播职责、因果机制与身份性线索可辨认；③核心机制已在开场截止时间前落地；④对当前商品有专属性；⑤Hook 与主打卖点存在因果回答；⑥主证明有事实支持；⑦实际故事脚本和最终 Prompt 均通过同一份 Hook 验收合同；⑧每次换场或回访都有新增职责。

### Style

Style 控制媒介形式、写实度、镜头、构图、美术设计、道具、服装、色板、材质、光线、剪辑节奏、过渡质感、排版文字、氛围、拟音与音乐密度。将模糊的标签转化为这些制作维度。Style 永远不替代证明或因果关系。

### Play

Play 是一种可组合的动作、状态、表演、视觉、证明或转化模式。将其解析为时间与状态：

```yaml
state_change:
  entity_id:
  from_state:
  to_state:
  trigger:
  transition_mode:
  occurs_at:
  invariants: []
```

对于换装，先定义造型顺序、身份不变项、触发条件、过渡方法、参考绑定、营销职责与检查。当形变可能混合或凭空生成权威商品时,优先使用清晰的切换、遮挡、匹配动作或重置。当某个造型没有提供图像时,将其视觉细节视为创意推断,而非权威的商品事实。

组合不是串联顺序。用 `事实底座 × 主证明 × Hook 注意力职责 × Play 推进职责 × Style 生产语法 → 同一份融合创意规格 → 分镜`。若用户已有锁定脚本，用模板机制替换或强化脚本中职责相同的节拍，不额外插入模板段落。只有两个机制在同一时长内确实互斥且等价改写仍无法兼容时，才向用户提出一个简明问题。

## 故事与脚本

使用同一条推进线:

`注意力 -> 情境或欲望 -> 商品或品牌动作 -> 可观察的证明 -> 回报或记忆 -> 行动或有意的结尾`

匹配机制:

- 演示:条件 -> 动作 -> 结果 -> 意义;
- UGC:压力 -> 个人契合 -> 使用/证明 -> 资格 -> 行动;
- 故事:压力 -> 选择 -> 商品介入 -> 证据 -> 改变的结果 -> 转化;
- 促销:场合/收益 -> 商品理由 -> 证明 -> 获取路径 -> 行动;
- 品牌:张力/欲望 -> 品牌主导的介入 -> 后果 -> 助记式收尾;
- 展示/Play:结果预览 -> 有序状态 -> 递增的证明或欲望 -> 最终商品或记忆。

### 成熟度规则

- `intent_only`:创建一个方向、创意、推进线、商品角色、Hook、证明,以及有用时的文案与结尾。不要膨胀。
- `story_provided`:保留主体、前提、事件、关系、基调、结尾与固定措辞。只补充整合、证明、因果、过渡、时序、CTA 与可行性。
- `storyboard_provided`:保留有序的视觉表达。只修复缺失的营销功能、无支撑的主张、文案过载、含糊的动作/状态、缺失的绑定、时序、连贯性或运行时可行性。

将台词、旁白、达人口播、画面文字、优惠卡文字、CTA 与纯声音节拍分开。保留已锁定的措辞与顺序。当记忆或转化依赖商品名称时,要说出商品名。口播文案应诠释可见的动作,而非替代它。使用一个 CTA。使用 `sandbox_generate_video` 时,计划中的台词、旁白、达人口播、口播、语气、停顿与时序应直接写入视频提示词,以获得音画同步的输出。将普通字幕放在拼接阶段,而不要要求视频模型渲染密集文本。

**先定台词占比、再定台词字数——这是两件事,分两步做。** 一段视频里"有人在说话"该占整片多大比例(如 15 秒该铺 7 秒还是 10 秒台词),不要凭感觉铺满整片,先按 [台词占比](dialogue-ratio.md) 判定:把视频归入 6 类营销类型之一、直接取该类型的**推荐占比**(口播讲述/种草 90%、促销带货 85%、演示证明/对比 75%、剧情带货短剧 65%、品牌/情感/故事片 55%、声音/音乐主导 45%,判不出类型才用默认 70%),类型重叠时按该文档「选择规则」唯一确定一类,仅在命中可见证明留白、字幕负载、多人对白、复杂卖点、可听 CTA 等因子时在该类型 ±5% 内微调,乘整片时长得出**目标口播时长**。拿到目标口播时长后,才进入下面的语音时长核算——把这个秒数作为 `count_chars.py` 的 `--target` 传入。

估算语音时长前，先按场景确定目标语速档位，再评估文案是否放得进目标时长——不要用一个固定速率套所有场景，也不要用一种语言的速率套所有语言：

- 语速分档（`--scene`）：`fast` 高语速（广告冲刺 / 卡点 / 促销催单 / 快节奏达人口播）、`normal` 正常（常规讲解 / 对话 / 种草 / 教程）、`slow` 慢语速（情感与品牌片 / 吟诵强调 / ASMR / 庄重旁白）。先判定这条口播属于哪一档，再传入对应 `--scene`。
- 语言（`--lang`，必传）：由你按文案语种显式指定枚举 `zh|ja|ko|en|es|fr|de`，脚本不做自动识别（缺省会报错）。每种语言用各自的计量单位与基准速率（CJK 系按字·音节/秒，拉丁系按词/秒），因为跨语言的信息率大致恒定、但音节/词速差异很大，单一"字/秒"速率不成立。文案语种**超出这 7 种**（如葡语、俄语、泰语、越南语等）时传 `other`：脚本按每段台词实际的 Unicode 书写体系就近取代理档——拉丁字母系为主套 `en` 词速、CJK/表意字为主套 `zh` 字速——并在输出打「⚠近似估算」标注；你把结论当粗估看待、宁可估长给文案留余量即可，不必自己猜代理码，也不必为此弹表单打断用户；只有连书写体系都归不了类的极端情况才在对话里顺带问用户。拼错受支持语种仍会报错（不会被静默降级成 `other`）。一次调用里 `--lang` 对所有段落统一生效，若不同段语种不同就分多次调用。
- 多段一次估算：把每段作为独立的引号参数依次传入即可，`--scene` / `--lang` 对本次所有段落统一生效；脚本逐段输出各自时长，并在末尾自动累加出总字数与总时长区间。想分段就必须给每段各加一对引号，不要拼成一整个字符串。
- 目标时长删减折算（可选 `--target 秒数`）：当你手上有明确的目标时长（如这段口播要卡进 15 秒）时，加 `--target 15`。脚本会在合计时长之外再输出一行「预期耗时」：把合计时长区间与目标比对，若超时则按"时长与字数成正比"折算出大致需删减多少字/词——超时给删减区间（下限=念快也要放下、上限=念慢也稳妥），仅念慢会超则给单个稳妥删减量，已在目标内则提示无需删减并报余量。这只是给你调文案长度的粗略参照，锁定文案的处理仍遵循下一条规则。

```bash
# 单段
python3 scripts/count_chars.py --lang en --scene slow "The night was quiet and still"
# 多段一次估算（统一语种与档速率），逐段输出并给出【合计】
python3 scripts/count_chars.py --lang zh --scene fast "限时三天，全场五折" "手慢无别错过" "点击下方立即抢购"
# 带目标时长：多输出一行「预期耗时」，超时时折算大致需删减多少字
python3 scripts/count_chars.py --lang zh --scene normal --target 15 "限时三天全场五折" "手慢无别错过好机会" "点击下方立即抢购" "现在下单再送好礼"
# 语种超出 7 种枚举（如葡语）：传 other，脚本按书写体系就近代理并标「近似估算」
python3 scripts/count_chars.py --lang other --scene normal "A noite estava silenciosa e tranquila"
```

如果在选定场景语速档位下，下限语音时长仍超过用户设定的时长,不要删除、改写或加速已锁定的文案。**分两种情况处理**：

- **Agent 自己新写的文案**（非用户提供）:可自行精简、改写以适配现有动作时间与场景语速,使其放进目标时长。
- **用户提供的成型口播/锁定文案**(明显是用户希望被念出来的成段带货话术/种草文案)超时:**不要私自删改,也不要只会问"延长还是改词",而是给用户两个方案让他拍板**——**方案一(完整版)**完整遵循用户口播、不删内容,说明大约需要多长时长并给出这一版故事脚本的大致走向;**方案二(精简版)**卡进用户选定时长,明确说清要删/合并/弱化哪些段落(哪段铺垫砍掉、哪个次要卖点让位、CTA 如何压缩)并给出这一版故事脚本的大致走向;用 `dynamic_questionnaire` 让用户在"方案一(完整版) / 方案二(精简版)"间一键选择(遵守「动态表单合同」)。绝不因为用户选了短时长就默默砍掉他口播的一半内容,也不擅自把视频拉长——两条路都摆到用户面前。详见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「用户口播意图保真合同」。

### Hook 融合后的脚本输出

Hook 的时间只服务信息职责，不在面向用户的脚本里额外输出 `Hook Scope`、`Bridge`、`Body takeover` 或内部质量字段。把融合结果自然写进故事脚本分镜表。

短视频默认职责：首拍建立问题、欲望、反差或结果；商品化触发把 Hook 动作接入专项主线；主体推进用商品证明改变人物、任务或关系；证明后再落 CTA 或品牌记忆。15 秒优先把时间给一个购买理由，30 秒可增加压力升级、第二证明或异议处理，但不重复同一 Hook 效果。

拒绝或重写：Hook 与商品可以无损拆开；只是照抄模板动作而没有产品因果；奇观反复出现却没有新增证据；商品到后段才出现且不改变故事；证明全靠口播；结尾只有定格或口号。

### 投放可用的脚本质量

将脚本写成投放可用创意,而非中性摘要。脚本只有在具备以下要素时才算投放可用:

- 一条清晰的消费主线或核心记忆句;
- 当 Hook 生效时,有可观察的商品化触发与主证明交接;
- 有排好序的卖点顺序,而非平铺的清单;
- 在结论之前有可见的商品证明或使用动作;
- 简短、可配音且情感有导向的口播文案;
- 跟在证明之后的 CTA 或结尾记忆。

脚本请求的默认输出顺序是指定时长脚本表、实际口播，以及用户需要时的成片提示词。核心记忆、模板解析、融合规格和质量自检只作内部推理，不泄漏给用户。

如果用户只要求一个脚本,则只输出该时长。如果用户要求同时覆盖 15s 和 30s,则用相同的商业主线产出两者,而不是两个不相关的创意。

以上默认输出顺序**只用于对话式的纯脚本回答**,其中 `成片提示词`、`质量自检` 是对话脚本专有的段落。**一旦进入营销视频生产链、需要落成必须确认的产物,就改用 `故事脚本.md` 的固定模版。** `故事脚本.md` **就是一张 8 列分镜表**(镜号 / 时长 / 画面描述 / 景别 / 光影氛围 / 对白·旁白 / 音效 / 运镜)。把对话脚本各段按下表各归其位:

| 对话脚本的段 | 归到哪里 |
|---|---|
| 核心记忆句 | 作内部推理放 `营销脑图.md`,并体现在分镜表的卖点顺序与画面里 |
| Hook 与模板融合 | 作内部推理放 `营销脑图.md`,并体现在分镜表的触发、推进、证明与回响里 |
| 脚本表 | 8 列分镜表(画面描述 / 景别 / 音效 / 运镜) |
| 口播 | 分镜表的「对白·旁白」列,内联到触发动作处 |
| 成片提示词 | 最终生成信息确认的 `视频生成Prompt.md` |
| 质量自检 | 你自己的内部检查 |

严格按 frozen-formats.md 的故事脚本格式:`故事脚本.md` 全文就是这一张分镜表、外加表下的 `**全片 BGM**` 说明行(面向用户、大白话描述音乐);成片的美术/打光/声音系统工程级参数归 `视频生成Prompt.md`。

时长语法:

| 时长 | 结构 |
|---|---|
| 6-10s | Hook -> 一个证明/动作 -> CTA 或记忆 |
| 11-20s | Hook -> 过渡 -> 主要使用/证明 -> 场景/欲望 -> CTA |
| 21-40s | Hook -> 铺垫/故事 -> 分层证明 -> 额外证明/异议 -> CTA |
| 40s+ | Hook -> 章节;每个章节必须增加一个新的购买理由 |

使用 15s 默认节拍:

```text
0-3s Hook + 桥接
3-7s 产品铺垫/使用
7-12s 证明/欲望
12-15s CTA/记忆点
```

使用 30s 默认节拍:

```text
0-3s Hook
3-10s 铺垫/故事
10-20s 核心演示/证明
20-27s 额外证明、异议处理、场景、反应,或优惠
27-30s CTA/记忆点
```

将 Hook 类别映射到脚本角色:

- 视觉奇观、极端尺度、超现实场景、微距、分屏、商品世界 -> 停止滑动的开场;通过商品揭示、母题、动作、镜头、声音或收益过渡;
- 街头采访、GRWM、Vlog、挑战、转场、开箱、试穿、教程、测评、前后对比等结构化形式 -> 只有当 Play 也需要时才把该形式当作内容主线;否则将其作为 Hook 并过渡进入商品证明;
- 痛点、误区、结果先行、人群点名、悬念、对比、挑战等文案/口播 Hook -> 把第一句话变成问题、承诺或好奇缺口,然后用商品证明来回应;
- ASMR、操作声、咬合、喷雾、环境声、扩音、预告片配音等声音 Hook -> 让声音开启注意力,然后让商品动作解释这个声音为何重要;
- 新闻、动画、吉祥物、电影预告、动漫反应、故障、PIP、编辑式画框等风格 Hook -> 把风格用于包装与节奏,而不是作为证明的替代。

将 Play 机制映射到正片主导者:

- 信任主导的 Play:正片是生活情境、个人理由、真实证明、CTA;
- 证明主导的 Play:正片是条件、操作、结果、结论;
- 欲望主导的 Play:正片是形态、质感、契合、感官吸引、场景、CTA;
- 转变主导的 Play:正片是初始状态、触发、转变、结果证明、记忆;
- 丰盛主导的 Play:正片是揭示、多样性、突出理由、使用/选择、CTA;
- 新奇主导的 Play:正片是把不可能的前提简短转化为一个真实收益,然后是商品证明与 CTA。
- 品牌主导的 Play:正片是品牌含义、标志性资产、感官世界、商品形态、品牌记忆、软性 CTA 或助记收尾;
- 故事主导的 Play:正片是角色压力、商品/品牌介入、转折点、改变的结果、记忆或 CTA。

品牌与故事的例外:

- 对于品牌片,不要强行把每个节拍都塞进硬销演示。以商品为主导意味着在 Hook 过渡之后,由品牌资产、商品形态、材质、世界、价值、承诺或助记主导正片。只有在氛围能建立具体的品牌记忆时,才把它当作说服手段使用。
- 对于剧情/剧情类广告,不要强行铺陈平淡的功能清单。以商品为主导意味着商品或品牌引发剧情转折、化解压力、揭示角色欲望、触发转变,或在落点处成为可记忆的符号。
- 对于 15s 品牌/故事脚本,使用一条干净的情感或戏剧弧线:Hook -> 品牌/故事铺垫 -> 商品或品牌转折 -> 记忆/CTA。
- 对于 30s 品牌/故事脚本,使用分层弧线:Hook -> 角色/世界铺垫 -> 张力升级 -> 商品/品牌介入 -> 情感证明/回报 -> 记忆/CTA。
- 如果某个 Hook 是电影化或超现实的,除非所选的 Play 明确是需要连续世界的品牌片或短剧,否则将其保留为入场画面。即便如此,延续的世界也必须由品牌/故事含义主导,而不仅仅由 Hook 奇观主导。

拒绝那些机械正确但不投放可用的脚本草稿:

- 节拍读起来像内部说明,而不像可拍摄的广告瞬间;
- 没有可记忆的句子或面向消费者的承诺;
- 商品出现了,却不驱动购买理由;
- 品牌/故事的娱乐性很强,但品牌含义、商品角色或商业记忆很弱;
- 证明在文案里被主张,却在动作中不可见;
- 15s 脚本试图包含太多卖点;
- 30s 脚本重复同一个证明,而不增加信任、异议处理、场景或优惠;
- Hook 受到约束,但正片平淡、通用或与开场脱节。

当故事具有清晰的载体、连贯的推进、结构化的商品角色、可见或可听的证明、结尾职责,且没有未解决的方向选择时,把故事连同可执行分镜一起编入 `故事脚本.md`（一张 8 列分镜表，见 frozen-formats.md 的故事脚本格式）。故事脚本是承接素材检查与最终方案的中间产物,写完后用 `present_sandbox_file`（`interrupt: false`）展示给用户过目、有意见随时提,然后直接推进到素材完整性检查。用户真正拍板的确认门只在最终生成信息确认（`视频生成Prompt.md`）,故事脚本先展示、再继续即可。

## 通用形式

形式塑造构建方式,而非路由:

- 数字人/口播主持:定义讲述者角色、权威度、镜头关系、语速密度、手势、眼神与商品插入;在没有信任的情况下不要称其为 UGC;
- 知识/教程:以一个实用问题开场,一次讲解一条因果规则或步骤,将无形的概念可视化,并以一条可执行的选择规则结尾;
- 宠物/吉祥物:定义写实度、物种、斑纹、比例、配饰、声音与行为程度;让写实动作保持安全;
- 音乐/舞蹈/卡点:定义节拍图、动作乐句、状态序列、过渡触发与助记姿势;绝不隐藏商品身份;
- 引言/文案主导:保留措辞,估算语音,给每个想法有意义的视觉推进,并通过反复出现的母题统一;
- 风景/地点:保留地理真实,构建从门槛到抵达的推进,并为本地生活加入到访或预订证明;
- VFX/动作/转变:定义位置、阶段、触发、力、接触、中间状态、后果与镜头关系;每个节拍使用一条主导规则;
- 分镜网格:保留分格顺序、身份、构图与动作;从表达推断时序,而非从分格数量;
- 固定脚本:保留措辞、顺序、讲述者与语言;围绕它构建可见证据;
- 参考混剪:只借用经授权的结构、镜头、节奏、表演、Style 或声音维度;除非获得授权,否则替换受保护的身份、品牌标识、台词与编舞。

```yaml
  music_density:

```

用镜头来揭示信息、证明、关系、状态与后果。在有实质意义时,定义比例、角度、高度、距离、构图、运动、主体关系与起止状态。

对于人物,定义角色、受众关系、面部/发型锚点、服装、姿态、眼神、手势、操作、表情习惯、说话质感,以及导致每次情绪变化的事件。

对于商品与材质,保留比例、支撑、重力、手部接触、数量、包装、logo 与状态。只有在能揭示价值时,才使用微距、反光、边缘光、受控操作或拟音。

对于 VFX,建立可信的基底,改变一条规则,定义触发/中间/后果,保留光、影、遮挡、比例与材质反应,并绝不暗示无支撑的商品功能。

用声音来吸引、证明、过渡、强化与收束。为语音、操作、证明与静默留出空间。字幕默认不加——视频生成阶段不烧录字幕,交付阶段也默认交付无字幕成片(生成模型若私自烧录,交付时用 `sandbox_process_video` 擦除兜底);仅当用户明确要求成片带字幕时,才在交付阶段用 `render_video` 为成片后期生成干净字幕。画面内文字保持简短,并绝不遮挡面部、手、商品、logo、证明或准确的优惠文字。

音色锚点是可选的连续性参考,而非提示词撰写的口播台词的替代。当视频工具能生成带画面的语音时,默认不要把口播脚本转成单独的 TTS 素材。

每个节拍都必须说明观众首先看到什么、什么发生变化、它为何存在、镜头如何揭示它、商品/人物/模块如何运作、听到什么,以及交接的是什么状态。

追踪:

- 人物:身份、面部/发型、体型、角色、姿态、眼神、情绪、位置、服装、声音;
- 商品:SKU、形状、颜色、logo、标签、数量、开/合状态、填充、摆放、手部接触;
- 造型:造型 ID、来源素材、服装身份、配饰、允许的片段;
- 场景:几何、光向、时间、天气、道具、画面侧向;
- 音频:讲述者、音色锚点、台词状态、环境声、音乐、衔接提示。

只有意图内的过渡才可以改变状态。每次变化都需要触发、方法、时间与不变项。

**空间锚定全局做一次,位置变化靠过渡承载(硬性,见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「空间定位与位置连续性合同」)。** 整片初始空间关系在 `视频生成Prompt.md` 的 `场景：`/`主体：` 段落里一次性定住作为全片空间基线,各节拍默认沿用、不逐镜复述;同一实体位置/朝向变化时不写增量,靠该处本就有的动作/过渡描写自然带出移动过程,让上一节拍的出场位置(`exit_state`)连续过渡到下一节拍的入场位置(`entry_state`);唯一需重新定位的是硬切换场,硬切时为新场景重新锚定并标注。除硬切外禁止无交代、又非硬切的位置跳变。

将每个使用的素材绑定到其角色、受管辖的实体/状态、允许的片段、保留范围与运行时参考顺序。

## 运行时优先的请求数量

在分段之前,从当前会话中可调用的工具 schema、运行时解析器或明确的能力响应发现当前能力。不要在本 Skill 内读取或维护模型/版本能力矩阵。

- 镜头、节拍、场景、镜头、素材与用户分段的数量不决定请求数量;
- 如果生效的运行时支持所请求的时长、比例、任务类型与所需的参考组合,使用一个视频请求,并在其中表达所有定时节拍;
- 只有当生效的运行时无法接受完整包时才拆分,例如时长、比例、任务类型、参考输入或不可避免的顺序依赖限制;
- 绝不因为内容感觉复杂或密集而拆分;应简化创意、修改时序或解决文案过载;
- 当能力迫使拆分时,记录确切的限制,并使用自然的故事或动作断点。

对于多个请求,定义 `independent`、`semantic`、`tail_frame`、`tail_video`、`edit_source`、`extend_source` 或 `keyframe` 依赖。在需要连贯性的地方,后续入场状态必须匹配前一个出场状态。

保持两条时间线互不混淆。分镜评审可以使用整片时间范围,以便拼接后的视频易于阅读。生成计划的请求提示词必须为独立的视频工具调用使用局部时序:每个请求从 `0s` 开始,所有定时节拍都相对该请求偏移,提示词在请求时长处结束。一个覆盖整片 `13-24s` 的请求应从 `0-11s` 描述其提示词动作,只用简短的前一部分情境或首帧依赖来承载连贯性。

## 创意退出检查

- 一条内容主线主导时长；Hook、专项引擎与主证明属于同一因果事件。
- Hook 保留传播职责、因果机制、身份性线索和开场位置；实现变量由商品情境、受众、专项方向和证明改写，且故事脚本/最终 Prompt 均通过同一 Hook 验收合同。
