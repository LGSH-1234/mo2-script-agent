
# 台词占比

**这份文档只解决一个问题:一支营销视频里,"有人在说话(台词/旁白/口播)"的时间应该占整片时长的多大比例。** 它回答"这条 15 秒的营销视频,台词铺 7 秒、9 秒还是 12 秒更合适"这一类判断:为每种营销视频类型给出一个**明确的推荐占比**,只留很小的微调空间,避免同一类型在很宽的区间里凭感觉乱选。

台词占比和台词字数估算是**两件事,分开处理**:

- **本文档 = 占比**:先定"这支视频该说多久话"(目标口播时长 = 整片时长 × 台词占比)。
- **`scripts/count_chars.py` = 字数**:再拿一段具体文案去核算"这些字念出来要多久、放不放得进目标口播时长"。

正确顺序:**先用本文档定出目标口播时长 → 再把这个秒数作为 `count_chars.py` 的 `--target` 去核算文案长度**。不要跳过占比、直接拿文案凑满整片时长;也不要用占比去反推、压缩已锁定的文案(锁定文案的处理仍遵循 `creative-and-storyboard.md` 的规则:**用户提供的成型口播若放不进选定时长,不擅自删改,而是给用户方案一完整版/方案二精简版两个方案让他拍板,见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「用户口播意图保真合同」;Agent 自己新写的文案才可自行精简**)。

## 为什么要有台词占比

营销视频不是"配了画面的有声书"。画面本身承担吸引、证明、情绪与记忆的职责,台词是**诠释画面**的,不是**替代画面**的。做口播脚本时反复被验证的一条经验:**字太多 → 念得赶、画面被旁白盖住、观众喘不过气;字太少 → 出现尴尬静默、画面和声音脱节。** 占比就是要把这个"刚刚好"的量先定下来。

不同营销内容对"说多久话"的需求差别很大,所以必须按类型给定值,而不是一个占比套所有:

- **口播主导型**(达人口播、数字人、知识讲解、种草测评)本身就是"以说带看",信息靠嘴说,话密度天然最高;
- **演示/证明型**(商品演示、功能证明、前后对比、带操作教程)要给"可见证明"留出被看清的时间(操作、对比、结果、质感特写),说与看交替,话密度居中;
- **品牌/情感/氛围型**(品牌 TVC、情感片、故事片、卡点、拟音带货)靠画面、音乐、留白建立记忆,台词只在关键节点点睛,话密度最低。

## 各营销视频类型的推荐占比

**先把视频归入下表某一类型,直接取「推荐占比」作为目标。** 类型已按"信息与证明由谁承载"合并成互不重叠的 6 类(把达人口播、种草测评、知识讲解等"以说带看"的都收进同一类,不再拆成十几种细类)。推荐值是默认直接用的那个数;「微调区间」是命中下一节因子时才允许小幅浮动的边界(最多 ±5%),不命中任何因子就用推荐值,不要在区间里凭感觉乱走。占比 = 有人声台词/旁白/口播覆盖的时长 ÷ 整片时长。

| 营销视频类型 | 推荐占比 | 微调区间 | 涵盖的常见形态 | 画面在干什么 |
|---|---|---|---|---|
| **口播讲述 / 种草** | **90%** | 87%~93% | 达人口播、数字人口播、知识讲解、教程(无操作)、街头采访、种草测评、文案主导(痛点/误区/引言) | 说话的人为主 + 少量佐证,信息几乎全靠嘴说,近乎全程有声 |
| **促销带货** | **85%** | 80%~90% | 限时促销、催单、优惠播报、清单式带货 | 催单口播为主,但要露出商品、价格与优惠画面 |
| **演示证明 / 对比** | **75%** | 70%~80% | 商品演示、功能证明、前后对比、带操作步骤的使用教程 | 关键证明镜头(操作/结果/质感/对比)要看清,旁白间歇让位 |
| **剧情带货短剧** | **65%** | 60%~70% | 剧情带货、情景短剧、UGC 剧情种草、反转/误会带货 | 靠人物对白与反转推进,需留反应/停顿/眼神间隙 |
| **品牌 / 情感 / 故事片** | **55%** | 50%~60% | 品牌 TVC、情感片、纯画面叙事故事片 | 品牌资产/氛围/音乐/画面叙事主导,台词只在转折与记忆句 |
| **声音 / 音乐主导** | **45%** | 40%~50% | 卡点混剪、ASMR 带货、拟音带货 | 音乐节奏或声音设计主导,台词多为短句点缀 |

## 类型重叠时怎么选(选择规则)

一支视频常常同时像好几类(例如"达人口播"又是"种草测评"),这时**不要犹豫,按下面规则唯一确定一类**:

1. **先看合并**:很多看似不同的形态其实已被收进同一类。达人口播、种草测评、知识讲解、街采、文案主导都属于**口播讲述 / 种草**同一类,推荐值一样(90%),不存在"选哪个"的问题——直接归为该类即可。用户举的"达人口播 vs 种草测评"就是这种情况。
2. **跨类冲突时,按"谁承载了这支视频的核心说服力"决定,取下面第一个命中的类**(优先级从上到下):
   - 卖点主要靠**人物对白 / 剧情反转**成立 → **剧情带货短剧**;
   - 说服主要靠**音乐节奏或声音设计**(卡点、ASMR、拟音) → **声音 / 音乐主导**;
   - 说服主要靠**品牌氛围 / 情绪 / 纯画面叙事**,而非讲解或演示 → **品牌 / 情感 / 故事片**;
   - 卖点主要靠**可见证明**(操作 / 效果 / 质感 / 前后对比)成立 → **演示证明 / 对比**;
   - 有明确的**催单 + 价格/优惠**主导 → **促销带货**;
   - 以上都不主导、主要靠**人开口讲**把信息说清 → **口播讲述 / 种草**。
3. **仍难取舍时,取占比更低的那一类**:占比低意味着给画面多留呼吸,宁可让画面多讲一点,也不要把台词铺过量导致念得赶、盖住画面。

判类型的总原则:**看"信息由谁承载"**——主要靠人说出来 → 口播讲述/促销带货(高);靠画面演示 + 台词解读 → 演示证明(中);靠画面/音乐/情绪/剧情本身 → 剧情/品牌情感/声音主导(低)。

## 微调因子(±5% 以内)

**默认直接用推荐值。** 只有命中下面这些**与营销直接相关**的情形,才在该类型「微调区间」内小幅调整,且不得跨出区间、不得叠加到越界。这些因子只用于在推荐值附近微调,不用来推翻类型定值。

**往推荐值下沿走(台词少一点、画面多一点):**

- 该片核心卖点靠**可见证明**成立(操作 / 前后对比 / 质感特写 / 效果展示)——给证明镜头留出无旁白或轻旁白的时间;
- 画面内已有**密集字幕或优惠卡文字**承载信息——口播不必复述,只念最该"听到"的那句;
- **多人对白 / 剧情**需要反应、停顿、眼神的表演间隙——有效台词之间留空隙。

**往推荐值上沿走(台词多一点):**

- 卖点或功能**复杂、画面难以自明**,必须靠口头讲清;
- **强转化**,结尾 CTA 必须可听且要点名商品 / 品牌 / 搜索词 / 商品卡动作(见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「口播 CTA 合同」)——为可听 CTA 预留时长;
- **无字幕、纯语音交付**,信息只能靠听。

关于语言:占比只决定"说多久",与语种无关;**同样的占比下不同语言能塞多少字差别很大,这交给 `count_chars.py` 按语种核算**,不要用某种语言的字数感去改占比。

## 默认占比(判不出类型时兜底)

**只有当视频归不进上表任一类型时,才用默认目标占比 70%。** 这对应"常规解说/对话"的主流口播密度,信息说得清、又给画面留约三成呼吸。一旦能判定类型,就用该类型的推荐值,不要停留在默认值。

## 占比计算流程

1. **判类型 → 取推荐占比**:把视频归入上表某类型,直接取该类型的推荐值;判不出类型才用默认 70%。
2. **看有无微调因子 → 定最终占比**:逐条对照上一节因子,命中就在该类型微调区间内小幅调整,不命中就保持推荐值。落定一个具体占比数。
3. **× 整片时长 → 目标口播时长**:占比 × 整片秒数 = 这支视频的**目标口播时长**(秒)。例:15 秒商品演示(演示证明 / 对比,推荐 75%)→ 目标口播 15 × 0.75 ≈ **11.25 秒 ≈ 11 秒**。
4. **分配到节拍**:把目标口播时长按分镜/节拍铺开——开场钩子停顿、证明镜头留白、CTA 可听收尾都要预留,不要平摊成"全程匀速说话"。
5. **交给 `count_chars.py` 核算文案**:把第 3 步的目标口播秒数作为 `--target` 传入,核算实际文案念出来放不放得下(见下一节)。

一个 15 秒商品演示的示例:
- 类型 = 商品演示 → 推荐占比 **75%**;
- 微调:有一个明显的前后对比镜头要看清(↓),但带货要可听 CTA(↑),两者大致抵消 → 保持 **75%**;
- 目标口播 = 15 × 0.75 ≈ **11 秒**;
- 节拍分配:0~1.5s 钩子（短口播，或一眼可懂的强视觉/特征声音事件；不做无信息留白）、1.5~4s 铺垫解说、4~8s 演示+对比(此段少旁白、让画面说话)、8~12s 证明解读、12~15s 可听 CTA;把台词铺在解说/解读/CTA 上,凑够约 11 秒;
- 再拿这 11 秒去核算文案:`--target 11`。

## 与 count_chars.py 的衔接

**占比定"说多久"(本文档),count_chars 定"这些字够不够/超不超"(脚本)。** 两步串联:

1. 本文档算出**目标口播时长**(如 10 秒);
2. 把它作为 `count_chars.py` 的 `--target` 传入,连同按情绪/节奏选的 `--scene`、按语种选的 `--lang`,核算实际文案:

```bash
# 目标口播 11 秒、中文、常规语速,核算这几句够不够 11 秒
python3 scripts/count_chars.py --lang zh --scene normal --target 11 "开箱就被质感惊到" "上手实测三个细节" "同款点下方链接带走"
```

3. 脚本会多输出一行「预期耗时」,告诉你当前文案落在目标之内还是超时、超时大概要删多少字;
4. 据此调文案长度,使口播恰好落在"占比算出的目标口播时长"里,而不是铺满整片、也不是空出大段静默。

**还没写文案、只想先知道"这个档位下 N 秒大概能装多少字"时:不传台词、只给 `--lang`/`--scene`/`--target`,脚本走「容量反查」。**

```bash
# 20 秒、中文、fast 档大约能装多少字
python3 scripts/count_chars.py --lang zh --scene fast --target 20
# → 容量反查：目标 20s 在该档位下大约可容纳 106~120 字
#   106 字 = 念慢也放得下的稳妥量(有停顿/留白/音效时按这个写)
#   120 字 = 念到最快才刚好塞满的上限(不留呼吸,慎用)
```

写完文案后仍要按上面第 2 步把实际台词传进来做**正向核算**,容量反查只用于先定篇幅。注意容量反查必须给明确语种,`--lang other` 只能在传入实际台词时用(它靠台词书写体系选代理档)。

### 抖音原生速度不是增加卖点的借口

当平台为抖音/TikTok、且内容属于快节奏达人带货或商品实操，中文默认改用：

```bash
python3 scripts/count_chars.py --lang zh --scene douyin --target 11 "短句一" "短句二" "短句三"
```

- `douyin` 档按 5.5–6.5 有效字/秒估算；每句单独核算，并在句间保留约 0.15–0.35 秒停顿。
- 口播覆盖率与口播速度是两个维度：75% 覆盖率可以由多段短促口播组成，不等于 11 秒从头到尾匀速朗读。
- 促销爆点只能短时到 6.5–7.2 字/秒；安全/使用限制退回 4.5–5.5 字/秒。任何一句需要超过 7.2 字/秒才能放下时，应删减信息或延长视频。
- 提速只让表达更利落，不提高本条卖点容量；卖点数量仍以 [contract-platform-and-execution.md](../../contract-platform-and-execution.md)「时长—卖点—信息节拍预算」为准。
- “让画面说话”主要用于 Hook 建立后的证明段。第一镜对白为空时，必须满足 [contract-platform-and-execution.md](../../contract-platform-and-execution.md)「首秒信息可读合同」：视觉或特征声音在 1 秒内独立讲清问题；否则无信息静默最多 0.4 秒，并应补一句短 Hook，而不是把证明段留白机械挪到开头。

**注意边界**:占比是给你估目标口播时长的参照;一旦文案已被用户锁定,处理规则以 `creative-and-storyboard.md` 为准——占比/时长核算发现用户提供的成型口播放不下时,不擅自压缩、加速或删改,而是给用户方案一(完整版)/方案二(精简版)两个方案让他拍板(见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「用户口播意图保真合同」);Agent 自己新写的文案才可自行精简。

## 常见误区

- **把整片时长当口播时长**:直接拿满 15 秒去凑文案,导致从头讲到尾、画面没有呼吸、证明镜头被旁白盖住。先乘占比。
- **用一个占比套所有视频**:品牌片按口播讲述型的 90% 铺台词会毁掉氛围;演示片按品牌情感型的 55% 铺又讲不清卖点。必先判类型、取该类型推荐值。
- **在宽区间里凭感觉乱选**:类型推荐值是默认直接用的数,不命中微调因子就别动它;命中了也只能在 ±5% 内小幅调。
- **CTA 只给字幕不给声音**:强转化视频结尾必须留出可听 CTA 的时间(见「口播 CTA 合同」),这部分口播时长要在占比里预留。
- **多人对白顶满占比**:对白剧情不留反应/停顿间隙,表演僵硬;多说话人反而要留白。
- **用占比去压锁定文案**:占比只用来估目标、指导新写文案的长度;用户提供的成型口播超时是"给两方案让用户拍板"(完整版/精简版),不是"自己删"。
