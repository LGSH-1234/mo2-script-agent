
# Markdown 产物冻结格式

三个 Markdown 产物（`营销脑图.md` / `故事脚本.md` / `视频生成Prompt.md`）的字段级冻结格式正文，是这三份格式的唯一权威。产物目录规则、三产物白名单与产物职责在 [输入与项目状态](intake-and-project-state.md)「Markdown 产物」；本文件只承载三套格式的完整定义。第 4 步写 `故事脚本.md`、第 6 步写 `视频生成Prompt.md` 时直接读本文件对应小节，不必整读 intake。

## 营销脑图格式（`营销脑图.md`，半固定骨架）

`营销脑图.md` 与另外两个产物不同：它是**内部推理产物**，不喂用户、不喂模型，价值在于能按任务灵活展开营销思考，因此**不整篇冻结**。但它采用一套**半固定骨架**——**标题骨架必含、两个关键区块冻结、其余推理区自由**：

```markdown
# 营销脑图

## 需求理解与交付契约
（自由展开：原始意图、production_task、平台/目标市场/时长/比例/口播语言/画面文字语言/人物本地化、人物参考权限、已确认输入、待解决问题）

## 营销策略
（自由展开：受众、压力/渴望/情境、主要价值、信任、证明、情绪、记忆、行动、创意契约）

## 创意方向
（自由展开：所选方向用中文名——品牌片/达人 UGC/剧情带货/季节促销/通用营销；核心创意、Hook 到正片的过渡、故事主线）

## 商品模型
（涉及具体商品时必含；按「商品模型」小节的**半固定骨架**登记——两大部分与填写铁律冻结，维度字段按品类增删改名；适用却缺标 unknown、品类不适用标 n/a。多商品按 产品1/产品2…… 逐一登记）

## 卖点账本
（涉及具体商品时必含；按「卖点账本」小节的固定 YAML 结构登记，先于分镜写好）

## 待问清单
（把商品模型与卖点账本里所有 unknown 关键缺口汇总于此，供第 2 步一次性向用户问清）
```

骨架规则（硬性）：

- **标题骨架必含**：`需求理解与交付契约 / 营销策略 / 创意方向` 三个区块的标题必须存在，但**内容按任务自由展开**——推理深浅、要点取舍随任务而定，不冻结成填空格子。这是脑图作为思考空间的弹性所在。
- **`商品模型`、`卖点账本` 两个区块必含**：只要涉及具体商品，这两个标题**必含**。`卖点账本` 内部**严格套用** [输入与项目状态](intake-and-project-state.md)「卖点账本」小节的固定 YAML 结构；`商品模型` 采用**半固定骨架**——两大部分（参数与形态 / 功能与使用）、填写铁律、下游据它压商品尺寸台账并把保真事实带进 Prompt 这三样冻结，具体维度字段按品类增删改名。二者都要喂给下游（分镜勾稽、视角覆盖必判、覆盖矩阵校验、商品尺寸台账），刚性与另外两个产物同级。不涉及具体商品时可省略这两个区块。
- **`待问清单` 区块**：涉及具体商品时必含，汇总所有 `unknown` 关键缺口，服务第 2 步的一次性问清。
- **就地更新单一真相源**：用户补充素材或修正后，就地更新对应区块（尤其 `商品模型`/`卖点账本`），使 `营销脑图.md` 始终是商品事实与营销判断的最新单一真相源。
- 区块可按任务增补（如加「专项方向要点」），但上述必含标题与两个冻结区块不得缺省或改结构。

## 故事脚本格式（`故事脚本.md`）

`故事脚本.md` 是一个**固定模版,只需填空,不许增删表列**。全文只能包含标题 `# 故事脚本`、下面这一张 8 列分镜表、紧跟其后的一行贯穿全片的 `**全片 BGM**` 说明；禁止在表格前另写 Hook Scope、Bridge、Body takeover、创意摘要、库编号、自检过程或其它内部字段，严格遵循列名与顺序:

| 镜号 | 时长 | 画面描述 | 景别 | 光影氛围 | 对白·旁白 | 音效 | 运镜 |
|---|---|---|---|---|---|---|---|
| 1 | 8s | 画面内容描述，对关键实体加粗；自然描述前态、触发、商品动作与可见后态；人物承担内容职责时写具体可观察行为与行动意图，不用抽象情绪标签代替表演；台词内联到触发动作处，不写内部编号或勾稽标签 | 近景 | 根据所选 Style、平台与情境填写 | [旁白]... 或 [角色名]... | 与动作同步的现场声 | 与信息职责匹配的手机/商业镜头语法 |
| 2 | 10s | ... | 中景 | ... | ... | ... | ... |

**全片 BGM**：根据用户所选 Style、平台执行底线、商品动作与口播密度填写，禁止复制模板样例；写明曲风、情绪、速度、主要声音、是否有人声及随分镜变化。动作型短视频优先让真实动作声承担首屏留存。

- 分镜表承载全片的镜头描述:画面、景别、光影氛围、声音、运镜逐镜写清;口播台词内联进「对白·旁白」列、紧贴触发动作处。
- **空间锚定全局做一次、位置变化靠过渡承载(硬性,见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「空间定位与位置连续性合同」)**：整片初始空间关系在 `视频生成Prompt.md` 的 `场景：`/`主体：` 段落里一次性定住作为全片空间基线,故事脚本「画面描述」列默认沿用、不逐镜复述;位置变化靠过渡描写承载、硬切才重新定位。完整规则以合同为准。
- **「对白·旁白」列台词如实登记(硬性)**:有台词(口播/旁白/对白/达人讲述)的镜头必须把台词内联写进该列、紧贴触发画面动作处,不得漏记或藏进画面描述、也不得只写"此处口播介绍卖点"这类占位而不写实际台词;但不是每个镜头都要有台词,纯画面/无人声/纯音乐的镜头该列留空即可,整片本就没有台词也正常,不为凑而硬加。要杜绝的只有一种:明明这一段有人在说话却没把台词落进该列。写完自检:有人说话却没落台词即为不合格,须补齐后再展示。用户已提供成型口播时,台词直接取自其锁定文案(见 [contract-creative-and-script.md](../../contract-creative-and-script.md)「用户口播意图保真合同」),完整意图必须承载、不为凑时长擅自删改;用户未提供时按台词占比与商用脚本要求撰写可念出的台词。
- **「音效」列只写逐镜的现场音 / 拟音 / 点缀音效**（键盘敲击、布料摩擦、开瓶气声、脚步、UI 提示音等），**不写背景音乐**——BGM 是贯穿全片的，写进下面单独的「全片 BGM」说明行。
- **全片 BGM 说明（硬性，紧跟在分镜表下方）**：分镜表后必须补一行 `**全片 BGM**：…`，用大白话把音乐描述到用户闭眼能"脑内播放"的程度，而不是「轻快的背景音乐」「大气的音乐」这种谁都看不出所以然的空话。至少讲清这几点：
  - **曲风 / 类型**：如 lo-fi 慢拍、法式浪漫香颂、80s 复古合成波、国风古筝、trap 鼓点、史诗管弦、民谣木吉他、city-pop 等;
  - **情绪基调**：如温暖治愈、燃 / 热血、松弛慵懒、悬疑紧张、高级冷感、俏皮可爱;
  - **节奏与速度**：快 / 中 / 慢，有没有明显鼓点或卡点，大致 BPM 感（如"约 120 BPM 的轻快四拍"）;
  - **主奏乐器 / 编曲**：谁在主导，如钢琴独奏、合成器 pad 铺底 + 808 低音、弦乐渐强、原声吉他扫弦;
  - **有无人声 / 歌词**：纯器乐，还是有人声哼唱 / 带歌词（带歌词要说明语种与是否会盖住口播）;
  - **一个通俗类比**：给一个"像什么"的参照帮用户秒懂，如"类似咖啡店背景乐""像运动品牌广告那种鼓点""接近婚礼现场的抒情钢琴"（**只作风格类比，不得指定受版权保护的具体曲目 / 歌手 / 品牌配乐**）;
  - **随片段的动态变化**：跟着分镜走的强弱起伏，如“0 秒起低音量铺底并给首句口播让位 → Hook 动作落点鼓点进入 → 主证明段推到最满 → CTA 收束”。只有首镜已经由一眼可懂的视觉反差或特征声音独立传递信息、且「对白·旁白」列确实为空时，才可写短暂无口播；不得把证明段的声音留白机械挪到开头。
  - 若用户已提供指定 BGM 音频，则此行改为标注"使用用户提供的 BGM @音频N"，并简述其风格与卡点用法，不再另行描述。
- 画面描述里对关键实体（人物、服装、道具、商品）用**加粗**标注，保持跨镜一致。
- **动态状态因果（硬性）**：画面描述要让读者看见商品相关前态怎样被 Hook 放大、Play 怎样推动商品行动、主证明怎样产生后态、Style 怎样调制表演与视听。真人出镜时将情绪翻译为触发源、视线/呼吸/姿态/手势/环境作用、行动意图和结果反应；不固定情绪类型或数量。无人脸时用物体、环境和任务状态完成同样的变化。
- **卖点勾稽（硬性，内部完成）**：在 `营销脑图.md` 建立 `shot_selling_point_map`，把核心卖点映射到真正呈现它的镜号、动作、结果或台词。**篇幅按优先级分配**：主打卖点与 P00 应占最多镜头/时长，一条核心卖点可被多镜覆盖，不必给每个原子事实各留一镜。面向用户的故事脚本只写自然画面与台词，不显示 `[USP] / P00 / 卖点#N` 等内部标签。
- 时长列各行相加应等于整片时长。
- **声音一致性（硬性）**：每镜是否有人声以「对白·旁白」列为单一真相源。全片 BGM 行不得与分镜另立一套声音时间线；首镜已经写台词时，禁止再写同期“留白、只留环境音、无口播、无旁白或不说话”。
- **成品实文校验（硬性）**：新写或修改后，必须在展示前用 `scripts/validate_story_script.py` 直接扫描实际 `故事脚本.md`；未通过就改原文件并重跑，不能用内部计划或自检摘要代替。**字段模版见 [contract-json-schemas.md](../contract-json-schemas.md) 第 2 节；返回的 `errors` 已是中文自然语言,照着改产物即可(能否读校验器源码等规则统一见该文件抬头)。**
- 其余信息各归其位:营销方向、核心创意、Hook 与正片关系等创意判断留在内部 `营销脑图.md`;成片的美术、打光、色彩材质、以及声音系统的**工程级参数**（分层混音、精确 BPM、频段、音色锚点等）写进 `视频生成Prompt.md`——但**面向用户的 BGM 风格描述必须在故事脚本的「全片 BGM」行就写清楚**，让用户在确认脚本阶段就能感知音乐大概是什么样，而不是等到内部 Prompt 才第一次出现;素材缺口在故事脚本写好后的素材完整性检查里于对话中逐一交涉。

## 最终生成信息格式（`视频生成Prompt.md`）

`视频生成Prompt.md` 是一个**固定填空模版,也是封闭集合:全文就是一段可直接投喂 Seedance 的 Prompt,只允许出现下面模版里的字段,禁止另加任何段落**。它不是项目档案,不写标题以外的营销元信息、不写来源素材清单表、不写生成参数块。整片时间范围只能出现在文件顶部的一行元信息或拼接备注里,各分镜正文使用请求本地时间（从 `0s` 起）：

```text
时长：15秒以内，比例：16:9。任务：生成品牌TVC。

标题：《...》

风格与视觉参考：
风格参考：...
风格关键词：...

镜头语言：...

视觉与美术规则：...

色彩与材质系统：...

打光规则：...

剪辑节奏：...

声音方向：...

场景：
场景1是...，对应@图片3（只采用空间、家具、光线，不采用图中人物或商品）

主体：
品牌1：...
产品1：...，对应@图片2（只采用结构、材质、颜色、Logo/标签位置）。产品尺寸（内联自商品尺寸台账，用可核验描述、不堆空话）：约一节 AA 电池大小、掌心可完全握住；全片保持同一真实尺寸与相对比例。（注：形态/颜色/文字/朝向等保真事实已由上句「只采用…」采纳条款承载，不再重复列 match 表；source 是内部台账字段，不写进本 Prompt；使用类镜头须写清功能部位朝向，见分镜示例）
主体1：...，对应@图片1（只采用五官、发型、妆容、服装、姿态，不采用图中任何物品作为产品1）

各个分镜的具体内容：

0-3秒
拍法：...
画面内容：...（正文内联复用同一图序号，如「主体1（@图片1）拿起产品1（@图片2）」）
品牌/产品露出：...
声音：...

3-7秒
拍法：...
画面内容：...
品牌/产品露出：...
声音：...

（按需继续 7-12秒、12-15秒……）

全片保持品牌1、产品1、主体1与场景1连续一致；...
```

- **只允许上面这些字段,禁止再加别的段落。** 尤其禁止出现:独立的「元信息」块（整片时长/视频请求次数/来源素材/生成素材等）、独立的「来源素材清单」表、「生成参数」块（`Duration`/`Ratio`/`Resolution`/`ImageList`/`VideoList` 等）。这些要么是 故事脚本 的信息、要么是运行时工具入参,都不属于这段 Prompt 正文。
- **实体↔图片的指代信息必含,内联写在 `场景：`/`主体：` 定义处（硬性）**：每个用到参考图的场景、品牌、产品、主体,都要在其定义行内用 `对应@图片N` 显式声明它绑定哪张图,并紧跟该图**只采用/不采用**哪些维度(沿用素材隔离与多图借鉴的 adopted/ignored 写法)。这是把"哪张图对应哪个产品/人物/场景"这一指代关系钉进 Prompt 的唯一位置——它是**内联声明,不是被禁止的独立清单表**,不要另起一节做表格。没有任何参考图的纯文本生成请求可省略 `对应@图片N`。
- **产品尺寸默认内联进 `产品1：` 定义行（硬性）**：涉及具体商品时,把第 6 步压出的商品尺寸台账用**可核验描述**内联进 `产品1：` 定义行——写清 `真实尺寸`/`可见比例`(如「约一节 AA 电池大小、掌心可完全握住」),而非「大小合适」这类空话,并在「全片连续一致性说明」里锁定全片保持同一真实尺寸与相对比例,杜绝忽大忽小/整体失真。**形态/部件/材质/颜色/文字/朝向等保真维度不再单列 match 表或否定清单**——它们已记在「商品模型」、并通过 `产品1：` 定义行的「只采用@图片N 的结构/颜色/标签位置…、不采用其背景与无关物」采纳条款承载,避免与商品模型重复登记。约束**作为定义行内描述文本存在,不另起段落、不做独立清单表**,保持封闭集合结构不变。`source` 是内部台账追溯字段、不进 Prompt 正文(来源已由 `对应@图片N` 承载)。**尺寸未确定(`真实尺寸`=unknown 且未向用户澄清)时禁止进入本阶段——见「商品大小保障原则」,先问清或按品类标准推导再编译。**
- **图序号即传入顺序(硬性)**：`@图片N` 里的 N 是**稳定图序号**,必须等于执行阶段调用视频生成工具时该图在 `ImageList` 里的位置(第 1 张=@图片1、第 2 张=@图片2……)。编号一旦在本文件里分配,正文所有分镜复用同一序号,不得改指;执行时**严格按图序号从小到大、无缺位地把对应素材依次传入 `ImageList`**。多参考类型混用时,视频/音频标签同理(`@视频N`/`@音频N` 各自按其列表顺序)。若某序号在正文未被任何实体绑定,应删掉该空号并把后续序号前移,保持序号连续、与传入顺序一一对应。
- **参考图在分镜正文里内联复用同一序号**,例如「画面中的年轻女性(@图片1)拿起帽子(@图片2)」。真正传给视频工具的 `ImageList`/`Duration`/`Ratio` 等是调用参数,由执行阶段按上面的图序号顺序填入工具调用,不写进这个 md。
- 顶部第一行只保留 Seedance 需要读的 `时长 / 比例 / 任务`;营销方向、核心创意、Hook 与正片关系等创意判断属于内部推理,归 `营销脑图.md`。
- 当拆成多个 `视频生成Prompt-XX.md` 时，每个文件独立完整，可单独作为一次 Seedance 输入执行；文件顶部可用一行元信息标注 `full-film range: 13-24s` / `part 2 of 3`，但分镜正文时间从 `0s` 开始。
- 每个分镜四段固定：`拍法`、`画面内容`、`品牌/产品露出`、`声音`，缺一不可。
