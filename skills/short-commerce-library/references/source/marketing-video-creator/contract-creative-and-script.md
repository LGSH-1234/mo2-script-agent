
# 创意与脚本契约（时间轴 · 模板商品化适配 · Hook · 商用脚本 · 口播/剧情/CTA · 空间连续）

> 本文件是以下约束的**唯一权威正文**：请求本地时间轴、任意用户所选模板的商品化适配合同、Hook 脚本合同、可投放商用脚本合同、用户口播意图保真合同、台词如实登记合同、空间定位与位置连续性合同、剧情带货因果合同、口播 CTA 合同。SKILL.md 只做激活与调度，遇到这些主题以本文件为准。

### 请求本地时间轴

每个 `sandbox_generate_video` 请求都是独立的。每个 `视频生成Prompt.md`（多次调用时为 `视频生成Prompt-XX.md`）里的 Prompt 正文，都必须使用从 `0s` 开始的**请求本地**时间轴，无论该片段落在整片哪个位置。整片时间范围只能出现在文件元信息或拼接上下文里，绝不能泄漏进 Prompt 正文。`故事脚本.md` 可用整片时间范围以便审阅；写每个 `视频生成Prompt-XX.md` 前，先把整片时间换算成请求本地偏移。

具体写法：

- 用 `0s`、`3秒后`、`本片段第5秒`、`本请求的0-11秒`；
- 当前请求本身只有 11 秒时，不要写 `18s later`、`画面至24秒`、`13-24s` 这类整片提示时间；
- 续接片段：先说明首帧或开场状态与上一片段衔接，再在当前请求内从 `0s` 继续；
- 尾帧或关键帧依赖：把上一片段的最终帧绑为输入素材，但当前请求的所有新动作时间仍保持请求本地。

### 任意用户所选模板的商品化适配合同

只要用户任意选择了一个或多个 Hook 模板、创意模板（Play）或风格模板（Style），就必须在写故事、分镜和视频 Prompt 前完成一次**模板适配编译**。用户选择的是要发挥作用的创意约束，不是要求把模板示例中的商品、场景、人物、道具和镜头逐字复制。

先建立四类输入：

1. **用户 Prompt**：营销目标、目标人群、使用情境、主推卖点、平台、时长、明确想保留的文案/场景/动作及禁止项；
2. **商品事实**：只取商品模型与卖点账本中已知、可追溯的功能、结构、材质、尺寸、使用方式、主张与证据；
3. **商品图片可见特征**：只提取画面确实可见的轮廓、比例参照、颜色、材质观感、结构部件、包装层级、Logo/文字位置、纹理与适合展示的角度；图片看不到的背面、内部、功能、用法和效果仍为 `unknown`；
4. **模板结构**：拆成 `传播职责（必须保留）`、`因果机制（必须保留）`、`身份性验收项（必须保留）`、`实现变量（可改写）`、`用户明确锁定元素（必须保留）` 和 `成功标准`。

按职责适配，而不是让三个模板互相抢叙事控制权：

- **Hook 模板**负责“观众为什么停下来”：保留传播职责、触发—升级—结果的因果机制与 1-2 个标志性线索，用当前商品的真实人群情境、痛点/欲望、可见结构或证明动作改写场景、人物、道具、具体动作和 bridge；
- **创意模板 / Play**负责“内容如何推进”：保留其叙事结构、动作模式或状态变化，把角色、道具、冲突、转折和结果替换成当前商品能够真实承担的使用或证明路径；
- **Style 模板**负责“内容如何被拍出来”：把它翻译成镜头、构图、光线、色板、材质、节奏、声音和排版语法，并用商品图片中的颜色、轮廓、纹理、结构和包装特征选择具体执行；Style 不得改变商品真实颜色/形态、遮挡关键卖点，或替代证明。

适配优先级为：**事实、安全与平台边界 > 用户明确要求及锁定元素 > 主证明成立 > 专项说服机制 > 模板传播职责与因果机制 > 标志性线索 > 基于商品图片的视觉发挥 > 实现变量与 UI 默认值**。发生冲突时先改写低优先级的表层执行；不得静默换掉用户选择的机制。只有模板核心与商品事实、安全或另一个用户锁定要求确实不可兼容时，才用一个最小问题让用户决定。

每个所选模板必须绑定至少一个可见或可听的分镜落点，并在内部形成：`用户意图绑定 + 商品事实绑定 + 图片特征绑定（如有） + 保留项 + 改写项 + 分镜落点 + 成功标准`。若模板移除后成片没有任何可观察差异，说明模板没有发挥作用；若商品可以无损替换成大量无关商品，说明适配仍然通用，必须重写。最终脚本与 Prompt 只呈现适配后的自然内容，不暴露内部字段。

**Hook 额外执行「原始选择 → 验收合同 → 实际产物」三层追溯。** 改写任何场景前，先从用户选中的 Hook ID、名称和原始 Prompt 生成 `hook_acceptance_contract`：保留原文片段、核心机制、商品因果绑定、与主证明的交接、开场截止时间，以及可在分镜文字中直接验收的身份性要求。后续不得用模型自己重写的简化版反向替代原始选择。

### Hook 脚本合同

当用户提供商品信息外加 Hook 提示词时，所有脚本、分镜和生成提示词都必须让 Hook 与商品、专项创意和主证明组成同一个因果事件。Hook 不是必须在某个固定秒点“退出”的贴片，也不能成为与商品无关的完整故事。

**用户选择 Hook 默认确认四层内容：**

- **传播职责（必须保留）**：观众为什么停下来，例如异常、结果先行、感官打断、危险逼近、尺度反差、信息缺口、第一视角卷入或突然反转；
- **因果机制（必须保留）**：什么触发什么、如何升级、造成什么可观察后果；
- **身份性线索（必须保留）**：去掉就不再是该模板的动作、声音来源、构图、状态变化或顺序。
- **开场位置（必须保留）**：模板定义为 Hook 的核心机制必须在开场首镜、且不晚于验收合同的截止时间出现，不得挪到 7–12 秒的中段再补。

地点、景别数量、颜色、布景和不承担模板身份的普通道具，默认属于**实现变量**。但只要某个动作、构图、声音来源、状态变化或动作先后是该 Hook 的身份，它就不是实现变量。例如：分屏 Hook 必须真有同时分屏对照；360° 自拍必须有可辨识旋转；“人物摔倒”必须有可见失衡/跌倒，不能只留击打声；咔嚃声 Hook 的声源必须来自商品食用或其因果动作，不能移植到无关道具。

完整脚本、专项引擎或 UI 默认推荐与用户明选 Hook 冲突时，先设计**等强融合**：可换场景和道具，但必须同时保住原机制、身份线索、开场位置和商品因果。只有事实/安全/用户另一个硬要求使两者真正不可兼容时才询问；UI 默认值永远不能静默覆盖用户明选 Hook。

先从商品模型、卖点账本和专项引擎建立 `目标人群真实情境 → 痛点/欲望触发 → 商品特定动作或证明 → 可观察结果 → 人物判断/任务/关系改变 → 行动`，再让 Hook 的传播职责、因果机制与标志性线索进入这条链。商品不能默认从首帧被人物举着讲；除非商品揭示本身就是机制，否则先让观众看到问题、反差、结果或信息缺口，再让商品作为答案进入。

至少选择一种商品化方式：痛点实体化、收益戏剧化、证明先行、物件/动作转义或情境碰撞。Hook 最后一个动作必须与专项主线或主证明第一个动作相同或连续，形成真实 bridge，而不是 Hook 结束后硬切到商品介绍。

Hook 的世界规则、运动、声音或母题可以贯穿后续，只要每次出现都新增商品证据、人物判断、任务状态、关系变化或品牌记忆；不得用同一奇观重复填时长。短片优先一个主世界，但允许 `A→B→C→D` 的单向多场景推进，只要每场新增不同且必要的信息职责并共享同一 USP、商品身份和转场逻辑。`A→B→A` 不是自动禁用：若 A 的回归完成此前埋下的因果回报、主证明或关系改变，可以保留；若只是重复背景、静态定格或“高级感呼应”，必须删除。用户锁定首尾回环时仍须新增可见验证。

敲定脚本与生成提示词前执行六项检查，任一失败都回到第 3 步重写：

1. **首屏停留**：0.5 秒内有可理解信息，1 秒内可说出问题、欲望、反差或观看收益；
2. **专属性**：去掉当前商品后，Hook 与后续是否仍能原样成立？若是，必须重写商品化触发；
3. **因果性**：Hook 提出的问题、欲望或异常是否由商品动作/证明回答，而非硬切后口播介绍；
4. **可辨认性**：传播职责、因果机制和至少一个标志性线索是否仍可观察；
5. **证明性**：是否存在与主打卖点一致、由权威信息支持且静音可读的主证明；
6. **状态推进**：Hook 是否改变人物、物体、关系或任务状态并自然触发商品行动；若只是奇观背景加静态举品，必须重写。

### 可投放商用脚本合同

用户要脚本时，产出**投放可用脚本**而非中性镜头概要——要能被创意制片、提示词撰写者或视频生成器以极少改写直接使用。

脚本须有一条消费主线：一个可记忆的承诺、张力、渴望、证明路径或购买理由组织整片。不要平均罗列所有卖点，把商品信息排序为：

1. 开场留存任务；
2. 主要的相信理由或渴望；
3. 可见证明或使用动作；
4. 场景或情绪；
5. CTA 或记忆点。

针对不同时长，套用同一条商用主线：

- 6-10秒：一个 Hook、一个商品证明/动作、一个 CTA 或记忆点；
- 11-20秒：Hook、bridge、一条主证明路径、一个场景/渴望节拍、CTA；
- 21-40秒：Hook、铺垫/故事、分层证明、额外证明或异议处理、CTA；
- 更长：仅当每一章都新增一个购买理由时才重复证明章节。

15秒优先：`0-3秒 Hook+bridge`、`3-7秒 商品铺垫/使用`、`7-12秒 证明/渴望`、`12-15秒 CTA/记忆点`。

30秒优先：`0-3秒 Hook`、`3-10秒 铺垫/故事`、`10-20秒 核心演示/证明`、`20-27秒 额外证明/异议/场景`、`27-30秒 CTA/记忆点`。

质量标准：

- 脚本应听起来像真实广告或达人口播稿，而非模板说明。
- 用可自然念出的简短台词。
- 每个节拍先展示可见动作或证明，再让文案解读它。
- 正片要卖商品，而不是仅为视觉新奇而延续 Hook。
- 品牌片可通过品牌含义、素材记忆、氛围与渴望来销售，而非直接演示，但 Hook bridge 之后商品或品牌素材仍须主导正片。
- 剧情脚本可通过人物冲突与回报来销售，但商品或品牌必须导致、揭示、象征或化解转折点，不要让剧情娱乐替代商用职责。
- CTA 要针对商品/品类、在能推断出更好动作时不落于泛泛；除非用户明确要求静默输出，否则须念出声并辅以视觉。

用 `scripts/count_chars.py` 估算台词与旁白：先按场景选定语速档位、并按文案语种显式指定语言枚举，再评估文案能否放进目标时长。两个枚举都要你判断后显式传入，脚本不做任何自动识别：

**动手核算文案字数之前，先定这段视频"该说多久话"。** 台词占比(整片里有人声台词/旁白的时长比例)与台词字数是两件事：占比决定**目标口播时长**、字数核算决定**这些字放不放得下**。先按 `references/base/dialogue-ratio.md` 判定目标口播时长(把视频归入 6 类营销类型之一、直接取该类型推荐占比——口播讲述/种草 90%、促销带货 85%、演示证明/对比 75%、剧情带货短剧 65%、品牌/情感/故事片 55%、声音/音乐主导 45%，判不出类型才用默认 70%；类型重叠时按该文档「选择规则」唯一确定一类；仅命中可见证明留白/字幕负载/多人对白/复杂卖点/可听 CTA 等因子时在该类型 ±5% 内微调)，再把这个秒数作为下面 `count_chars.py` 的 `--target` 传入核算文案。不要跳过占比、直接拿文案凑满整片时长。

- `--scene`（语速档位，按这条口播的**情绪与节奏**判定）：`fast` 高语速——广告冲刺 / 卡点 / 促销催单 / 快节奏达人口播；`normal` 正常语速——常规讲解 / 对话 / 种草 / 教程；`slow` 慢语速——情感与品牌片 / 吟诵强调 / ASMR / 庄重旁白。默认 `normal`，先对号入座再传。
- `--lang`（语言，必传，按文案**实际书写语种**选）：`zh` 中文 / `ja` 日语 / `ko` 韩语 / `en` 英语 / `es` 西语 / `fr` 法语 / `de` 德语。文案语种**超出这 7 种**时传 `other`——脚本会按每段台词的书写体系就近取 `zh`/`en` 代理档给出**近似估算**并明确标注,你无需自己猜代理码。拼错受支持语种(如把 `zh` 写成 `zn`)仍会报错,不会被静默降级。缺省会报错；同次调用对所有段落统一生效,不同语种的文案分多次调用。
- `--target`（目标时长秒数，可选）：手上有明确目标时长（如这段口播要卡进 15 秒）时加 `--target 15`。脚本会在合计时长外多输出一行「预期耗时」：把合计区间与目标比对,超时时按"时长与字数成正比"折算出大致需删减多少字/词(超时给删减区间、仅念慢会超给单个稳妥删减量、已在目标内报余量)。这是调文案长度的粗略参照。

不悄悄压缩、省略或快念超载文案。选档细则见 `references/base/creative-and-storyboard.md`。

### 用户口播意图保真合同（硬性，优先于时长）

**内容质量优先于凑时长。** 当用户输入本身就是一段成型的口播/文案/带货话术（明显是"希望被念出来的内容"，而非仅一句创意意图），把它当作**已锁定文案**：最终成片的口播**必须承载这段内容的完整意图与核心信息**，不得为了塞进某个时长而擅自删改、压缩、改写、加速或丢弃其中的卖点、痛点、机制说明与 CTA。判定"是不是用户口播"看特征——成段、有主张有论证有号召、口语化、指名商品/功效/使用方法（例如"家长忽视孩子脚臭的后果……家里有脚臭的真的可以试试哦！！！"这类完整种草话术）。这属于 `story_provided` 里的"固定措辞"，按成熟度规则原样保留。

**当"完整承载用户口播所需时长"与"用户选定的时长限制"冲突时，不要私自删、也不要只会问"延长还是改词"，而是给用户两个方案让他选**（此规则取代旧的"仅询问延长时长或修改措辞"）：

1. 先把用户口播按语速档位与语种用 `count_chars.py` 核算出**完整承载所需的目标时长**（如需 ~45s），与用户选定时长（如 15s）比对，确认确实放不下。
2. 若放得下：直接完整保留，无需给两方案。
3. 若放不下：输出**两个方案**交用户选择——
   - **方案一(完整版)**：完整遵循用户口播、不删内容，说明它大约需要多长时长（如约 45s），并给出这一版大致的故事脚本走向（承载哪些段落、节奏如何）。
   - **方案二(精简版)**：卡进用户选定的时长（如 15s），**明确说清要删/合并/弱化哪些部分**（例如砍掉哪段铺垫、哪个次要卖点让位、CTA 如何压缩），并给出这一版大致的故事脚本走向。
   - 用 `dynamic_questionnaire` 让用户在"方案一(完整版，延长到约XXs) / 方案二(精简版，保持XXs)"间一键选择（问卷只按真实候选出题，遵守「动态表单合同」）。选定后再据此落 `故事脚本.md`。
4. **绝不静默选边**：不因为用户填了 15s 就默默砍掉他口播的一半内容当作理所当然，也不因为想保内容就擅自把视频拉长——两条路都要摆到用户面前由他拍板。

Agent **自己新写**的文案（非用户提供）仍须适配现有动作时间与场景语速、可自行精简，不走两方案流程；两方案流程只针对"用户提供的成型口播/锁定文案放不进选定时长"这一冲突。

### 台词如实登记合同（硬性）

**有台词就必须写上、不得漏记——但不是每个镜头都得有台词。** `故事脚本.md` 的「对白·旁白」列按镜头如实登记:哪个镜头有口播/旁白/对白/达人讲述,就把台词内联写进该镜头这一列、紧贴触发画面动作处;没有台词的镜头该列留空即可,纯画面/无人声/纯音乐的镜头乃至整片本就没有台词也完全正常,不必为凑而硬加。要杜绝的只有一种情况:**明明这一段有人在说话,却没把台词落进「对白·旁白」列**(尤其别把它藏进画面描述、或只写"此处口播介绍卖点"这类占位而不写实际台词)。用户已提供成型口播时,台词直接取自其锁定文案、完整承载(见「用户口播意图保真合同」);Agent 自写台词时按台词占比与商用脚本要求写成可念出的句子。

### 空间定位与位置连续性合同（硬性）

**空间锚定在 `视频生成Prompt.md` 里全局做一次即可，位置变化交给过渡描写承载、不逐镜重复写、也不写增量——目的是不许人物/物品位置无交代地跳来跳去。** 分三部分：

- **空间锚定（全局做一次）**：在 `视频生成Prompt.md` 的 `场景：` 与 `主体：` 段落里，把整片的初始空间关系一次性定住，作为全片的**空间基线**，而不是每个分镜都重写一遍。至少交代清楚：① **环境／场景**是什么（室内/室外、什么空间、地面与背景关系）；② **每个人物/主体的初始站位**（在画面左/中/右、前景/中景/背景、坐/站/蹲、面朝哪个方向）；③ **人物之间的相对位置**（谁在谁的左边/右边/对面/身后）；④ **关键物品的初始位置与朝向**（放在哪、被谁持握、功能部位朝向哪——朝向沿用「产品真实形态与使用逻辑合同」的具名功能部位写法）。空间关系用可核验的方位词写清（左/右/前/后/面朝/背对/身侧），不要写"合理站位""错落有致"这类空话。分镜正文默认沿用这条全局基线，不必逐镜复述空间关系。
- **位置变化靠过渡描写承载（不写增量）**：当同一实体（人物、产品、道具）在相邻分镜之间、或同一分镜内部**位置/朝向/所在发生变化**时，不需要额外补一段"位置增量"，而是**在该处本就有的动作/过渡描写里自然带出移动过程**——是谁从哪儿移动/转身/走位/递物到哪儿、经由什么动作完成，让上一镜的出场位置能连续过渡到下一镜的入场位置。只要过渡描写把移动交代清楚，位置连续性即已满足，无需再单列增量说明。
- **硬切重新写定位**：唯一需要重新写一次空间定位的情形是**硬切场景**（预期本就是一次突变的换场/跳切/蒙太奇）。硬切时为新场景**重新给一次空间锚定**（新环境、人物新站位、物品新位置），并明确标注为硬切即可，不需要从旧场景过渡过来。除硬切外，禁止让人物"这一镜在左、下一镜突然在右"却不靠过渡描写交代怎么过去的——这种无交代、又非硬切的位置跳变即为不合格，须补上过渡描写或改成硬切并重新定位。

进入生成前方案检查时核对：`视频生成Prompt.md` 是否有一处全局空间基线；相邻镜之间实体位置若有变化，过渡描写是否把移动交代清楚；硬切处是否已标注并重新定位。发现无交代、又非硬切的位置跳变即回到 `故事脚本.md`／`视频生成Prompt.md` 补齐。

### 剧情带货因果合同

对剧情主导、爱情、剧情、喜剧、反转、误会、梗改编或人物带货类视频，不要从 Play 提示词直接跳到镜头表。先建一条紧凑的故事因果链，再写对白链，最后写分镜。

写脚本表之前，在可见的 `核心记忆句` / `Hook-body 融合` / 脚本铺垫中，或（当用户没要求看规划细节时）在内部方案里，锁定这些决定：

- 商品或品牌在故事里确切的角色；
- 人物的压力、渴望、误会或选择；
- 商品或品牌为何在那个时刻登场；
- 什么可见或可听的证明改变了处境；
- 关系、身份、判断或结局如何改变；
- CTA 如何由那个改变自然引出。

对白驱动的短剧，先写对白链再展开节拍。每句有效台词都必须回应或递进上一句。不要靠沉默、凝视、泛泛的内心独白或密集字幕承载因果逻辑。商品信息应通过人物动作、发问、认知、证明或反转进入，而非粘贴功能清单。

生成的剧情带货脚本使用**最低有效对白数**：15秒至少 4 句有效对白，30秒至少 8 句，60-90秒至少 14 句。有效对白指带有问答、情绪反应、身份揭示、证明或决定改变的人物台词。商品口号、孤立的感叹、纯旁白解释、只有 CTA 的文本都不计入。

### 口播 CTA 合同

对带转化、召回、搜索、商品卡、直播间、预约或购买意图的商用视频，最终 CTA 必须**可听**，而非仅有文本。把一句简短口播 CTA 写进脚本、分镜和生成提示词，并给出说话人、时间、演绎语气以及有用时的配套屏幕文字。

除非用户明确要求静默、无对白或纯音乐输出，否则采用以下默认：

- 最后 1.5-4.0 秒必须包含由达人、旁白、主角、数字人、吉祥物或品牌声念出的口播 CTA；
- 口播 CTA 在可用时须点名商品、品牌、搜索词、商品卡动作、直播间动作、预约动作或购买路径；
- 屏幕 CTA 文字和商品 Hero Shot 可强化口播,但不能替代它；
- 若平台或运行时无法生成语音,披露该限制并询问是改用纯字幕还是单独音频制作；
- 呈现或执行生成方案前,凡 CTA 仅为 `屏幕文字`、`字幕`、`Logo`、`搜索词` 或静默 packshot 的提示词,判为不通过并重写。

有效口播 CTA 示例：

```text
女主轻声口播：“同款搜【商品名】，把这份心动带回家。”
男主低声口播：“想要这个味道，搜【品牌/商品名】。”
旁白口播：“现在点商品卡，领取同款组合。”
品牌声口播：“上新已开，搜【搜索词】。”
```
