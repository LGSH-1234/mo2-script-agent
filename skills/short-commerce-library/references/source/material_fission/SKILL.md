# 职责
你负责基于一个参考视频批量制作多条新视频。本能力是 `imitation_video` Skill 的上级编排：取得视频、反解、单版本规划、素材裁剪、视频生成、合并的通用规范均以 `imitation_video` 对应步骤为唯一来源，本 Skill 仅定义裂变特有的多版本决策与编排。执行本流程前须先加载 `imitation_video`；引用其步骤时以步骤编号为准（如“复刻第四步”指 `imitation_video` 的“第四步：规划新视频”），步骤语义不变时本 Skill 无需跟随修改。
固定流程如下：
`load_skill imitation_video（学习复刻技能）→ 取得参考视频（复刻第一步）→ 反解一次（复刻第二步）→ 裂变方向与版本矩阵（本 Skill）→ 逐版本规划（复刻第四步＋本 Skill 差异）→ 共享镜头校验与素材准备（本 Skill＋复刻第五步）→ 批量并发生成（复刻第六步＋本 Skill 差异）→ 按版本合并交付（复刻第七步＋版本对照表）`

# 适用场景
以下请求适用本能力：
- “基于这个视频裂变”“给我出一批”“多做几个版本”；
- “按不同人群／开头／场景／卖点各出一条”等明确的多版本请求；
- 要求在保留参考视频爆款结构的同时，批量派生多条成片。
仅制作一条视频的“做同款”“二创”“参考这个视频做一个”等请求，直接使用 `imitation_video`；无参考视频的批量文生视频、仅剪辑已有成片或泛创意讨论，不适用本能力。
本流程产出的母版与版本矩阵保留至交付。用户查看结果后要求“以某一条为基础再裂变”“继续出变体”时，回到第三步，以用户指定的版本作为母版派生新版本，无需重新反解。

# 第一步：取得参考视频与商品图，确认用户意图
  - 完全按复刻第一步执行。链接解析、sandbox 路径、多候选视频由用户指定等规范均以该处为准。
  - [IMPORTANT]**必须主动向用户索要需裂变的商品图片**，并在后续复刻链路中统一使用。
  - **判断用户提供的商品与视频中商品是否为同一 SKU**：若为同一 SKU，则按裂变流程直接执行，无需询问用户；若视频中的品牌与用户提供的商品图片差异过大，必须询问用户选择 1:1 复刻替换还是自由发散裂变——1:1 复刻替换走纯复刻链路，自由发散裂变走卖点、场景等发散链路。禁止在未询问用户的情况下自行推导，必须显式确认。


# 第二步：反解参考视频
完全按复刻第二步执行，整条裂变链路仅调用一次 `pippit_video_tool_imitation_reverse_analyze_sandbox`。补充两条裂变特有约束：
- 裂变方向设想、问卷答案和替换素材不传入反解工具；
- 反解成功后，本批次全部版本共用同一份反解结果，任何版本规划前不再调用反解工具。
反解结果的字段含义、`content_blocks` 双层结构和路线语义按复刻第二步理解。问卷使用 HITL checkpoint 协议的要求与复刻一致；部署配置非 HITL 协议时，不启用本链路。

# 第三步：分段引导用户完成裂变方案
本步骤为裂变特有。裂变的交互原则是**逐步引导用户完成一批，而非一次性收集全部决策**：反解完成后，按以下三个环节依次与用户确认，每个环节一次问卷或一次对话，前一环节确认后方可进入下一环节；用户对某一环节已给出明确、可执行的说明时，该环节不再询问，但各环节产物均须显式呈现给用户确认。

本步骤以向导姿态与用户交互。每个环节固定按四步进行：先向用户呈现当前已知信息（反解结论、母版、矩阵或预览），再给出 Agent 基于事实的建议和可选项，然后主动询问该环节需要用户补充的信息或素材，最后复述用户确认的产物后再进入下一环节。用户随时可以推翻或跳过建议；用户要求“一步步带我做”时，不在一次回复里堆叠多个环节的决策。

仅表示进入本流程的入口文案，以及“下载视频”“解析链接”“调用某个工具”等操作要求，不构成裂变方案。用户另有补充时，仅采纳与新视频内容相关的要求进行判断。

## 3.1 复用与商品适配（定母版）
先将反解结果转译为用户语言向用户呈现：源视频的核心爆点是什么、哪些是必须保留的结构（钩子、卖点链路、视听风格）、哪些是可调整的可变项（人群、场景、商品、话术、包装等），以及各候选改动分别需要用户补充什么信息或素材。
引导用户确认本批次的**母版**：全部版本共同遵守的固定项——产品是什么、核心卖点是什么、必须保留的源事实有哪些、本批次固定不变的内容是什么。用户上传商品图、人物图或给出商品信息时，在此确认其对应源片中的哪个对象、是否在所有版本中一致使用。
产物：一份经用户确认的母版说明，包含源事实继承项和本批固定项两部分。

## 3.2 单条／批量规划（定版本矩阵）
母版确认后，基于母版向用户提出针对本视频具体可行的**裂变方向**（常见方向包括更换人群、开头钩子、场景、卖点侧重、人物、包装、语言或商品；反解显示某维度没有裂变空间时不提供该选项），每个选项用当前视频的事实说明保留什么、改变什么。
同一次交互中询问版本数：Agent 给出建议值作为默认选项（通常 2 至 5 条），由用户确认或自定。
用户选定方向后，**逐版本引导用户细化**：将每个版本改哪些对象、改成什么、保留什么，细化到可直接转写为封闭改动清单的颗粒度（“主体、动作或关系、客体、完成状态”），措辞优先原文引用用户回答。例如，仅确认“换人群”尚不充分，须确认到“版本二人群换成考研党、钩子场景换深夜书桌、卖点话术按熬夜背书重写”。
每个版本的细化结果必须满足复刻第三步的全部可执行性检查（素材是否已上传、R2V 编辑目标是否明确、素材能否唯一绑定源对象等），逐版本核对；某版本不满足时，按复刻第三步的对应规则处理（说明需要上传的素材并结束本轮，或收窄该版本的改动范围）。
产物：一份经用户确认的**版本矩阵**——每行一个版本、每列一个裂变维度，单元格写明该版本在该维度改成什么；未指定的维度在所有版本中保持一致，矩阵之外的变化不产生。版本数以用户确认的数量为准。

## 3.3 生成规划预览（定镜头方案）
版本矩阵确认后、首次调用 Plan 之前，向用户呈现一份**生成规划预览**，让用户确认“接下来具体要生成什么”：
- 每个版本拆成哪些镜头段、各段走 R2V 还是 Semantic 路线、时长多少；
- 哪些镜头段被矩阵声明为候选共享（全部版本一致、只生成一次）；
- 各版本分别需要哪些素材、素材绑定到哪个源对象；
- 共享范围的场景连续性检查：相邻源内容段场景或事件不同、而后续段又被定为全部版本共享时，该后续段很可能因画面连续性分叉——向用户说明后，由其选择将该段一并划入可变维度或调整裂变维度，不在矩阵中假定其可共享。
用户确认或调整后，才将最终方案作为第四步逐版本规划的输入。本环节不产生新的内容决策，仅确认生成切分与资源安排；用户对方案的内容改动回到 3.2 调整矩阵。预览是基于反解与版本矩阵的预估：实际片段切分以各版本规划工具的返回为准，候选共享也可能在第五步比对后收缩，最终方案与预览有出入时在交付说明中如实反映。
产物：经用户确认的镜头级生成方案，含候选共享标记和素材清单。

## 双层内容的逐版本范围
反解 `content_blocks` 同时包含 `CORE_CONTENT` 与 `WRAPPER_CONTENT` 时，复刻第三步的双层默认策略逐版本适用（默认 `PARTIAL_RECREATE + CORE_CONTENT`，完整复刻或包装改动必须由用户明确提出，单一人物素材不扩大到包装等），并在 3.2 的逐版本细化中为每个版本独立确定 `RecreateScope` 与 `ChangeScope`：不同版本可使用不同的复刻范围和改动范围，逐版本记录在矩阵中。

# 第四步：逐版本规划
版本矩阵固化后，对每个版本各调用一次 Plan：按复刻第四步执行该次调用，其公开 Schema、必填参数、Checker 行为、时长上限和路线规则均以该处为准。裂变仅叠加以下差异：
- 全部版本的规划调用相互独立，**并发执行**，待全部返回后再进入第五步；不在两次调用之间传递或拼接另一版本的规划结果；
- `RecreateScope`、`ChangeScope` 传该版本在矩阵中记录的取值；普通视频均传空字符串；
- `ImageList`、`VideoList`、`AudioList` 仅传该版本确实要使用的用户素材；某份素材仅被部分版本使用时，只出现在这些版本的调用中；
- `AgentInstruction` 在复刻第四步的构造规范（剔除入口文案与操作要求、不补充用户未提及的内容）之上，按三段式组织：先按复刻规范剔除；再用一两句写明母版固定项（“本次为参考视频的素材裂变第 N 版，除下述改动外，人物、产品、话术、场景、结构等全部继承源片”），固定项内容以用户确认的版本矩阵为准；最后按原顺序逐条拼接本版本的封闭改动清单，措辞优先原文引用问卷答案；
- 同一版本仅调用一次规划工具；内部修复重试由工具完成，返回错误时不得再次调用重试。个别版本规划失败时，记录失败原因并在交付说明中告知，其余版本照常进入后续步骤；全部版本规划失败时停止并告知用户。

# 第五步：共享镜头校验与素材准备
全部版本的规划返回后，先执行共享校验（裂变特有），再按复刻第五步为每个待生成片段准备素材（ffmpeg 裁剪命令、参考预算、媒体标签规范均以该处为准）。

## 共享镜头校验
对版本矩阵中声明为候选共享的片段，跨版本逐项比对规划结果中决定生成内容的全部字段：
- `route`、`片段时长`、`reference_video`（名称与时间范围）、`source_element_mappings`、`material_usages` 完全一致；
- `SEMANTIC_RECREATE` 片段再比对 `prompt` 正文逐字一致；
- 引用“前一段生成视频”的片段，仅当其引用的前段在本版本中同样复用同一来源结果时才允许复用；否则该片段在各版本分别生成；
- 上述任一字段不一致时，该片段不再视为共享片段，各版本分别生成，不得通过修改规划结果强行对齐。
比对一致的共享片段，全批次仅生成一次，生成结果供所有引用版本共用。比对仅使用规划结果的字段，不比较或改写 Checker 返回的最终 Prompt。

## 素材准备的裂变补充
按复刻第五步裁剪和组装各片段的素材列表。仅补充一条：共享片段复用他版生成结果时，后续片段引用“前一段生成视频”解析为本版本实际承接的那份生成结果，再按规划范围裁剪。
暂不支持关键帧提取、图片生成或编辑等素材校准能力；规划所需的图片素材以用户上传为准。

# 第六步：批量并发生成视频
对每个待生成片段，按复刻第六步执行单次生成调用：参数取值、模型选择、时长规范、`need_extend` 语义和音乐版权恢复流程均以该处为准。裂变仅叠加以下编排差异：
- 按依赖分层并发：先将全部待生成片段按依赖关系分层——不依赖任何生成结果的片段（`need_extend=false` 且不引用“前一段生成视频”）为第 0 层；依赖前段结果的片段归入其前段之后的层。同一层内的片段并发调用 `sandbox_generate_video`，全部成功后再开始下一层；依赖多个前段的片段等待其全部前段成功；
- 共享片段仅调用一次生成，其余版本直接使用该结果，不重复调用；共享片段失败会阻塞所有引用它的版本；
- 复刻第六步“多片段必须串行生成”的约束不适用于本流程：同一版本内 `need_extend=true` 的相邻片段仍因分层天然保持顺序，无依赖片段（包括不同版本的首段、同版本内相互独立的新场景片段）均可并发；
- `IsIntermediate`：将进入按版本合并或被后续片段引用的片段传 `true`；某版本只有一个生成片段且直接交付时不传；
- 失败处理在复刻第六步的基础上按版本界定：任一片段失败且不属于可恢复的音乐版权信号时，已完整生成的版本照常交付，失败版本不交付部分片段；仅停止依赖该失败片段的片段及所在版本，无依赖关系的其他层和版本继续生成；交付说明中如实告知哪些版本失败及失败环节。
建议在规划全部返回后，先并发执行第 0 层中的共享片段和第一个完整版本，确认可用后再扩大其余版本的并发规模，以便尽早暴露素材或规划问题。

# 第七步：按版本合并并交付
合并调用与单版本交付判定按复刻第七步执行：某版本只有一个生成片段时直接作为该版本成片；多片段版本待其全部片段（含复用的共享片段）就绪后，按该版本 `生成视频脚本` 的顺序调用 `render_video` 合并，合并失败时不交付该版本的部分结果。
最终交付全部成功版本的成片，并附版本对照表，逐版本说明：
- 该版本在版本矩阵中的裂变维度取值；
- 保留了什么、改变了什么；
- 复用了哪些共享片段，哪些片段为本版独立生成。
交付说明同时简述：原视频最关键的爆点、本次采用的裂变方向与版本数。存在失败版本时，明确列出失败版本和失败环节。
不展示内部 JSON、媒体路径、临时裁剪视频或中间生成片段的规范与复刻第七步一致；版本对照表仅使用用户可理解的语言描述异同。

# 注意事项
1. 明确采用发散式裂变还是纯商品素材 1:1 替换（仅走复刻，不发散）；无法确定时，必须向用户确认。
2. 不同品牌商品的价格与促销活动存在差异：当用户提供的裂变视频与该商品品牌不一致时，禁止复用原商品的 CTA，如“原价才600多呢”“拍2发3”等——新商品可能不适用，须及时向用户询问相关商品价格信息并完成替换；**禁止不同商品直接套用原商品的价格和促销话术**。
3. 如果用户已经有裂变脚本请遵循用户的裂变脚本，无需再发散裂变。
