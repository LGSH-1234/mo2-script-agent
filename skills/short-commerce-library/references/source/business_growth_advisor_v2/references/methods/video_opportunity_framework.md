
# 视频机会识别框架

## 什么时候引导用户做视频

当满足以下任一条件时，可以引导创作视频：

- 用户说不知道拍什么、素材不转化、开头留不住、投放素材跑不动、卖点太多讲不清。
- 商品、卖点、人群、平台和素材已基本明确。
- 有投放数据指向素材问题：CTR 低、CVR 低、ROI 衰退、素材疲劳。
- 有自然内容数据指向可复制机会：某条视频播放、收藏、评论、转化明显更好。
- 有参考爆款、竞品信息、截图、关键帧、用户描述或可读取的参考内容。
- 有活动、节日、上新、直播、促销节点。
- 用户已经有脚本、素材包、口播、商品图或达人素材。

如果用户只给了链接而当前环境无法读取，不要直接进入视频方案；先要求用户补充封面、前 3 秒画面、关键帧、标题、文案、评论区问题或希望参考的具体点。

## 视频方案模板

输出视频方案时包含：

- 用户正在痛的问题：这组视频先解决停不住、点不进、买不下、跑不久还是说不清。
- 经营目标：这条视频解决什么问题。
- 目标人群：给谁看。
- 核心卖点：主卖点和辅助卖点。
- 卖点来源：主卖点对应的商品事实、用户痛点、结果收益和可信证明。
- 视频类型：口播、测评、对比、痛点、场景、教程、直播切片、达人种草。
- 结构：前 3 秒钩子、中段证明、结尾行动。
- 素材需求：已有素材和缺口。
- 测试建议：做几版、变量是什么、看什么指标。

## 视频 readiness

| Readiness | 条件 | 动作 |
|---|---|---|
| 高 | 商品、平台、人群、主卖点、素材或参考、目标指标都明确 | 直接输出视频 brief，并交给可用视频能力 |
| 中 | 商品和目标明确，但证据或素材有缺口 | 输出 1-3 个初步方向 + 最小补充清单 |
| 低 | 商品、目标或平台不清楚 | 先回到 intake，不强推视频 |

商品图、商品名、卖点、目标人群或素材中任意两项明确时，至少达到中 readiness：可以先给 3 个初步方向，但不能把投放效果说成确定结论。

给 3 个方向前先调用 `selling_point_analysis.md` 做主卖点排序，确保三条方向验证的是不同卖点或不同表达变量。

## 从指标到视频类型

| 触发信号 | 视频方向 |
|---|---|
| CTR/点击弱 | 痛点开头、场景冲突、强对比、第一秒产品结果展示 |
| 3 秒/5 秒弱 | 多 hook 测试，优先改 visual action、首句和屏幕文字 |
| 完播弱 | 改 3-15 秒 on-ramp，缩短铺垫，提前展示证明 |
| CVR 弱 | 测评、FAQ、信任证明、真实使用场景、评论回复 |
| 素材疲劳 | 同卖点多开头、多场景、多创作者口吻 |
| 评论反复问同一问题 | 评论回复型、教程型、解释型视频 |
| 有表现好的自然内容 | 扩写同款、系列化、投放版改写 |

## Hook Matrix

当进入视频方案或 brief 时，至少给 2-3 个 hook 版本：

```markdown
| 版本 | Visual action | Spoken line / VO | Caption text | 目的 |
|---|---|---|---|---|
| A | | | | |
| B | | | | |
| C | | | | |
```

三个组件要分工，不要重复同一句话。画面负责停住滑动，VO 负责打开悬念或承诺，字幕负责静音可读和锚定卖点。

每个 hook 都要服务不同假设，例如：

- 痛点版：验证目标人群是否被问题击中。
- 结果版：验证产品结果是否能停住滑动。
- 对比版：验证差异化卖点是否比价格更有吸引力。
- FAQ 版：验证用户疑虑是否是转化阻塞。

## 不适合立刻做视频的情况

- 用户没有明确商品或目标。
- 数据口径混乱，无法判断问题。
- 商品/价格/履约问题明显，视频无法解决根因。
- 平台规则或合规风险未确认。
- 用户只是想诊断经营问题，还没有创作意愿。

此时应先补充数据或给经营动作，不要强推视频生成。

## 从诊断到视频的表达

可以这样引导：

> 从你现在的数据看，问题更像是素材没有把核心卖点讲清楚，而不是预算太小。现在信息已经足够做一组测试视频。我建议先做 3 个版本：痛点版、对比版、真实使用场景版。每版只改开头和主卖点，投放后看 CTR、CVR 和 ROI。

如果用户只提供商品和卖点，也可以这样说：

> 现在还不能判断哪条一定能跑出来，但已经足够先做低成本创意测试。我建议先测 3 个方向：一个打痛点，一个打结果，一个打对比。先看前 3 秒留存和点击，再决定要不要继续扩写。
