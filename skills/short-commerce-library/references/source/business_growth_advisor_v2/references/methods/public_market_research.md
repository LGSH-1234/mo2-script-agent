
# 公开市场搜索

`生意增长顾问` 不是只看用户发来的商品图和卖点，还要在用户提供线索后，主动用 `pippit_omni_search` 补齐公开市场参照。搜索的目标是帮助判断“用户真正关心什么、竞品怎么表达、平台上常见内容怎么拍”，再回到卖点分析、视频方向和测试变量。

## 何时必须搜索

只要当前运行时可用 `pippit_omni_search`，并且用户给出以下任一线索，就应先搜索再做主卖点排序：

- 商品名、品类、SKU、价格带、核心功能或包装图。
- 行业、人群、使用场景、门店类型、服务类型或 B2B 领域。
- 平台和地区，例如抖音、TikTok Shop、小红书、本地生活、巨量千川。
- 竞品名、同行账号、爆款、参考视频、商品链接、笔记标题、直播间话术或广告截图。
- 用户痛点涉及“同行都在卷价格”“不知道怎么拍”“素材跑不动”“客户看不懂”“团购转化差”。

如果用户只要求计算自己给出的 ROI、CPA、毛利或保本点，并且没有卖点/创意/竞品问题，可以先做指标口径与程序计算；后续进入创意诊断时再搜索。

## 搜索目标

每轮搜索只服务当前判断，不做泛泛调研。优先找这五类公开信息：

| 搜索目标 | 用途 | 示例问题 |
|---|---|---|
| 用户语言 | 找到目标用户怎么描述痛点 | 用户会搜什么、评论里在问什么、标题常怎么写 |
| 竞品表达 | 判断行业标配和差异化空间 | 同类商品都在打什么卖点、哪些点已经卷烂 |
| 视频形态 | 找可拍的 hook、场景、证明方式 | 开头怎么停住人、中段怎么证明、CTA 怎么落 |
| 平台语境 | 判断内容是否适合当前平台 | 抖音更偏强钩子和即时成交，小红书更重搜索种草 |
| 风险边界 | 避免编造规则或夸大功效 | 有没有平台规则、敏感承诺、虚假宣传风险 |

## 工具使用

使用当前 agent 暴露的 `pippit_omni_search` 工具。按工具 schema 填参，不要臆造 schema；如果工具要求 `Query` 和 `SearchType`，按以下思路选择：

- 通用公开信息：用商品/品类/人群/平台/痛点组合成 `Query`，`SearchType` 选择当前 schema 中最接近的通用网页或内容搜索类型。
- 抖音公开视频参考：若 schema 支持 `douyin_video`，可用 `SearchType=douyin_video` 搜索品类、竞品、场景或 hook。
- 分享链接/口令：把用户原始链接或口令作为 `Query`，让工具解析公开内容；解析失败时请用户补截图、标题、封面、关键帧或文字。
- 不知道 search type：优先使用工具默认能力，或先用最通用的公开搜索类型；不要因为不确定类型就跳过搜索。

搜索 query 要具体，避免只搜行业大词。推荐组合：

```text
平台/地区 + 商品品类 + 目标人群 + 痛点
商品名/竞品名 + 卖点/场景 + 短视频/测评/评论
门店类型 + 城市/商圈/人群 + 团购/到店 + 痛点
B2B 行业 + 客户角色 + 成本/效率/风险 + 案例
```

## 搜索后的整理

搜索结果不要原样堆给用户，先整理成“可进入卖点分析的证据”：

```markdown
## 公开市场观察

| 观察 | 来源类型 | 支持的卖点/风险 | 可转成的视频变量 | 置信度 |
|---|---|---|---|---|
```

每条观察必须标注来源类型，例如公开搜索结果、公开视频摘要、商品页公开文案、公开评论/标题。不要把搜索结果当成用户自己账号的真实经营数据，也不要外推竞品销量、转化率或投放 ROI。

## 与卖点分析的衔接

完成搜索后，把公开观察并入 `selling_point_analysis.md`：

1. 将公开高频用户语言写入“用户任务与痛点”。
2. 将竞品常见表达写入“差异化”评分。
3. 将公开视频形态写入“视频表达映射”。
4. 将评论、测评、商品页公开信息写入“可信证明”候选，但标注来源为公开信息。
5. 将平台规则或敏感承诺写入“质量红线”或“风险边界”。

搜索结果只能改变卖点排序和创意方向，不能替代用户商品事实。没有用户明确提供或可验证的功能、价格、资质、效果数据时，只能把对应卖点写成假设。

## 输出边界

- 不要说“我查到这个竞品卖得很好”，除非搜索结果本身有可靠公开销量字段。
- 不要用搜索结果证明用户自己的产品有效。
- 不要复制爆款脚本；只能抽象其 hook 类型、证明结构、场景和 CTA。
- 不要把平台公开规则说成用户账号当前审核状态。
- 搜索结果冲突时，保留多个可能解释，并把下一步设为低成本素材测试。
