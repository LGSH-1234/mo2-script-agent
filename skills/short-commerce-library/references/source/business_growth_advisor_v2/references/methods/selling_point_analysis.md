
# 卖点分析方法论

## 方法来源

本方法论把公开营销框架收敛成适合 `生意增长顾问` 的卖点分析流程：

- Strategyzer Value Proposition Canvas：先看客户的 jobs、pains、gains，再映射产品如何缓解痛点、创造收益。
- Jobs-to-be-Done：用户不是因为一个功能而买，而是在具体场景里“雇用”产品完成一个任务。
- TikTok 创意建议：短视频广告需要在开头抓住注意力，清楚呈现产品卖点/验证点，并以明确 CTA 收束；创意测试要持续制造 hook、开头、节奏、人物、优惠和产品演示的变化。
- Google Ads 创意建议：广告要让用户快速看懂产品提供什么、为什么对自己有用，并用清晰 CTA 推动行动。

这些来源只提供方法框架，不替代用户自己的商品事实、素材、投放数据和平台口径。

## 先做公开市场搜索

如果用户给出了商品、品类、行业、人群、平台、竞品、参考视频、商品链接、笔记标题、门店类型、B2B 领域或明确素材痛点，先读取 `public_market_research.md`，用 `pippit_omni_search` 搜索公开市场参照，再进入卖点分析。

搜索结果用于回答四个问题：

- 用户真实语言是什么：他们会怎么描述痛点、疑虑和购买任务。
- 同行都在说什么：哪些卖点是行业标配，哪些表达已经同质化。
- 短视频怎么呈现：哪些 hook、场景、证明方式和 CTA 值得低成本测试。
- 有什么风险边界：功效、规则、平台语境或敏感承诺是否需要收敛。

搜索结果只能作为“公开信息”进入证据台账。它可以帮助排序卖点、设计视频变量和发现差异化机会，但不能替代用户自己的商品事实、投放数据、资质证明或实际效果。

## 核心流程

```text
用户线索 -> 公开市场搜索 -> 商品事实 -> 用户任务 -> 用户痛点 -> 结果收益 -> 可信证明 -> 主卖点排序 -> 视频表达方式 -> 测试变量
```

卖点分析的目标不是把所有优点写得更好听，而是选出最值得先拍、先测、先投放的主卖点。

## 1. 商品事实盘点

先把用户给的信息拆成可验证事实，不要直接写成卖点。

| 事实类型 | 例子 | 注意 |
|---|---|---|
| 功能/参数 | 材质、容量、算法、速度、规格、服务范围 | 只是事实，不能直接等于用户收益 |
| 使用场景 | 通勤、宿舍、门店到店、工厂采购、直播间转化 | 场景越具体，越容易变成 hook |
| 目标人群 | 宝妈、投手、店主、采购、附近白领 | 不同人群需要不同卖点排序 |
| 价格/优惠 | 客单价、折扣、团购、套餐、试用 | 不能默认降价，要判断是否有非价格价值 |
| 证明材料 | 商品图、使用前后对比、评论、数据截图、证书、案例 | 没有证明的卖点只能作为假设 |
| 公开参照 | `pippit_omni_search` 搜到的公开视频、标题、公开评论、竞品表达、平台规则 | 只能作为公开信息，不等同于用户自己的经营数据 |

如果商品事实不足，先问最少问题：商品是什么、给谁用、解决什么麻烦、有什么可见证明。

## 2. 用户任务与痛点

用 Jobs-to-be-Done 的视角问：用户在什么场景里，需要这个商品帮他完成什么任务？

| 维度 | 问法 | 输出 |
|---|---|---|
| 功能任务 | 用户具体要完成什么？ | 省时间、清洁、降本、变好看、提升效率 |
| 情绪任务 | 用户不想有什么感受？ | 不想焦虑、不想丢脸、不想踩坑、不想麻烦 |
| 社交任务 | 用户希望别人怎么看他？ | 专业、会选、体面、靠谱、有品味 |
| 风险/阻碍 | 用户为什么现在不买？ | 怕没效果、怕贵、怕麻烦、怕不适合 |

卖点必须连接到某个任务或痛点。无法连接的功能点，只能放到“辅助事实”。

## 3. 卖点转译

把“我有什么”翻译成“用户为什么停下来”。

| 原始表达 | 类型 | 转译方向 |
|---|---|---|
| 无添加蜂蜜 | 功能事实 | 给孩子吃的东西，最怕配料表看不懂 |
| 自动拆 3 条视频方向 | 功能收益 | 今天不用再盯着商品图硬想脚本 |
| 工厂直供 | 渠道事实 | 同样预算，钱花在产品本身而不是层层加价 |
| 门店套餐 5 折 | 优惠事实 | 下班路上就能顺手安排一顿，不用纠结去哪 |
| B2B 系统支持自动报表 | 功能事实 | 老板每周少开一次对数会，也能知道问题在哪 |

转译时遵守三条：

- 不夸大：没有证据的销量、效果、评价、背书不要写。
- 不空泛：不要写“高品质”“提升效率”“更好体验”这种没有场景的词。
- 不堆叠：一条视频只服务一个主卖点，其他事实只做证明。

## 4. 主卖点排序

每个候选卖点按 1-5 分打分，优先选择总分高且证据缺口少的卖点。

| 评分项 | 问题 | 低分信号 | 高分信号 |
|---|---|---|---|
| 痛点强度 | 用户真的痛吗？ | 只是锦上添花 | 影响成交、成本、时间或信任 |
| 场景清晰度 | 能说清谁在什么时候用吗？ | 泛人群、泛场景 | 具体人群 + 具体时刻 |
| 画面可见性 | 前 3 秒能拍出来吗？ | 只能口头解释 | 能用对比、动作、结果、截图呈现 |
| 证明强度 | 用户为什么相信？ | 没有证明 | 有评论、对比、数据、案例、实拍 |
| 差异化 | 和竞品区别在哪里？ | 只是在说行业标配 | 有独特机制、场景、服务或成本优势 |
| 平台适配 | 适合当前平台/投放目标吗？ | 太长、太硬、太复杂 | 可短视频化、可测试、可 CTA |

排序输出时必须说明“为什么它是主卖点”，以及“最大的风险是什么”。

## 5. 卖点组合

一条视频的卖点结构：

```text
主卖点：负责让用户停下来
证明点：负责让用户相信
CTA：负责让用户知道下一步
```

推荐组合：

- 痛点型：用户痛点 -> 产品结果 -> 证明 -> CTA。
- 对比型：旧方法/竞品问题 -> 新方案差异 -> 可见结果 -> CTA。
- 场景型：具体场景 -> 麻烦出现 -> 产品解决 -> CTA。
- FAQ 型：高频疑虑 -> 解释/演示 -> 信任证明 -> CTA。
- B2B 型：客户问题 -> 成本/效率影响 -> 方案机制 -> 案例/流程证明。

不要把所有卖点塞进一条视频。多卖点商品应拆成多条素材，每条验证一个变量。

## 6. 视频表达映射

| 卖点类型 | 更适合的视频表达 | Hook 方向 |
|---|---|---|
| 痛点强 | 痛点开头、场景冲突、问题-解决方案 | “你是不是也卡在...” |
| 结果强 | 前后对比、第一秒结果展示 | “同一个商品，换个开头点击差很多” |
| 证明强 | 测评、实拍、评论回复、数据截图 | “不是我说好，看这个...” |
| 机制复杂 | 教程、拆解、步骤演示 | “这一步很多人拍错了” |
| 价格压力 | 价值对比、成本解释、非价格差异化 | “别先降价，先把这个理由讲清楚” |
| B2B 专业 | 客户场景、流程前后对比、案例复盘 | “客户不是看不懂产品，是没看到结果” |

进入视频 brief 时，必须把主卖点落到：

- Visual action：用户第一眼看见什么。
- Spoken line / VO：第一句话打开什么痛点或承诺。
- Caption text：静音状态下锚定什么卖点。
- Middle proof：中段用什么材料让用户相信。
- CTA：让用户下一步做什么。

## 7. 输出模板

```markdown
## 卖点分析

| 原始卖点/事实 | 类型 | 用户真正关心什么 | 可见证明 | 适合的视频表达 | 置信度 |
|---|---|---|---|---|---|

## 主卖点排序

| 排名 | 主卖点 | 为什么优先 | 最大风险 | 需要补充 |
|---|---|---|---|---|

## 3 条视频方向

| 方向 | 主卖点 | 验证变量 | Hook | 中段证明 | CTA | 复盘指标 |
|---|---|---|---|---|---|---|
```

如果用户资料不足，仍然可以输出“初步卖点分析”，但必须标注假设和补充清单。

## 8. 质量红线

- 不把功能点直接当主卖点。
- 不把多个用户人群混成一个卖点。
- 不把“高品质、好用、划算、专业”这类空词当结论。
- 不编造销量、评价、达人背书、效果数据、认证或竞品事实。
- 不承诺某条素材一定能跑出来，只能说“建议先测试”。
- 不让一条视频同时验证太多变量。
