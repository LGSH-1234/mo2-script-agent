
# 用户增长档案

用户增长档案是持续更新的经营上下文，不是一次性表单，也不是 JSON schema。它的目标是让 agent 在多轮会话中记住用户已经提供过的业务事实、数据口径、素材资产、历史判断和待验证问题，并在后续诊断、执行计划和视频 brief 中复用这些信息。

## 固定路径

档案固定沉淀在：

```text
/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md
```

- `project_or_shop_or_merchant`：当前项目、店铺或商家的稳定标识。优先使用用户提供的项目名、店铺名、商家名或品牌名；如需要落盘，转换成文件系统安全的短标识。
- `xxx.md`：当前经营范围对应的档案文件。默认使用 `user_growth_profile.md`；当同一商家下有明显独立的业务线、店铺或商品组，也可以使用 `shop_name.md`、`platform_shop.md`、`product_line.md` 等更具体的文件名。
- 同一商家下的多平台、多账号、多商品，默认放在同一档案里的不同对象小节，不要一开始就拆成多个孤立档案。
- 不同商家、不同项目或明显无关的店铺，必须使用不同目录或不同档案，不能混写。
- 如果当前轮次还无法识别项目、店铺或商家，先询问一个最小问题；若必须继续推进，可使用临时档案 `/workspace/growth_profiles/unknown/current_profile.md`，并在识别后调整路径或改名。

## 档案原则

- **按经营对象归档**，不要假设用户只有一个平台、一个账号或一个商品。
- **字段可以缺失，对象不能混淆**。缺字段时标注待补充；不要把 A 商品的数据套到 B 商品上。
- **事实、判断、假设分开写**。用户说过的话不等于验证后的事实，agent 的判断也不等于平台数据。
- **保留来源、时间窗、口径和置信度**。同一个 ROI/ROAS 指标可能来自投放后台、店铺后台或用户手算，不能混算。
- **保留计算方法**。凡是由 advisor 计算得到的 ROI、CPA、利润或保本点，都要记录公式、字段来源、计算时间窗和未纳入成本。
- **发现冲突时保留冲突**，先询问，不要覆盖旧信息。
- **档案要短而可用**。优先保留会影响下一步行动的信息，避免流水账。

## 每轮生命周期

每次处理用户提供的新资料、诊断请求、计划请求或视频请求时，按以下流程维护档案：

1. **解析档案路径**：从用户当前话题和历史上下文识别项目、店铺、商家、平台、账号、商品或业务线，确定 `/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md`。
2. **读取已有档案**：如果档案存在，先读取，再基于档案继续工作；如果不存在，创建一个简短 Markdown 档案骨架。
3. **抽取本轮信息**：把新资料拆成事实、用户判断、agent 假设、指标计算、执行动作、视频机会和待补充信息。
4. **合并更新**：只更新有变化的部分；不要无故重写整份档案。新信息和旧信息冲突时，同时保留并标注冲突来源。
5. **用于本轮输出**：诊断、执行计划和视频 brief 必须引用更新后的档案上下文，避免重复询问已知信息。
6. **写回档案**：本轮输出产生的新判断、计划摘要、计算结果、视频机会或用户纠正，应写回同一档案。

如果当前运行环境没有文件写入能力，不要放弃档案流程；在回复中输出“档案更新片段”，说明应写入的目标路径和 Markdown 片段。

## 必须更新档案的触发

- 用户提供新的截图、表格、文本、压缩包、素材、商品信息、账号信息或口头描述。
- 用户提供可读取链接内容，或提供不可读取链接的截图、复制文本、关键帧、标题、封面、评论摘要。
- 完成 ROI、ROAS、CPA、CAC、CPC、CPM、CTR、CVR、利润、毛利或保本点等程序化计算。
- 形成新的诊断、假设、验证方式、风险判断或优先级判断。
- 输出 Markdown 执行计划，至少记录计划标题、目标、对象、关键动作、复盘指标和待补充信息。
- 识别到视频机会或输出视频 brief，记录关联对象、触发原因、素材需求、readiness 和下一步。
- 用户纠正旧信息，必须保留更正记录，并在相关字段旁更新当前有效口径。

## 经营对象写法

当用户有多个对象时，用对象小节而不是硬塞进一张大表：

```markdown
### 商品：便携榨汁杯 A
- 平台：TikTok Shop US
- 价格带：$29-$39
- 目标人群：健身、通勤、宿舍场景
- 已知素材：3 条历史投放视频，1 组商品图
- 当前问题：CTR 尚可，CVR 偏弱
- 初步判断：可能是信任和使用场景证明不足

### 商品：保温杯 B
- 平台：抖音电商
- 价格带：99-129 元
- 当前问题：自然内容播放低，未进入投放放量阶段
```

## 信息更新规则

- 新事实进入“已知事实”或对应经营对象小节。
- 用户主观判断进入“用户判断与偏好”，不要直接写成事实。
- agent 推断进入“关键假设”，必须写验证方式。
- 程序计算得到的 ROI、CPA、利润或保本点进入“指标计算记录”，并关联到对应经营对象。
- 输出过的执行计划进入“历史诊断与执行计划”，记录摘要，不复制全文。
- 视频相关机会进入“视频机会队列”，不要散落在聊天记录里。
- 参考链接只有在当前环境可读取时才写入“已知事实”；不可读取链接写入“待补充信息”，并注明需要截图、文本、表格或关键帧。
- 如果用户后来纠正信息，保留必要的更正记录，例如：“2026-08-26 用户纠正：ROI 口径为广告消耗口径，不含达人佣金。”

## 成长感表达

随着交流增加，agent 应该自然引用档案：

- “我现在知道你主平台是 TikTok Shop US，但你这次截图来自投放后台，所以先不和店铺 GMV 混算。”
- “你之前提过便携榨汁杯 A 的主卖点是宿舍和通勤，所以这次视频方向优先看场景证明。”
- “目前缺的不是创意数量，而是每条素材对应的 CTR、CVR 和成交口径。”
- “现在信息已经足够整理成一条视频 brief，缺口只剩商品实拍或历史素材。”
