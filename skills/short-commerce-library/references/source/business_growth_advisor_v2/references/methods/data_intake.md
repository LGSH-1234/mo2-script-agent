
# 数据接入与口径对齐

## 最小必问信息

无论用户给截图、表格、文本还是压缩包，先确认：

- 痛点：素材不转化、不知道拍什么、投流亏钱、ROI 掉、同行卷价格、门店客流少、产品专业但客户看不懂，或其他。
- 平台：TikTok Shop、抖音电商、千川或其他。
- 地区：国家/市场。
- 目标：成交、ROI、起量、降本、内容增长、商品点击、涨粉、获客。
- 时间窗：今天、近 7 天、近 30 天、单场直播、单条视频、单个计划等。
- 对象：店铺、商品、账号、直播间、短视频、达人、投放计划、素材。
- 当前动作：自然内容、直播、投放、商品页、达人合作、活动促销。

确认项目、店铺或商家标识后，先解析并读取用户增长档案：

```text
/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md
```

如果已有档案中已经记录了平台、地区、商品、目标或口径，不要重复追问；只确认本轮数据是否沿用旧口径。若当前材料属于新的商家、项目或明显无关的店铺，切换到新的档案路径，不要混写。

如果用户已经提供商品图、商品名、卖点、目标人群或素材中的任意两项，不要因为缺少完整后台数据而停住。先按 `pain_point_entry.md` 输出“初步 3 个素材/视频方向 + 最小补充清单”，再说明哪些判断需要数据验证。

## 常见输入处理

### 截图

先提取可见字段，不要猜不可见字段。输出：

- 截图来源。
- 可读指标。
- 时间窗。
- 可疑异常。
- 需要用户补充的字段。
- 截图无法确认的部分。

### 表格

先识别每列含义、时间粒度和主键。若列名模糊，先问用户：

- 每行代表什么。
- 指标来自哪个后台。
- ROI/ROAS/转化是否含退款、佣金、优惠、广告费。

如果用户给多张表，先确认是否可以按商品、素材、账号或时间合并。不能确认时不要自行合并。

### 文本

将文本拆成：

- 事实。
- 用户判断。
- 用户目标。
- 用户正在痛的问题。
- 未证实假设。
- 可行动信息。

### 压缩包

先枚举文件类型和文件名，根据内容分为：

- 数据文件。
- 商品素材。
- 历史视频。
- 脚本/文案。
- 参考资料。

不要在没有看清文件内容前直接诊断。

### 参考线索

参考链接可能是竞品、爆款、商品页、平台规则或公开视频，但链接不是稳定数据源。很多链接需要登录、被风控、动态加载、地区限制，或当前 agent 环境没有读取能力。处理时先判断链接用途和可读性：

- 如果链接可读取：提取公开可见的表达、结构、卖点、素材形式或规则信息，并标注为公开信息。
- 如果当前运行时可用 `pippit_omni_search`：先用用户提供的链接、标题、商品名、竞品名或痛点作为 query 尝试搜索/解析公开信息，再进入卖点分析。
- 如果链接不可读取且搜索也无法补齐：不要假装已经看过；请用户补充截图、复制文本、导出表格、视频关键帧、标题、封面或简短描述。
- 如果是竞品/爆款：即使可读取，也不要假设其真实投放效果；只能说“公开内容值得参考或低成本测试”。
- 如果是商品页：优先让用户补充商品页截图或关键字段，避免链接动态加载导致漏读。
- 如果是平台规则：可通过 `pippit_omni_search` 补齐公开规则或指标解释，并标注信息来源。
- 如果是参考视频：若当前环境不能看视频，只能基于用户描述、标题、封面、截图、关键帧或公开文字做初步判断。

链接不可读时可这样回复：

> 这个链接我当前无法稳定读取。为了避免误判，你可以发我 3-5 张关键截图、复制页面文字，或告诉我视频前 3 秒、核心卖点和评论区高频问题。我会基于这些可见信息先做判断。

## 口径提醒

- ROI/ROAS 在不同平台口径可能不同。
- GMV、成交、订单可能受退款、取消、优惠和佣金影响。
- CTR 高不代表转化好，CVR 高也不代表能放量。
- 自然内容数据和投放数据不能直接混算。
- 单日数据波动大，尽量看趋势和样本量。

## 指标测算入口

当用户要求“帮我算 ROI / CPA / 投产 / 获客成本 / 保本点 / 利润 / 毛利 / 转化率”，或上传的数据足以产生这些指标时，进入指标测算流程：

1. 先确认指标口径、字段来源、时间窗、对象、归因和成本范围。
2. 将截图或表格中的字段整理成结构化数据。
3. 使用 `metric_calculation.md` 的规则编写并运行程序计算。
4. 输出公式、字段来源、程序结果、未纳入成本和置信度。

如果用户只给了平台截图中的 ROI 或 CPA，但没有原始字段，可以引用平台显示值并解释口径；不要反推不存在的字段，也不要把平台投产当作真实利润。

## 接入后的档案写回

每次完成输入处理后，必须把可复用信息写回用户增长档案：

- 新平台、地区、账号、店铺、商品、SKU、素材、达人、直播间或投放对象，更新到“当前经营地图”。
- 新目标、时间窗、成功指标或当前经营问题，更新到“当前目标”。
- 当前痛点、痛点分类、初步素材方向和待验证假设，更新到“痛点与素材机会”。
- 可见截图字段、表格字段、用户提供事实和可读取公开信息，更新到“已知事实”，保留来源、时间窗、口径和置信度。
- 用户主观表达，更新到“用户判断与偏好”。
- 链接不可读、字段缺失、口径不清、关键素材缺失，更新到“待补充信息”。

如果当前运行环境不能直接写入 `/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md`，在回复中输出可写入档案的 Markdown 更新片段。

## 不做的接入

- 不要求用户配置 API key、developer token、OAuth 应用或开发者账号。
- 不自动登录平台后台。
- 不承诺自动长期监控账号。
- 不从用户未授权的系统读取数据。

如果用户希望分析平台后台数据，引导其上传截图、导出的表格或口头说明需要分析的字段。
