
# Markdown 执行计划

当用户需要“下一步怎么做”“帮我出方案”“看完这些数据给个计划”“整理成文档”时，输出 Markdown 执行计划。计划应足够具体，能让用户照着执行或交给团队执行。

输出计划前，先读取当前用户增长档案：

```text
/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md
```

计划应基于档案中的已知事实、口径、历史诊断、计算记录和视频机会，不要重复询问档案已有信息。

## 适用场景

- 数据或截图已经足够形成初步判断。
- 用户明确要求方案、计划、复盘、行动建议。
- 用户已经说清一个具体痛点，需要把它转成 3-7 天可执行的素材测试动作。
- 当前不适合立刻做视频，但可以先做经营动作或补齐数据。
- 当前适合做视频，但需要先把目标、素材和测试方式写清楚。

```markdown
## 2. 已知事实

|---|---|---|---|

## 3. 初步诊断
- 判断 1：
- 判断 2：
- 目前不能确定的部分：

## 4. 指标测算
- 是否已测算：
- 使用口径：
- 程序计算结果：
- 未纳入成本：

## 5. 关键假设
| 假设 | 依据 | 如何验证 | 优先级 |
|---|---|---|---|

| 动作 | 关联对象 | 为什么做 | 需要素材/数据 | 时间 |

```

## 7 天轻量计划

当用户处于早期、资料不足或需要快速行动时，优先给 7 天计划：

```markdown
## 7 天行动计划

### Day 1-2：补齐口径
- ...

### Day 3-4：低成本测试
- 拍或改 3 条素材方向，分别验证痛点、结果、对比或 FAQ 中的一个变量。

### Day 5-6：制作/改版素材
- 根据 Day 3-4 的数据保留有效 hook，替换弱证明、弱 CTA 或弱承接。

### Day 7：复盘
- ...
```

## 计划质量要求

- 每个动作都要说明“为什么做”，不要只列任务。
- 能用用户已有素材就优先使用，降低执行门槛。
- 如果需要视频，写清楚视频解决哪个经营问题。
- 素材测试计划必须写清楚每条素材验证的变量，避免 3 条方向只是同一脚本换标题。
- 如果计划引用 ROI、CPA、利润或保本点，必须说明是否已通过程序计算；未计算时只能列为待补充或待测算。
- 不要求用户配置平台 API、developer token 或广告账户权限。
- 不要给泛化建议，例如“多做内容”“优化素材”。要写成“用商品实拍做 3 个开头版本，分别测试痛点、场景、对比”。

## 计划后的档案写回

输出 Markdown 执行计划后，在用户增长档案的“历史诊断与执行计划”中记录摘要：

- 计划标题和日期。
- 关联平台、店铺、商品、账号、素材或投放对象。
- 主目标和成功指标。
- 关键诊断或假设。
- 3-5 个最重要动作。
- 复盘时间窗和复盘指标。
- 仍需用户补充的信息。

不要把完整计划全文复制进档案；档案只保留后续对话需要复用的摘要。
