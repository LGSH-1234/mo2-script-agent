
# 视频 Brief Handoff

当判断适合做视频时，先输出稳定的视频 brief。brief 的目标是把经营诊断转成视频创作任务，让当前 agent 环境里可用的视频 skill 或工具可以继续执行。

brief 必须从具体转化痛点出发，不要写成泛品牌宣传片。先说明这条视频要解决“停不住、点不进、买不下、跑不久、说不清”中的哪一个问题，再展开脚本结构。

进入 brief 前，先读取当前用户增长档案：

```text
/workspace/growth_profiles/project_or_shop_or_merchant/xxx.md
```

brief 应复用档案里的商品、人群、卖点、素材资产、平台约束、历史诊断、计算记录和视频机会队列。若本轮产生了新的创意角度、素材缺口或 readiness 判断，输出后写回同一档案。

如果本轮还没有明确主卖点排序，先读取 `selling_point_analysis.md`，把主卖点、证明点和 CTA 定下来，再写 brief。

## 触发条件

满足以下任一条件，可以进入视频 brief：

- 商品、目标人群、平台和主卖点已经明确。
- 用户提供了商品图、历史视频、脚本、口播、达人素材、参考截图、关键帧、描述或可读取的参考内容。
- 数据显示问题可能在素材：CTR 低、3 秒留存弱、完播弱、CVR 弱、ROI 衰退、素材疲劳。
- 用户提供了表现好的内容，适合扩写同款或系列化。
- 用户主动要求“做一条视频”“改脚本”“做广告素材”“参考这个爆款”。

如果商品或目标不清楚，不进入 handoff；先补齐最小信息。

## Hook 写法规则

视频前 3 秒由三件事组成：

| 组件 | 作用 |
|---|---|
| Visual action | 画面上正在发生什么，用来停住滑动 |
| Spoken line / VO | 第一麦说什么，用来打开悬念或承诺 |
| Caption text | 屏幕文字，用来让静音观看者立刻理解 |

三者不要重复同一句话。强 brief 应该让三者分工：

- 画面展示商品使用或对比结果。
- VO 说用户痛点或反常识判断。
- Caption 锚定最强卖点或人群身份。

## 视频类型选择

| 经营问题 | 更适合的视频类型 |
|---|---|
| CTR 弱 / 前 3 秒弱 | 强 hook、对比、场景冲突、痛点开头 |
| CVR 弱 / 点击后不买 | 解释型、测评、信任证明、真实使用场景 |
| 商品卖点复杂 | VSL、教程、机制解释、问题-解决方案 |
| 素材疲劳 | 同一卖点多开头、多场景、多表达方式 |
| 评论中反复出现疑问 | FAQ、评论回复、测评证明 |
| 有表现好的自然内容 | 同款扩写、系列化、不同开头复用 |

## Handoff 边界

- brief 不等于投放建议；它只负责视频创作信息。
- brief 不承诺投放结果；它只定义要验证的创意假设和复盘指标。
- 不要求用户接入广告账户或后台。
- 不编造评价、数据、达人背书或功效承诺。
- 如果需要使用参考视频，只学习结构和表达方式，不复制对方素材、脚本、音乐或品牌表达。
- 如果参考链接不可读取，brief 中必须标注“参考内容未直接读取”，并列出需要用户补充的截图、关键帧或描述。

## Brief 后的档案写回

输出或交接视频 brief 后，在用户增长档案的“视频机会队列”或“历史诊断与执行计划”中记录：

- 视频机会或 brief 标题。
- 关联平台、店铺、商品、账号或素材。
- 视频要解决的经营问题。
- 创意角度和 hook 方向。
- 已有素材与缺口。
- readiness：高 / 中 / 低。
- 下一步：生成脚本、生成分镜、生成成片、多版本测试或等待用户补素材。

若当前 agent 成功生成了具体视频，也记录视频文件或可访问结果、使用的 brief、版本差异和建议复盘指标。
