
# 图像与视频 Prompt 编写范式

> 可适配的模式与句式，按场景改写，不要逐字照搬。

## 语言硬规则

当用户使用中文输入或加载中文语言环境时，提示词 prompt 必须用中文书写。但 prompt 中有关旁白/对话的内容须严格遵循 Final_Video_Spec 中的输出语言。

## 图像 Prompt（文生图/图生图）

### 通用原则

提示词不只是描述"画面里有什么"，而是像一位导演和调色师在给团队下指令：

- 用连贯的自然语言描述场景内容（主体 + 行为 + 环境）
- 用短语描述视觉美学（风格、颜色、灯光、构图）
- **拒绝文学修辞**：不解释角色动机或内心状态（如"好像他并不关心"）。只描述物理上可见的元素。
- 不描述画面外或不可见的元素。

### 目标为 key_element 时（数字人/产品单独生成）

围绕以下结构构建：

- **主体与身份**：明确该元素是什么（角色/道具/场景）。对角色包括定义性的身份特征（年龄、体格、显著特征）。
- **特征细节**：描述必须在不同镜头中保持一致的关键视觉特征。
  - 角色：面部特征（眼型、下颌线、发型/发色）、妆容、服装与配饰（材质、合身度、颜色）。
  - 产品：形状、材质、颜色、尺寸、包装上的文字/标签。

### 目标为关键帧时

- **镜头取景**：中近景或胸像，脸部占比大且清晰。避免广角建立镜头和脸部太小的全身镜头。
- **产品可见性**：产品在关键帧中必须清晰可读——不能太小或在画面中丢失。偏好让主角拿着或佩戴产品，使其与脸部共同占据前景注意力。
- **镜头语法**：交替使用双人镜头、越肩镜头（OTS）和单人镜头增加变化，不破坏连续性。

### 图像 Prompt 示例结构

```
<主体身份与特征>, <行为/姿态>, <环境/场景>,
<视觉风格: 写实摄影/手机拍摄感>,
<灯光: 自然光/室内光, 干净>,
<构图: 中近景, 主体前景>,
<色彩: 自然肤色, 无厚重滤镜>,
<画质: 2K, 高细节>
```

## 视频 Prompt（音频驱动口型同步）

### 核心原则

视频 prompt 的主要目的是描述**"变化"和"动态"**——让场景生动起来，而非重新描述参考图中已有的静态细节。

### 基本结构

提示词 = 主体 + 动作，背景 + 动作，摄像机 + 动作

- 使用简单、直接的措辞和短句结构
- 后期添加背景音乐时，在 prompt 中包含"无音乐"指令，以免生成片段与最终混音冲突
- 若工具支持文本对齐，包含确切的台词或对音频片段的意译

### 音频驱动模型的独特结构

必须明确描述由音频驱动的角色状态（说话、唱歌、边说边笑等）。

**最佳实践模板：**

```
<摄像机运动> + <说话者的情绪> + <说话状态> + <特定的身体动作> + （可选）背景事件
```

**示例：**
镜头跟随一名女子转身面向镜头，同时以亲切、自信的表情说着话。她先是用手指轻触产品瓶身，然后单手举起产品展示给镜头，显得真诚自然。背景中的室内光线柔和稳定。

### 表达力偏好

偏好清晰发音的提示（"有节奏的语速"、"友好的解说者"）而非诗意的修辞。

## 实体标签

使用稳定标签绑定复现实体，确保全片一致：

- `Avatar1` — 数字人
- `Product1` — 产品
- `Scene1` — 场景

在所有 prompt 中统一使用这些标签引用同一实体。

## 落 prompt 前自检

- prompt 是否只用中文书写（旁白/对话部分除外）？
- 是否只描述物理可见元素、无文学修辞？
- 关键帧 prompt 是否确保产品和脸部都清晰可读？
- 视频 prompt 是否描述"变化与动态"而非重述静态细节？
- 视频 prompt 是否包含说话状态和身体动作？
- 是否使用了实体标签（Avatar1/Product1/Scene1）？
- 后期配乐时是否已包含"无音乐"指令？
