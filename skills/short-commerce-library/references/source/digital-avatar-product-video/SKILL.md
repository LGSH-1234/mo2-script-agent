# 数字人产品视频

## 核心原则

不要把数字人当成"念稿机器"，而要把它做成"可信的产品证人"——观众必须觉得这个人是真的在用、真的信，才会买。

持久引擎（因果链）：

**产品品类 → 受众画像 → 数字人角色（外观+语调） → 统一场景 → 口播脚本 → 关键帧合成（人+产品+场景） → 音频驱动镜头 → 最终合成**

每一环的输出是下一环的约束：品类决定受众，受众决定数字人形象，数字人+产品决定场景，脚本按场景展开，关键帧锁定视觉一致性，音频驱动口型与节奏，合成交付。

### 质量测试（可证伪）

创意只有通过这条测试才算成立：

**把产品从画面中移除后，这个数字人没有任何理由站在那里对着镜头说话——则创意成立。**

产品必须在画面中有物理存在（被拿在手中、放在身旁桌上、佩戴在身上），而非仅靠旁白提及。

## 输入诊断

生产前，识别或合理假设以下维度：

- 目标市场 / 语种：优先级从高到低——数字人角色设定语言 > 用户明确要求 > 用户输入语言
- 产品品类与核心卖点（用户上传的产品图/描述）
- 目标受众（越窄越好：年龄+使用场景+购买动机）
- 品类张力 / 痛点（受众在不用该产品时遇到的具体困境）
- 产品真相（产品能让人看见的最小具体能力）
- 证据标准（受众需要看到什么才相信：质地、效果、对比、使用过程……）
- 数字人设定：年龄/性别/服装/语调；若用户上传了肖像/全身参考图 → 以此为基准
- 场景选择：从数字人+产品推导一个固定场景（居家/健身房/书店/办公室等），全片不换场景
- 片种 / 体裁：数字人广告与产品视频
- 视觉风格：写实摄影，干净灯光，智能手机前置摄像头拍摄风格
- 画幅与时长：默认 9:16、按需调整；单镜头 ≤15s，总时长由脚本决定
- 模型偏好：生图用高分辨率多模态图像模型（2K），生视频用音频驱动口型同步模型（1080p）
- 合规敏感点：AI 数字人须在平台要求时标注；产品宣称保守不夸大

若用户给的上下文很少，做合理假设并继续。仅当产品、市场或目标确实无法推断时才发问。

## 工作流（步骤）

严格按依赖顺序执行，每个阶段完成后暂停、展示产出、等待用户确认再继续。

### 步骤 1：编写视频规格

产出文件：`Final_Video_Spec.md`，包含：

- 标题
- 类型：数字人广告与产品视频
- 比例：默认 9:16（按用户要求调整）
- 时长（由脚本长度决定）
- 视觉风格：写实摄影，干净灯光，智能手机前置摄像头拍摄风格
- 模型偏好：生图——高分辨率多模态图像模型（2K）；生视频——音频驱动口型同步模型（1080p）
- 语言：优先级——角色画像 > 用户需求 > 用户输入语言

依赖：无。完成后暂停确认。

### 步骤 2：设计故事板

依赖步骤 1 的视频规格。

**关键元素设计：**

- **数字人**：根据规格创建（年龄、性别、服装、语调）。若用户上传了肖像/全身参考图 → 以此为基准进行风格统一，保留可识别的面部特征，输出一张干净、适合电商使用的参考静图。
- **产品资产**：优先要求用户上传产品图（包装、单品 SKU、抠图或场景内照片）。若无上传 → 根据品类简报生成一个合理的产品（保持外观/颜色/包装风格一致），并明确告知用户这仅供演示，稍后可替换为真实照片。
- **场景**：从数字人+产品推导一个固定场景，全片不换场景。配音侧重使用场景/卖点，不得因文案修改而更改背景。

若用户提供了参考媒体并指定为关键元素，描述必须与该资产相符。

**镜头设计：**

- 镜头数量：仅由配音分段或 15 秒限制决定。不为叙事节奏或镜头规模变化增加镜头。若音频过长需分镜头，务必优先保持句子完整性——在完整句子结束后切分，不直接按时间切。
- 视觉一致性：全片保持一个场景、一种构图、一张关键帧图像（相同 asset_id）。禁止"切换到中景/切换到特写/改变角度"等多机位设置。
- 取景：中近景（MCU）或特写，主体占据画面主导地位。除非简报明确要求展示全身，否则避免全身镜头。
- 外观：写实摄影，手机拍摄感（自然光或室内光，轻微手持稳定感，自然肤色，无厚重美颜滤镜）。

**独立音频层设计：**

- 背景音乐：至少一条全局背景音轨。
- 旁白/配音：定义声音标识、语调、确切脚本，以及关联镜头的 layout_instruction。

完成后暂停确认。

### 步骤 3：生成元素图像

依赖步骤 2 的故事板。

- 数字人：使用文生图生成全新角色；若用户上传了参考图 → 使用图生图进行风格统一。
- 产品：使用文生图生成；若用户上传了产品图 → 以其为参考保持一致。
- 推荐分辨率：2K。

完成后暂停确认。

### 步骤 4：生成关键帧图像（每镜头一张）

依赖步骤 2 的故事板。

- 使用图生图，将数字人 + 产品 + 场景合成为一张关键帧。
- 全片使用同一张关键帧的 asset_id，在每个镜头中重复使用。
- 取景：中近景或胸像，脸部占比大且清晰；产品必须清晰可读（不能太小或在画面中丢失）。偏好让主角拿着或佩戴产品，使其与脸部共同占据前景。
- 灯光、构图及产品拿取方式全片不变。
- 推荐分辨率：2K。

完成后暂停确认。

### 步骤 5：生成配音与背景音乐

依赖步骤 2 的故事板。

- 配音：基于用户上传的文本脚本或产品卖点生成；声音标识、语调、时间轴入点/出点必须与计划匹配。
- 背景音乐：设计至少一条全局背景音轨，与配音不冲突。
- 每段配音对应一个镜头，按句子完整性切分。

完成后暂停确认。

### 步骤 6：逐镜头生成最终视频

依赖步骤 4（关键帧）和步骤 5（音频）。

- 每个镜头：引用对应关键帧 + 对齐的音频片段，使用音频驱动口型同步生成视频。
- 时长 ≤15s 的镜头一次生成完整成片；>15s 的镜头拆成若干 ≤15s 片段分别生成再拼接。
- 推荐分辨率：1080p。

完成后暂停确认。

### 步骤 7：最终合成

所有素材就绪后：

- 以配音时间轴为定时的唯一事实来源，按顺序拼接每个镜头的视频。
- 将生成片段上的额外音频轨道静音，避免配音重复。
- 不改变播放速度，不对资产或视频轨道做音频淡出处理。
- 合成完成后展示最终视频，引导用户导出。

## 输出契约

默认产出结构：

```
Final_Video_Spec.md（步骤 1 产物）
├── 标题
├── 类型：数字人广告与产品视频
├── 比例 / 时长 / 视觉风格 / 模型偏好 / 语言
```

故事板产物（步骤 2 产物）：
```
关键元素：
  - 数字人：<描述 + asset_id>
  - 产品：<描述 + asset_id>
  - 场景：<描述>

镜头列表：
  镜头 1：
    时长：0-Xs
    关键帧 asset_id：<同一张>
    配音脚本：<文本>
    旁白语调/声音标识：<描述>

音频层：
  - 旁白（类型 narration）：声音标识 / 语调 / 脚本 / layout_instruction
  - 背景音乐：全局音轨描述
```

视频生成 prompt（每个镜头）：
```
镜头 N（Xs-Ys）:
  image_generation_prompt: <关键帧的完整描述>
  video_generation_prompt: <动态描述：主体动作 + 说话状态 + 特定身体动作 + 背景事件>
  audio_ref: <对应的音频片段>
```

时长 ≤15s 的视频用一次视频生成即可拿到完整成片；成片 >15s 时拆成若干 ≤15s 片段各自一次生成，再做后处理拼接。

## 静默自检

交付前内部执行，重写弱项。除非用户要求点评，否则不外显。

- 因果链每一环是否都成立？
- 质量测试是否通过（产品从画面移除后，数字人是否还有站那说话的理由）？
- 全片是否保持单场景、单构图、同一关键帧 asset_id？
- 镜头数是否仅由 VO 分段和 15 秒限制决定？
- 关键帧中产品是否清晰可读、占比合理？
- 镜头视频的口型是否与音频对齐？
- 配音时间轴是否为合成定时的唯一事实来源？
- 生图 prompt 是否只描述物理可见元素、拒绝文学修辞？
- 生视频 prompt 是否描述"变化与动态"而非重述静态细节？
- 合成时是否已将片段额外音频静音、未改变播放速度？
- 全文语言是否与目标市场一致、无混杂？
- 产品宣称是否保守不夸大？
