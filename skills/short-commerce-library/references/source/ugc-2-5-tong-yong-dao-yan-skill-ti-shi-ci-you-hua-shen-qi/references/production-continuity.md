# 多段、长项目与连续性

用于有真实跨段依赖、完整制作包、分集创作或需要恢复进度的任务。简单独立提示词只记录自己的初始状态、事件和末态。

## 1. 从整片组织到局部执行

在适用范围内依次完成：源与原话 → 导演读解 → 媒介与视听方向 → 时长与叙事段 → 资产及进入状态 → 表演与动作 → 机位与剪辑 → 分镜 → 生成提示词 → 审核与修复。

这些是决策依赖，不是强制十次交付或十次审批。已知方向直接继承，无人物跳过角色心理；用户只要分镜就在分镜检查后交付。不得为完成流程添加无关内容。

长剧本先读全局，或说明目前实际读到的范围。建立场景和事件顺序、跨场景依赖与批次计划，再按有意义的范围展开。一次上下文装不下时保存真实进度，不把未完成部分称为完成，也不以“下一次再做”代替当前仍能推进的已授权工作。

## 2. 时间预算

区分三种时间：整片主时间、独立生成段本地时间、镜头内事件时间。本地生成段从 `0.00s` 开始；主时间对应后期/整片位置，不混写。

先给对白、动作、感知、场景变化和用户要求的片头片尾预算，再安排覆盖镜头。重要事件可用短/常见/较慢三种可行读法或做法估时。字数只能估发音时间，不能包含全部表演与动作成本。

- 有实测台词或音轨时优先使用实测。没有时按角色语速、停顿、语义重点和动作负荷估计，并标注是计划。
- 只有真的可并行且能看懂、听清的事件才共用时间；占同一只手、同一发声能力的动作不能凭排表强行并行。
- 不删原话，不靠不自然加速塞进短段，不把必要接触和反应当零成本。
- 镜头数量由观看任务决定，时长不等分；持续观察可以只需一个整镜区间。
- 指定片长与内容负荷冲突时，优先在不改故事的范围内调整覆盖和节奏。仍不可能时说明冲突，提供保留原话的加时/分段方案，以及需要用户授权才能采用的删改方案。

单次上限和可选档位取自 [小云雀适配](platform-adapter.md)。未知时可完成导演计划，但不能宣称已满足真实生成规格。长片总长不受某单段示例长度约束。

## 3. 资产与状态

只为当前任务需要的对象建简表：

| 对象 | 稳定锚点 | 随剧情更新的状态 |
|---|---|---|
| 人物/动物 | 身份外观、辨认特征、媒介/物种规则 | 姿态、位置、视线、已知信息、衣物状态、伤势、任务 |
| 服装 | 组件、颜色、材质、穿着方式 | 干湿、破损、污迹、已脱下或更换 |
| 场景 | 地标、通道、入口、相对空间 | 天气、时间、灯光开关、环境变化 |
| 道具/产品 | 形状、材质、已知功能和必要标识 | 持有者、手、位置、朝向、完整性、机械状态 |
| 接触与力量 | 当前世界的作用规则 | 接触点、支撑、作用方向、运动相位、释放/持续 |
| 声音 | 说话者/声源身份、空间声学 | 正在说的内容、持续声、起止、音画关系 |

独立段写足执行锚点，不只说“跟上一段一样”。稳定外观和动态状态分开，避免“始终站在左侧”与后续穿过房间互相否定。

只有用户描述、没有可读原素材的修复任务，允许先完成动作补丁并明确外观与接缝尚待核对；这不等于一个外观锚点齐全的独立生成段。当前编辑工具实际绑定原片时才可依靠该绑定保留外观，不能虚构已经建立的绑定。具体交付见 [提示词编译](prompt-compiler.md) 的局部修复说明。

首帧、身份、服装、构图、场景拓扑、道具、动作、声音和氛围参考分别限定职责。同图可兼任多个角色，但必须明确；某图控制身份不意味控制服装或结局。多个参考冲突时先按用户分工、时间和局部范围解决，仍影响源锁的冲突再询问。

## 4. 镜头切点与独立生成边界

同一生成段中的画面切换，可在一句台词或一个动作中发生：声音连续，动作相位衔接，不能重演。

独立生成边界应选择可承接状态。四种方法按真实能力选择：

| 方法 | 出段与入段应说明什么 |
|---|---|
| 完成关键事件后接下一段 | 句子/必要反应完成，位置、手、道具和末态明确；允许普通持续运动 |
| 动作匹配 | 同一动作的两端相位、方向、速度趋势、接触和构图锚点，明确如何用参考或后期匹配 |
| 遮挡拼接 | 遮挡来源、进入方向、覆盖时刻/窗口、显露顺序、两边声音和运动；实际遮满需生成后核实 |
| 平台续接 | 已确认当前入口支持，使用真实前段尾部或末帧及返回标识；不可只靠文字宣称原生续接 |

跨独立生成段的未完台词，需要实际支持的续接或完整连续音轨及后期方案；否则在整句后重分段，不能把半句随意截开。隐藏剪辑与真实一镜到底不同，不能替换用户明确的一镜到底要求。

最终独立片段没有下一段时，只写清末态，不虚构交接对象。末态可以是持续下雨、走动或受力，关键是状态唯一且符合剧情，而非强制静止。

## 5. 连续性与修改传播

按相邻镜头/段依次核对：谁在什么位置、拿什么、哪只手、看向哪里、知道什么、声音在哪、作用力是否持续、物件是否已改变。改变后的状态必须进入后续，不在下一镜自动复位。

修改时先确定最早受影响的决定：

- 台词或结果改变：更新相应事件、时长、人物感知和后续依赖。
- 物件/位置/伤势改变：更新相关动作、机位和承接，保留无关部分。
- 仅光色或画幅改变：检查可见性、构图与参考职责，不重写剧情。
- 用户说只改某镜：交付该镜的完整替换正文，并说明必要的相邻接续调整；不要让其自行拼接碎句。

生成结果中的随机道具、台词或伤势不自动写入设定。先按用户目标判断接受、忽略还是修复。

## 6. 可复制项目状态卡

有恢复需求时保留如下实际信息，可用对话、画布备注或文件；取决于宿主现有能力。不要虚构保存成功、文件校验和或已生成任务。

```text
项目名与当前版本：
用户要交付什么、当前已授权范围：
已读取源范围与仍未读取部分：
不可改的身份/关系/对白/结果/媒介等：
已选导演方向和重要设计依据：
素材及其真实标识、控制职责：
当前入口与已确认能力；未知项：
场景/生成段顺序、主时间与本地时长：
角色、道具、空间与声音的当前状态：
已完成且检查过的方案/段/镜：
已提交真实生成任务及状态/结果链接：
上一完成段的实际末态或尚未生成的计划末态：
当前具体问题与受影响范围：
下一步与承接所需信息：
本次检查范围（文本/连续画面/抽帧/声音）：
```

不适用字段可省略。恢复时先确认用户有没有新修改、状态卡与实际素材是否一致，再从依赖成立的位置继续。旧记录是恢复线索，当前用户的新指令和实际生成证据优先。
