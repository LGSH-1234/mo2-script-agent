# 视频本地化（Video Localization）

把一段源视频改造成目标地区 / 语言的版本。**最高原则：只改用户明确点名要改的东西
（语言、人物、字幕），其余一切——画面、构图、动作、表情、手势、环境、时长、节奏、音乐、
音效——全部原样保留。** 任何超出用户明确要求的改动都是错误。

工作语言：与用户一致（用户中文则全程中文）。

---

## 需要用到的工具与资源

- `marketing_video_analysis`：解析视频内容（镜头、时间轴、人物、逐句台词及起止时间）。
- `scripts/video_splitter.py`：**内置视频切分工具**，第 4 步按分段表把源视频切成片段。
- `sandbox_generate_video`：视频生成 / 编辑工具。按画面实际内容灵活组装的提示词，逐段生成本地化片段（人物替换 + 台词替换 + 口型同步）。该工具支持用 `ModelName` 参数指定生成模型。**只有在用户同意 / 要求使用某个模型之后，才传入 `ModelName`；用户未表态时不要传，让工具走它自己的默认模型。** 需要传时按第 3 步的枚举对照表取值（如 Seedance 2.5 传 `seedance_2.5`）——偶尔用户选定的模型并非默认模型，届时显式传入以锁定其选择。
- 字幕擦除 / 视频修复（inpaint）工具：第 5.4 步逐段抹除画面里烧录的原字幕。**擦除失败即视为工具异常，须停下来提示用户，不得带着未擦净的字幕继续。**
- 视频合并工具：把处理后的片段按序无缝拼回一整条即可。**本流程最终交付无字幕版本,合并阶段不再挂载 / 烧录任何目标语种字幕**（见第 6 步）。
- `dynamic_questionnaire`：**动态表单确认工具**。两处必须用它：① 命中"非营销场景 / 出境人数较多（>3 人）/ 视频生成模型非 Seedance 2.5"三类风险中的任意一条时，弹问卷说明可能效果较差、请其确认是否继续（见第 0 步）；② **台词或画面里出现任何价格 / 货币金额、或 US 鞋码 / 服饰数字码时，必须弹问卷确认如何处置（见第 5.2.1 步）——定价与上架码段都是商业决策，不得自行折算后直接使用。**
- `references/segmentation_guide.md`：分段规则。分段前**必须先读**。
- `scripts/speech_rate_evaluator.py`：语速评估 + 目标语言译文长度预算。翻译每句台词时使用。
- `scripts/unit_localizer.py`：**货币与计量单位本地化换算助手**。翻译台词时用它扫描价格、英制单位、华氏温度、US 尺码（见第 5.2.1 步）。**A 类（长度/重量/容量/温度/日期）结果可直接采用；B 类（价格/货币、鞋码）只给建议值，必须用 `dynamic_questionnaire` 问过用户才能写进译文。**「制式/单位未适配」是实测中最集中的扣分项之一，此脚本不可跳过。

> 若当前环境里上述某个能力以别的工具名提供，选用语义等价的工具即可，流程不变。

## 总体流程

1. 解析视频 →
2. 核对人物替换清单 →
3. 确认目标语言 + 视频生成模型 →
3.5. 风险确认（命中"非营销场景 / 出境人数 >3 / 模型非 Seedance 2.5"时，用动态问卷让用户确认一次）→
4. 读分段规则并切割 →
5. 逐段处理（提取台词 → 逐句翻译 → 生成片段 → **语言替换音频验收** → 逐段擦除原字幕）→
6. 合并片段（交付无字幕版本，不再挂载任何字幕）→
7. 交付。

下面逐步展开。**遇到信息缺口就停下来问，不要替用户脑补。**

---

### 第 1 步：解析视频

调用 `marketing_video_analysis`（传入视频地址的时候，必须传递从 `/workspace` 开始的完整路径） 解析源视频，得到：镜头/场景切分、时间轴、
**出场人物列表（含每人的肤色/种族等外貌描述）**、**逐句台词（含说话人、声源"出镜说话/画外音"、起止时间）**、
**每段每个人物的出镜形态（完整出镜/部分肢体/无人物）**、**画面字幕信息（有无字幕、字幕文字及其起止时间、位置与样式）**、画面/环境描述。
后续每一步都依赖这份解析结果，务必拿全。**特别是「出镜形态」「台词声源」「肤色/种族」这三类标注，
是第 5.3 步灵活生成编辑提示词的唯一依据——本流程的编辑模型只读这份解析文本、看不到画面，缺了标注就无法正确判断。**

---

### 第 2 步：核对人物替换清单

这一步要同时确认**两件事**，缺一不可：

1. **对应关系**：哪张图片替换哪个人物（`图片X → 人物Y`）。
2. **数量匹配**：把用户给的图片数量 / 替换项，和第 1 步解析出的出场人物数量逐一对齐。

判断分支：

- **用户没要求换人物**（只想换语言/字幕）→ 跳过人物替换，第 5 步的提示词里
  保留原人物、只替换台词语言。
- **图片与人物一一对应齐全** → 直接采用。
- **人物数量与图片对不上**（图片少于人物，或用户没说清某些人怎么办）→ **必须停下来问**：
  没有被指定替换图的那些人物，是**保持原样**还是**其他处理**？逐个确认清楚再继续，
  不要自作主张替换或忽略。

> 记住最高原则：没被点名的人物默认**保持原样**，但当"对应关系不完整"时要主动向用户确认，
> 避免把用户其实想换的人漏掉。

#### 2.1 替换图从哪来：用户提供 or AI 生成

替换图可能是**用户直接提供的图片**，也可能是**用户要求由 AI 现场生成的人物素材**。若走 AI 生成这条路，必须遵守以下两条硬性要求：

- **① 保持身份、但形象必须有明显差异（发型、服饰默认为强制不同项，但受"剧情锁定"约束）**：AI 生成的新形象要在"仍是一个可信、独立的人物"这一前提下，与**被替换的原人物拉开明显、一眼可辨的差异**。目的是让观众一眼就能看出"这个角色被换掉了"——若新形象与原人物过于接近，用户根本感觉不到替换发生，本地化就失去意义。因此**默认**有两条**硬性红线**：
  - **发型默认必须不同**：新形象的发型/发色/发质要与原人物明显区分（如原为"黑色寸头直发"→新形象改为"金色卷发"或"齐肩棕发"等），默认**绝不允许沿用相同或近似的发型**。
  - **服饰默认必须不同**：新形象的服装款式/颜色/风格要与原人物明显区分（如原为"米白色高领针织衫"→新形象改为"深色衬衫"或"亮色卫衣"等），默认**绝不允许穿相同或近似的衣服**。
  - 在此基础上，其余可见维度也应**尽量主动放大差异**（最典型的是解析里已写明的肤色 / 种族，其次是脸型五官、年龄段、体型），而不是笼统地"生成一个人"。

  **⚠️ 剧情锁定例外（优先级高于上面两条红线）**：某样物品 / 某个形象特征该不该被替换、能不能改，**必须先看它在这条营销内容 / 剧情里扮演什么角色**。**凡是承载了卖点、剧情或视觉逻辑的特征，一律锁定为"不可替换/不可修改"，必须在新形象上原样保留**——此时它不再受"必须不同"红线约束，也不允许为了"制造差异"而擅自改掉。判断口径：
  - **发型是内容主体时锁定**：营销内容本身就在讲这个角色的发型（如洗发 / 护发 / 造型 / 染发 / 蓬松顺滑等卖点，或剧情靠发型变化推进），则**发型必须原样保留**，不得按红线改发型；差异改从其他维度（肤色、脸型、服饰、年龄段等未被锁定的项）去拉开。
  - **特定服装承载卖点 / 剧情时锁定**：服装本身是内容表达的一部分（如**白色衣服用来突出产品的清洁 / 去污 / 亮白能力**、制服 / 工装体现职业身份、特定颜色贯穿剧情叙事等），则**该服装的关键属性（颜色 / 款式 / 品类）必须原样保留**，不得按红线换衣服；差异改从其他维度去拉开。
  - **同理适用于任何道具 / 配饰 / 标志性物品**：只要它是卖点或剧情的关键载体（如被演示的产品本身、剧情关键道具），就锁定原样保留。
  - 判断步骤：**先通读剧情 / 台词 / 卖点，列出"被剧情锁定、必须保留"的特征清单 → 从"可自由改变"的维度里挑至少 1~2 项去拉开明显差异**。若发型、服饰都被锁定，务必靠肤色 / 种族、脸型五官、年龄段、体型等其余维度制造"一眼可辨"的差异；若几乎所有可辨识维度都被剧情锁定、无法在保留卖点的同时拉开差异，**停下来向用户确认**该如何取舍，不要擅自破坏卖点。
- **② 人物素材图规格固定**：所有 AI 生成的人物素材图，统一要求**比例 3:4、全身图（含完整头脚、不裁切肢体）、背景纯白 / 空白（无场景、无道具、无文字）**。全身+空白背景是为了给第 5.3 步的替换编辑提供干净、完整、可自由缩放的人物参考，避免背景元素干扰或肢体缺失导致换人翻车。

**示例 case（AI 生成替换图的提示词该怎么写）**

假设第 1 步解析出的原人物为：「品牌方的女主播（女性，约 28 岁，浅肤色白人；金色长卷发、大波浪、中分刘海；瓜子脸、单眼皮，妆容精致；身材纤细；身穿米白色高领针织衫）」，用户要求把她本地化为一位**东亚年轻女性**。据此写出的生图提示词应形如：

> 生成一张人物素材图：一位东亚年轻女性，约 25 岁，浅黄肤色；**发型改为齐耳黑色短直发、无刘海（区别于原人物的金色长卷发）**；圆脸、双眼皮，淡妆；身材纤细；**服装改为亮橙色宽松卫衣配牛仔裤（区别于原人物的米白色高领针织衫）**；**全身正面站姿、比例 3:4、纯白空白背景，无任何道具、文字、水印**。

要点回看：① 肤色/种族按本地化目标改（白人→东亚）；② **发型强制不同**（金色长卷发→黑色齐耳短直发）并在提示词里点名"区别于原人物的……"；③ **服饰强制不同**（米白高领针织衫→亮橙卫衣牛仔裤）同样点名对比；④ 结尾固定规格串（全身+3:4+纯白背景+无文字）。用户给出别的目标形象时，按同样套路逐项改写即可。

**示例 case 2（剧情锁定特征时，该保留就保留）**

沿用上面的女主播，但假设这条内容是**洗护发广告**，卖点就是她那头"蓬松顺滑的金色长卷发"；同时她穿的**白色上衣是为了突出产品把衣服洗得洁白如新的去污力**。此时发型和白色上衣都被剧情锁定，生图提示词应形如：

> 生成一张人物素材图：一位东亚年轻女性，约 25 岁，浅黄肤色；圆脸、双眼皮，淡妆；身材纤细；**发型原样保留原人物的金色长卷发、大波浪、中分刘海（这是本片洗护发卖点的核心，不得改动）**；**上衣原样保留原人物的白色款式（用于突出产品去污 / 亮白能力，颜色与品类不得改动）**；差异改从肤色 / 种族（白人→东亚）与脸型五官上拉开；**全身正面站姿、比例 3:4、纯白空白背景，无任何道具、文字、水印**。

要点回看：① 先判断"发型 = 卖点、白衣 = 卖点"→ 两项都锁定、原样保留，并在提示词里点明"不得改动"的原因；② 差异改从**未被锁定的维度**（肤色 / 种族、脸型）去拉开，仍保证"一眼可辨是换了人"；③ 结尾固定规格串照旧。**核心口径：先看剧情决定哪些能改、哪些必须留，再去制造差异——绝不为了"必须不同"而牺牲卖点。**

### 第 3 步：确认目标语言 + 视频生成模型

1. **目标语言**：转成什么语言（英语？日语？还是多语言各出一版？）——**没说清就咨询一次再往下走，不要默认**。
   目标语言 code 参照 `speech_rate_evaluator.py` 支持的列表，当前覆盖 **21 个语种**：
   zh 中文 / en 英语 / ja 日语 / ko 韩语 / es 西班牙语 / fr 法语 / de 德语 / pt 葡萄牙语 / it 意大利语 / ru 俄语 / id 印尼语 / th 泰语 / vi 越南语 / ar 阿拉伯语 / tr 土耳其语 / pl 波兰语 / ur 乌尔都语 / hi 印地语 / tl 他加禄语 / ms 马来语 / nl 荷兰语。
   传参可用 code、中文名或英文名（"印度尼西亚语""俄罗斯语""菲律宾语"等常见别名均已收录）；**也可直接传目标地域名**（如 `--lang 墨西哥` → 自动按西班牙语计算，`--lang 巴西` → 葡萄牙语）。若脚本报"未知目标语言"，它会列出全部受支持语种，按提示改传即可，**不要跳过语速评估直接凭感觉翻译**。
   ⚠️ **注意区分"语言"与"地域"**：地域只用于推断语言和决定口音，**同一语言的不同地域必须在提示词里单独交代口音**（如墨西哥 vs 西班牙同为 es，但口音要求不同；巴西 vs 葡萄牙同为 pt 亦然）。
2. **视频生成模型**：用哪个模型跑第 5 步的生成——这直接决定**每个片段的最大长度**，也决定第 5 步调用 `sandbox_generate_video` 时**是否**传 `ModelName` 参数：

   分段上限（本流程已知的两档）：

   | 生成模型 | 单段最大长度 |
   | --- | --- |
   | Seedance 2.0 | 15 秒 |
   | Seedance 2.5 | 30 秒 |

   `sandbox_generate_video` 的 `ModelName` 可选枚举（需要传时按此对照取值）：

   | `ModelName` 传值 | 模型 |
   | --- | --- |
   | `seedance_2.5` | Seedance 2.5 |
   | `seedance2.0_fast` | Seedance 2.0 Fast VIP |
   | `seedance2.0_vision` | Seedance 2.0 VIP |
   | `seedance_2.0_mini_lite` | Seedance 2.0 Mini 体验版 |
   | `seedance_2.0_mini` | Seedance 2.0 Mini |
   | `MiniMax-H3` | MiniMax H3 |
   | `wan3.0` | Wan 3.0 |

   - **用户没指定模型时**：分段（第 4 步）默认按 Seedance 2.5 的 30 秒上限规划，无需追问；但第 5 步调用 `sandbox_generate_video` 时**不要传 `ModelName`**，让工具走它自己的默认模型。
   - **用户同意 / 要求某个模型时**：按该模型的上限分段（上限不在上表两档内的模型，向用户确认其单段时长上限），并在第 5 步调用时用 `ModelName` 传入上面对照表里对应的枚举（如用户选定 Seedance 2.5 就传 `seedance_2.5`，用以锁定用户的选择——因为工具自身默认偶尔并非 2.5）。
   
   模型选择必须在分段（第 4 步）之前定下来，否则无法确定切割上限。默认按 2.5 的更大上限规划，也有利于把片段做长、减少生成调用（见第 4 步）。**`ModelName` 只有在用户同意 / 要求后才传入，其余情况不传。**

### 第 3.5 步：风险确认（动态问卷）

**在开始分段与生成之前，先做一次风险自查。** 本流程是为「营销视频、少量出镜人物、用 Seedance 2.5 生成」这一主场景调优的；一旦偏离，本地化效果可能明显变差。因此**只要命中下列任意一条风险，就必须用 `dynamic_questionnaire` 弹出一次动态问卷让用户确认，用户确认继续后才往下走**：

- **① 非营销场景**：源视频不是营销 / 广告 / 带货类内容（如纯剧情片、教学、纪录、访谈等）。
- **② 出境人数较多**：第 1 步解析出的出场人物数量 **大于 3 人**（>3）。
- **③ 生成模型非 Seedance 2.5**：第 3 步确定的视频生成模型不是 Seedance 2.5（如 Seedance 2.0 或其它模型）。

**问卷内容要求**（保持简洁，只需一次确认）：

- 明确列出本次命中的具体风险项（哪条命中就写哪条，可多条同时命中）：
  - 非营销场景 → 说明"当前为非营销场景，本地化效果可能较差"；
  - 出境人数 >3 → 说明"当前出境人数较多（实际 N 人），人物替换的准确性与一致性可能较差"；
  - 模型非 Seedance 2.5 → 说明"当前使用的生成模型为 {模型名}、非 Seedance 2.5，生成效果 / 单段时长上限可能较差"。
- 问卷末尾给出一个明确的确认选项：**"是否继续？"**（继续 / 取消）。

**处理规则**：

- **三条都不命中**（营销场景 + 出境 ≤3 人 + 模型为 Seedance 2.5）→ **跳过本步，不弹问卷**，直接进入第 4 步。
- **命中任意一条或多条** → 调用 `dynamic_questionnaire` 弹一次问卷，把命中的风险项与"可能导致效果较差"如实告知用户：
  - 用户**确认继续** → 照常进入第 4 步，按既定流程执行；
  - 用户**选择取消 / 不继续** → 停在此处，不再往下生成，等待用户进一步指示（如换成营销素材、减少出境人物、改用 Seedance 2.5 等）。
- 本问卷**每次本地化任务只需确认一次**，确认后不再就同一风险重复弹出。

### 第 4 步：读分段规则并切割视频

1. 读 `references/segmentation_guide.md`，理解两条铁律、切分优先级与硬约束。
2. 依据第 1 步的解析结果，按该规则产出**分段表**（JSON，格式见规则文件末尾），
   并在表里写入所选模型与其上限（`generation_model` / `max_segment_seconds`）。
   要点回顾（**核心目标：分段越少越好、Seedance 调用越少越好**）：
   - **默认整段**：先把整条视频当作"一整段"，能一段直出就绝不拆。**"场景 / 镜头切换 / 景别变化"本身不是切的理由**——只要多个镜头连起来是一段完整演绎、没把任何台词或连续动作卡在中间，就保留为同一段。镜头切换点只是"万一要切时的最佳落刀点"，不是"必须在此切"。
   - **最高铁律：台词完整**——**绝不在一句台词内部切断**，宁可片段偏长也不切断台词。
   - **次高：片段最大长度是"软上限"**——单段尽量不超过所选模型上限（Seedance 2.0=15s / 2.5=30s）；但**只超出极小幅度（最多 0.1 秒，绝不允许超过 0.1 秒，如 15s 上限对 15.1s）时先按单段尝试一次直出，Seedance 因时长报错了再回头拆**，不做预防性拆段；超出 0.1 秒则在分段阶段就拆。两者冲突时长度让位于台词完整。
   - **唯一的切分理由：整段明显超上限（超出容差）且无法一次生成。** 除此之外一律保持整段。
     **【禁止】不得以"有无对白 / 有无台词"作为分段依据或切点**——段内的空镜、纯产品展示、片头片尾、说话间隙的静默等,
     哪怕成规模,也**绝不能因此单独摘成一段**,它只应留在所属整段里随整段一起处理。确需切时，切点落在镜头切换 / 说话人间隙 / 句间停顿处；相邻片段首尾相接、无空隙无重叠；**单段不得低于 4 秒**（不足则与相邻片段合并，但不切断台词）——**绝不允许把低于 4 秒的片段单独送视频生成工具**；单句本身超上限则整段略超并标 `over_limit`；确需拆分时也拆成**尽量少**的段数（能两段绝不三段）。
   - **`has_dialogue` 只是"要不要翻译/配音"的标记，既不是切分理由、也不单独决定要不要换人**：因时长被切出来的段若通篇无对白，标 `has_dialogue=false`；但这**不允许你为了摘无对白内容而额外切段**，也**不意味着该段就能原样透传**——只要该段里仍有被要求替换的人物/道具出镜，照样要送 Seedance 换人（是否透传见第 5 步★判据）。无对白段落也要保序、不漏，否则合并会缺片。
3. **切割前先判断要不要切**：
   - **整条视频就是一段（`segments` 只有 1 项，即 start=0、end=总时长）→ 跳过切割,直接把原视频文件当作该段素材**。此时切割没有任何意义（切出来就是原片本身），还会平白多一次重编码、徒增画质损耗与耗时。这也是"分段越少越好"最理想的情形。
   - **只有分成多段时,才把分段表交给内置切分脚本** `scripts/video_splitter.py`,将源视频切成对应片段文件：

   ```bash
   python3 scripts/video_splitter.py split \
       --video /workspace/xxx/source.mp4 \
       --plan  /workspace/xxx/segments.json \
       --outdir /workspace/xxx/segments
   ```

   - 脚本默认**精确重编码**切分（帧级精确、片段干净，直接可喂生成模型）；输出 `seg_{index:03d}.mp4`（H.264+AAC），并打印结果 JSON，逐段给出「期望时长 / 实际时长 / 是否达标」与 `all_ok`。
   - **务必核对返回 JSON 的 `all_ok=true`**；若某段 `ok=false`，检查该段 start/end 与源时长再重切。
   - 极少数只需无损快切的场景可加 `--copy`（流拷贝、极快），但切点会吸附到最近关键帧、可能有零点几秒偏差，**默认不要用**——喂生成模型一律用默认的重编码模式。
   - 底层 ffmpeg 由脚本自动处理：**优先复用环境里已有的 ffmpeg，没有才自动装一次 imageio-ffmpeg**，你**无需手动安装、也不要**改用其它分割工具。

### 第 5 步：逐一处理每个片段

对分段表里的每个片段，按顺序执行。

> **★ 关键判据:一段要不要送 Seedance,看的是"这段里有没有需要改的东西",不是"有没有对白"。**
> "需要改的东西"= ①有要翻译/配音的台词，**或** ②有被用户要求替换的人物 / 道具在这段**出镜**（依据分析文本里该段的「出镜形态」判断——完整出镜、部分肢体都算出镜）。
> - **只要满足 ① 或 ② 任一 → 必须送 Seedance 处理**（有台词就配、有待替换对象就换）。
>   **特别注意:一段"无对白"（`has_dialogue=false`）但待替换人物仍在画面里(哪怕只是站着不说话) → 依然要送 Seedance 换人**，否则成片里这个人会一会儿是新形象、一会儿变回原样,前后穿帮。
> - **只有 ① ② 都不满足**（既无台词、也没有任何待替换的人物 / 道具出镜,如纯空镜、纯环境镜头、或不涉及替换的产品特写）→ 才**原样透传、不调用 Seedance**。
> - **`has_dialogue` 字段只决定"要不要翻译 / 配音（走 5.1~5.2）"，绝不能单独用它决定"要不要送 Seedance / 要不要换人"。** 换人与否由「出镜形态」+ 用户的人物替换清单共同决定。

**无对白且无任何待替换对象出镜的片段**：不翻译、不替换，原样保留待合并。**无对白但有待替换人物 / 道具出镜的片段**：跳过 5.1~5.2 的翻译，但仍要走 5.3 组装"只换人 / 换物、不动台词（本段无台词）"的编辑提示词送 Seedance。**有对白的片段**：完整走 5.1~5.3。

#### 5.0 音色锚定：多段先生成音色参考，单段直接交给 Seedance

**在逐段处理之前先做一次判断：本次本地化最终会不会分成多段送 Seedance？** 分段来源有两种——① 一开始按 `segmentation_guide.md` 就切成了多段；② 5.3 生成时因时长超限被迫拆段。**只要同一个说话人的配音会落在两段及以上里,就必须先锚定音色**,否则各段各配各的,同一个人在成片里会一段一个嗓音,前后穿帮。

- **多段(≥2 段含同一说话人配音）→ 先生成"音色参考",再作为后续统一输入**：
  1. **在处理任何片段之前**,先为该说话人生成一份**音色参考**(一小段目标语言的参考配音),其性别、年龄段、音色气质与原人物一致,且**符合第 3 步确定的目标地域口音**(见 5.3 ③ 的口音要求)。
  2. 后续每一段的 Seedance 生成,都把这份音色参考**作为统一的音色锚点一并传入**,要求"新配音的音色 / 音质 / 口音与该音色参考保持一致",让所有片段共用同一把嗓子。
  3. 有多个说话人时,**每个跨段出现的说话人各自生成一份音色参考**,分别锚定,互不混用。
- **单段(全部配音都在同一段里)→ 不必单独生成音色参考**,该段本来就一次生成、音色天然自洽,**直接按 5.3 组装提示词交给 Seedance 即可**,不要多此一举去做音色参考。

> 判断口径:音色参考解决的是"跨段音色不一致"问题。段数以**实际送 Seedance 的片段数**为准;若一开始规划为单段、5.3 才因时长报错被迫拆成多段,则在拆段那一刻补做音色参考,再对拆出的各段统一锚定。

#### 5.1 提取台词（保持逐句列表，不要合并）

从该片段的 `lines` 里取出**每一句**台词，连同其说话人与时长。
保持列表结构——每句要单独评估、单独翻译，**不要把多句拼成一段**。

#### 5.2 逐句翻译（语速 + 语种 + 时间三者对齐）

对每一句台词：

1. **评估源语速**：用脚本判断这句是慢/正常/快。

   ```bash
   python3 scripts/speech_rate_evaluator.py evaluate --text "台词原文" --duration 该句时长秒
   ```

2. **拿到译文长度预算**：把时长 + 语速档位 + 目标语言喂给脚本，得到译文该有多长
   （英语给词数、日语给拍数等）以及舒适区间。可用 `plan` 一步到位：

   ```bash
   python3 scripts/speech_rate_evaluator.py plan --text "台词原文" --duration 该句时长秒 --lang en
   ```

3. **按预算翻译**：把这句译成目标语言，使**译文长度落在脚本给出的舒适区间内**。
   这样既不会因为太长而"说不完"或被迫赶话，也不会因为太短而留下长时间停顿。
   **信息可以合理扩充或精简**——不必逐字对译，只需保证含义传达正确、自然口语化、
   符合目标地区表达习惯。语速快的句子往往需要更凝练的译法，语速慢的可以更从容。

4. **按 5.2.1 做货币与计量单位本地化换算**（凡台词或画面里出现价格、尺寸、重量、容量、温度、尺码时，此步不可跳过）。

产出：该片段每个说话人、每一句的译文（保持"人物 → 有序台词列表"的结构）。

#### 5.2.1 货币与计量单位本地化换算（**高频扣分项，必做**）

**翻译语言 ≠ 本地化。** 把 `$39.99` 直接念成 `39,99`、把 `$70` 译成 `70 dólares` 卖给墨西哥观众、把英寸和磅原样搬进德语版，都属于**制式/单位未适配**——这是实际评测中最集中的失败类型之一，一旦出现，本地化质量分会被直接判到最低档。

**★ 但两类量值的处置权限完全不同，绝不可混为一谈：**

| | 类别 | 处置方式 |
| --- | --- | --- |
| **A 类：客观换算** | 长度 / 重量 / 容量 / 温度 / 日期格式 | **自行换算、无需询问**。这些是物理量的等价转换，只有算对算错，没有决策空间 |
| **B 类：商业决策** | **价格与货币**、**鞋码 / 服饰尺码** | **必须先问用户，不得自行决定**。价格：汇率取哪天的、要不要取整成心理价位、当地是否本来就有另一套定价、是否干脆保留原币种，都只有业务方知道。鞋码：各品牌自有码表（同一 US 码在不同品牌可能差半号到一号），且"该商品在当地实际上架哪几个码"属业务信息 |

**A 类：直接用脚本换算**

| 类别 | 换算要求 |
| --- | --- |
| **长度 / 尺寸** | 英寸 inch/"、英尺 ft、码 yard → 公制市场换 cm / m；美国 / 英国等英制市场保留 |
| **重量** | 磅 lb、盎司 oz → kg / g。**必须用脚本算**——实测出现过「4磅→2磅」错案（4 lb ≈ 1.8 kg） |
| **容量** | 液量盎司 fl oz、加仑 gallon → ml / L |
| **温度** | 华氏 °F → 摄氏 °C（公制市场） |
| **日期格式** | 美式 MM/DD → 欧陆 DD.MM 等当地书写习惯 |

```bash
# 扫描台词，揪出所有需要本地化的量值（含 A 类与 B 类），并给出换算建议
python3 scripts/unit_localizer.py scan --text "12 pack, only \$39.99. Fits 10.5 inch, 4 lb." --region 墨西哥

# 单个 A 类数值换算
python3 scripts/unit_localizer.py convert --value 4 --unit lb --region 德国   # → 1.8 kg

# 查看支持的地域 / 单位
python3 scripts/unit_localizer.py info
```

脚本对巴西 BR 码、日本 JP 码等非 EU 码制市场会附额外提示（这类码制与 EU 码非线性对应）。

**B 类：价格与鞋码必须走问卷确认，禁止自行闭环**

**只要台词或画面里出现任何价格 / 货币金额、或 US 鞋码 / 服饰数字码，就必须用 `dynamic_questionnaire` 弹一次问卷向用户确认后再翻译，不允许直接把折算结果写进译文。** 原因：

- **价格**：脚本内置的汇率只是**粗略参考值**（会随市场变动），取整规则也只是"看起来像本地标价"的经验做法；而真实售价涉及定价策略、税费、当地渠道价，**agent 无权代替业务方决定一个商品在另一个市场卖多少钱**。
- **鞋码 / 尺码**：**各品牌自有码表**，同一 US 码在不同品牌可能差半号到一号；且"该商品在当地实际上架哪几个码"是业务信息；巴西 BR、日本 JP（厘米制）、韩国 KR（毫米制）与 EU 码并非线性对应。**说错码数会直接导致消费者买错尺寸退货**，比说错价格更难挽回。

静默编一个数字写进广告片，是把不确定的商业信息伪装成既定事实。

**流程：**

1. **先跑脚本拿到建议值**（不要跳过，问卷里要给用户具体数字做参考）：

   ```bash
   python3 scripts/unit_localizer.py convert --value 39.99 --unit usd --region 墨西哥
   # → 建议 740 MXN / 口播 740 pesos（原始折算值 739.82，带 decision_required=True）

   python3 scripts/unit_localizer.py convert --value 8 --unit us --region 德国 --kind shoe
   # → 建议 EU 38.5（女鞋；男鞋加 --gender men）
   ```

2. **用 `dynamic_questionnaire` 弹问卷**，把下列信息如实摆给用户，**一次问清全片所有价格与尺码**（不要一个数字问一轮）：

   - **原片数值原文**（如 `$39.99`、`$70`、`US 8`）及其出现的句子；
   - **脚本给出的建议值**，并明确标注其不确定性——价格标"汇率为内置粗略参考值、非实时"，鞋码标"各品牌码表有差异"；
   - **请用户选择处置方式**：

   | 类别 | 选项 |
   | --- | --- |
   | **价格** | ① 采用建议折算值 ② **我提供目标市场的实际售价**（最推荐）③ 保留原币种不换算（跨境购买场景 / 确实以美元结算）④ 去掉具体价格（改用"超值价""特惠"等说法） |
   | **鞋码** | ① 采用建议对照值 ② **我提供当地实际上架码**（最推荐）③ 保留原码制但注明制式（口播说"US 8 码"而非裸说"8 码"，避免被听成当地码）④ 不提具体码数（改说"多码可选"等） |

3. **严格按用户的回答执行**：
   - 用户选 ② → 用用户给的数字，**不要再套脚本的取整 / 对照规则去改动它**；
   - 用户选 ① → 采用建议值，并在交付说明注明口径（价格注明汇率、鞋码注明按通用对照表）；
   - 用户选 ③ → 保留原制式，此时**不算"未适配"**（是用户明确决定的），但仍要在交付说明写明；**鞋码选 ③ 时务必在译文里保留"US"字样**；
   - 用户选 ④ → 译文里不出现具体数值；
   - **用户未回答 / 问卷被取消 → 不要擅自替他选一个**。此时应保留原数值原文并**明确告知用户"价格 / 尺码未做本地化，需确认后再定稿"**，不得静默编数字。

4. **本问卷每次本地化任务只需问一次**（一次覆盖全片所有金额与尺码），确认后不再重复弹。

> 若第 3.5 步的风险问卷尚未弹出，可**把价格 / 尺码确认合并进那一次问卷**，避免连续打扰用户；若风险问卷已经弹过，则单独再弹一次。

**换算后的三条通用口径（A / B 类都适用）**

1. **敲定数值后要回过头重跑长度预算**：数字念法变长会改变时长（`setecientos cuarenta pesos` 比 `39,99` 长得多）。**必须用 `speech_rate_evaluator.py plan` 重新核对该句是否仍落在舒适区间**，超了就精简句子其余部分，不要靠赶语速硬塞。
2. **数字必须写成目标语言的口语形式交给模型**：Seedance 是念出来的，阿拉伯数字容易被按源语言或错误语种读。**台词里的价格、尺寸建议直接写成目标语言的拼写数字**（西语 `setecientos cuarenta pesos`），或至少确保数字与币种紧邻且语种标注明确。
3. **币种名用当地口语说法**：墨西哥说 pesos、巴西说 reais、德国说 Euro，不要一律说 dollars。

**⚠️ 例外——不要为了换算而破坏事实或卖点：**

- **画面里烧录/印在包装上的数字不可改**：若价格、规格是**印在产品包装、贴纸、价签上的实拍画面**，口播可以按用户确认的结果调整，但不得要求模型去改画面上的实物文字（那会破坏产品真实性）。此时**在交付说明里注明"画面实物标价仍为原币种"**。
- **产品规格型号不是计量单位**：型号名里的数字（如 `iPhone 15`、`50x60` 是产品品名的一部分）、法定标称容量（如注册商品名含 `500ml`）**原样保留**，不要"换算"、也不需要问用户。判断口径：**这个数字是"消费者要理解的量"还是"产品的名字"**——是量就处理，是名字就保留。

**自检**：本片段所有台词过一遍——A 类（`inch`/`lb`/`oz`/`°F`/日期格式）是否都已换成目标市场量值？B 类（`$`/`£`/任何金额、`US 8` 等尺码）是否**都经用户问卷确认过**、而不是自己拍的数字？有没有"墨西哥版仍在说美元""德语版仍在说英寸""直接把 US 码当当地码念出来"这类未经确认的残留？

#### 5.3 组装本片段的编辑提示词（按解析文本组装，不套死模板）

**本流程的编辑模型只读第 1 步的解析文本、看不到画面。** 所以不能凭空假设"画面里有个完整的人"，
一切判断都从解析文本里现成的标注来：**该段每个人物的「出镜形态」、每句台词的「声源」、人物列表里的「肤色/种族」等描述。**
死模板会在很多情况下翻车：解析明明写了"仅双手入镜"，模板却还写"将原有的人物A替换为……"；把白人换成黑人时只笼统说"保持一致"，
却没抓住解析里已经写明的肤色差异；解析已标"画外音"，模板却还用"某人的第几句台词"去绑定一个不在画面里的人。
因此本步**不给死模板**，而是教你按解析文本**现场组装**提示词。

**★ 核心铁律：提示词里禁止用"角色 / 人物X / 某人 / 第几个人"等代号指人，必须用「画面位置 + 外观特征 + 性别」的具体定位来指认。**
编辑模型看不到画面、也不认识"人物A""角色""某人"这类抽象代号——这些词无法在画面里定位到唯一的对象，模型只能靠猜，极易**替换错人、张冠李戴、或把两个人混为一个**。所以凡是要指认画面中的某个人（无论是"要被替换的人"还是"要绑定台词的人"），**一律不许写成"角色/人物A/某人"，必须改写成一句能唯一定位到 TA 的具体指称**。

定位三要素（按解析文本能拿到的信息尽量写全，让"指的是谁"唯一确定）：
- **画面位置**：此人**首次出现时**在画面中的方位 / 占位，如"画面左侧""站在最前面的""靠窗那位"。**⚠️ 位置 / 姿态只用来"第一次把人认出来"，绝不能写成替换的"条件"**：像"坐在椅子上的那位小男孩""正在递水的那只手"这类**带瞬时姿态 / 动作**的指称，会让模型误以为"只有保持这个姿态时才替换"——一旦人物起身、离开椅子、换个动作，模型就当成"不是同一个人"而停止替换，导致同一角色一会儿是新形象、一会儿变回原样。**因此定位优先靠"外观特征"（跨镜头稳定），位置 / 姿态最多作辅助,且要表述成"就是那个人本身"而非"处于某姿态时才算"。**
- **外观特征**：解析里已写明的可辨识特征——肤色 / 种族、发色 / 发型、服饰颜色与款式、体型、年龄段等。**这是跨镜头唯一稳定的锚,应作为主指称。**
- **性别**：男性 / 女性。

三要素组合成一句无歧义的指称，例如"画面左侧那位穿白衬衫的浅肤色男性""坐在右边、扎马尾的女性"。同理，替换图也**不要写成"@图片N 中的角色"**，写成"@图片N 中的人物形象"或直接"@图片N"。信息不足以三项写全时，至少写"位置 + 一个最显著的外观特征 + 性别"，务必保证唯一可定位。

一条编辑提示词由三块拼成，每块都要**先查解析文本里本片段对应的标注**再决定怎么写：

> 起手固定为 `对@视频1进行编辑：`，随后依次拼接【人物/画面替换块】【台词替换块】【保真约束块】。`@视频1` 指向当前片段，`@图片N` 指向第 2 步替换清单里对应的替换图。**指认画面中的人时一律用「位置+外观+性别」的具体定位，禁止用"角色/人物A/某人"代号（见上文核心铁律）。**

**① 看解析里的「出镜形态」标注——决定人物替换块怎么写，甚至写不写**

| 解析标注的出镜形态 | 人物替换块的写法 |
| --- | --- |
| **（完整出镜）** | 用「位置+外观+性别」定位到要换的那个人再下指令，如"将画面左侧那位浅肤色白人男性替换为@图片N中的人物形象"，并按 ② 点明关键差异；**不要写成"将人物A替换为角色"** |
| **（部分肢体：某部位）** | **不要写成替换整个人**，只针对解析写明的那个部位下指令，并用位置定位该部位，如解析写"仅双手入镜"→"将画面中央出镜的这双手替换为@图片N人物的手，肤色与之一致"；解析没提到的部位一概不写 |
| **（无人物画面：…）** 或某替换图人物本段未出镜 | **不写人物替换块**，跳过，只处理台词（见 ③ 画外音写法） |

**② 人物替换块：按解析里的「可见差异」强调，别只说"保持一致"**

"保持一致"太空，模型不知道该盯哪里。做法是**拿解析里的原人物描述与替换图对比，挑出变化最明显、最该锁定的属性**写进提示词。
最常用的就是解析已显式写出的**肤色 / 种族**（如原人物写"浅肤色白人"、替换图是黑人 → 明确写"肤色替换为深肤色"），
其次是发色 / 发型、性别、年龄段、体型胖瘦、标志性服饰 / 配饰。

原则：**只强调解析里本段看得见（出镜形态覆盖到）、且本次替换真的会变的那几项**——"仅双手入镜"就只提手部肤色与形态，不提发型脸型；
完整出镜才提五官 / 发型。变化不明显的属性不必赘述。

**③ 台词替换块：按解析里的「声源」标注选表述**

**⚠️ 先看三条硬性写法要求（不遵守极易出现"语言没换掉"）：**

- **A. 台词一律用花括号 `{}` 包裹**：这是 Seedance 识别"这段文字是要念出来的台词"的专用符号（音乐用 `（）`、音效用 `<>`、字幕用 `【】`）。译文不加 `{}` 时，模型可能把它当成场景描述而不是要配的音。
- **B. 非中英文的目标语言，必须在台词前显式标注语种**：写成"用马来语说道{…}""用日语说道{…}"。**这是官方明确要求：台词为小语种（非中英文）时必须标注语种。** 只给一串马来语 / 泰语 / 越南语文本而不写语种，模型可能按别的语种（甚至原语种）发音，这是"语言没换掉 / 念成别的语言"的高频原因。目标语言为英语时也建议写"用英语说道"。
- **C. 必须明确点出"原语言 → 目标语言"的替换关系**：写成"将原葡萄牙语的画外音旁白，替换为如下马来语旁白"。**只写"替换为{译文}"而不点明原语种被弃用，模型容易保留原音轨、或做成双语叠加。**

| 解析标注的声源 | 写法 | 是否要口型同步 |
| --- | --- | --- |
| **出镜说话** | 绑定到说话人，但**用「位置+外观+性别」定位这个人，禁止写"人物A/某人"**："将画面左侧那位穿白衬衫的男性所说的原中文台词全部替换为{目标语言}台词：第一句用{目标语言}说道{译文1}，第二句用{目标语言}说道{译文2}……" | **要**，写"口型与新台词匹配" |
| **画外音** | **不要绑定到某个人、不要用"某人的第几句"**；直接对音轨下指令："将原{原语言}的画外音旁白整条替换为{目标语言}旁白：第一句用{目标语言}说道{译文1}，第二句用{目标语言}说道{译文2}；原{原语言}人声不再出现" | **不要**提口型 |
| 一段里既有出镜对白又有画外音 | 两种写法各写各的，互不混淆 | 仅对出镜部分要求口型 |
| **本段无任何台词**（`has_dialogue=false`，但因有待替换人物出镜仍需送 Seedance） | **不写台词替换块**，明确写"本段无台词，仅替换人物形象、不改动任何配音 / 声音" | **不要**提口型（画面里没有说话的脸） |

台词顺序始终与原片一致；内容用 5.2 的译文。**同一条提示词里台词语言必须统一，不要中外混用**（专有名词除外）。若译文含多音字 / 生僻字导致发音不准，可换成同音常用字规避。

**★ 台词替换块必须交代「怎么念」——按 5.0 的单段 / 多段判定二选一,不要两种都写**:替换台词时不能只给译文、放任模型用"标准 / 无地域"发音。具体写法取决于 5.0 是否已生成音色参考:

- **单段场景(5.0 判定无需音色参考)→ 直接向 Seedance 提口音要求**:在台词替换指令后紧跟一句口音约束,例如"新配音须为地道的{目标地域}口音、发音与语调符合当地母语者习惯"。口音跟随第 3 步确定的目标语言 / 地域(英语→美式 / 英式 / 印度英语等;日语→日本本土口音;西语→西班牙 / 拉美等);目标地域不明确时取该语言最通用的主流口音,并在与用户确认目标语言时一并问清地域。
- **多段场景(5.0 已生成音色参考)→ 只传音色参考、不再单独写口音句**:本段台词替换指令里把 5.0 的音色参考一并传入,要求"新配音的音色 / 音质 / 口音与该音色参考保持一致"。**因为口音已经固化在音色参考里,此时不要再重复写"新配音须为地道的{目标地域}口音……",避免与参考音频冲突、也避免各段口音表述不一致**——口音统一由音色参考带过来即可。
- **出镜说话与画外音同等适用**:两类台词都按上面的单 / 多段分支处理;区别只在出镜说话额外要口型同步,画外音不提口型。
- **只约束"怎么念"、不改译文含义**:无论走哪个分支,都不改变 5.2 已定稿的译文文字。

**④ 保真约束块（每段都要，务必强调，不能省）**

这一块是"只改该改的"的技术保证。

> **⚠️ 写法铁律（最容易翻车、必须严格遵守）：保真约束块必须写成「先正面列出本次允许修改的内容清单 → 再用『除上述指定修改项外，其余内容保持不变』收口」。**
> **严禁**写成"本次编辑只替换人物本身，除人物外的一切都必须与原视频严格保持一致"这类句式。原因：本地化任务里**「台词的语言与配音」同样是被允许修改的项**，而"只替换人物""除人物外的一切都保持一致"在字面上把**音频也划进了"不许动"的范围**，与前面的【台词替换块】直接自相矛盾。模型面对互相冲突的指令时，很可能选择保留原语言音轨——**表现就是画面换人成功、但台词语言压根没换掉**。约束块的兜底词只能是"除上述**指定修改项**外"，绝不能是"除**人物**外"。

必须写足以下几点：

- **① 允许修改清单（正面逐项列举，一项不漏）**：把本段真正要改的东西写成清单，如"本次允许修改的内容：① 出镜的手部人物形象；② 画外音旁白的语言与音色（由原葡萄牙语替换为上述马来语台词）"。
  **本段只要有台词替换，就必须把"台词的语言与配音"显式写进这份清单**——不能只写在前面的台词替换块里、指望约束块不去否定它。本段无台词时，清单里只列人物 / 道具，并另写明"不改动任何配音 / 声音"。
- **② 其余不变（用"除上述指定修改项外"收口）**：紧接着写"除上述指定修改项外，其余内容全部与原视频严格保持一致——动作、姿态、走位、手势、镜头运动、构图、背景、环境、光线、节奏、时长均不得改动、不得增删"。
- **③ 动作一致性**：单独强调替换后人物的**动作、姿态、时序与原视频逐帧一致**（这是最容易被模型擅自"优化"的地方，必须点名）。
- **④ 画面不得出现字幕/文字**：按官方约束词写法明确要求"**保持无字幕，避免生成任何文字或字幕，不要生成水印，不要生成 Logo**"——因为原字幕会在 5.4 擦除、且本流程**最终交付无字幕版本、不再补任何目标语种字幕**，生成阶段必须产出干净无字的画面。
- **⑤ 防"双胞胎"**（本段有 ≥2 人出镜时加）：写"视频全程禁止出现外形、着装完全一致的人物，禁止生成同款分身 / 双胞胎，同一画面中每个角色仅保留单个对应人物"。
- 条件项：**只有本段存在"出镜说话"的台词时**才加"面部表情、手势与新台词口型匹配"；**纯画外音 / 无人物段落不要写口型和面部表情约束**——画面里没有说话的脸，硬加反而诱导模型乱改。

**⑤ 当一个 Seedance 片段内部含多个镜头 / 场景、且同一人物跨镜头换了姿态动作 → 必须用「分场景结构」逐场景重新锚定同一人物**

一次 Seedance 生成的片段里,常常包含好几个连续镜头(如:坐在安全座椅里 → 从车上下来 → 背着书包走向学校),同一个待替换人物在不同镜头里**姿态、动作、景别都在变**。若只在开头用一句"坐在椅子上的那位小男孩"下指令,模型极易把替换理解成"仅在他坐着时才换",人物一起身 / 离开椅子就恢复原样,造成前后穿帮。**解决办法:把提示词写成"分场景 / 分镜头"的结构,按时间顺序逐段列出,每个场景都重新点名同一人物(靠稳定的外观特征锚定),并描述该场景里他此刻的动作,让模型明白"是同一个人贯穿始终、每个镜头都要替换"。**

写法要点:
- **开头交代整体**:一句说明这是什么视频、总时长、"分为多个场景,按以下顺序逐段编辑"。
- **逐场景分块**:用 `【场景N,起止秒】` 起头,块内写明该场景里该人物**此刻的动作 + 稳定外观特征**(而非用姿态当替换条件),并指向同一张 `@图片N`。**首次出现的场景**写全"原→新"的差异对照(按 ② 的关键差异);**后续场景**只需点名"同一位{外观特征}的人物(已替换为@图片N形象),此刻正在{当前动作},完整出镜"即可,不必重复全部差异。
- **每个场景各自处理本场景的台词 / 声源**(按 ③),无台词的场景写明"本段无台词,仅替换人物形象"。
- **保真约束块只在结尾写一次**,统管所有场景。
- 单镜头、人物姿态不变的简单片段**不必**套这套结构,按前面 ①~④ 直接写一条即可。

**组装示例（仅示范写法，实际按解析标注替换花括号内容，人物数 / 台词句数按实际增减；指人一律用「位置+外观+性别」定位，勿用角色代号）**

> **以下示例默认为「单段场景」**,故台词后直接写口音句"新配音须为地道的{目标地域}口音……"。**若为多段场景(5.0 已生成音色参考),把这句口音句替换为"新配音的音色 / 音质 / 口音与传入的音色参考保持一致",并一并传入 5.0 的音色参考,不要再写"地道的{目标地域}口音"那句**(口音已在音色参考里,重复会冲突)。

- 解析标（完整出镜）+ 原人物"浅肤色白人男性、站在画面左侧"换黑人图 + 台词标（出镜说话，原中文→目标马来语）：
  `对@视频1进行编辑：将视频中画面左侧那位浅肤色白人男性替换为@图片1中的人物形象，肤色替换为深肤色、发型与之一致；将该男性所说的原中文台词全部替换为马来语台词——第一句用马来语说道{译文1}，第二句用马来语说道{译文2}，原中文人声不再出现，新配音须为地道的{目标地域}口音、发音语调符合当地母语者习惯。本次允许修改的内容：① 该男性的人物形象；② 其台词的语言与配音。除上述指定修改项外，其余内容全部与原视频严格保持一致——替换后人物的动作、姿态与原视频逐帧一致，镜头、构图、背景、环境、光线、节奏、时长均不得改动或增删；面部表情与手势和新台词口型匹配。保持无字幕，避免生成任何文字或字幕，不要生成水印，不要生成 Logo。`
- 解析标（部分肢体：仅双手入镜）+ 台词标（画外音，原葡萄牙语→目标马来语）：

#### 5.3.1 生成后必做：语言替换验收（不验收不得往下走）

**Seedance 返回视频 ≠ 语言已经换好。** 生成模型对"替换音轨语言"的执行并不稳定，可能出现：仍是原语种、双语叠加、念错语种、只换了部分句子。**因此每个含台词的片段生成后，必须逐段做一次音频验收，通过后才能进入 5.4；不得只凭"工具调用成功"或视频画面描述就判定语言替换完成。**

验收方法（任选其一，优先第 1 种）：

1. **听写核对**：对生成片段的音轨做一次语音识别 / 转写，核对转写文本是否为目标语言、且与 5.2 定稿的译文一致（允许口语化的细微差异）。
2. 若环境无转写能力，则**如实告知用户"本段语言替换未经音频验证"**，并请用户试听确认——**不允许在未验证的情况下声称"已完成语言替换"**。

判定与处理：

- **转写为目标语言且句序、句数与译文对齐 → 通过**，进入 5.4。
- **仍为原语种 / 双语叠加 / 语种错误 / 漏句 → 不通过**。按以下顺序排查后**重跑该段**：
  1. 检查提示词是否犯了 ③ 的三条硬性写法（台词是否用 `{}` 包裹、小语种是否标了语种、是否点明"原{原语言}人声不再出现"）；
  2. 检查 ④ 保真约束块是否出现"只替换人物 / 除人物外一切保持一致"这类会**否定音频修改**的句式，若有立即改成"除上述指定修改项外"的写法；
  3. 两次修正后仍不通过 → **停下来告知用户**："当前模型在本片素材上未能稳定执行语言替换"，说明是哪几段、具体表现（如仍为原语种），等待用户指示（换模型、改用单独配音再合轨等），**不得带着未换语言的片段继续合并交付**。



#### 5.4 逐段擦除原字幕

片段生成完成后，**逐一对每个片段做一次字幕擦除**，把画面里烧录的原字幕抹掉，得到"无字幕画面"版本。**擦除完成即为该片段的最终形态——本流程不再重新挂载任何目标语种字幕（见第 6 步）。**

- **依据解析「视频字幕信息」判断该段要不要擦**：某片段的时间范围内若有字幕文字，就用**字幕擦除 / 视频修复（inpaint）工具**按其位置把字幕抹除干净；对应区间标为「字幕为「无」」的，本段没有字幕，**跳过、不做擦除**。
- **对所有片段一视同仁**：不论该片段是第 5.3 步用 Seedance 生成的、还是原样透传未送 Seedance 的，只要其时间范围内有原字幕，都要在这一步擦掉。**字幕擦除是独立于 Seedance 的操作，不消耗生成调用**，因此不影响"少调 Seedance"的原则。
- **只擦字幕、不动其他**：擦除时只去掉字幕文字，不改动画面、人物、配音等任何其他内容。
- **软字幕例外**：若原字幕是独立字幕轨（软字幕/外挂字幕）而非烧录进画面，则无需逐段擦除画面，去掉字幕轨即可（软字幕同样不再替换为目标语种字幕）。
- 若解析「视频字幕信息」表明**全片无画面内字幕**，则整个 5.4 跳过。

**⚠️ 擦除失败 = 工具异常，必须停下来提示用户，不得继续**：只要某个片段的字幕擦除**报错、返回失败、或产出的画面里字幕仍未被抹净**（残留原字幕、出现明显修复痕迹 / 花屏等），即视为**字幕擦除工具异常**。此时**立即停止后续流程（不要带着未擦净的字幕去合并、更不要静默跳过或强行交付）**，明确告知用户「字幕擦除工具出现异常，无法得到干净的无字幕画面」，并说清是哪个 / 哪些片段、具体的失败表现，等待用户指示（重试、换工具或人工介入）后再继续。**绝不允许把带残留字幕的片段当作"已擦除"混入成片。**

### 第 6 步：合并片段（交付无字幕版本）

用**视频合并工具**，按分段表的 `index` 顺序，把处理后的片段（含 5.4 已擦除字幕的片段、以及原样透传未送 Seedance 的片段）
无缝拼回一整条视频。校验总时长与原片一致、接缝无异常。

#### 6.1 最高原则：交付无字幕版本，不挂载任何字幕

- **本流程最终产物是"无字幕"的本地化视频**：原片烧录的字幕已在 5.4 逐段擦除，本步**不再重新生成、烧录或挂载任何目标语种字幕**。
- **不开启合并工具的字幕功能**：不传自定义字幕文案、不开自动识别、不生成字幕轨。若合并工具存在"默认自动识别原声补字幕"之类的行为，**必须显式关闭**，确保成片画面干净、无任何字幕文字。
- **软字幕情形**：原字幕若是独立字幕轨（未烧录进画面），直接去掉该字幕轨即可，同样不替换为目标语种字幕。
- **前置校验**：合并前先确认 5.4 已对所有含字幕片段完成擦除且无残留；**若 5.4 曾发生擦除失败（工具异常），此时不应进入合并——应已在 5.4 停下并提示用户**。

得到一条完整的、画面干净无字幕、且语言 / 人物已按要求本地化的视频。

### 第 7 步：交付

把成片交付给用户，并简要说明：改了什么（语言 / 人物）、保留了什么、目标语言与地区，以及字幕的处理方式（**原字幕已逐段擦除，最终交付为无字幕版本；原视频全片无字幕的则未做擦除**）。**还须说明语言替换的验证方式**：是通过音频转写核对确认的（附核对结论），还是未能验证（此时必须如实写明"语言替换未经音频验证，请试听确认"，不得笼统宣称"已完成配音替换"）。**若台词里做过单位、价格或尺码处理，须一并说明**：A 类单位换了哪些量值（原值 → 新值）；**B 类（价格 / 鞋码）要写明"用户在问卷中选择了哪种处置方式"**（采用建议值 / 用户提供的实际值 / 保留原制式 / 不提具体数值），若采用的是建议值则注明口径（价格注明汇率并写"实际售价需业务方最终确认"、鞋码注明"按通用对照表、建议核对品牌码表"），若用户未确认则写明"价格 / 尺码保持原文、未做本地化"；以及画面实物标价是否仍为原币种。**若中途字幕擦除工具异常、或 5.3.1 语言验收未通过，则不交付成片，而是如实告知用户异常情况并等待其指示。**
