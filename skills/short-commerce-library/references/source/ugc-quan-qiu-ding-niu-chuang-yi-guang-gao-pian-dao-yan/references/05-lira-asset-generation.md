# 05-LIRA SYSTEM 图像提示词与资产圣经 (Image Prompts & Asset Bibles)

> **归属系统**：LIRA Master Image Prompt Director  
> **核心铁律**：**凡资产必须先确定 (Assets First, Everything Second)**  
> 在进行任何分镜视频生成前，必须先在即梦 (Dreamina) 界面中完成角色 (@CHAR)、场景 (@SCN)、道具 (@PROP) 的资产展板生成与锁定。本系统 100% 基于即梦 Seedance 2.5 体系及 Web 端图形界面操作。

## 一、 LIRA 4-D 诊断开发方法论

任何图像提示词的优化与构建，必须通过以下 4 个阶段：

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 1. Deconstruct│ ──> │ 2. Diagnose  │ ──> │ 3. Develop   │ ──> │ 4. Deliver   │
│  (解构需求)  │     │  (诊断缺陷)  │     │  (重构开发)  │     │  (交付输出)  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

1. **Deconstruct (解构)**：提取核心故事基因、时代背景、历史材质与角色性格。
2. **Diagnose (诊断)**：检查是否有会导致 AI 假感的模糊修饰词（如“好看的”、“逼真的大片”），排查可能导致失真或漂移的逻辑漏洞。
3. **Develop (重构开发)**：应用 LIRA 骨架与“去 AI 假感词库”，添加 6 坐标历史定位与物理质感。
4. **Deliver (交付)**：输出即梦 Web 端专用的中英文双语提示词及参数设定（画幅比例、镜头焦点、照明模式）。

## 二、 角色资产图规范（分图多视角 · 无头全身取景框硬约束）

> **吸收自**：诺兰 IMAX 电影 master 资产多视角规范（06b）——**每个视角单独生成一张图，禁止单图内多视角拼贴**。
> **根因修正**：旧版"单图拼贴展板"（一张图同时放无头躯干+背面+面部特写）会让模型把整张图视为一个完整人物生成，**必然补画头部**。改为**分图生成 + 取景框语言**后，"无头全身照"约束即可 100% 生效。

### 1. 分图多视角规范（每视角单独一张图）

```
角色资产图 @角色:[中文名]（每个视角独立生成一张图，禁止单图拼贴）：
V1: 正面全身·无头（服装/身形/比例主锁区）  V2: 背面全身·无头（后领/发型/背部走线）
V3: 3/4 侧面半身（含头，锁轮廓与姿态）     V4: 正侧面（轮廓线）
V5: 正面半身·含头（面部+上半身过渡）       V6: 俯视 45°（头身比例空间感）
V7: 面部极特写（毛孔/眼神/皮肤质感主采区）  E1-E4: 表情组（中性/高峰/痛苦/决意）
```

- **无头视角（V1/V2）与含头视角（V3/V5/V7）分离生成**：面部采样只允许来自 V7 面部极特写图，其余视角一律禁止出现头部——从采样源上根除"从小人脸采样导致面部漂移"。
- **分镜生成时上传对应视角参考图**：全身戏传 V1/V2，面部戏传 V7，半身戏传 V5，各司其职。
- **背景统一纯白/柔白** `#F5F2EC`，无环境、无 logo、无水印（避免模型把背景当场景采样）。

### 2. 无头全身照取景框硬约束（V1/V2 必写）

**核心：用"取景框/裁切"语言，而非只说"无头"。** 模型对"无头 (headless)"的理解不稳定（可能画头再隐去、或画成无头怪），对"取景框裁切"的理解是构图操作，稳定得多。两条公式缺一不可：

```
【取景框公式】= [裁切起点] + [头部完全在画框外] + [保留内容] + [背景] + [负向]
【中文】
正面全身参考图，无头版本：取景框自【锁骨线/下颌线以下】开始，头部完全位于画框之外——
画面内不得出现头、脸、发际线、耳朵、下巴以上任何部分；完整展示服装版型、布料材质纹理、
身形比例与站姿；纯白背景 #F5F2EC，无环境、无阴影、无 logo、无水印。
负向：no head, no face, no hair, no ears, no chin, no neck above collarbone,
no portrait crop, no selfie angle。

【EN】
Full-body front reference, headless version: the frame starts below the collarbone / jawline,
the head is completely outside the frame — no head, no face, no hairline, no ears, nothing
above the chin visible in frame. Fully showcase costume silhouette, fabric texture, body
proportions and standing pose. Plain white background #F5F2EC, no environment, no shadow,
no logo, no watermark. Negative: no head, no face, no hair, no ears, no chin, no neck above
collarbone, no portrait crop, no selfie angle.
```

### 3. 无头全身照验收标准（出图即检）

- [ ] 头部任何部分（发际线/耳朵/下颌/头发）出现在画面内 → **不合格，立即重新生成**
- [ ] 裁切起点在锁骨线附近（颈下），画面顶部恰切于肩线/锁骨 → 合格
- [ ] 服装版型、纹理、身形比例清晰可读（无头状态下依然能锁定全身）→ 合格
- [ ] 背景为纯白 #F5F2EC，无环境元素混入 → 合格
- [ ] 若模型仍固执画头：改用「裁切+遮挡」双保险——画面顶部用衣领/围巾/道具边缘自然遮挡颈上区域，负向词叠加 `head cropped at neckline, mannequin bust, tailor form`

### 4. 提示词编写硬轨（含头视角的补充）

- **含头视角（V5/V7）**：面部特写必须使用高清大肖像，写全五官描述（眼型/眉骨/鼻梁/唇形/下颌线≥4 项），并标注 `high-resolution face portrait, pore-level skin detail`。
- **IDENTITY LOCK（跨镜锁定·英文）**：角色外貌锁定描述用英文撰写并全片逐字附加（`@角色:[名] — [EN identity lock]`），**禁止翻译回写中文**——中文回写会破坏跨镜一致性（吸收自诺兰 06b）。
- **双轨锁定**：视觉轨 `@角色:[名]`（IDENTITY LOCK）+ 声音轨 `@音频:[名]`（六维音色指纹，见 references/06）同一步锁定，全片禁止更换。

## 三、 场景与道具展板规范

### 1. 场景展板 (@SCN_[名称])
- **画幅**：必须为 **21:9 变形宽银幕画幅**。
- **角度**：3/4 视角全景俯瞰图（非正面——正面"漂亮图"在宽银幕上会变成扁平墙纸，且边缘外模型每次都会发明新环境；3/4 视角给模型可读的纵深，几乎覆盖整圈机位）。
- **定位**：明确场景的三维结构、主光源位置（如右上角 45 度月光）、地面材质（如湿润苔藓/破碎大理石）与环境介质（体积雾/尘埃）。
- **锚点必留 (Anchor)**：场景中必须留一个锚点（柱/灯/沙发/石碑），分镜调度必须绑在锚点上——"英雄在灯旁，面对门"能成；"英雄在房间里"是抽奖。
- **单光源逻辑**：一个主光源、一个阴影方向，**永不同时出现两个太阳**——否则每个新机位都会重新发明打光。

### 2. 场景状态展板（每个时间/天气/损坏状态 = 独立资产 @SCN_[名称]_[状态]）
场景不是一张图，而是一个**状态资产族**。白天/夜晚/雨天/战后破损是**四个不同资产**，各有各的描述与参考图：

| 状态 | @标签示例 | 描述要点 |
|---|---|---|
| 基准态 | `@SCN_长安_日` | 完整结构、主光源方向、材质包浆 |
| 夜晚态 | `@SCN_长安_夜` | 光源换为月光/灯火，阴影方向不变 |
| 雨天态 | `@SCN_长安_雨` | 湿润反射、积水、雾气，同一光源逻辑 |
| 战后/破损态 | `@SCN_长安_战后` | 断壁残垣、焦痕、弹孔——结构几何必须与原基准一致 |
| 黎明/黄昏态 | `@SCN_长安_晨` | 色温与光比改变，锚点与结构不换 |

**铁律**：把状态混进一段文字，模型就会在镜头间混搭状态——**拆状态比与模型搏斗便宜**。分镜提示词引用场景时，@ 必须精确到本镜的时间/天气/损坏状态，绝不引用基准态代替。

### 3. 道具状态展板（@PROP_[名称]_[状态]）
- **状态 1：静止/完整态**（展示原貌、刻字与材质氧化包浆）。
- **状态 2：使用/握持态**（展示与手掌/人体的物理接触关系与比例）。
- **状态 3：特殊/激活态**（发光、变形或物理破损状态）。
- **状态 4：受损/染血态**（破损、缺口、血渍、焦痕——如 Hell Grind 神器"染血小版"用于掌心揭示特写）。
- **状态 5：隐藏/封印态**（表面完整但内部能量被封——提示词禁止展示核心、只许缝隙透光，如"握拳镜头只露指缝蓝光"）。
- **状态 6：场景态**（道具在特定场景中与环境光的相互作用——参考卡带环境光参考，如武器在月光下的冷边）。

> 道具每个被剧情改变的状态都是一张独立资产图。分镜中道具 @ 必须精确到本镜的状态（完整/染血/激活/隐藏），与提示词描述一字不差。

## 四、 历史还原六坐标定位法 (Six-Coordinate Location)

在生成历史题材或特定时代背景的资产图时，必须对以下 6 个维度进行坐标化定位：

1. **时代材质**：砖石、粗羊毛、青铜锈蚀、手工锻造铁器质感。
2. **时代光源**：油灯、松脂火把、烛光、自然日光方向。
3. **时代色彩**：朱砂、黛蓝、赭石、石青等传统矿物颜料色板。
4. **磨损痕迹**：皮革折痕、袖口磨损、受潮水渍与岁月包浆。
5. **时代声学**：石砌大殿高混响、竹木隔间干吸音。
6. **时代道具**：符合该历史时期生产力水平的农具、武器与日常生活器皿。

## 六、 资产双元组铁律 (Asset = Descriptor + Reference)

> **吸收自 Hell Grind 制作简报 (Pre-Production: Assets)**

**资产是一个简单二元组：文本 + 图像。**
- **文本 = 描述符 (Descriptor)**：角色/地点的完整文字描述。**逐字进入每一个提示词，从不缩短**——视频模型没有记忆，漏写半句，下一镜他就换了张脸和外套。
- **图像 = 参考 (Reference)**：模型用它作锚点。两者共同让主角从镜到镜保持同一个人。
- **描述符作为常量 (Descriptor Constants)**：每个项目维护 `descriptors` 与 `Style Prefix` 常量文件，一次编辑同步更新所有镜头。
- **每次都完整描述**：同一条铁律——`Describe everything, every time. The model has no memory.` 描述符逐字粘贴、从不缩写。

### 资产压测 (Stress Test — 锁定前必过)
每个资产在锁定前必须通过压力测试：
- **10 次生成**：不同姿势、不同光线，角色必须 10/10 可识别。
- **同框测试**：与其他资产同框、在真实场景光线下测试——单独稳定的人在与人同框时常崩。测试失败 = 描述的问题，不是模型的问题——重写文字再测。

### 每个状态是独立资产 (Every State Is a Separate Asset)
湿了、受伤了、换了衣服——那是 `@CHAR_罗科`、`@CHAR_罗科_湿`、`@CHAR_罗科_血`，各有各的描述。把状态混进一段文字，模型就会在镜头间混搭状态。地点同理：白天/夜晚/雨天是三个不同资产。道具同理：神器有"完整版（特写用）/染血小版（掌心揭示）/隐藏版（握拳镜头，提示词禁止显示晶体、只许指缝透蓝光）"三版。**拆状态比与模型搏斗便宜。**

> **完整的状态资产体系（状态资产树 / @命名规范 / 分镜-资产匹配 / 状态资产生成）见下方「六·五 状态资产体系」专章——它是本段铁律的可执行完整版，任何长片项目必须按专章执行。**

### 资产卡保持"刻意无聊" (Keep the Sheet Boring)
- 中性灰背景、平光、真实皮肤可见毛孔、无修图。电影感**不住在角色卡里**——它住在场景与视频提示词里。把胶片颗粒和电影镜头烤进资产卡，角色会把那种观感带进每个场景、不再响应新光。
- 模型理解最好的资产卡：**3/4 大肖像**（脸微转，不正面）。
- 服装/伤疤/血迹作为**点修改 (Point Changes)** 叠加：在原始资产卡上做局部修改，mask 只放改动的部分（夹克/伤疤/血）盖在原件上，其余不动——**一张图绝不完整过模型两次**，每多一次 pass 毁纹理、漂颜色（两次后脸变对称、塑料、死气）。

## 六·五、 ⭐ 状态资产体系 (State Asset System — 全项目资产状态管理专章)

> **吸收自 Hell Grind 制作简报**：`Every state of a character is a separate asset. Wet, wounded, changed clothes — that is @roco, @roco_wet, @roco_blood, each with its own description. Mix the states in one text, and the model starts mixing them between shots. Locations work the same way: day, night and rain are three different assets.`
> **核心铁律**：**只要一个资产在剧情中发生任何可见改变（受伤/妆造/神态/衣服/健康/年龄/时间/天气/损坏……），就必须基于最初的基准资产，生成一套对应的新状态资产。每个状态都是独立资产，拥有独立 @ 标签与独立描述符。**

### 0. ⭐ 底层逻辑：状态资产单一衍生源公理 (Single-Source Derivative Axiom — 最高优先级)

**这是整个状态资产体系的底层逻辑，一切规则都从它推导：**

> **每次资产状态的改变，都必须以「最初确定并锁定压测通过的那个基准资产」作为唯一的初始状态进行修改。每个状态资产都直接从基准资产一次性点修改生成，全片绝不允许任何形式的链式修改。**

```
❌ 禁止链式修改 (Chained Modification — 资产漂移的根源)：
基准资产 → (修改) → 受伤态 → (再修改) → 重伤态 → (再修改) → 战损态
每多一次修改 pass，就多毁一次纹理、多漂一次颜色；改到第 3 次时，
脸已变对称、塑料、死气——与最初锁定的身份面目全非。

✅ 正确做法 (Single-Source — 每个状态只过两次模型)：
基准资产 ──点修改──> @CHAR_唐末_受伤
基准资产 ──点修改──> @CHAR_唐末_重伤
基准资产 ──点修改──> @CHAR_唐末_战损   (受伤+换装+湿 一次性从基准改出)
```

- **"最初确定后的资产" = 基准资产 (Base Asset)**：剧本初始形态、压测 10/10 通过、写入命名字典的那张锁定资产。它是全片唯一的"修改母本"。
- **每个状态资产只允许过模型两次**：第一次生成基准，第二次从基准点修改出该状态。任何状态资产都**不再是其他状态资产的修改结果**。
- **组合状态（多重叠加）同样从基准一次性生成**：战损态（受伤+换装+湿）不是"先改受伤、再改换装、再改湿"——而是在基准资产上一次点修改同时叠加全部变化，一次成型。
- **为什么这条公理成立**：Hell Grind 铁律「一张图绝不完整过模型两次，每多一次 pass 毁纹理、漂颜色」。链式修改 = 一张图过 N 次模型 = 漂移随修改次数指数累积；单一衍生源 = 每张状态资产永远与基准保持同一纹理基底、同一身份连续。
- **操作落地**：即梦界面中，状态资产生成时永远以「基准资产图」为底图做局部编辑（画刷圈出改动区域 + CHANGE/PRESERVE 手术编辑模板），**绝不把已修改的状态资产图当作下一状态的底图**。

### 1. 状态资产树 (State Asset Tree)

每个角色/场景/道具从**基准资产 (Base State)** 生长出一棵**状态资产树 (State Asset Tree)**。基准资产是锁定锚点；状态资产从它点修改衍生，身份连续但状态独立。

```
角色状态资产树 @CHAR_唐末（全部状态 ← 单一衍生自基准资产）：
├── @CHAR_唐末             (基准态：完整外貌/服装/年龄，锚点 — 唯一的修改母本)
├── @CHAR_唐末_受伤         (轻伤：绷带/血渍/淤青 — 基准+一次点修改)
├── @CHAR_唐末_重伤         (重伤：血流满面/衣服破损/虚弱姿态 — 基准+一次点修改)
├── @CHAR_唐末_换装         (剧情换衣：新服装=新资产 — 基准+一次点修改)
├── @CHAR_唐末_妆造         (妆容改变：战妆/易容/蒙尘 — 基准+一次点修改)
├── @CHAR_唐末_老年         (年龄变化：皱纹/白发/佝偻 — 基准+一次点修改)
├── @CHAR_唐末_病态         (健康恶化：病容/消瘦/疲惫 — 基准+一次点修改)
├── @CHAR_唐末_湿           (环境状态：淋雨/落水/湿衣 — 基准+一次点修改)
└── @CHAR_唐末_战损         (受伤+换装+湿 多重叠加 — 基准+一次性点修改全部叠加，绝不逐级改)

场景状态资产树 @SCN_长安_宫城：
├── @SCN_长安_宫城_日       (基准态：白日/完整结构)
├── @SCN_长安_宫城_夜       (夜态：月光/灯火，单光源逻辑不变)
├── @SCN_长安_宫城_雨       (雨态：湿润反射/积水/雾气)
├── @SCN_长安_宫城_战后     (损坏态：断壁/焦痕，几何与基准一致)
└── @SCN_长安_宫城_晨       (黎明态：色温改变，锚点与结构不换)

道具状态资产树 @PROP_圣晶石：
├── @PROP_圣晶石           (完整态：特写用)
├── @PROP_圣晶石_染血       (染血小版：掌心揭示用)
├── @PROP_圣晶石_激活       (激活态：发光/变形)
└── @PROP_圣晶石_隐藏       (隐藏态：握拳镜头，只许指缝透蓝光)
```

### 2. 状态资产生成规则 (State Generation Rules)

- **第一规则（见 §0 公理）：每个状态资产 = 基准资产的一次点修改，单一衍生源，绝不链式修改。** 生成任何状态资产前，先自问："我是否以最初锁定的基准资产为底图？"——答案必须是"是"。
- **状态资产 = 基准资产的点修改 (Point Change)**：在基准资产卡上做局部修改，mask 只放改动的部分（伤口/新衣服/妆容/白发）盖在原件上，其余像素不动——**一张图绝不完整过模型两次**，每多一次 pass 毁纹理、漂颜色。
- **状态描述符 = 基准描述符 + 状态增量**：状态资产的描述符以基准描述符为基础，**叠加**本状态独有的可见特征（`@CHAR_唐末_受伤 — [基准描述符逐字] + 左臂绷带、脸颊血渍、干裂嘴唇`）。
- **身份连续铁律**：任何状态资产的面孔/体型/比例/核心特征必须与基准 100% 连续——状态变了，身份不变。每张状态资产都要通过"与基准同框不串"压测。
- **状态随剧情推进而累积**：角色被故事磨损，状态资产要随剧情逐步生成（先受伤、再换装、再老年……），**绝不一次生成全部状态，只生成剧情需要的状态**；也不允许在生成后重置回基准（退化累积，见 references/04 §十一）。

### 3. ⭐ @ 标签命名字典规范 (Naming Dictionary — 资产名 = 提示词名)

**资产命名是状态资产体系的中枢：资产卡的 @ 标签名，必须与分镜图生视频提示词中的 @ 引用名一字不差、完全一致。同一个 @ 名在文档、提示词、界面中通用。**

- **命名格式**：`@类型_名称_状态`
  - 角色：`@CHAR_唐末`（基准）、`@CHAR_唐末_受伤`（状态）
  - 场景：`@SCN_长安_宫城_夜`
  - 道具：`@PROP_圣晶石_激活`
- **每个状态一个名字，绝不混写**：`@CHAR_唐末_受伤` 就是 `@CHAR_唐末_受伤`，不能写成 `@CHAR_唐末 受伤了`，不能在一个 @ 里塞两个状态。
- **命名字典表 (Naming Dictionary Table)**：项目维护一张总表——`@标签 | 资产名 | 状态 | 描述符(逐字) | 参考图编号 | 所属分镜范围`。**所有分镜提示词的 ACTIVE REFERENCES 必须逐字复制命名字典中的 @ 标签与描述符**，实现"资产的名称命名与分镜图生视频提示词描述一致"。
- **@ 引用必须关联最相关准确的资产**：分镜写提示词时，@ 必须指向**该镜状态下最准确的那张资产图**——角色带伤出场就引用 `@CHAR_唐末_受伤`（而非基准 `@CHAR_唐末`），夜戏就引用 `@SCN_长安_宫城_夜`（而非白天基准）。**绝不引用错误的基准态/旧状态**，否则模型会把伤口画没、把夜晚画成白天。
- **同名同义同用**：命名字典一旦锁定，全片不可改名、不可翻译回写、不可缩写（吸收自 03 §七：同一个命名字典全项目通用）。

### 4. ⭐ 分镜-资产匹配清单 (Storyboard-Asset Match)

写每个分镜的提示词前，先列出本镜的**激活资产清单 (Active Asset List)**：

```text
【本镜激活资产】
- 角色：@CHAR_唐末_受伤 for character reference — [命名字典中的受伤态描述符，逐字粘贴]
- 场景：@SCN_长安_宫城_夜 for location reference — take only the space and the texture: [夜间宫城材质/光影]。Do not use as a starting frame, do not inherit the composition, the angle or the color.
- 道具：@PROP_圣晶石_激活 for prop reference — [激活态描述符]
```

- **每条 @ 引用必须带"角色命名"**（`for character reference` / `for location reference` / `for prop reference`）——否则模型自己决定参考用途，会抄构图而非脸、抄脸而非色板。
- **状态变化跨镜连续性**：上一镜角色受伤，下一镜必须仍引用 `@CHAR_唐末_受伤`——伤口/血/破损跨镜保持，绝不重置（多镜剪辑连续性锁，见 references/03 §十）。

### 5. 状态资产锁定与压测流程 (State Asset Lock & Stress Test)

1. **基准资产先锁定**并压测（10 次生成 10/10 可识别 + 同框测试）——它成为全片唯一的修改母本。
2. **逐场景扫描剧本**，列出所有"资产状态改变事件"（受伤时刻/换装时刻/年龄跨越/天气变化/损坏时刻）。
3. **为每个事件生成对应状态资产**：**一律以最初锁定的基准资产为底图**做一次点修改 + 独立压测（10/10 + 与基准同框不串 + 与他资产同框不崩）。**绝不从其他状态资产再改。**
4. **登记命名字典表**：@标签 / 状态 / 描述符 / 参考图编号 / 适用分镜范围。
5. **分镜蓝图引用命名字典**：每镜的 ACTIVE REFERENCES 逐字复制字典中的 @ 标签与描述符。
6. **G2 门禁强确认**：状态资产树 + 命名字典 + 分镜-资产匹配清单全部确认后才进入分镜生成。
7. **⚡ 单一衍生源自检 (每次生成状态资产前必答)**：①底图是最初锁定的基准资产吗？②本状态只过这一次修改吗？③有没有拿"上一状态"当底图？（有 = 立即停止，回到基准重做）

### 6. 状态资产 10 套示例 (Character With 10 State Assets — 示例)

一个主角可能拥有 10 套甚至更多资产图，全部与剧情相匹配（不同状态/不同年纪/受伤与否/衣服/健康状态）：

| # | @ 标签 | 状态 | 剧情触发 |
|---|---|---|---|
| 1 | `@CHAR_唐末` | 基准态 | 第一幕日常 |
| 2 | `@CHAR_唐末_受伤` | 轻伤 | 遭遇战 |
| 3 | `@CHAR_唐末_重伤` | 重伤 | 决战前 |
| 4 | `@CHAR_唐末_换装` | 换装 | 潜入/婚礼/新身份 |
| 5 | `@CHAR_唐末_妆造` | 战妆/易容 | 伪装戏 |
| 6 | `@CHAR_唐末_老年` | 老年 | 时间跳跃 |
| 7 | `@CHAR_唐末_病态` | 病容 | 中毒/瘟疫 |
| 8 | `@CHAR_唐末_湿` | 淋雨/落水 | 雨夜戏/落水 |
| 9 | `@CHAR_唐末_战损` | 战损叠加 | 最终决战 |
| 10 | `@CHAR_唐末_亡` | 阵亡/遗体 | 悲剧结局 |

> **场景同理、道具同理**：场景的日/夜/雨/战后/晨是 5 个资产；道具的完整/染血/激活/隐藏是 4 个资产。全片所有可见改变都有对应状态资产，且 @ 名与分镜提示词描述 100% 一致。

## 七、 图像提示词反失败规则 (LIRA Anti-Fail Rules)

> **吸收自 LIRA SKILL.md（模型无关部分，适配即梦体系）**

1. **自然散文，不堆关键词**：`4k, masterpiece, trending` 之类关键词堆叠毫无作用；写连贯的场景描述句。
2. **别膨胀提示词**：精准胜过冗长——精炼的 80-150 词胜过散乱的 400 词；每多一句多余的子句都在稀释注意力。目标 ≤1500-2000 字符，砍填充词、留锚点。
3. **正向 > 负向 (Positive > Negative)**：即梦图生视频无负向提示参数——一切不需要的东西通过"正向描述你想要什么"来消除：干净皮肤写 `clean dry skin` 而非 `no acne`；空街道写 `empty deserted street` 而非 `no people`。NOT 堆叠（"not cartoon, not anime..."）反而会注入这些概念。**例外：局部编辑操作中删除是合法操作**（"Remove the lamppost"），但必须配上填充物（"continuous brick wall behind"）。
4. **画幅与分辨率 = 平台参数**：在界面里设置，绝不写进提示词正文。构图词（"wide panoramic frame"）可以，参数语法（16:9、4K）不行。
5. **技术性光影与材质，而非模糊情绪**：`single overhead key light, soft 2:1 ratio, smooth falloff` 胜过 `dramatic cinematic lighting`。命名真实材质+表面处理（"board-formed concrete"、"oxidized copper verdigris"）。镜头语言（焦段/角度/景别/景深）可以，但光学/景深语言属于角色，不属于地点。
6. **60:30:10 调色板 (Palette Control)**：百分比在模型上很好读：`palette of 60% warm ochre, 30% deep charcoal, 10% rust-red`。从用户指示/场景语境/参考图推导，绝不凭空发明。
7. **插画漂移 (Illustration Drift)**：`character reference sheet` 和 `painterly` 触发概念艺术观感——写 `studio photographs / film character sheet / cinematic film still`。用正向电影锚（胶片型号、镜头、真实材质）修复漂移，不用 NOT 堆叠。
8. **文字/纹身/真实人物**：画面内文字给精确原文+字体/粗细/颜色（`Write 'GENUINE' in bold red serif on the sign`）；纹身给具体真实设计（`classic swallow`）+ `clean line-work`；绝不写真名人物（翻译成描述性特征）；无 IP/品牌名。
9. **手术编辑模板 (Surgical-Edit Template — 局部编辑模式)**：
   ```text
   Edit the image: [one-line goal].
   CHANGE: [only the single thing that changes, described precisely].
   PRESERVE EXACTLY:
   - [list every element that must stay identical: face, clothing, props, positions, wall/floor, camera angle, all existing shadows]
   - Color grade, palette, contrast, grain, falloff
   ONLY CHANGE: [restate the one change]. 100% identical otherwise.
   ```
   教训：用户说你"改过头了"= 你变了太多——锁死一切，只改一件。一次只改一处。
