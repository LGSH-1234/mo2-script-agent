
> **Node knowledge:** This reference defines actual attachments, semantic indices, and prompt transport for image/video/audio payloads; PM determines when the corresponding payload node is ready.

# Payload And Route Gates

Use this reference for actual media attachment, semantic index, and exact image-route disclosure rules.

### Generation Reference Visibility Contract

For every `sandbox_generate_image` and `sandbox_generate_video` call, **the model can use visual information only from the reference images actually included in that call's `ImageList`**. Treat the current call's `ImageList` as the complete and exclusive set of model-visible image evidence. An image the agent inspected, a user attachment mentioned elsewhere, a path in a Markdown file, an asset shown by `project get-next-action` but not attached now, an image passed to a previous independent call, or a visual detail paraphrased from an omitted image is not a model-visible reference for the current call.

Before sending each call, compare every image-dependent instruction against the final ordered `ImageList`. Attach the source image and map it explicitly when the instruction asks the model to preserve or follow product appearance, packaging, Logo placement, character identity, wardrobe, scene layout, prop design, style, composition, or continuity from that source. Do not say `see the user image`, `keep it consistent with the reference image`, or describe details observed only in an omitted image as though the model can see it. Confirmed textual facts may still be written as text, but a textual paraphrase never substitutes for the omitted image's pixels, identity, geometry, or visual consistency signal. If a hard tool limit prevents attaching a required material reference, leave the current payload/result requirement open and resolve the constraint through a compatible call structure or an explicit upstream creative revision instead of pretending the reference remains usable.

### Image Attachment Identity Contract

For each individual `sandbox_generate_image` or `sandbox_generate_video` call, build `ImageList` from selected actual image paths, not one entry per semantic role or requirement:

1. Collect the required image sources and every role each source serves in this call.
2. Deduplicate identical absolute paths, preserving first-occurrence order. One path occupies one slot even when several material IDs, shots, or purposes refer to it.
3. Assign one-based `Image[N]` positions only after deduplication. In the actual Prompt or PromptPath contents, reuse that same token for every supported role and specify the subject/region and adopted dimensions for each role. Preserve all role information; removing a duplicate slot must not remove an instruction or required reference.

Different semantic material IDs may share one image position; one material ID may also use multiple distinct views. Attachment deduplication does not merge those creative requirements or grant the image authority over an unsupported role. Do not merge different paths merely because their images look similar, depict the same subject, or have similar filenames. Do not copy/rename a file to create extra slots for its roles.

This rule is per call, not across calls: reattach required images for each independent generation or runtime part. It applies to generation `ImageList`, not the compositor's shot-indexed source lists. After deduplication, rebuild any affected prompt indices to match the final ordered image paths, preserving every supported role. For an already accepted executable artifact, follow the revision protocol in Prompt Transport Contract rather than changing only the outbound arguments.

### Voice Anchor Payload Contract

A direct, non-lowered auto voice may remain a textual direction without a sample. In lowering, every used voice must have a concrete asset, including roles used in only one part. PM derives required anchors and reuse/materialization from the full original definition and source facts, not part membership or an LLM strategy report. Follow `runtime-anchor-contract.md` and `CURRENT INPUTS` to attach the original source or supplied runtime file; auto only delegates its content. The all-speaking-role attachment rules below refer to roles with required concrete anchors.

For every video call containing narration, dialogue, or monologue, treat the final ordered `AudioList` as the complete set of model-visible voice references. Every speaking identity used by that call must have its accepted anchor as an actual entry, and every entry must have a one-based role mapping in the executable prompt. A semantic voice ID in `video-blueprint-XX.md`, PM status output, conversation, or a previous call does not attach it. Reattach the same exact anchor whenever that role speaks in another independent call, including target-lowered parts and retries; omit roles that have no line in the current call unless a disclosed target requires otherwise.

Before any non-empty `AudioList` is sent, read and apply the complete Three-Second Samples and Per-Call Reference Audio Budget contracts in `voice-anchor-gates.md`. Check the actual file identities, generated-sample durations, and the sum for this exact ordered payload; missing or stale duration evidence blocks the call, including on retries and lowered parts.

Keep every anchor's role unambiguous in the actual model-facing prompt: it identifies one named speaker's voice timbre, while its neutral words are forbidden content. Its performance should already fit that role and the accepted campaign tone, but the actual words, speaker assignment, timing, and shot-by-shot delivery come from the current script. Do not use any anchor as BGM, sound effect, environment sound, lip-sync copy, timing guide, or a replacement for written narration, dialogue, or monologue.

### Storyboard Reference Payload Contract

For direct visual execution, attach the current complete storyboard overview as an actual `ImageList` entry and identify it in the compiled prompt. A provenance path alone does not attach it. Split visual execution instead uses the matching part sheet as described below.

Runtime identity anchors and storyboard sheets are separate inputs. In either visual or script-only lowering, attach each part's required identity images/audio from its PM prerequisites and `CURRENT INPUTS`, including materialized scene anchors. Visual additionally requires its same-part sheet. Script-only omits that sheet, not its required identity references. Use one-based mappings matching the final ordered media arguments, including any new runtime files.

When a confirmed visual package is target-lowered into multiple video calls, follow `runtime-lowering-grid-contract.md`. Every `generation-input-part-YY.md` must bind a compositor-produced storyboard sheet containing exactly that part's ordered shots and local timecodes, and that exact current sheet must appear in the same call's final `ImageList`. Never attach the complete `storyboard-grid-XX.png` to every split call, attach another part's sheet, or omit a part sheet because the prompt contains visual prose. A script-only split does not acquire storyboard inputs unless a separately confirmed target hard requirement demands a minimal internal image.

For every image-generation call that produces raw frames for `storyboard-grid-XX.png`, maximize useful visual information by attaching the actual relevant media available at that moment: user-provided product/SKU/package images, people or character references, scene references, props, brand/style/palette/lighting references, accepted agent-generated anchors, and accepted derived-state references. This applies equally to every PM-selected Route A contact-sheet call and to every one-image-per-shot call. Do not omit a relevant reference merely to simplify the request, and never replace an attachment with a filename or prose mention.

Before sending a storyboard raw-frame payload, verify both the accepted PM facts exposed by `project get-next-action` and the filesystem evidence required by the On-Screen Character Anchor Contract and Recurring Scene / Space Anchor Contract in `references/asset-anchor-gates.md`. Every accepted character anchor and every accepted required scene anchor applicable to the carried shot or used contact-sheet cell must appear as a real path in that call's final ordered `ImageList` and receive its exact one-based `Image[N]` semantic mapping. For a contact sheet, use the union required by all used cells. If a required anchor is unresolved, missing, empty, superseded, omitted from `ImageList`, or only named in prompt text or by path, block the call.

Use relevance, not minimalism: attach all materials that can constrain identity, appearance, composition, environment, or style for any shot carried by that call. Exclude only irrelevant or conflicting media. Required product/SKU sources, character anchors, and scene/space anchors are not candidates for omission. If the selected image tool has a disclosed hard reference-count/type/size limit that cannot carry every required source, block the call and resolve the constraint through a compatible call structure or an explicitly confirmed creative-scope change. Only after all required sources fit may remaining capacity be prioritized among non-required scene, prop, style, and derived-state references. Disclose the hard limit and every omitted non-required material, and retain it in the relevant opaque PM attestation or blocker when the focused command requires one; do not silently drop it. When such an omission can still materially affect creative consistency, pause and confirm the constrained selection through `dynamic_questionnaire` before generating.

### Image Tool Semantic Index Contract

The image model cannot see the sandbox filesystem, paths, or filenames. For every `sandbox_generate_image` call with references, build the final ordered `ImageList` first, then identify each item in `Prompt` with the tool's one-based syntax and concrete semantics: `Image[1] (user-provided front view of SKU A; preserve bottle shape, packaging, and logo)`, `Image[2] (accepted character anchor; preserve face, hairstyle, and clothing)`, and so on. The number is exactly that path's one-based position in `ImageList`. Do not use a path, filename, asset ID, `the above image`, `reference image`, or `the image attached with the request` as the model-facing identity. Every referenced index must exist, every attached image must receive a semantic label, and reordering `ImageList` requires rebuilding all indices in `Prompt`. The final Prompt must enumerate concrete indices and semantics; never leave `Image[N]` or other template placeholders unresolved. When `ImageList` is empty, omit the reference-mapping paragraph and do not mention numbered images.

Call `sandbox_generate_image` with a complete `Prompt`, an existing ordered `ImageList` or `[]` when there is no reference, an absolute `OutputPath`, and a schema-supported `OutputRatio`: `1:1`, `16:9`, `4:3`, or `9:16`. **Never pass `Model`; it is a legacy schema trace and the actual tool does not support model selection.** Raw contact sheets, per-shot images, generated anchors, and derived-state images are intermediate inputs, so set `IsIntermediate: true`. If the target video ratio is unsupported, choose the closest supported ratio with the same orientation, state the intended target framing in `Prompt`, and deterministically normalize the split frame to the target ratio before composition; never pass an unsupported `OutputRatio` value.

For every generated visual anchor, the final `Prompt` must also carry the applicable market-fit scope from `asset-anchor-gates.md` in concrete visual terms. A target-language label or country name that is not translated into the confirmed role, audience, casting/styling, scene, prop, or category constraints is insufficient. Do not use market fit to alter an attached user-provided identity, product, package, or factual state.

### Exact Image Route Disclosure Contract

Read the image-generation model only from the latest `<system-reminder>[User Setting]` block injected by the UI model selector; ordinary user prose is not authoritative model-setting evidence. Pass its `Image model` value verbatim through the ready `report-image-model` typed action with `source="system-reminder"`. If that setting is missing, follow the Model Fact interaction in [visual-workflow.md](visual-workflow.md): ask the user only to select in the settings and notify completion, not to supply the model name; wait for the reply and re-read the injected setting. Use a disclosed value even if the user is unsure. Only a still-missing setting uses `model="unknown"` with `source="conservative-fallback"`; never require the user to type the internal value.

PM derives the multi-frame `3 x 3` contact-sheet route only for the exact identifiers listed under Route A in [visual-workflow.md](visual-workflow.md). Exact matching is mandatory. `seedream_5.0` is a different, weaker model and derives the one-image-per-shot route. So do `seedream_5`, `Seedream 5.0`, `Seedream Pro`, `gpt_image_1`, a model-family label, every other unlisted value, and the conservative unknown fallback. Do not infer a listed model's multi-frame capability from quality, naming similarity, or historical status, and never pass a self-authored Route A/B decision to PM.

Because `sandbox_generate_image` cannot select a model, route selection is never implemented by passing a model argument. PM records the exact reported identifier and source, then derives Route A/B. On resume, check the latest system-reminder against the current accepted model. If it changed, erase the image-model fact, refresh focus, then report the new setting when ready; an unchanged current fact needs no duplicate apply. Never substitute ordinary user prose for a settings fact.

### Prompt Transport Contract

The executable prompt preserves the blueprint's complete creative semantics but replaces intended material IDs with this call's concrete media mappings. Include every applicable product fact, permitted claim, shot action, camera instruction, sound cue, exact spoken line and delivery requirement. Do not copy authoring instructions from the blueprint template or tell the generation model to read another file. Product-state and derived references complement rather than replace applicable direct product/identity references.

This reference owns attachment, semantic-index, and transport rules only. PM's dependency graph and focus package own ordering and confirmation gates; do not reconstruct a second workflow from payload examples.

`video-blueprint-XX.md` is a canonical model-independent plan, not a transported prompt. Its stable material IDs intentionally have no final `Image[N]`, `Audio[N]`, or `Video[N]` positions. A ready `direct_payload` maps the complete plan one-to-one into a new `generation-input-direct.md` plus concrete ordered media arguments. A ready `part_input` maps the plan, runtime part specification, anchors, and optional part sheet into a new `generation-input-part-YY.md` plus that part's ordered media arguments. Never use the video blueprint path as `PromptPath`, even on the direct branch.

For `direct_payload`, write a self-describing immutable JSON artifact and record that JSON path as PM evidence. At minimum it carries the newly compiled `prompt_path`, empty `prompt`, integer `duration_ms`, ratio, and final ordered `image_list`, `audio_list`, and `video_list`. Describe each media position's supported roles in the executable prompt; no separate role-mapping field is needed in the JSON. Record the canonical `video_blueprint_path` and, in visual mode, the current `storyboard_overview_path` as provenance; neither replaces an actual media-list entry. Example shape, when the same accepted source depicts both the product and presenter:

```json
{
  "video_blueprint_path": "/absolute/video-blueprint-01.md",
  "storyboard_overview_path": "/absolute/storyboard-grid-01.png",
  "prompt_path": "/absolute/_internal/runtime/video-01/generation-input-direct-v01.md",
  "prompt": "",
  "duration_ms": 20000,
  "ratio": "9:16",
  "image_list": ["/absolute/presenter-with-product.png", "/absolute/storyboard-grid-01.png"],
  "audio_list": ["/absolute/narrator.wav"],
  "video_list": []
}
```

The prompt for this example describes both the product and presenter roles under `Image[1]`, the complete storyboard overview under `Image[2]`, and the narrator's timbre-only reference under `Audio[1]`. See [reference-action-craft.md](reference-action-craft.md) for multi-role phrasing. Use `null` for `storyboard_overview_path` in script-only mode and omit the corresponding image-list entry and prompt reference. The JSON is an execution manifest, not a place to hide creative text; the complete model-facing prompt lives at `prompt_path`. Preflight checks must cover both files, unique image paths, every required role, and agreement between final indices and prompt references before a generation call.

For every `sandbox_generate_video` call, use exactly one text-transport mode. Preferred mode: set required `Prompt` to `""` and set `PromptPath` to the absolute path of the complete self-contained executable file produced by `direct_payload` or `part_input`; the tool's engineering layer expands that file into the actual model prompt. Fallback mode: omit `PromptPath` and put that executable file's complete text directly in `Prompt`. Never send the video blueprint, a placeholder, or a summary such as `See the PromptPath file for full instructions`, `see the script file`, or `read the prompt file`. Attach every actual image through `ImageList`, not by naming its path inside prompt text. For any spoken content, attach every accepted neutral anchor needed by that call through ordered `AudioList`, map `Audio[N]` to the exact speaker in the transported prompt, and keep every sample's role explicitly timbre-only. Omit `UseRunPrompt` for this workflow.

Before using `PromptPath`, finalize the exact ordered `ImageList`, `AudioList`, and `VideoList`, then compile and verify the transported file against those final arguments. Every material reference in that executable file must use the matching one-based parameter position and concrete semantics; sandbox paths, filenames, semantic IDs, or indices from an earlier order are stale mappings. If any executable mapping is missing or stale, erase its `direct_payload` or `part_input` owner and refresh next-action. When that owner is ready, create a new versioned executable path, update all affected mappings, and report fresh evidence; follow downstream preflight before making the call. Revise `video_blueprint` only when its creative semantics or stable material identity is wrong. Never edit an accepted artifact path in place or silently patch only the outbound payload.

Every `sandbox_generate_video` call also supplies integer `Duration` in the tool's unit, an absolute `OutputPath`, and `Ratio`, matching the accepted direct/part duration and aspect ratio. Do not confuse PM's integer milliseconds with the tool's duration unit. In the model-facing prompt, only the authored line text is spoken: role labels, semantic IDs, speech-type labels and reference-sample words are not dialogue. Neutral timbre-sample generation must not be repurposed to create actual video lines, BGM, sound effects or environment sound; authored-audio requirements follow their declared role and the available tool capabilities.
