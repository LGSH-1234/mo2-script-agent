# 项目式故事开发

## 一、启动原则

用户只有模糊想法时，不立即要求填写复杂问卷。

先提供2至4个差异明显的故事方向，每个方向包含：

- 暂定名称；

- 一句话梗概；

- 主角；

- 外在目标；

- 内在需要；

- 核心阻力；

- 独特切口；

- 类型看点；

- 情感命题；

- 观看动力；

- 可能结局；

- 创作风险。

不同方案必须在故事发动机、人物关系或价值冲突上有实质差异。

## 二、开发阶段

### 阶段0：创意方向

回答：

- 谁想得到什么？

- 谁或什么阻止他？

- 为什么必须现在行动？

- 失败代价是什么？

- 为什么这个故事只能发生在当前设定中？

- 观众会因为什么继续观看？

交付故事种子，等待方向确认。

### 阶段1：观众契约与故事发动机

明确：

- 类型；

- 目标受众；

- 核心观看体验；

- 开场承诺；

- 中段升级方式；

- 高潮兑现；

- 能持续产生冲突的机制。

故事发动机不足时，不急于扩写。

### 阶段2：世界观与人物

只建立影响人物行动的规则：

- 时间地点；

- 社会和组织结构；

- 权力如何分配；

- 特殊规则；

- 使用规则的限制和代价；

- 谁受益；

- 谁受损；

- 违反规则的后果。

建立主角、对手、主要配角和核心关系。

### 阶段3：完整故事简介

输出300至1000字完整故事，必须写明：

- 开端；

- 诱发事件；

- 主角承诺行动；

- 中段变化；

- 关键损失；

- 最低谷；

- 高潮选择；

- 具体结局；

- 情感余韵。

不得用“真相逐渐浮出水面”等空话替代事件。

### 阶段4：结构大纲

为每个节点记录：

&gt; 发生什么 → 为什么发生 → 谁作出选择 → 造成什么后果。

根据题材选择合适结构，不强制固定三幕比例。

### 阶段5：分场大纲

每场至少记录：

- 场次；

- 地点和时间；

- 人物；

- 场景目标；

- 各方诉求；

- 冲突；

- 行动；

- 信息或关系变化；

- 场尾推动力；

- 对后续的因果作用。

### 阶段6：完整剧本

按幕、章节或场次分批完成。

每批：

- 遵守项目圣经；

- 延续人物状态；

- 维护时间、道具、伤势和信息；

- 不擅自更改已确认结果；

- 在合适节点等待确认。

### 阶段7：诊断与定稿

先诊断：

1. 因果；

2. 人物；

3. 结构；

4. 类型承诺；

5. 情感；

6. 连续性；

7. 场景；

8. 对白；

9. 视听；

10. 制作可行性。

再进行定向修改。

## 三、阶段确认

以下事项改变前必须确认：

- 核心故事方向；

- 主角目标；

- 对手身份或立场；

- 世界底层规则；

- 中段重大转折；

- 高潮选择；

- 结局；

- 核心人物命运。

局部场景、对白和调度可在保护项范围内主动优化。

## 四、阶段回退

后续发现前置问题时，不得暗改。

输出：

- 问题源头；

- 当前影响；

- 最小修复；

- 深度修复；

- 受影响章节；

- 用户需要作出的选择。

## 五、创作发散与收敛

发散阶段：

- 允许大胆、矛盾和未验证方案；

- 暂不使用全部质量规则压制创意；

- 先寻找独特人物、关系和场面。

收敛阶段：

- 检查因果和规则；

- 淘汰重复方案；

- 确认故事发动机；

- 建立可持续结构；

- 记录项目状态。
