
# 成片检查

审阅对象是最后交付的 MP4。先为每个分镜选一张代表帧，逐张看图、记录具体问题并返修；复杂机制再看前中后。修复后复查画面，再连续播放最后版本确认。渲染成功、工具摘要、抽帧数量和自动评分都不能替代这条流程。

## 选择代表帧

每个分镜由创作者确定 `review_at`：主体和关键标注已到位、当前动画状态清楚、相关字幕仍在屏上的时刻。它应能代表该镜的完成构图，不自动取镜头开始、时间中点或字幕中点。明确无字幕的视频不要求字幕在屏；字幕时序未知时可以审阅画面，但要保留字幕验收缺口。

抽出后逐张核对选点。若还在入场、构图未建立、关键标签未到位或相关字幕已经消失，人工调整 `review_at` 再抽。找不到合适时刻时，检查动画与字幕编排是否留出了共同可读的时段，必要时修改视频。脚本只能核对指定时间及时间线预期，不能判断动画是否到位，也不能据此判定审美或原理正确。

复杂机制额外指定 `events` 的动作前、关键变化最清楚时、动作完成后；不要为每个普通镜头强凑三帧，也不要把过程平均切三份。转场遮挡、短暂错误或需要单独复查的位置加入 `checkpoints`。文字还要覆盖最密、移动最靠边、缩放最大以及前后镜文字共同可见的时刻；将布局检查报告中的问题时间加入补查，不能只挑静止且已避开的代表帧。

## 检查点数据格式

`--checkpoints` 读取一个 JSON 对象。时间单位为秒；时间必须来自本次分镜与实际视频，字幕分段不自动等同于镜头。

| 字段 | 内容 |
| --- | --- |
| `scenes` | 分镜对象数组；首次视觉审阅列全片分镜 |
| `scenes[].id` | 稳定、可辨认的非空字符串，在整份 `scenes` 中唯一；重复、空白或缺失 ID 直接报错 |
| `scenes[].start / end` | 镜头实际起止时间，`0 <= start < end` |
| `scenes[].review_at` | 人工选定的代表时刻，`start <= review_at < end` |
| `scenes[].expectation` | 可选预期文字：应出现的主体、动作状态、关键标签与相关字幕内容；不要只写“检查细节” |
| `scenes[].events` | 可选复杂机制数组；每项有 `id / start / peak / end`，满足 `scene.start <= start <= peak <= end <= scene.end` |
| `checkpoints` | 可选补查对象数组；每项有 `time / label`，可有 `id`；label 写此刻可观察的预期 |

没有 `review_at` 的分镜会记录缺口，不自动把场景开始或中点当成完成代表。缺少 `scenes` 的首次视觉审阅也不能声称逐镜覆盖。机制事件的前中后需要更具体预期时，在同一时刻增加有描述的 checkpoint；同帧会合并理由，不重复导出。

## 抽取检查帧

脚本只依赖 Python 标准库、`ffmpeg`、`ffprobe`。先把 `SKILL_DIR` 设为当前 Skill 的实际安装目录、`PROJECT_DIR` 设为本次视频项目目录的绝对路径，不依赖固定工作目录。

```bash
python3 "$SKILL_DIR/references/scripts/review_video.py" \
  --video "$PROJECT_DIR/final.mp4" \
  --timing "$PROJECT_DIR/audio-build/timing.json" \
  --mux-report "$PROJECT_DIR/final.mux-report.json" \
  --checkpoints "$PROJECT_DIR/checkpoints.json" \
  --mode visual \
  --output "$PROJECT_DIR/review/round-1"
```

选择采样模式：

- `visual`（默认）：首尾、每分镜代表帧、已指定的机制事件和 checkpoints。常规画面审阅从这里开始。
- `captions`：首尾、每句字幕中点、字幕开始/结束边界两侧的实际相邻帧，以及显式 checkpoints；不自动加分镜代表帧和机制事件。**首次完成有声字幕成片、修改字幕显示逻辑或时间轴，以及出现字幕闪烁、遗漏时，必须做这项专项检查。**
- `full`：合并 visual 与 captions，适用于同时需要两种检查的版本；不把它作为常规审美的必经步骤。

字幕专项使用同一命令，将 `--mode visual` 改为 `--mode captions`，输出到新的专项目录。真实同步还需要播放听音，边界截图不能单独证明声音同步。

`--timing` 使用配音和字幕共用的 canonical JSON，优先读取 `display_captions` 的 `start / end / text`；旧格式回退到 `captions`。`observed_captions` 保留原始观察，不自动充当最终显示时间。不得为了抽帧捏造字幕时间。只有视频但没有字幕时间表时，可以用 `{"captions":[]}` 提取画面；工具将字幕时序标为 `unknown`，不能推断没有字幕或字幕通过。明确无字幕的 canonical 文件使用 `subtitle_mode: "none"`，或使用无字幕合成报告。

字幕由合成脚本烧录时传入 `--mux-report`。工具核对最终视频和 timing 的 SHA-256，再使用 `subtitles.captions` 中实际 ASS 量化后的 `ass_start / ass_end` 及 `display.text`；翻译字幕仍按最终显示文本审阅。旧文件没有报告时可省略，manifest 会记录未验证报告，边界使用 display 时间线。原观察区间仍保留在 manifest。

脚本按实际帧的呈现时间戳定位并去重，支持可变帧率。默认最多 48 张：优先保留首尾、各镜代表帧，再保留机制与指定点、字幕中点和边界。同优先级达到上限时分散选取，不把遗漏藏起来。

输出：

- `frames/`：全尺寸 PNG。每个分镜代表帧都要单独打开，必要时放大细节。
- `thumbs/` 与 `contact-*.jpg`：带帧号、时间的缩略图及联系图，只用于总览全片风格、尺度和推进关系。
- `manifest.json`：输入哈希、模式、代表帧与分镜关联、时间线预期、覆盖量和缺口。`expected_caption` 不是 OCR 结果，`extracted` 只表示图片已导出。
- `checklist.md`：每镜布局、文字、原理、风格的实际观察栏，问题/修改/同点复查链，以及最终播放记录；生成材料不代表通过。
- `recheck-points.json`：已抽取的实际时间与原检查理由，供同点复查。
- `omitted-points.json`：被上限省略的候选点。遗漏的代表帧和必要专项点要补查，不能宣称已覆盖。

## 逐帧目视检查

先看联系图了解全片，再**逐张单独打开每个分镜代表帧**，以 [质量目标](visual-direction.md#质量目标) 逐镜记录实际观察。不能只看九宫格、读预期文字或打勾。没有问题时也简短写出具体观察，不写空泛的“高级、精致、通过”，不设置自评分。

- **布局**：主要对象能否辨认，尺度、视觉焦点、空间关系、层级和留白是否服务解释；开场有主题相关的视觉锚点，允许及时且可追踪的入场。
- **文字**：标题、标签、字幕是否各司其职；中文缺字、断行、字号、对比度、遮挡和越界情况。先看完整画幅，再放大标题区及四周，核对整段文字的最后一个字、每行底部和相邻标签；文字锚点或容器在屏内不能证明字没有被裁。缩至手机尺寸仍能读到重点。
- **原理**：输入、作用位置、变化、方向与结果是否连在同一对象上；结构、比例、轨迹、变量编码是否表达已核实的知识。不能仅确认画面符合自己写的分镜；复杂机制再逐张看前中后。
- **风格**：主视觉是否完成，字体、色彩角色、线条、材质和素材边缘是否统一；是否粗糙、拥挤、空泛或机械重复。能播放但未达到质量目标不能判为审美通过。

具体问题要指出对象、位置或关系，例如哪个关键部件太小、哪些文字相互遮挡、哪一步因果未画出；检查后修改实际画面。对字幕、转场或机制的疑点按需补查，不用增加无目的截图代替判断。

文字动效还需连续播放核对：出现时点是否对应当前讲解，强调是否与图形联动，完整文字是否留足阅读时间，以及入场、强调、退场过程中有无裁字、碰撞或闪烁。将发现问题的时点加入 `checkpoints`，修改后复查相关动作全程。

## 修改与复查

顺序是：每镜看图并记问题 → 修改和重渲染 → 同点及相关状态复查 → 连续播放最后交付版本。每条问题记录“时间/帧号—分镜预期—实际差距—修改—复查证据—状态”。只改分镜文字或总结不算修复。文字越界与重叠的修复须重新覆盖原问题时刻及相关入场、移动、缩放、退场过程；同时核对引线落点，不能以裁字、遮盖或漏掉必要标签制造“无重叠”。浏览器布局报告不能证明后加字幕的最终遮挡情况，仍需检查合成后的画面。

同点复查或补查遗漏点，传入对应 JSON，使用兼容选项 `--only-checkpoints`：

```bash
python3 "$SKILL_DIR/references/scripts/review_video.py" \
  --video "$PROJECT_DIR/final-revised.mp4" \
  --timing "$PROJECT_DIR/audio-build/timing.json" \
  --mux-report "$PROJECT_DIR/final-revised.mux-report.json" \
  --checkpoints "$PROJECT_DIR/review/round-1/recheck-points.json" \
  --only-checkpoints \
  --output "$PROJECT_DIR/review/round-2"
```

`--only-checkpoints` 覆盖 `--mode`，只使用给定的 scenes/events/checkpoints 与首尾，不再追加字幕采样；补查遗漏时把输入换成 `omitted-points.json`。仍有遗漏则继续补查或明确缺口；确有必要时可提高 `--max-frames`，上限 240。补查文件须与首轮逐镜记录关联，它本身不重新证明全片覆盖。

修改配音或镜头时序后，更新 canonical timing、`review_at` 和机制事件，同时检查旧故障时点与新的语义位置。每轮使用新目录保留前后证据，不沿用旧截图的通过结论。没有新问题不重复同一检查；审美最多再做两轮聚焦优化，每轮集中解决 1–3 个具体问题。轮次上限不是质量放行条件：硬错或质量目标仍未满足时，继续修复或明确未完成。

静帧问题修复后，实际连续播放最后交付版本，核对运动、转场、阅读停留、口播完整性与字幕同步，并记录版本/哈希、实际观看与听音范围及结果。**只有工具确实支持且已经完成播放、听音，才能声明相应验收通过。** 无法播放或听音时保留缺口；媒体摘要和离散截图不能替代。之后再修改视频，须复查受影响画面并重新确认最后版本。

## 运行检查与覆盖范围

脚本不改视频、不烧录字幕，不做 OCR/ASR 或自动审美评价。没有看像素的能力时，只报告机械检查和视觉验收缺口；收到具体可执行反馈后可以修改，但不能伪称亲自验证了美感。

MP4 抽帧不能发现浏览器 console/page errors、字体/图片请求失败、异步加载竞态或正反向 seek 不一致。渲染前使用已有浏览器/HyperFrames 检查能力核对，修复真实错误；依赖不存在时说明未覆盖的检查项。

最终分别记录机械检查、实际逐镜看图范围、播放/听音范围、剩余问题。`awaiting_visual_and_audio_review` 是待审提醒，不是评分；不能用脚本成功或覆盖计数替代成片合格。
