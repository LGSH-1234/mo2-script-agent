# 抖音与电商创作扩展库

为现有产线补充创作方法和行业细节。主流程仍使用 `douyin-short`、`ecommerce-pdp-production` 和当前产线指引；本库按任务提供一个补充模块。商品详情页继续用原来的七段式输出；商品视频不强套详情页格式。

## 选择资料

先选择下表中一篇适配指南，再按需读它指向的原文。一次只取当前问题需要的材料。

| 文件 | 用途 | 何时读取 |
|---|---|---|
| hooks-and-copy.md | 商品钩子、种草脚本、口播、微叙事 | 前几秒留不住人、卖点讲不清、要直播话术 |
| product-visuals.md | 品牌母版、服装、美妆、珠宝、主图与详情页 | 商品图套件、模特展示、品牌一致性 |
| vlog-and-local.md | 探店、美食、通勤、家居、健身、购物与文旅 | 生活场景、到店种草、Vlog |
| shot-direction.md | 广告创意、分镜、表演、真实感和转场 | 已有创意需要变成可拍镜头 |
| growth-and-research.md | 热点、竞品、指标口径与素材复盘 | 找选题、分析不转化的原因 |
| variants-and-editing.md | 多版本矩阵、共享素材、局部修改与语言适配 | 批量裂变、素材疲劳、局部返工 |
| runtime-adaptation.md | 原平台能力与当前工具的对应及缺口 | 执行生成、编辑、研究或调度前 |
| source-index.md | 80 套技能的分类与读取路径 | 用户点名技能或指南未覆盖 |

调用示例：

```text
load_skill_reference(skill="short-commerce-library", name="hooks-and-copy")
list_skill_references(skill="short-commerce-library", prefix="source/generate-ecommerce-hook-videos")
load_skill_reference(skill="short-commerce-library", name="source/generate-ecommerce-hook-videos/SKILL")
```

`source/` 内保留用户目录的完整原件，包括 80 个 SKILL 及配套文件。它们是**来源资料，不是自动激活的 80 个技能**。原文中的 `load_skill("某原技能")` 改为按这里的来源路径读取；原文相对链接以该原文所在目录解析。文件很长时沿工具返回的 `offset` 读完相关部分，不把截断结果当全文。

需要源技能的参考章节时先 `list_skill_references` 查看该目录的真实文件名。原文所引用但目录中没有的技能或接口，不假装存在；优先采用本项目适配指南中的可行流程。原始脚本与示例资产随库保存，但不因读到原文就安装依赖、执行脚本或启动服务。

## 展示约定

常规回复、技能推荐、目录介绍与交付成品只展示能力、方法和结果，不附带本技能资料的原作者、原平台、来源名称、账号或导入目录。读取参考原文后也遵循此约定，不照搬其中的作者介绍和平台宣传。内部归档与许可记录保留用于维护，不自动作为署名信息输出；不将参考方法声称为本项目原创。商品事实、研究数据和引用证据的出处仍按任务要求保留。

## 本项目的执行约定

1. **用户交付目标决定工作范围。** 只要文案就交文案；已有脚本只改指定部分；明确了风格、时长、画幅、数量和素材就直接沿用。原文中的固定 5/15 秒、默认人物、强制批量、强制逐阶段确认均是原模板约定，不覆盖本次要求。
2. **先锁真实商品，再做表达。** 建立商品事实表：SKU、颜色、结构、规格、价格、活动期限、证据来源、允许使用的品牌资产。缺失数据标待补，不能套用示例的价格、销量、评价、功效、认证、店址或第一人称经历。
3. **方法能用，不代表接口已接入。** `sandbox_*`、`render_video`、`pippit_omni_search`、`dynamic_questionnaire`、`schedule_manage` 等是原平台名；不得调用、伪造返回或把名字简单替换后沿用参数。先读 `runtime-adaptation`，需要时 `load_tool_schema` 查看实际工具。
4. **模型沿用当前配置与锁。** 原文指定的 Seedance 2.5、Seedream、MJ、数字人服务等不构成可用性或换模型授权。不改 `.env`、模型配置、预算或权限来满足原文。付费调用和换模型继续走项目现有机制。
5. **产物进入现有资产链。** 方案/版本矩阵用 `save_draft(kind="outline")`，文案/分镜说明用 `copy`；返工保存新版本并填 `parent_id`。用 `fs_import` 登记用户素材、`fs_export` 导出。电商屏号、广告镜号不填写短剧 `episode`。
6. **营销文字后期排。** 将每镜拆成画面、口播、字幕/贴片、声音四栏。图像用无字底图加 `make_poster`；视频文字用 `overlay_text`。包装与商标保留可核对的商品参考，文字准确性另行检查。
7. **结果据实交付。** 参考资料只提供方法；真实感、ROI 和“爆款”不保证结果。平台规则、时效数据、模型规格必须结合实际来源核验。现有机审不等于平台审核；未生成、未检查、未合成的部分明确说明。
8. **失败有边界。** 单个创意问题修正最多两次后列出缺失条件；工具失败遵循现有重试/预算规则。已成功的版本保留，只补失败项。不能声称未运行的独立专家、多代理流程、定时任务、投放或发布已完成。

## 按交付物结束

- 文案：可直接使用的文本、事实依据和待补项。
- 方案：镜头/屏位顺序、时间、商品动作、台词、贴片、素材来源和下一步执行条件。
- 图片：实际图片资产、尺寸、版本和需人工核验项。
- 视频：实际成片资产与检查结果；只完成提示词时明确说是提示词。
- 复盘：可追溯的数据、口径、假设和下一轮可检验的素材变化。
