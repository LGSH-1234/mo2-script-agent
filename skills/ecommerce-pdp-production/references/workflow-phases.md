# 工作流细则（Phase 1-7）

> 接入说明：AGENT 名称表示职责分工，当前由主 Agent 按阶段执行。遵循 SKILL.md 中的执行约定：用户范围优先、已有确认沿用、参考规则待核验、修正重试有上限。

---

## Phase 1：需求解析报告

### 输入
用户提供的商品信息 + 现有素材。

### 动作
1. 读取 `style-routing.md` 获取品类路由表与复杂度档位
2. 提取商品要素，做特殊品类自动检测
3. 判定信息是否充足

### 输出

```
[需求解析报告]

>> 品类：[具体] / [路由到的品类]
>> 核心卖点：[1 主 + 2-3 辅]
>> 目标客群：[年龄/场景/价格敏感度]
>> 平台：[平台]
>> 复杂度档位：[S/M/L]（[N]屏，[N]张素材）
>> 路由结果：→ [品类]行 → [调性] + [主色] + [证明方式] + [首屏策略]
>> 自动检测：[命中特殊品类] → [追加合规规则]
>> 品牌资产：[有/无] → [沿用/新建]
>> 素材现状：已有 [清单] / 缺失 [清单]
>> 信息充足：[是 → Phase 2 / 否 → 需补充：[缺失项]]
```

### 判定
- 缺**商品图**或**平台** → 信息不足，必须补
- 缺**客群**或**价格带** → 可标【暂定】继续（但文案调性会受影响）
- 信息充足 → Phase 2

### 复杂度的判定不看用户说了什么

用户说"简单做一下"，但如果品类是美妆（15 屏）且客单价高，实际需要 L 档。
**按品类路由表的「长度」列 + 素材数量判定，不按用户主观描述。**

## Phase 2：AGENT-1A + AGENT-1B（并行）

### AGENT-1A：卖点结构与转化路径

**职责**：决定「每屏说什么、按什么顺序说」。

**输出**：

```
[AGENT-1A 输出]

一、核心卖点提炼
主卖点：[唯一，最可验证且有差异化的]
辅卖点：[2-3 个]
删除的卖点：[列出被删的 + 原因（无法验证/无差异/与主卖点冲突）]

二、决策疑虑排序
| 序号 | 用户疑虑 | 真实程度 | 该放第几屏 |
|---|---|---|---|
（按真实决策顺序排，不按卖点重要性排）

三、逐屏规划
| 屏 | 功能 | 疑虑 | 卖点 | 证明方式 | 卡 |
|---|---|---|---|---|---|
| 1 | 建立认知 | 这是什么 | 全貌 | 单品种草首屏 | hero__single-product-hero |
| ... | ... | ... | ... | ... | ... |

四、文案骨架
每屏主标题一句话（不超过 12 字）

五、行动指引
末屏 CTA：[具体文案]
```

**关键规则**：
- **决策疑虑的排序按用户真实决策顺序**，不是按卖点重要性
- 常见顺序：这是什么 → 适合我吗 → 凭什么信 → 值不值 → 怎么买
- 无法证明的卖点**删掉**，不硬写成"说明"
- 同一张卡在单页内 ≤2 次

### AGENT-1B：视觉与品牌工艺

**职责**：决定「长什么样、用什么参数」。

**输出**：

```
[AGENT-1B 输出]

一、色彩系统
主色：[#XXXXXX] 占比 XX%
辅色：[#XXXXXX] 占比 XX%
强调色：[#XXXXXX] 占比 ≤10%
理由：[为什么这套配色适合这个品类与价位]

二、字体系统
标题：[字体 + 字重]
正文：[字体 + 字重]
层级：[字号阶梯]

三、光影方向
主光：[方向 + 软硬 + 光比]
辅光：[...]
统一要求：[全页光影方向必须一致]

四、构图节奏
| 屏 | 景别/构图 | 商品占比 | 留白率 |
|---|---|---|---|

五、技术风险点
- [风险1] → [预防措施]
- [风险2] → [预防措施]
```

### 合并规则

1A 与 1B 冲突时：
- **卖点优先**（1A 决定说什么，1B 服务于它）
- 1B 的技术限制无法满足 1A 时（如"要体现免烫但没有对比素材"），1A 降级为「说明」而非「证明」
- 冲突必须在 Phase 3 门禁中显式记录

## Phase 3：Quality Gate 1（四维审查）

读取 `quality-gate-spec.md`。

| 检查项 | 通过标准 |
|---|---|
| 卖点 ↔ 视觉 | 主卖点有对应视觉证据 |
| 规格 ↔ 平台 | 尺寸/大小/白底/水印合规 |
| 手法 ↔ 决策阶段 | 首屏认知、中屏比较、末屏促动 |
| 品牌色 ↔ 品类路由 | 与路由一致或说明打破理由 |

不通过 → **回到 Phase 2 改具体项**。

---

## Phase 4：串行精修

### AGENT-2A：真实性工程

**职责**：消除「一眼假 / 一眼摆拍」的痕迹。

**检查项**：

- [ ] **材质不完美**：面料有轻微起毛、金属有加工痕迹、食品断面不规则
- [ ] **使用痕迹**：衣物有自然褶皱、器具有使用磨损、包装有轻微压痕
- [ ] **场景杂讯**：背景有其他生活物品、光线有方向与色温、非严格对称
- [ ] **手模真实**：有指节纹理、指甲不完美、皮肤有毛孔
- [ ] **配件关系**：拉链/扣子/缝线有真实结构，不是贴图
- [ ] **全局禁忌**：无塑料光泽、无过度磨皮、无死白背景

**输出**：
```
[AGENT-2A 输出]
瑕疵/真实感清单（≥3项，跨≥2类别）：
1. [类别] — [具体做法]
2. [类别] — [具体做法]
3. [类别] — [具体做法]
反摆拍措施：[...]
全局排除：[...]
```

### AGENT-2B：合规与规格锁

**职责**：确保页面能上架。

读取 `compliance.md`。

**检查项**：
- [ ] 规格：尺寸/分辨率/文件大小/白底/水印
- [ ] 绝对化用语：逐条排查
- [ ] 效果声明：限定条件完整
- [ ] 对比图：同条件
- [ ] 特殊品类专项：已按检测结果执行
- [ ] 肖像/品牌授权

**输出**：
```
[AGENT-2B 输出]
规格核对：[逐项]
合规扫描：发现 [N] 处风险 → [逐条列出 + 修改建议]
品类专项：[已执行的规则]
```

### AGENT-2C：配套素材设计

**职责**：把详情页内容延展到其他渠道。

**输出**：
```
[AGENT-2C 输出]
社媒尺寸：
- 小红书 3:4（1242×1656）
- 抖音 9:16（1080×1920）
- 微信朋友圈 1:1（1080×1080）

短视频钩子：前 3 秒 [具体]
搜索关键词：[主词 + 长尾词，5-8 个]
页内锚点：[可被跳转链接指向的屏位]
```

## Phase 5：结构化整合输出

**逐屏输出，每屏输出后立即自检。**

读取 `output-format.md`。

### 流程

```
for each 屏:
    1. 按七段格式输出设计
    2. 整合为可执行指令（七层）
    3. 立即三维自检（转化 / 视觉 / 合规）
    4. if 不通过: 当场重写 → 回到 1
    5. if 通过: 进入下一屏
```

### 三维自检

| 维度 | 检查点 |
|---|---|
| ① 转化 | 本屏解决了一个真实疑虑 / 卖点有依据 / 不重复上一屏 |
| ② 视觉 | 信息点 ≤3 / 留白 ≥30% / 色号正确 / 商品外观一致 |
| ③ 合规 | 无绝对化用语 / 效果声明有据 / 品类专项已过 |

**自检不通过必须当场重写，不进入下一屏。**

---

## Phase 6：Quality Gate 2

读取 `quality-gate-spec.md`。

- **三代自检**：转化 → 视觉 → 合规
- **五重会审**：转化设计师 / 品牌视觉总监 / 视觉摄影指导 / 合规审核官 / 目标用户代表

全部通过 → 确认门。

---

## Phase 7：确认门

```
[确认门]
1. 方案整体是否符合品牌意图？
2. 请选择图片生成/拍摄方式？（实拍 / AI生成 / 混合）
3. 详情页长度？（5屏 / 9屏 / 15屏）
4. 是否需要社媒素材延展？
```

**全部确认后才可执行。产出不加元数据头。**

---

## Phase 8：局部返工

用户指出某屏问题时：

```
1. 定位问题屏
2. 判断是「屏级问题」还是「结构级问题」
   - 屏级（构图/文案/视觉）→ 只重做该屏 + 检查衔接
   - 结构级（卖点排序/疑虑错配）→ 回 Phase 2 修正后重跑 Phase 5
3. 重做后检查与相邻屏的一致性（色号/光影/商品外观）
```

**原则**：局部问题局部修。但**卖点结构问题必须回 Phase 2**——在错误的骨架上修肉是无效的。

### 判断是屏级还是结构级

| 症状 | 级别 |
|---|---|
| 「这屏图不好看」 | 屏级 |
| 「这屏文案太弱」 | 屏级 |
| 「第 3 屏讲的东西我不关心」 | 结构级（疑虑排序错） |
| 「整页看完不知道重点是什么」 | 结构级（卖点未提炼） |
| 「颜色不统一」 | 结构级（Phase 1B 问题） |
